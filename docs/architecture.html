Audio_ALG 架構說明

單通道全雙工語音增強 Pipeline — linear AEC + echo-aware NR/RES gain fusion

AEC (PBFDKF + Shadow + RES)  ·  NR (MMSE-LSA + MCRA + SPP)  ·  8/16/48 kHz power-of-two grids / float32

範圍：本頁只說明 conventional mono pipeline，不是 AINR、 AIAEC 或 4-channel signal-grid contract。實際 API、memory sizing 與 tuning 以 pipelines/README.md 為準;呼叫順序與時序圖見 integration_sequence,mono 參數的外部／內部分級見 pipeline_mono_params。

1. 整體架構與訊號流

Pipeline 共四個處理階段，每次 process 一個 grid hop。預設為 16 kHz、256-sample frame/FFT、128-sample hop；另支援 16 kHz 512/256、48 kHz 1024/512 與 8 kHz 256/128（AEC 的 legacy 格點，非產品格點）。所有 grid 都是 frame=FFT、50% overlap，不做 zero-padding：

圖 1：整體 pipeline 概觀
關鍵點（echo-aware joint 設計）：
  1. HPF 只對 mic path 做；ref（far-end）不經 HPF（far-end HPF 預設 OFF，downstream Saturation / DelayEst 吃原始 ref）
  2. AEC 只做線性消除，輸出 E(f) + AecResContext（殘響回音功率 R²、res_gain、CNG、ERLE、DT 指標）
  3. NR 把 R² 折進雜訊地板：ξ = S²/(N²+R²)，用一個 MMSE-LSA gain 同時壓雜訊＋殘響回音（無 re-FFT）
  4. gain fusion g_total = min(G_nr, G_res)：每個 bin 取兩個 gain 的較小者，沒有 near-end floor；comfort noise 只補 RES 切掉的 bin
  5. 分析 STFT 在 AEC 內做一次（periodic sqrt-Hann、50% overlap），合成由應用的 AcIstft 做一次（iFFT + sqrt-Hann OLA）；中間的 NR 與 gain 融合都是頻域 block，可替換（NN seam）

2. HPF 高通濾波器

目的：移除 DC offset、低頻 rumble、50/60 Hz 電源 hum，避免污染 AEC 自適應演算法。

圖 2：HPF 頻率響應 — 80Hz 以下大幅衰減，語音頻段透通
項目規格
類型2nd-order Butterworth (IIR)
截止頻率80 Hz (−3 dB)

位置mic-path HPF 在 AEC module（lib/aec config 預設 ON）；另有獨立 C 元件 audiolib/common/src/hpf.c 供應用層使用
注意：HPF 只對 mic path 做一次；ref（far-end）不經 HPF（lib/aec config 預設 mic-path HPF=ON / ref HPF=OFF）。downstream Saturation / DelayEst 吃原始 ref。

3. AEC — PBFDKF + Shadow Filter

線性 AEC 的核心是 PBFDKF（Partitioned Block Frequency-Domain Kalman Filter）搭配 shadow filter 的雙濾波器策略，並有 Echo Path Change（EPC）偵測與 stationary far-end 的 double-talk 保護。結構圖、config 常數與各機制的觸發條件收在 architecture_aec.html（拆頁以維持單頁大小）；演算法本體見 lib/aec/docs/aec_methods.md。

4. NR — SPP + OMLSA

NR 處理 AEC 輸出的 error 訊號，移除背景噪音同時保留近端語音。三大組件：MCRA + SPP + MMSE-LSA。

整合 pipeline（joint echo-aware）：NR 直接吃 AEC 的頻域 E(f)（無 re-FFT）， 並把 AEC 估的殘響回音功率 R² 折進先驗 SNR：ξ = S²/(N²+R²)，讓同一個 MMSE-LSA gain 一次壓掉雜訊＋殘響回音。底下的 MCRA/SPP/MMSE-LSA 是 NR 單獨運作時的演算法本體。
圖 6：NR 三組件協作流程

4.1 MCRA — 噪音追蹤

用 minimum tracking 估計噪音 PSD；L 依 grid 換算，以維持接近的 wall-clock 統計視窗（16 kHz 256/128 預設為 64 hops，約 512 ms）：

P[k,n] = αp · P[k,n−1] + (1−αp) · |Y[k,n]|²
Pmin[k] = min over L hops
Sr = P / Pmin < δ → 更新 noise_psd

4.2 SPP — 語音存在機率

對每個 frequency bin 估計「該 bin 是語音」的後驗機率：

γ[k] = |Y[k]|² / noise_psd[k]   (a posteriori SNR)
ξ[k] = α · ξprev + (1−α) · max(γ−1, 0)   (decision-directed)
p[k] = 1 / (1 + (1+ξ) · e−v · q/(1−q))

4.3 MMSE-LSA — 對數頻譜 MMSE 增益

Ephraim & Malah 1985 的對數頻域 MMSE 估計，加上 SPP 加權（OMLSA）：

GLSA[k] = (ξ / (1+ξ)) · exp(½ ∫v∞ e−t/t dt)
G[k] = GLSAp[k] · gmin1−p[k]

5. Post-filter — RES + CNG

RES 是 AEC3-aligned 的抑制鏈（AecState → ResidualEchoEstimator → SuppressionGain），在 AEC 內部以頻域計算 G_res(f) 與 R²(f)，經 AecResContext 交給 pipeline；它不是 NR 之後的第二個時域濾波器。演算法本體見 lib/aec/docs/aec_methods.md §3。mono 的 RES 增益就是這個 AEC 自己的 ctx.res_gain（經 aec_get_res_context() 讀 AecResContext.res_gain，強度用 aec_set_level()）；4ch 的 post-beam RES 不在 mcab 內（mcab_fuse() 讓 g_res_ctx 為 NULL），而是由 libaec 管理、應用在自己的 init 建立的 AecRes（aec_res_get_mem_size()／aec_res_init()，每 hop aec_res_process(res, &in)，強度用 aec_res_set_level(res, …)）；NR 與最後合成一律是另外初始化的函式庫物件。

5.1 Gain fusion

g_total = min(G_nr, G_res)，每個 bin 取兩個 gain 的較小者並對 E(f) 套用一次；沒有 near-end floor。NR 把 R² 折進先驗 SNR，因此兩個 gain 不是重複計算同一件事。

5.2 CNG (Comfort Noise Generation)

Comfort noise 由 AEC 的 comfort_noise PSD 產生，只填 G_res 切掉的 bin；位準再乘該 bin 的 G_nr（下限 −10 dB，範例內的 CNG_NR_GAIN_FLOOR／MCAB_SAMPLE_CNG_NR_GAIN_FLOOR），讓補進去的噪聲落在降噪後的底噪。pipeline 預設 enable_cng=1。
