全鏈延遲預算表

概要

演算法延遲（不含排程／緩衝）逐階段的預算：mono 與 4ch 的 ULCNet pipeline、以及 DFN2 變體（mono 與 4ch）。 格點、視窗與 framing 慣例在 conventions。4ch 的前級是 mcab flow（共享 delay + 四條注入的 lane， mcab_process_front() → beamformer → mcab_fuse()；範例用 sample helper mcab_sample_beam_* 做 SRP-PHAT + BF）； mcab 不含 RES，DFN2 的 4ch 範例由 main 自己用 libaec 的 AecRes 算 RES 增益，所以下表「RES gain」一列的歸屬依應用而異。

mono ULCNet pipeline（16 k / 512 / 256；48 k 為 1024 / 512）

階段新增延遲說明
AEC 線性路徑（pbfdaf_frontend，overlap-save） +0 hop線性誤差與輸入同 hop 交付（AecResContext.formed_hop）
Align-ULCNet 鏈（rolling center=False STFT ×2 → NN callback → WOLA） +1 hop（16 k: 256 smp = 16 ms；48 k: 512 smp = 10.67 ms） ulcnet_process.h：hop#0 無輸出（pipeline 補零）、hop#p 輸出 對應輸入 [（p−1)·HOP, p·HOP)
合計1 hop（16 k: 16 ms；48 k: 10.67 ms） ulcnet/ulcnet_nn_stage.h：「Timing: one hop of added latency; hop #0 of the stream emits zeros」；輸出 hop p ≙ 輸入 hop p−1

4ch ULCNet pipeline（16 k / 512 / 256；48 k 為 1024 / 512）

階段新增延遲說明
共享 delay matcher + 4×AEC lanes + SRP-PHAT DOA + BF 權重 （mcab_sample_beam_process_with_activity()：mcab_process_front → doa_step → bf_process_with_weights）； 這條 pipeline 的 mcab enable_post = 0，不建 RES +0 hop同 hop 產生 beamformed 線性誤差頻譜
BF 頻譜直送模型（不重建、不再分析）+0 hop bf_spectrum 已是當前 hop 的 sqrt-Hann、50% overlap、一 hop 一幀 分析幀（各 lane 在 AEC 內分析，beamformer 只逐 bin 加權），拆成 err_re/err_im 直接餵 model
far 分支 AcStft（center 0）+0（平行） 同一 hop 的 far 走同樣的一 hop 一幀 framing（center=False）， 兩路幀對恆屬同一輸入 hop；沒有補償 buffer
Align-ULCNet synthesis（WOLA 半窗 trim）+1 hop （16 k: 256 smp = 16 ms；48 k: 512 smp = 10.67 ms）同 mono 變體
合計（新增）1 hop（16 k: 256 samples = 16 ms； 48 k: 512 samples = 10.67 ms） ulcnet/ulcnet_nn_stage.h 的 timing 契約：僅 hop#0 輸出零； 輸出 hop p（p≥1）≙ 輸入 hop p−1 的 beamformed 線性誤差。 測試以 far 單位脈衝釘住：16 k far[2085]→out[2341]（= 脈衝位置 + 1 hop = 256 samples，offset +0）； 48 k：far[4133]→out[4645]（= 脈衝位置 + 1 hop = 512 samples，offset +0），make -C pipelines/4ch_aec_bf_nr_res test-grids 兩個格點各跑一次

NN 模型本身：Align-ULCNet 演算法 lookahead = 0 （readiness 總覽矩陣）；上表已含其 framing 的半窗 lookahead。

DFN2 變體（mono 與 4ch）

DFN2 stage 永遠在 48 k / 1024 / 512；host 則跑產品自己的取樣率。下表先列 48 k host，再列原生格點多付的 rate-bridge 延遲。

階段新增延遲說明
傳統前級（mono：線性 AEC，RES 增益在 aec_process_context() 內算出，經 aec_get_res_context() 的 res_gain 取得； 4ch：mcab 的共用 delay → 4 lane → SRP-PHAT → BF 逐 bin 加權 → mcab_fuse()（經 helper 則為 mcab_sample_beam_fuse()），RES 增益由 main 自建的 libaec AecRes 經 aec_res_process() 算；兩者皆可再加 comfort noise） +0 hop同 hop 交出兩個頻譜：error_spec/beamformed_error（E，pre-RES，即 dfn_res_stage_begin() 的 estimate_spec）與 post-RES 頻譜（P = E·G_res，開啟 CNG 時再加 comfort noise；DFN2 變體預設關；即 apply_spec）
dfn_res_stage 的尺度換算+0 hop 入 2^-5（0x1p-5f）、出 2^5（0x1p5f）：pipeline 頻譜是 audio-scale 未正規化 STFT，DFN2 邊界要 torch.stft(normalized=True)。兩者都是精確的 2 的次方， 往返在 float32 下逐位元可逆（pipelines/dfn/dfn_res_stage.h）
DFN2 模型 lookahead（48 k host）+L hop，L = M + D（出貨 pair 1/1：+2 hop = 1024 samples = 21.33 ms） DFN2_MASK_LOOKAHEAD + DFN2_DF_LOOKAHEAD，cascade 串聯相加而非取 max；M 為 0..2、D 為 0..4，共 15 個 pair，建置時以 make 變數選定（pipeline_dfn_detail）； 前 L 個 hop 的 stage 輸出是全零頻譜（寫滿，故延遲是純延遲）。DFN3（平行）的模型延遲為 max(M, D)（ainr_dfn2_detail）
host／應用的 sqrt-Hann WOLA（48 k：各 main 的 ac_istft_push() 或 dfn_hop_end() 內的 ac_istft_push()）+1 hop（512 samples = 10.67 ms） OLA 狀態屬於收尾的那個 AcIstft；同一個物件上混用兩種收尾方式仍連續
合計（48 k host）L + 1 hop；出貨 pair：3 hop = 1536 samples = 32.0 ms 兩個範例 main.c 印出的延遲（48 k：hop * (DFN_RES_STAGE_LOOKAHEAD_FRAMES + 1)；原生格點：hop + dfn_rate_bridge_added_delay_samples()）； 兩支 C 測試（test_mono_dfn.c、test_4ch_dfn.c）釘住 added delay 與 48 k 的 L+1 hop（出貨 3）
dfn_rate_bridge（host 在 8/16 k 時取代上面兩列的 lookahead + WOLA） host 的 1 hop WOLA + added delay added delay = prefill + lat_up + (DFN_RES_STAGE_LOOKAHEAD_FRAMES+1)×512×sr/48000 + lat_down×sr/48000 個原生樣本 （dfn/dfn_rate_bridge.c；prefill 由 init 用真正的 resampler 量出，lat_up／lat_down 是升/降頻 resampler 的 audio_resampler_latency_input_frames()）。 出貨 pair：16 k/hop 128 → 672（42.0 ms），總延遲 800 = 50.0 ms； 16 k/hop 256 → 629（39.3 ms），總 885 = 55.3 ms； 8 k/hop 128 → 330（41.3 ms），總 458 = 57.3 ms（mono 專有）。 (L+1)×512×sr/48000 是整數除法；L+1 不是 3 的倍數時 stage 延遲含小數個原生樣本而向下取整（pair 0/1：501／458／244；pair 2/4：1354／1311／671）， 脈衝峰值可落在 added delay 或其後一個樣本。延遲由脈衝釘住，但訊號經兩顆 FIR resampler 往返，不是逐位元等值 （pipelines/dfn/dfn_rate_bridge.c、 pipelines/dfn/tests/test_dfn_rate_bridge.c）

DFN2 的分析本來就是 center=False 串流（見 conventions 的 framing 一節），所以 48 k host 的格點與窗 就是模型的格點與窗——E 直接是一個合法的 DFN2 分析幀，不需要第二次 transform （pipelines/dfn/dfn_res_stage.h）；8/16 k host 則由 rate bridge 在 48 k 上另做一次同款 sqrt-Hann 1024/512 分析。AEC delay 改變不重置 stage 或 bridge：兩者都不消費 far-end。
