串接範例:四條 pipeline 怎麼組三個 lib

三個 lib 的 API 說明各自在 AEC API／NR API／audiolib API。本頁是「怎麼把它們接起來」的實作範例——四條出貨 pipeline 就是四份可編譯、已測試的參考接線。各 pipeline 自身的演算法說明在 pipeline_mono／pipeline_4ch／pipeline_ulcnet_mono／pipeline_ulcnet_4ch。

0. 先決定使用層級

需求入口
完整 mono AEC + NR + RESpipelines/mono_aec_nr_res/audio_pipeline.h
完整 4ch 4×linear AEC → BF → mono NR+RESpipelines/4ch_aec_bf_nr_res/audio_pipeline_4ch.h
4ch linear AEC 前端 + 外部 beamformer seam(自己串後級)pipelines/4ch_aec_bf_nr_res/4aec_nr_res.h(four_aec_front_process / four_aec_fuse)
mono linear AEC + NN 後級pipelines/mono_alignulcnet/audio_pipeline_ulcnet.h
4ch linear AEC + SRP/GSC + NN 後級pipelines/4ch_alignulcnet/audio_pipeline_4ch_ulcnet.h
mono 線性 AEC + 自己的頻域 stage 鏈audio_pipeline_process_spec() + audio_pipeline_synthesize()(見 2.5)
只做單路 AEC,或自行組合其他 post-filteraec.h
已有 STFT/WOLA,只需要頻域 NRanr.h
產品要的若是既有完整 flow,優先呼叫 pipeline API。不要在 application 重新複製 AEC/NR gain fusion、window、OLA 或 CNG 邏輯——那些細節(尺度換算、CNG LUT 索引)很容易做錯而且不會報錯。

1. 四條共通的骨架

面向四條一致的事實
AEC 一律 linear-seam四條全部無條件設 enable_res = 0、return_res_context = 1。AEC 只當線性前級,殘留抑制由 pipeline 自己(或 NN)做
沒有一條用 streaming APIaec_analyze_render()／aec_process_capture() 在 pipelines/ 下零引用 → AecBufferingEvent 在出貨路徑上結構性不可達
audiolib 只用到少數符號fft_*、ac_stft_*／ac_istft_*、sk_min_f32、sk_capply_gain_f32、ALIGN16/ck_*。沒有任何一條用 hpf_*／audio_pre_gain_*／audio_resampler_*——HPF 在 AEC 內部,gain 與 resample 是 pipeline 之外的前級
32-byte 固定寬度 descriptor四條的 *MemReq 形狀一致,都走 get_mem_requirements() → init_ex() 的 descriptor gate

2. 誰做 FFT、誰擁有 window、WOLA 在哪

這是接線時最容易搞錯的一件事,四條 pipeline 給了三種不同答案:

forward FFTanalysis windowNR gain 怎麼套inverse + WOLA
mono_aec_nr_resAEC 內部(ctx.error_spec 就是它的 50% overlap periodic-sqrt-Hann STFT)AEC 擁有NR 只算 gain 不套,pipeline sk_min_f32 融合後一次套pipeline 自己(獨立的 FftHandle)
4ch_aec_bf_nr_res每條 lane 的 AEC 內部,pipeline 借指標不複製各 lane 的 AEC同上,但 RES gain 來自一個共用 SuppressionGain(不屬於任何 Aec)pipeline 自己
mono_alignulcnetAEC 的 FFT 完全不用——ULCNet 自己的 STFT（AcStft，center 0，一 hop 一幀）做 forwardULCNet(rolling sqrt-Hann)沒有 NR(沒有 AnrDenoiser 實例)ac_istft_push_planar()（AcIstft）
4ch_alignulcnet頻域直送:① 每 lane AEC 的 STFT → SRP-PHAT + GSC;② GSC 的 mono 頻譜直接當 model 的 error 幀(不重建、不再分析),far 分支用 ac_stft_push_planar()（center 0）取同一 hop;③ model → ac_istft_push_planar()(吃掉 1 hop)
4ch_alignulcnet 的總演算法延遲 = 1 hop(16 k 256 smp/16 ms、48 k 512 smp/10.67 ms),只來自 synthesis 的半窗 trim。兩個 branch 都從當前 input hop 取幀,所以不可以有 far 補償 buffer——加回去就是 error[t] 配 far[t-1] 的一 hop 偏斜,而這種對齊細節沒有任何自動檢查。

2.5 串一個新的頻域 stage

四條 pipeline 共用同一個接縫:前端交出借用的 SeSpecFrame(pipelines/common/se_stage.h),增益類 stage 是 _gain(st, frame) -> const float*,NN 類 stage 是 _begin → (呼叫端跑 NPU) → _end。沒有函式指標表:每個應用自己把鏈寫出來,順序固定是 sk_min_f32 → sk_capply_gain_f32 → aec_cng_fill → ac_istft_push。

/* 一個 hop:frame 是借用視圖,有效至下一次前端呼叫;任何 stage 都不得寫入 */
const float *res_gain = se_res_stage_gain(res, &frame);           /* 增益 stage */
const float *nr_gain  = se_anr_stage_gain(nr, &frame, scratch, 1);   /* 另一個增益 stage */
sk_min_f32(total_gain, nr_gain, res_gain, frame.n_freqs);          /* 缺席的來源讀 unity 全 1 向量 */
sk_capply_gain_f32(spec, frame.e, total_gain, frame.n_freqs);      /* 套在 frame.e 上 */
aec_cng_fill(&rng, spec, frame.cn, res_gain, nr_gain, SE_CNG_NR_GAIN_FLOOR, frame.n_freqs);
ac_istft_push(istft, spec, out);                                   /* 這裡才呼叫 ISTFT:每 hop 恰一次 */
規則內容
記憶體stage 的 pool 由應用 carve:先用 *_get_mem_size() / *_mem_size() 查大小,再 *_init() 在 16-byte 對齊的區塊上建構;four_aec_nr_res_stage_configs() 與 mono 的 se_derive() 給出各 stage 的 config。process 路徑零 heap
非有限增益sk_min_f32 讓非有限增益一路傳到輸出的 finite gate(不像 fminf 把它蓋掉)
NN stage 的 fail-open_end(rc):rc≠0、輸出非有限、或 job 沒被取走 ⇒ identity,時鐘仍各前進一次

3. 範例 A:mono_aec_nr_res — 最完整的參考接線

建立

AudioPipelineConfig cfg = audio_pipeline_default_config(16000);
/* cfg.fft_size=0(rate default) aec_preset=BALANCED nr_mode=BALANCED
 * aec_only=0 enable_cng=1 legacy_amin=0 */

AudioPipelineMemReq req;
if (audio_pipeline_get_mem_requirements(&cfg, &req) != 0) { /* reject-first */ }
void *pool = platform_alloc(req.bytes, req.alignment);   /* 16-byte aligned */
AudioPipeline *p = audio_pipeline_init_ex(pool, req.bytes, &cfg, &req);

int hop = audio_pipeline_hop_size(p);                    /* 128 @16k default */
while (streaming) audio_pipeline_process(p, mic, ref, out);   /* 三者皆 hop floats */

audio_pipeline_reset(p);      /* echo path 變更時;不動 pool */
audio_pipeline_destroy(p);    /* 不釋放 caller pool */

每 hop 對底層 lib 的精確呼叫序列

這就是「怎麼串」的答案。aec_only=1 時只有第一行,其餘整段跳過:

audio_pipeline_process(p, mic, ref, out)
 │
 ├─ aec_only ─→ aec_process(p->aec, mic, ref, out)        ← 直寫 caller 的 out,結束
 │
 └─ 1.  analyse_hop():
          aec_process_context(p->aec, mic, ref)             ← 不取時域輸出,省一次 memcpy
          aec_get_last_timing(p->aec, ...)                  ← 只有 PROFILE=1 才有數值
          aec_get_res_context(p->aec, &ctx) + aec_get_linear_context(...)
          → SeSpecFrame f(借用 AEC 的 per-hop buffer)
    2.  nr_gain = se_anr_stage_gain(p->nr, &f, extra, !legacy_amin)
        └ extra[k] = f.r2[k] / PSD_SCALE(int16² → audio power, 32768²);無 NR 時 = unity 向量
    3.  sk_min_f32(g_total, nr_gain, res_gain, n_freqs)       res_gain = enable_res ? f.g_res_ctx : unity
        └ gain fusion = 逐 bin 取小
    4.  sk_capply_gain_f32(spec, f.e, g_total, n_freqs)
    5.  aec_cng_fill(&rng_state, spec, f.cn, f.g_res_ctx, nr_gain, SE_CNG_NR_GAIN_FLOOR, n)
        └ bins 1..n-2:a = sqrt(1-G_res²) * sqrt(N²/PSD_SCALE) * max(G_nr, 0.316)
    6.  ac_istft_push(p->istft, spec, out)
        └ AcIstft(ACCUMULATE):fft_inverse → acc += ifft*w → hop emit + shift
為什麼是 aec_process_context() 而不是 aec_process():兩個入口只差「要不要把結果複製出來」,所以純粹是成本選擇。aec_only=1 時 AEC 的輸出就是 pipeline 的輸出 → 用 aec_process() 直寫 caller 的 out;aec_only=0 時下游只讀 ctx.error_spec、從不碰 AEC 吐出的 hop → aec_process_context() 省掉那次複製。

Init 期的接線順序

aec_get_mem_size → aec_init
ac_istft_get_mem_size → ac_istft_init     ← AcIstft 自帶 FFT 與 sqrt periodic-Hann 窗,獨立於 AEC 內部的 FFT
anr_get_mem_size → anr_init
三個 scratch(＋選配 unity gain)逐一 carve + memset
grid agreement guard:
   aec_get_res_context(p->aec, &ctx0)  → 比對 n_freqs / hop
   fft_get_n_freqs() / anr_get_n_freqs() → 再比對一次
那個 grid agreement guard 值得照抄:三個 lib 各自 resolve 自己的 grid,如果 config 讓它們對不上,不檢查就會在頻域靜默錯位。自組 chain 時務必在 init 尾端做同樣的三方比對。

4. 範例 B:4ch_aec_bf_nr_res — 前端 + fuse,外部 beamformer

前端每 hop 兩個呼叫,中間是外部 beamformer:four_aec_front_process() 交出借用的 FourAecFront,four_aec_fuse() 用權重投影並填 SeSpecFrame。RES／NR／CNG／ISTFT 不在前端內,由應用明寫串接(完整範例:4aec_nr_res_static.c 與 tests/conv_chain_4ch.h)。沒有 token:fuse 要求之前至少處理過一個 front frame(否則 SEQUENCE_ERROR)。

FourAecFront front;
SeSpecFrame  frame;
int st = four_aec_front_process(core, mics_interleaved, far, &front);
if (st != FOUR_AEC_NR_RES_OK) { /* 見下方 status 表 */ }

/* ── 外部:SRP-PHAT / GSC,用 front.linear_spectra[4] 算出 Complex[4][n_freqs] 權重 ── */

st = four_aec_fuse(core, weights, NULL /* 或 GSC 已算好的 beamformed 頻譜 */, &frame);
/* 後級由應用串接;frame 為借用視圖,有效至下一次 front_process／reset */
res_gain = se_res_stage_gain(res, &frame);
nr_gain  = se_anr_stage_gain(nr, &frame, extra_noise, 1);
sk_min_f32(total_gain, nr_gain, res_gain, frame.n_freqs);
sk_capply_gain_f32(spec, frame.e, total_gain, frame.n_freqs);
aec_cng_fill(&rng, spec, frame.cn, res_gain, nr_gain, SE_CNG_NR_GAIN_FLOOR, frame.n_freqs);
ac_istft_push(istft, spec, out);

front 半的呼叫序列(重點在 far-FFT 共用)

1. inputs_finite(mic_interleaved, hop*4) && inputs_finite(ref)   ← 唯一的輸入 NaN gate
2. de-interleave proxy channel → mic_lane
3. update_shared_delay(...)          ← duty 決策 + matched filter + ERLE watchdog
4. align_render(ref, delay)  → aligned_ref
5. if (delay.changed) 四 lane 各跑 aec_apply_external_realign(lanes[ch], delta)
6. for ch in 0..3:
     de-interleave lane ch
     ch==0 : aec_process_context(lanes[0], mic_lane, aligned_ref)
     ch!=0 : aec_process_context_shared_far(lanes[ch], mic_lane, aligned_ref, shared_far_spec)
     aec_get_res_context(lanes[ch], &context)
     ch==0 → shared_far_spec = context.far_spec        ← lane 0 算,1..3 借
     bind_lane_view(&snapshots[ch], &context)          ← 借指標,不複製
7. front-valid 旗標置位(four_aec_fuse 的序列閘)
四條 lane 這一 hop 看到同一個 aligned_ref 指標,所以 lane 0 的 far-FFT 對其他三條逐位元相同 → 4 次 far-FFT/hop 變成 1 次。這是 aec_process_context_shared_far() 存在的理由,也是它嚴格的 same-hop/same-reference 前提的由來。

fuse 半

1. front-valid 檢查                         ← 序列協定
2. validate_weights():逐元 isfinite + Σ|.| > 1e-12
3. fuse_contexts():coherent projection,四 lane far_power 一致性檢查
   → 填 SeSpecFrame(e/y/x/r2/cn/far_hop/formed_hop/max_dt/max_sat/all_converged/delay 旗標)

之後是應用自己的幾行(上方範例):各 stage 回傳 const float* 增益,sk_min_f32 取小,sk_capply_gain_f32 套在 frame.e 上,aec_cng_fill 補舒適噪音,ac_istft_push 合成。輸出 NaN gate 由 wrapper(run_post_stages())對輸出 hop 做。

FOUR_AEC_NR_RES_* 狀態意義front frame
OK(0)成功可繼續使用至下一次 front_process
INVALID_ARGUMENT(−1)NULL、非有限輸入、權重不合法fuse 失敗時保留,可修正權重後重試
SEQUENCE_ERROR(−2)fuse 之前沒有 front frame—
DSP_ERROR(−3)內部已 self-reset已丟棄
四條 lane 都以 spatial_linear_context 建立,永遠走不到自己的 suppression path → 對 lane 呼叫 aec_set_preset() 依構造是無效操作。要改強度請用 audio_pipeline_4ch_set_aec_preset(),它針對的是 wrapper 自己 carve 的那個共用 post 級抑制器。

5. 範例 C／D:兩條 ULCNet pipeline — 接 NN 的做法

從 AEC 拿什麼

aec_process_context(p->aec, mic, ref);
aec_get_res_context(p->aec, &rctx);      /* rctx.formed_hop     ← 時域線性誤差 */
aec_get_linear_context(p->aec, &lctx);   /* lctx.aligned_far_hop ← 對齊後的 far  */

注意 mono 拿的是「時域」兩個 tap,不是頻譜——它有自己的 STFT,AEC 的 error_spec 完全不用;兩路都走 center 0 的 AcStft 與 ac_stft_push_planar()(rolling,不是 centered)。4ch不做 error 分析:bf_spectrum 直接當 error 幀,far 分支走同一個 ac_stft_push_planar()。排程由建立 AcStft 時的 center 決定(出貨 pipeline 都是 0;centered 只剩 parity 測試當基準)。

邊界偵測與 reprime

if (lctx.delay_state == AEC_LINEAR_DELAY_CHANGED
    || (FIXED 模式下 UNLOCKED→LOCKED 的首次轉換)) {
    if (p->model.reset) p->model.reset(user);   /* 通知 NN 丟棄跨 frame 狀態 */
    p->reprime_frames = REPRIME;                /* mono=1, 4ch=1 */
}
reprime frame 數是量測出來的,不是猜的:兩條都是 1——兩條的兩個 branch 都從當前 input hop 取幀,50%-overlap 幀橫跨兩個 hop,只有邊界 hop 那一幀還蓋到切換前的 hop。常數綁定 hop 結構,改 framing 必須重新量(test_reprime_straddle_derivation())。

Fail-open 三層 + FULL-WRITE CONTRACT

if (reprime_frames > 0) {
    /* identity,不 step model */
} else if (model.infer) {
    for (k) { mdl_re[k] = NAN; mdl_im[k] = NAN; }   /* ← 先全填 NaN */
    rc = model.infer(user, err_re, err_im, far_re, far_im, mdl_re, mdl_im);
    if (rc == 0 && ulcnet_frame_is_finite(mdl_re, mdl_im)) { /* 採用 */ }
    /* 否則 identity */
}
ac_istft_push_planar(synth, sre, sim, out + wrote);
Fallback 條件行為
infer == NULLidentity
infer 回非 0identity
輸出有任何非有限值identity

三種情況的時序路徑完全相同 → latency 不隨 model 健康度變動。先全填 NAN 是為了把「沒寫」變成可偵測——finite guard 抓得到未寫入,但抓不到寫錯形狀。

把推論留給 NPU:begin / nn_begin / nn_end / end

兩條 ULCNet 與兩個 DFN 應用都把一個 hop 拆成四個呼叫;加速器就坐在 nn_begin 與 nn_end 之間,模型 config 的 infer 回呼因此可以不設。一次呼叫的 process() 就是這個序列加上已安裝的回呼。

UlcnetNnJob job;
audio_pipeline_ulcnet_process_begin(p, mic, ref);             /* AEC、err／far 分析 */
if (audio_pipeline_ulcnet_nn_begin(p, &job) > 0) {            /* 1 = 有一幀;0 = 本 hop 無模型幀 */
    int rc = board_run_npu(job.err_re, job.err_im, job.far_re, job.far_im,
                           job.out_re, job.out_im);            /* out 已預填 NaN,必須寫滿 */
    audio_pipeline_ulcnet_nn_end(p, rc);                       /* rc!=0 或非有限 ⇒ identity */
}
audio_pipeline_ulcnet_process_end(p, out);                     /* 合成剛好一個 hop */

DFN 應用的 nn_begin 在迴圈裡(while (nn_begin(p, &job) > 0) { rc = run_npu(&job); nn_end(p, rc); }),因為 rate bridge 在一個 native hop 內可能開 0..2 個 48 kHz 幀。

4 聲道 ULCNet 應用若要用「由同一 hop 的 lane 頻譜算出」的 mask 與 VAD(例如 masker 讀 lane 0),把 process_begin() 拆成 audio_pipeline_4ch_ulcnet_process_front(p, mics, far, &front) 與 audio_pipeline_4ch_ulcnet_process_beam(p, &front, vad_raw, vad_out, mask):呼叫端在兩者之間讀 front.lane_spectra[0],mask 可為 NULL;audio_pipeline_4ch_ulcnet_beam_state() 回 DOA(rad,NaN = 無)與 GSC 適應旗標。process_begin(v) 等於 process_front 加 process_beam(front, v, v, NULL)(見 pipeline_ulcnet_4ch)。

Model I/O descriptor 是必要的,不是選配

if (cfg->model.infer && !cfg->model.io_descriptor) return -1;
if (cfg->model.io_descriptor &&
    ulcnet_model_io_descriptor_validate(cfg->model.io_descriptor) != 0) return -1;
掛了真的 runtime 就必須提供 descriptor(identity model 才可以留 NULL)。理由:finite guard 只抓得到「沒寫」,永遠抓不到「寫錯形狀」——graph 的 D 與 descriptor 不符時會靜默地越界讀寫 pool。descriptor 內容包含 layout_version(必須等於 ULCNET_MODEL_IO_LAYOUT_VERSION)、delay_depth D ∈ [2,64]、grid 幾何、以及 far_input_mode 必須是 ULCNET_FAR_RAW。

4ch ULCNet 的 front-only 契約:拒絕而非忽略

core.enable_post = 0 時前端不 carve fuse 緩衝,wrapper 也不 carve 任何 denoiser／suppressor／comfort noise／post iFFT。因此以下欄位必須維持 _default_config() 的值,否則在 init 被拒:

欄位必須值理由
core.enable_post0—
core.enable_nr0core 自己的預設是 1;front-only profile 關掉它,讓欄位陳述此處的事實,而不是留一個不可能生效的值
core.enable_cng0沒有 suppressor 就沒有 CNG level
core.legacy_amin0post-only 欄位
core.nr_modeANR_MODE_BALANCEDenum 沒有 disabled 值,而且根本沒有 denoiser 實例 → 這是必要哨兵,不是強度選擇
auto_vad_*audio_pipeline_4ch 的預設內建 energy VAD 在此不可達(只有 _process_with_activity)

設計理由:「自以為設好 NR 的呼叫端,要在 init 就知道,而不是上板才發現。」pre-stage 欄位(delay_*／aec_preset／filter_length／capture_proxy_channel／max_delay_ms)照常生效。

6. layout_version 對整合者的意義

Pipeline目前版本
mono_aec_nr_resAUDIO_PIPELINE_LAYOUT_VERSION = 15
4ch_aec_bf_nr_res(核心)FOUR_AEC_NR_RES_LAYOUT_VERSION = 22
4ch_aec_bf_nr_res(完整 wrapper)AUDIO_PIPELINE_4CH_LAYOUT_VERSION = 17
mono_alignulcnetAUDIO_PIPELINE_ULCNET_LAYOUT_VERSION = 15
4ch_alignulcnetAUDIO_PIPELINE_4CH_ULCNET_LAYOUT_VERSION = 23

規則:pool 大小、carve 順序或 descriptor 內容任一改變,該模組的版本加一。

版本一動,任何持久化的 descriptor 都必須丟棄重查。關鍵微妙處:build_flags_hash 只是 carve token 字串的 FNV-1a,不含任何 sizeof／byte count → 當 control block 只是長大而 carve 結構沒變時,hash 不會動。所以 layout_version 是唯一訊號。
「a descriptor from a version-10 build must be refused, including when its cached byte count still covers the current pool」——descriptor 的 bytes 比較是下界,擋得住成長、擋不住等量語意變更。

4ch ULCNet 的版本會純轉播下層 core 的版本:core 只長 control block 時兩層 hash 都不動,只能靠本層 layout_version 一起 bump 來攔。

7. DEBUG:出貨板上還剩什麼

出貨板上唯一還活著的診斷面是「主動 poll 的結構化狀態快照」;事件式(log／trace)與時間式(stage timing)觀測在 release 組態下歸零,assert() 仍是活的,mono pipeline 沒有 finite 守衛。Release build 的 nm 實測、可照抄的板端監看迴圈與完整盲點表收在 integration_example_detail;新增哪些 DEBUG 資訊的提案見 docs/debug_observability_zh_TW.md。

8. 整合檢查清單

  • sample rate、frame/FFT、hop 是同一個合法 grid,且三個 lib 對得上(照抄 mono 的 grid agreement guard)。
  • mic/ref 同 sample rate、同 clock;ref 是實際 speaker render reference。
  • 每次呼叫恰好傳一個 hop。
  • 所有 pool 以 resolved config 查 size,base 至少 16-byte 對齊;descriptor 不可跨版本快取。
  • process hot path 沒有 malloc/free/file I/O/logging。
  • stream boundary 同時 reset DSP instance 與 caller 自己的 ring/WOLA state。
  • borrowed context/gain pointer 沒有跨下一次 process 保存。
  • AEC 的 r2／comfort_noise 交給 NR 前已除以 32768²。
  • 接 NN 時 descriptor 非 NULL,且其 D 與 graph 一致(這條沒有任何自動檢查)。
  • application 與三個 archive 使用相同 backend、SIMD、FP flags。
  • 最終 float→PCM 前做 saturating conversion;limiter 只放在整條 chain 最後。
  • 完整應用優先跑 pipeline tests,而不只跑各 library 的 unit test。
