串接範例:四條 pipeline 怎麼組三個 lib

三個 lib 的 API 說明各自在 AEC API／NR API／audio_common API。本頁是「怎麼把它們接起來」的實作範例——四條出貨 pipeline 就是四份可編譯、已測試的參考接線。各 pipeline 自身的演算法說明在 pipeline_mono／pipeline_4ch／pipeline_ulcnet_mono／pipeline_ulcnet_4ch。

0. 先決定使用層級

需求入口
完整 mono AEC + NR + RESpipelines/mono_aec_nr_res/audio_pipeline.h
完整 4ch 4×linear AEC → BF → mono NR+RESpipelines/4ch_aec_bf_nr_res/audio_pipeline_4ch.h
4ch linear AEC + 外部 beamformer seampipelines/4ch_aec_bf_nr_res/4aec_nr_res.h
mono linear AEC + NN 後級pipelines/mono_alignulcnet/audio_pipeline_ulcnet.h
4ch linear AEC + SRP/GSC + NN 後級pipelines/4ch_alignulcnet/audio_pipeline_4ch_ulcnet.h
只做單路 AEC,或自行組合其他 post-filteraec.h
已有 STFT/WOLA,只需要頻域 NRmmse_lsa_denoiser.h
產品要的若是既有完整 flow,優先呼叫 pipeline API。不要在 application 重新複製 AEC/NR gain fusion、window、OLA 或 CNG 邏輯——那些細節(尺度換算、near-end floor gate、CNG LUT 索引)很容易做錯而且不會報錯。

1. 四條共通的骨架

面向四條一致的事實
AEC 一律 linear-seam四條全部無條件設 enable_res = 0、return_res_context = 1。AEC 只當線性前級,殘留抑制由 pipeline 自己(或 NN)做
沒有一條用 streaming APIaec_analyze_render()／aec_process_capture() 在 pipelines/ 下零引用 → AecBufferingEvent 在出貨路徑上結構性不可達
audio_common 只用到少數符號fft_*、sk_min_f32、sk_capply_gain_f32、sk_wola_accumulate_f32、ALIGN16/ck_*。沒有任何一條用 hpf_*／audio_pre_gain_*／audio_resampler_*——HPF 在 AEC 內部,gain 與 resample 是 pipeline 之外的前級
32-byte 固定寬度 descriptor四條的 *MemReq 形狀一致,都走 get_mem_requirements() → init_ex() 的 descriptor gate

2. 誰做 FFT、誰擁有 window、WOLA 在哪

這是接線時最容易搞錯的一件事,四條 pipeline 給了三種不同答案:

forward FFTanalysis windowNR gain 怎麼套inverse + WOLA
mono_aec_nr_resAEC 內部(ctx.error_spec 就是它的 50% overlap periodic-sqrt-Hann STFT)AEC 擁有NR 只算 gain 不套,pipeline sk_min_f32 融合後一次套pipeline 自己(獨立的 FftHandle)
4ch_aec_bf_nr_res每條 lane 的 AEC 內部,pipeline 借指標不複製各 lane 的 AEC同上,但 RES gain 來自一個共用 SuppressionGain(不屬於任何 Aec)pipeline 自己
mono_alignulcnetAEC 的 FFT 完全不用——ULCNet 自己的 centered STFT 做 forwardULCNet(centered sqrt-Hann)沒有 NR(沒有 MmseLsaDenoiser 實例)ulcnet_synthesis_push()
4ch_alignulcnet頻域直送:① 每 lane AEC 的 STFT → SRP-PHAT + GSC;② GSC 的 mono 頻譜直接當 model 的 error 幀(不重建、不再分析),far 分支用 ulcnet_analysis_push_frame() 取同一 hop;③ model → ulcnet_synthesis_push()(吃掉 1 hop)
4ch_alignulcnet 的總演算法延遲 = 1 hop(16 k 256 smp/16 ms、48 k 512 smp/10.67 ms),只來自 synthesis 的半窗 trim。兩個 branch 都從當前 input hop 取幀,所以不可以有 far 補償 buffer——加回去就是 error[t] 配 far[t-1] 的一 hop 偏斜,而這種對齊細節沒有任何自動檢查。

3. 範例 A:mono_aec_nr_res — 最完整的參考接線

建立

AudioPipelineConfig cfg = audio_pipeline_default_config(16000);
/* cfg.fft_size=0(rate default) aec_preset=BALANCED nr_mode=BALANCED
 * aec_only=0 enable_cng=1 legacy_amin=0 */

AudioPipelineMemReq req;
if (audio_pipeline_get_mem_requirements(&cfg, &req) != 0) { /* reject-first */ }
void *pool = platform_alloc(req.bytes, req.alignment);   /* 16-byte aligned */
AudioPipeline *p = audio_pipeline_init_ex(pool, req.bytes, &cfg, &req);

int hop = audio_pipeline_hop_size(p);                    /* 128 @16k default */
while (streaming) audio_pipeline_process(p, mic, ref, out);   /* 三者皆 hop floats */

audio_pipeline_reset(p);      /* echo path 變更時;不動 pool */
audio_pipeline_destroy(p);    /* 不釋放 caller pool */

每 hop 對底層 lib 的精確呼叫序列

這就是「怎麼串」的答案。aec_only=1 時只有第一行,其餘整段跳過:

audio_pipeline_process(p, mic, ref, out)
 │
 ├─ aec_only ─→ aec_process(p->aec, mic, ref, out)        ← 直寫 caller 的 out,結束
 │
 └─ 1.  aec_process_context(p->aec, mic, ref)             ← 不取時域輸出,省一次 memcpy
    2.  aec_get_last_timing(p->aec, ...)                  ← 只有 PROFILE=1 才有數值
    3.  aec_get_res_context(p->aec, &ctx)
    4.  extra[k] = ctx.r2[k] / PSD_SCALE                  ← int16² → audio power(32768²)
    5.  mmse_lsa_process_gain(p->nr, ctx.error_spec, extra, NULL)
        └ gain_out=NULL:之後用 mmse_lsa_get_gain() 讀,省一次複製
    6.  sk_min_f32(g_total, mmse_lsa_get_gain(p->nr,NULL), ctx.res_gain, n_freqs)
        └ gain fusion = 逐 bin 取小
    7.  e2[k] = |ctx.error_spec[k]|²
    8.  near-end floor gate:far_active = ctx.far_power > 1e-4
    9.  per-bin echo-gated lift:
        echo_frac = clamp(extra[k]/(e2[k]+1e-12), 0, 1)
        lift      = nf_eff * ctx.res_gain[k] * (1 - echo_frac)
        g_total[k]= (1-lift)*g_total[k] + lift
   10.  sk_capply_gain_f32(spec, ctx.error_spec, g_total, n_freqs)
   11.  CNG(bins 1..n-2):a = sqrt(1-G_res²) * sqrt(N²/PSD_SCALE)
   12.  fft_inverse(p->fft, spec, ifft_buf)
   13.  sk_wola_accumulate_f32(ola, ifft_buf, synth_win, frame_size)
   14.  memcpy(out, ola, hop) ; memmove ; memset          ← hop emit + shift
為什麼是 aec_process_context() 而不是 aec_process():兩個入口只差「要不要把結果複製出來」,所以純粹是成本選擇。aec_only=1 時 AEC 的輸出就是 pipeline 的輸出 → 用 aec_process() 直寫 caller 的 out;aec_only=0 時下游只讀 ctx.error_spec、從不碰 AEC 吐出的 hop → aec_process_context() 省掉那次複製。

Init 期的接線順序

aec_get_mem_size → aec_init
fft_get_mem_size → fft_init                 ← 獨立於 AEC 內部的 FFT
mmse_lsa_get_mem_size → mmse_lsa_init
七個 scratch 逐一 carve + memset
synth_win = sqrt periodic-Hann
grid agreement guard:
   aec_get_res_context(p->aec, &ctx0)  → 比對 n_freqs / hop
   fft_get_n_freqs() / mmse_lsa_get_n_freqs() → 再比對一次
那個 grid agreement guard 值得照抄:三個 lib 各自 resolve 自己的 grid,如果 config 讓它們對不上,不檢查就會在頻域靜默錯位。自組 chain 時務必在 init 尾端做同樣的三方比對。

4. 範例 B:4ch_aec_bf_nr_res — pre/post 分裂,外部 beamformer

這是唯一有狀態協定的 API:process_pre() 產生一個 pending frame,外部做 beamforming,再 process_post() 消費它。

FourAecNrResPreFrame pre;
FourAecNrResStatus st = four_aec_nr_res_process_pre(core, mics_interleaved, far, &pre);
if (st != FOUR_AEC_NR_RES_OK) { /* 見下方 status 表 */ }

/* ── 外部:SRP-PHAT / GSC,用 pre.linear_spectra[4] 算出 Complex[4][n_freqs] 權重 ── */

st = four_aec_nr_res_process_post(core, &pre.token, weights, out);
/* 或 four_aec_nr_res_abandon_pre(core, &pre.token) 放棄這一 frame */

pre 半的呼叫序列(重點在 far-FFT 共用)

1. inputs_finite(mic_interleaved, hop*4) && inputs_finite(ref)   ← 唯一的輸入 NaN gate
2. de-interleave proxy channel → mic_lane
3. update_shared_delay(...)          ← duty 決策 + matched filter + ERLE watchdog
4. align_render(ref, delay)  → aligned_ref
5. if (delay.changed) 四 lane 各跑 aec_apply_external_realign(lanes[ch], delta)
6. for ch in 0..3:
     de-interleave lane ch
     ch==0 : aec_process_context(lanes[0], mic_lane, aligned_ref)
     ch!=0 : aec_process_context_shared_far(lanes[ch], mic_lane, aligned_ref, shared_far_spec)
     aec_get_res_context(lanes[ch], &context)
     ch==0 → shared_far_spec = context.far_spec        ← lane 0 算,1..3 借
     bind_lane_view(&snapshots[ch], &context)          ← 借指標,不複製
7. mint token(frame_index / generation / owner_cookie / instance_epoch)
四條 lane 這一 hop 看到同一個 aligned_ref 指標,所以 lane 0 的 far-FFT 對其他三條逐位元相同 → 4 次 far-FFT/hop 變成 1 次。這是 aec_process_context_shared_far() 存在的理由,也是它嚴格的 same-hop/same-reference 前提的由來。

post 半

1. token_matches()                         ← 序列協定
2. validate_weights():逐元 isfinite + Σ|.| > 1e-12
3. fuse_contexts():coherent projection,四 lane far_power 一致性檢查
4. run_post_res_and_nr():
     suppression_gain_get_gain(&post_sg, ...)      ← 共用 post 抑制器
     mmse_lsa_process_gain(p->nr, error, nr_extra, NULL)   ← 僅 enable_nr=1
     total_gain[k] = min(nr_gain, res_gain)                ← enable_nr=0 時 = res_gain
     near-end floor gate + echo-gated lift(常數與 mono 相同)
     CNG → fft_inverse → sk_wola_accumulate_f32 → hop emit
5. return inputs_finite(out, hop)          ← 唯一的輸出 NaN gate
FourAecNrResStatus意義pending frame
OK(0)成功已消費
INVALID_ARGUMENT(−1)NULL、非有限輸入、權重不合法保留,可重試
SEQUENCE_ERROR(−2)token 不符 / 協定被違反—
DSP_ERROR(−3)內部已 self-reset已丟棄
四條 lane 都以 spatial_linear_context 建立,永遠走不到自己的 suppression path → 對 lane 呼叫 aec_set_preset() 依構造是無效操作。要改強度請用 four_aec_nr_res_set_aec_preset(),它針對的是那個共用的 post 級抑制器。

5. 範例 C／D:兩條 ULCNet pipeline — 接 NN 的做法

從 AEC 拿什麼

aec_process_context(p->aec, mic, ref);
aec_get_res_context(p->aec, &rctx);      /* rctx.formed_hop     ← 時域線性誤差 */
aec_get_linear_context(p->aec, &lctx);   /* lctx.aligned_far_hop ← 對齊後的 far  */

注意 mono 拿的是「時域」兩個 tap,不是頻譜——它有自己的 STFT,AEC 的 error_spec 完全不用;兩路都走 rolling push_frame()(2026-09-03 起,先前 centered)。4ch不做 error 分析:gsc_spectrum 直接當 error 幀,far 分支走同一個 push_frame。不可與 centered push() 混用同一 state(共用 history、不共用排程;現只剩 Python parity gate 用 centered 版)。

邊界偵測與 reprime

if (lctx.delay_state == AEC_LINEAR_DELAY_CHANGED
    || (FIXED 模式下 UNLOCKED→LOCKED 的首次轉換)) {
    if (p->model.reset) p->model.reset(user);   /* 通知 NN 丟棄跨 frame 狀態 */
    p->reprime_frames = REPRIME;                /* mono=1, 4ch=1 */
}
reprime frame 數是量測出來的,不是猜的:兩條都是 1——兩條的兩個 branch 都從當前 input hop 取幀,50%-overlap 幀橫跨兩個 hop,只有邊界 hop 那一幀還蓋到切換前的 hop(4ch 早先是 2,肇因於已移除的 WOLA)。常數綁定 hop 結構,改 framing 必須重新量(test_reprime_straddle_derivation())。

Fail-open 三層 + FULL-WRITE CONTRACT

if (reprime_frames > 0) {
    /* identity,不 step model */
} else if (model.infer) {
    for (k) { mdl_re[k] = NAN; mdl_im[k] = NAN; }   /* ← 先全填 NaN */
    rc = model.infer(user, err_re, err_im, far_re, far_im, mdl_re, mdl_im);
    if (rc == 0 && ulcnet_frame_is_finite(mdl_re, mdl_im)) { /* 採用 */ }
    /* 否則 identity */
}
ulcnet_synthesis_push(&synth, sre, sim, out + wrote);
Fallback 條件行為
infer == NULLidentity
infer 回非 0identity
輸出有任何非有限值identity

三種情況的時序路徑完全相同 → latency 不隨 model 健康度變動。先全填 NAN 是為了把「沒寫」變成可偵測——finite guard 抓得到未寫入,但抓不到寫錯形狀。

Model I/O descriptor 是必要的,不是選配

if (cfg->model.infer && !cfg->model.io_descriptor) return -1;
if (cfg->model.io_descriptor &&
    ulcnet_model_io_descriptor_validate(cfg->model.io_descriptor) != 0) return -1;
掛了真的 runtime 就必須提供 descriptor(identity model 才可以留 NULL)。理由:finite guard 只抓得到「沒寫」,永遠抓不到「寫錯形狀」——graph 的 D 與 descriptor 不符時會靜默地越界讀寫 pool。descriptor 內容包含 layout_version(必須等於 ULCNET_MODEL_IO_LAYOUT_VERSION)、delay_depth D ∈ [2,64]、grid 幾何、以及 far_input_mode 必須是 ULCNET_FAR_ALIGNED。

4ch ULCNet 的 pre-only 契約:拒絕而非忽略

core.enable_post = 0 時 core 完全不 carve denoiser／suppressor／comfort noise／post iFFT。因此以下欄位必須維持 _default_config() 的值,否則在 init 被拒:

欄位必須值理由
core.enable_post0—
core.enable_nr0core 自己的預設是 1;pre-only profile 關掉它,讓欄位陳述此處的事實,而不是留一個不可能生效的值
core.enable_cng0沒有 suppressor 就沒有 CNG level
core.legacy_amin0post-only 欄位
core.nr_modeMMSE_LSA_NR_BALANCEDenum 沒有 disabled 值,而且根本沒有 denoiser 實例 → 這是必要哨兵,不是強度選擇
auto_vad_*audio_pipeline_4ch 的預設內建 energy VAD 在此不可達(只有 _process_with_activity)

設計理由:「自以為設好 NR 的呼叫端,要在 init 就知道,而不是上板才發現。」pre-stage 欄位(delay_*／aec_preset／filter_length／capture_proxy_channel／max_delay_ms)照常生效。

6. layout_version 對整合者的意義

Pipeline目前版本
mono_aec_nr_resAUDIO_PIPELINE_LAYOUT_VERSION = 10
4ch_aec_bf_nr_res(核心)FOUR_AEC_NR_RES_LAYOUT_VERSION = 16
4ch_aec_bf_nr_res(完整 wrapper)AUDIO_PIPELINE_4CH_LAYOUT_VERSION = 11
mono_alignulcnetAUDIO_PIPELINE_ULCNET_LAYOUT_VERSION = 12
4ch_alignulcnetAUDIO_PIPELINE_4CH_ULCNET_LAYOUT_VERSION = 17
版本一動,任何持久化的 descriptor 都必須丟棄重查。關鍵微妙處:build_flags_hash 只是 carve token 字串的 FNV-1a,不含任何 sizeof／byte count → 當 control block 只是長大而 carve 結構沒變時,hash 不會動。所以 layout_version 是唯一訊號。
「a descriptor from a version-10 build must be refused, including when its cached byte count still covers the current pool」——descriptor 的 bytes 比較是下界,擋得住成長、擋不住等量語意變更。

4ch ULCNet 的版本會純轉播下層 core 的版本:core 只長 control block 時兩層 hash 都不動,只能靠本層 layout_version 一起 bump 來攔。

7.1 Release build 的實測結論

以 NO_STDIO=1 建出 archive 後用 nm 檢查,結果是一個很乾淨的分界:

類別存活消失
狀態快照(pull)aec_debug_status、aec_get_res_context、aec_get_linear_context、aec_linear_is_cancelling、aec_far_fft_real_compute_count、aec_get_mem_breakdown、mmse_lsa_debug_status、mmse_lsa_get_gain/_spp/_noise_psd、4ch 的全部 census/counter accessor—

一句話:出貨板上唯一還活著的診斷面,是「主動 poll 的結構化狀態快照」。所有事件式(log／trace／buffering event)與所有時間式(stage timing)觀測在 release 組態下歸零。任何 DEBUG 設計都必須建立在 pull 型快照上,而不是 printf。

7.2 可以直接照抄的板端監看迴圈

/* 每秒一次即可;三個 API 都是免費的(只讀引擎已維護的欄位) */
AecDebugStatus      a;  aec_debug_status(audio_pipeline_get_aec(p), &a);
MmseLsaDebugStatus  n;  mmse_lsa_debug_status(audio_pipeline_get_nr(p), &n);

log("delay=%d conf=%.1f upd=%d erle=%.1fdB usable=%d conv=%d "
    "near=%.4f out=%.4f duty=%llu/%llu | nr_init=%d gain=%.1f/%.1fdB "
    "spp=%.2f noise=%.1fdB",
    a.delay_samples, a.delay_confidence, a.delay_updates,
    a.erle_windowed_db, a.usable_linear, a.filter_converged,
    a.near_power, a.out_power, a.duty_hops_run, a.duty_hops_total,
    n.initialized, n.mean_gain_db, n.min_gain_db, n.mean_spp, n.noise_floor_db);
讀到這樣通常代表
delay=-1 一直不變從未鎖定。檢查 ref 是否真的是送往喇叭的訊號、電平是否過低
erle 低但 conv=1濾波器收斂了但 echo 仍在 → 懷疑鎖到錯的 delay(早期反射),或非線性失真超出線性模型
duty_run/duty_total 接近 1.0 且長時間不降duty-cycle 從未進入省電抽樣 → delay 一直不穩定
nr_init=0 持續還在啟動 pass-through(前 num_init_frames 個 frame),此時完全不降噪是正常的
mean_spp 長期接近 0判定沒有語音 → 檢查電平或噪聲底是否估過高
noise_floor_db 隨語音一起爬升噪聲估計正在吸收語音 → 檢查 delta_db／alpha_d
三個常見誤判,先看這裡再懷疑演算法:
  • aec_get_last_timing() 回全 0 不代表很快——代表沒有用 PROFILE=1 建 library。而且函式不會告訴你它沒被啟用。
  • delay_updates 是 matched-filter 的更新總數,不區分「同一值重複確認」與「跳到新值」,不能當成 lock 穩定度指標。
  • near_power／out_power 是 EMA(alpha=0.95),不是瞬時值;duty_* 會被 reset() 清零。

7.3 現況的已知盲點(整合前先知道)

盲點實情
per-hop CSV trace 四條 pipeline 全部不可達AecDebugTraceRow 的唯一填寫點要求 cfg.enable_res == 1 且走 aec_process()。四條 pipeline 全部設 enable_res = 0 → dominant_nearend／saturated_echo／usable_linear／fullband_erle／gain_mean 這些沒有第二個出口的量,在產品組態下永遠取不到。只有 CLI aec_wav --debug-trace 拿得到
層級式 log 是死碼AEC_DEBUG_LOG 在整個 library 的 src/ 有 0 個呼叫點(唯一命中是一句註解)。level 1/2/3、aec_debug_logf、時間/frame 前綴——整套四層基礎設施沒有任何 emit 端
assert() 在出貨板上是活的四個 Makefile 沒有任何一個設 -DNDEBUG。suppression_gain.c 的 table-length assert 沒有 release-path fallback,失敗即 abort()——沒有回傳碼、沒有 log、沒有 hook 可攔
self-reset 不計數DSP_ERROR 路徑會內部呼叫 reset(),而 reset() 本身清掉所有 instrumentation(realign counters／duty census 全歸零)→ 一次 self-reset 之後「之前發生過什麼」在計數器上完全消失
delay lock 遺失不計數AecLinearContext.delay_state 與 generation 每 hop 可讀,但 AecDebugStatus 兩者都沒有 → 只 poll aec_debug_status() 的整合者看不到 lock 的丟失與重獲
NN fail-open 是靜默的三種 fallback 走同一條 else 分支、無區別、無計數 → 「NPU 掛了整段跑 identity」與「NPU 正常但某幾 frame 吐 NaN」從外部無法區分
4ch init 失敗一個字都不說init_ex() 的 8 項檢查任一失敗都靜默回 NULL。mono 有逐欄位 stderr,但 NO_STDIO=1(正是板端組態)一開就沒了
沒有 frame counter四條 pipeline 都沒有 frame counter 的 public accessor → 「這條 stream 到目前為止處理了幾個 hop」都答不出來,遑論 xrun
mono pipeline 沒有 finite 守衛audio_pipeline_process() 輸入不檢、輸出不檢。只有 4ch 有(輸入與輸出各一道)
兩條 ULCNet pipeline 幾乎沒有觀測面mono ULCNet 只有 _get_aec();4ch ULCNet 只剩 _last_delay() 與尺寸查詢(_last_beamformed_error() 已隨 layout v17 移除)。兩條都沒有暴露 core handle → core 的 duty census、realign counters、timing、post floor 對整合者全部不可達

8. 整合檢查清單

  • sample rate、frame/FFT、hop 是同一個合法 grid,且三個 lib 對得上(照抄 mono 的 grid agreement guard)。
  • mic/ref 同 sample rate、同 clock;ref 是實際 speaker render reference。
  • 每次呼叫恰好傳一個 hop。
  • 所有 pool 以 resolved config 查 size,base 至少 16-byte 對齊;descriptor 不可跨版本快取。
  • process hot path 沒有 malloc/free/file I/O/logging。
  • stream boundary 同時 reset DSP instance 與 caller 自己的 ring/WOLA state。
  • borrowed context/gain pointer 沒有跨下一次 process 保存。
  • AEC 的 r2／comfort_noise 交給 NR 前已除以 32768²。
  • 接 NN 時 descriptor 非 NULL,且其 D 與 graph 一致(這條沒有任何自動檢查)。
  • application 與三個 archive 使用相同 backend、SIMD、FP flags。
  • 最終 float→PCM 前做 saturating conversion;limiter 只放在整條 chain 最後。
  • 完整應用優先跑 pipeline tests,而不只跑各 library 的 unit test。
