1. 四條共通的骨架

面向四條一致的事實
AEC 一律 linear-seam四條全部無條件設 enable_res = 0、return_res_context = 1(mono 的 derive_lane();4ch 的 mcab_apply_lane_contract())。AEC 只當線性前級;殘留抑制的增益由 AEC 自己算(mono 的 ctx.res_gain)或由 4ch 應用自備的 AecRes 算(aec_res_process()),套用在各 main 的逐 hop 串接裡(或交給 NN)
audiolib 只用到少數符號fft_*、ac_stft_*／ac_istft_*、sk_min_f32、sk_capply_gain_f32、ALIGN16/ck_*。這四條沒有任何一條用 hpf_*／audio_resampler_*——HPF 在 AEC 內部,gain 與 resample 是 pipeline 之外的前級(只有 DFN2 變體的 pipelines/dfn/dfn_rate_bridge.c 用 audio_resampler_*)
各自 init、32-byte descriptor 只在 mcab 與 DFN每個函式庫(Aec、AnrDenoiser、AcIstft、stage／bridge、4ch 的 mcab 與 helper)自己查大小、自己 init;帶 32-byte 固定寬度 descriptor 與 init_ex() 閘的是 4ch 的 mcab 與 DFN stage／bridge,其餘函式庫物件、sample helper 與 NN stage 範例沒有

2. 誰做 FFT、誰擁有 window、WOLA 在哪

這是接線時最容易搞錯的一件事,四個範例給了三種不同答案:

forward FFTanalysis windowNR gain 怎麼套inverse + WOLA
mono_aec_nr_resAEC 內部(ctx.error_spec 就是它的 50% overlap periodic-sqrt-Hann STFT)AEC 擁有NR 只算 gain 不套,main 的 sk_min_f32 融合後一次套main 自己(AcIstft,獨立的 FftHandle)
4ch_aec_bf_nr_res每條 lane 的 AEC 內部,mcab 借指標不複製各 lane 的 AEC同上,但 RES gain 來自一個共用 AecRes(應用自備的 post-beam RES,不屬於任何 Aec、mcab 或 helper)main 自己的 AcIstft
mono_alignulcnetAEC 的 FFT 完全不用——ulcnet_nn_stage 自己的 STFT（AcStft，center 0，一 hop 一幀）做 forwardULCNet(rolling sqrt-Hann)沒有 NR(沒有 AnrDenoiser 實例)ac_istft_push_planar()（AcIstft）
4ch_alignulcnet頻域直送:① 每 lane AEC 的 STFT → SRP-PHAT + BF(helper);② BF 的 mono 頻譜(beam.spectrum)直接當 model 的 error 幀(不重建、不再分析),far 分支用 ac_stft_push_planar()（center 0）取同一 hop;③ model → ac_istft_push_planar()(吃掉 1 hop)
4ch_alignulcnet 的總演算法延遲 = 1 hop(16 k 256 smp/16 ms、48 k 512 smp/10.67 ms),只來自 synthesis 的半窗 trim。兩個 branch 都從當前 input hop 取幀,所以不可以有 far 補償 buffer——加回去就是 error[t] 配 far[t-1] 的一 hop 偏斜,而這種對齊細節沒有任何自動檢查。

2.5 串一個新的頻域 stage

接縫都是函式庫交出的借用 view:mono 是 aec_get_res_context() 填的 AecResContext(error_spec = E,r2、comfort_noise、res_gain),4ch 是 mcab_fuse()／mcab_sample_beam_fuse() 填的 McabFrame(定義在 mcab.h)。增益類 stage 是普通函式(mono 的 mono_nr_gain()、4ch 的 mcab_sample_anr_gain()),NN 類 stage 是 begin → (呼叫端跑 NPU) → end。沒有函式指標表:每個應用自己把鏈寫出來(mono/aec_nr_res/main.c 的 mono_form() 是現成的一份),順序固定是 sk_min_f32 → sk_capply_gain_f32 → aec_cng_fill → ac_istft_push。

/* mono 的一個 hop:ctx 是借用視圖,有效至下一次 process 呼叫;任何 stage 都不得寫入 */
AecResContext ctx;  aec_get_res_context(aec, &ctx);
AecOutputBase b = { sizeof(b) };  aec_get_output_base(aec, &b);    /* b.base_spec = 渲染基底 B;守衛未觸發時等於 ctx.error_spec */
/* aec_post_reset_serial() 於本 hop 變動時,在 CNG 取亂數與 ac_istft_push 之前先 ac_istft_reset(istft)、rng = AEC_CNG_SEED */
const float *res_gain = ctx.res_gain;    /* AEC 已算好; 4ch 的 McabFrame.g_res_ctx 為 NULL, 改用 aec_res_process(自備 AecRes, &in) */
const float *nr_gain  = mono_nr_gain(r, &ctx, b.base_spec);    /* 另一個增益 stage(anr_process_gain 在 B 上估計 + anr_get_gain) */
sk_min_f32(total_gain, nr_gain, res_gain, n_freqs);    /* 無降噪器時改讀全 1 向量 */
sk_capply_gain_f32(spec, b.base_spec, total_gain, n_freqs);    /* 套在 B 上;error_spec 只是分析 seam */
aec_cng_fill(&rng, spec, ctx.comfort_noise, res_gain, nr_gain, CNG_NR_GAIN_FLOOR, n_freqs);
ac_istft_push(istft, spec, out);    /* 這裡才呼叫 ISTFT:每 hop 恰一次 */
規則內容
記憶體stage 的 pool 由應用 carve:先用 *_get_mem_size() / *_mem_size() 查大小,再 *_init() 在 16-byte 對齊的區塊上建構;mono 的 derive_lane()(4ch 的 mcab_lane_config())導出 lane 的 config,NR 用 anr_config_for_level_grid()、合成用 ac_stft_config_default() 並向 aec_synthesis_window() 借 AEC 的窗。process 路徑零 heap
非有限增益sk_min_f32 是 (a<b)?a:b:第二個運算元的 NaN 會傳到輸出的 finite gate,第一個運算元的 NaN 會被第二個取代(與 fminf 不同)
常數與輔助函式mono 的 main.c 自己定義 CNG_*、PSD_SCALE_INV;4ch 在 mcab_sample_post.h(MCAB_SAMPLE_CNG_*、mcab_sample_res_input()、mcab_sample_anr_gain());輸出檢查 skn_all_finite_f32()

3. 範例 A:mono_aec_nr_res — 最完整的參考接線

完整的呼叫順序、已編譯檢查的最小 C 範例、每 hop 程式流與 pool carve 在 Mono · AEC／NR／RES,時序圖在 整合時序圖。要點:anr_config_for_level_grid()、ac_stft_config_default() 與 derive_lane() 用同一個 grid.fft_size;三個函式庫各自 *_get_mem_size()(0 = 拒絕)→ 一塊 16-byte 對齊的 pool 依序 carve → init;每 hop aec_process_context() → aec_get_res_context() → aec_get_output_base() → mono_nr_gain() → sk_min_f32() → sk_capply_gain_f32() → aec_cng_fill() → ac_istft_push()(aec_post_reset_serial() 變動時,先 ac_istft_reset() 並把 CNG 種子重設為 AEC_CNG_SEED,不 reset AEC 與 NR);任一步被拒或輸出非有限,aec_reset()、anr_reset()、ac_istft_reset() 與 CNG 亂數種子一起重設。

為什麼是 aec_process_context() 而不是 aec_process():反向 FFT 與 overlap-add 一律由應用呼叫獨立的 ac_istft_push()。--aec-only 時 AEC 的輸出就是範例的輸出 → 把 ctx.linear_hop 複製到 caller 的 out(沒有合成);有後級時下游讀 aec_get_output_base() 交出的 base_spec(渲染基底 B)與 res_gain:NR 估計、RES、CNG、合成都作用在 B 上,ctx.error_spec 只是分析 seam,最後 ac_istft_push() 出 hop。

三方 grid 一致

三個 lib 各自 resolve 自己的 grid,如果 config 讓它們對不上,不檢查就會在頻域靜默錯位。範例用同一個 grid.fft_size 導出 AEC／NR／合成的 config,並在 --print-mem-size 比對 n_freqs／hop;自組時務必做同樣的三方比對。

4. 範例 B:4ch_aec_bf_nr_res — mcab front + fuse(外部 beamformer)或 flow + sample helper

mcab 每 hop 兩個呼叫,中間是 beamformer:mcab_process_front() 交出借用的 McabFront,mcab_fuse(p, weights, beamformed_error, frame) 填 McabFrame(g_res_ctx 為 NULL)。lane 與 estimator 由應用用各 lib 的 init 建立後以 McabLibs 注入;RES／NR／CNG／ISTFT 不在 mcab 內,由應用自備並明寫串接(完整範例:mcab_external_static.c 與 tests/conv_chain_mcab.h)。fuse 要求之前至少處理過一個 front frame(否則 SEQUENCE_ERROR)。要連 SRP-PHAT 與 BF 一起接好,用 sample helper McabSampleBeam:mcab_sample_beam_process_front() → mcab_sample_beam_process_beam() → mcab_sample_beam_fuse()(fuse 之後同樣由應用的 aec_res_process() 取增益;mcab_raw.c 的 raw_post() 與 mcab_static.c 的 static_hop() 是 flow＋helper 加自備 RES、NR、合成的接線;init 順序見 mcab_sample_flow.{h,c})。

範例在 四聲道 · AEC／NR／RES(flow＋helper)與 四聲道 參數與診斷(mcab + 外部 beamformer);錯誤矩陣在 整合時序圖。mcab 的每 hop 骨架:mcab_process_front() → 外部 SRP-PHAT／beamformer 用 front.linear_spectra[4] 算出 Complex[4][n_freqs] 權重 → mcab_fuse(p, weights, NULL, &frame)(NULL 或 BF 已算好的 beamformed 頻譜)→ mcab_sample_res_input(&frame, &in) + aec_res_process(res, &in) → mcab_sample_anr_gain() → sk_min_f32() → sk_capply_gain_f32() → aec_cng_fill() → ac_istft_push()。內部序列見 串接範例細節 第 4 節。

之後是應用自己的幾行(mcab_external_static.c 的 post_hop()):各 stage 回傳 const float* 增益,sk_min_f32 取小,sk_capply_gain_f32 套在 frame.b(渲染基底;frame.e 只作 RES／NR 的估計輸入)上,mcab_sample_post_reset_due() 為真時先 ac_istft_reset() 並重設 CNG 種子,aec_cng_fill 補舒適噪音,ac_istft_push 合成;輸出 NaN gate 由整合者做。

MCAB_* 狀態意義front frame
OK(0)成功可繼續使用至下一次 mcab_process_front()
INVALID_ARGUMENT(−1)NULL、非有限輸入、權重不合法fuse 失敗時保留,可修正權重後重試
SEQUENCE_ERROR(−2)fuse 之前沒有 front frame—
DSP_ERROR(−3)內部已 self-reset已丟棄
四條 lane 都經 mcab_apply_lane_contract() 蓋上 spatial_linear_context,永遠走不到自己的 suppression path → 對 lane 呼叫 aec_set_level() 依構造是無效操作。要改強度請對應用自備的那個共用 post-beam AecRes 呼叫 aec_res_set_level(res, …);mcab 與 helper 都沒有強度 setter。

5. 範例 C／D:兩條 ULCNet 範例 — 接 NN 的做法

從 AEC 拿什麼

aec_process_context(aec, mic, ref);
aec_get_res_context(aec, &rctx);      /* rctx.formed_hop     ← 時域線性誤差 */
aec_get_linear_context(aec, &lctx);   /* lctx.delay_state    ← 對齊事件; far 取呼叫端的 raw ref */

注意 mono 拿的是「時域」兩個 tap,不是頻譜——stage 有自己的 STFT(ulcnet_nn_stage_begin_time()),AEC 的 error_spec 完全不用;兩路都走 center 0 的 AcStft 與 ac_stft_push_planar()(rolling,不是 centered)。4ch不做 error 分析:beam.spectrum 直接當 error 幀(ulcnet_nn_stage_begin_complex()),far 分支走同一個 ac_stft_push_planar()。

邊界偵測與 reprime

/* gate_delay(): changed = (delay_state == AEC_LINEAR_DELAY_CHANGED); solid = (delay_state != UNLOCKED) */
if (delay.changed || (frame_index != 0 && !last_delay.solid && delay.solid)) {   /* 無 generation 事件的模式: 首次轉為可用也算邊界 */
    if (s->model.reset) s->model.reset(user);   /* 通知 NN 丟棄跨 frame 狀態 */
    s->reprime_frames = ULCNET_NN_STAGE_REPRIME_FRAMES;   /* mono=1, 4ch=1: 同一個 stage 常數 */
}
reprime frame 數是量測出來的,不是猜的:兩條都是 1——兩條的兩個 branch 都從當前 input hop 取幀,50%-overlap 幀橫跨兩個 hop,只有邊界 hop 那一幀還蓋到切換前的 hop。常數綁定 hop 結構,改 framing 必須重新量(mono/alignulcnet/tests/test_mono_ulcnet.c 與 4ch/alignulcnet/tests/test_4ch_ulcnet.c 的 test_reprime_straddle_derivation())。

Fail-open 三層 + FULL-WRITE CONTRACT

if (reprime_frames > 0) {
    /* identity,不 step model */
} else if (model.infer) {
    for (k) { mdl_re[k] = NAN; mdl_im[k] = NAN; }   /* ← 先全填 NaN */
    rc = model.infer(user, err_re, err_im, far_re, far_im, mdl_re, mdl_im);
    if (rc == 0 && ulcnet_frame_is_finite(mdl_re, mdl_im)) { /* 採用 */ }
    /* 否則 identity */
}
ac_istft_push_planar(synth, sre, sim, out + wrote);
Fallback 條件行為
infer == NULLidentity
infer 回非 0identity
輸出有任何非有限值identity

三種情況的時序路徑完全相同 → latency 不隨 model 健康度變動。先全填 NAN 是為了把「沒寫」變成可偵測——finite guard 抓得到未寫入,但抓不到寫錯形狀。

把推論留給 NPU:begin / nn_begin / nn_end / end

兩條 ULCNet 與兩個 DFN 範例都把一個 hop 拆成四個呼叫;加速器就坐在 nn_begin 與 nn_end 之間,模型的 infer 回呼因此可以不設。一次呼叫的 ulcnet_nn_stage_process()／dfn_hop_process() 就是這個序列加上已安裝的回呼。

UlcnetNnJob job;
ulcnet_nn_stage_begin_time(stage, rctx.formed_hop, ref, delay);   /* err／far 分析 (4ch: _begin_complex(stage, beam.spectrum, far, delay)) */
if (ulcnet_nn_stage_nn_begin(stage, &job) > 0) {   /* 1 = 有一幀;0 = 本 hop 無模型幀 */
    int rc = board_run_npu(job.err_re, job.err_im, job.far_re, job.far_im,
                           job.out_re, job.out_im);   /* out 已預填 NaN,必須寫滿 */
    ulcnet_nn_stage_nn_end(stage, rc);   /* rc!=0 或非有限 ⇒ identity */
}
ulcnet_nn_stage_end(stage, out);   /* 合成剛好一個 hop */

DFN 範例的 dfn_hop_nn_begin 在迴圈裡(while (dfn_hop_nn_begin(&hop, &job) > 0) { rc = run_npu(&job); dfn_hop_nn_end(&hop, rc); }),因為 rate bridge 在一個 native hop 內可能開 0..2 個 48 kHz 幀(板端每次跑前比對 dfn_res_stage_state_generation(dfn_hop_stage(&hop)),見 DFN2 pipeline 呼叫與時序);ULCNet 板端同樣比對 ulcnet_accelerator_adapter_state_generation(),變動時重載量化零。

4 聲道 ULCNet 應用若要用由同一 hop 的 lane 頻譜算出的 mask 與 VAD,把 helper 的 hop 拆成 mcab_sample_beam_process_front() 與 mcab_sample_beam_process_beam(),呼叫端在兩者之間讀 front.linear_spectra[0](見 四聲道 · Align-ULCNet)。

Model I/O descriptor 是必要的,不是選配

ulcnet_nn_stage_set_model():model->infer 非 NULL 而 io_descriptor 為 NULL ⇒ 回 −1;有 descriptor 但 ulcnet_model_io_descriptor_validate() 不為 0 ⇒ 回 −1。

掛了真的 runtime 就必須提供 descriptor(identity model 才可以留 NULL)。理由:finite guard 只抓得到「沒寫」,永遠抓不到「寫錯形狀」——graph 的 D 與 descriptor 不符時,會靜默地以錯誤形狀讀寫 state(float host 登錄的緩衝或加速器內的 state),pool 擋不住。descriptor 內容包含 layout_version(必須等於 ULCNET_MODEL_IO_LAYOUT_VERSION)、delay_depth D ∈ [2,64]、grid 幾何、以及 far_input_mode 必須是 ULCNET_FAR_RAW。

4ch ULCNet 的 front-only 契約

flow 以 enable_post = 0 建立(ulcnet_example_unit_config(&grid):mcab_default_config(grid.sample_rate) 加 fft_size = grid.n_fft)時,mcab 不 carve fuse 緩衝,lane 只留線性 context(AEC_CONTEXT_LINEAR_ONLY),mcab_sample_beam_fuse() 回 INVALID_ARGUMENT;mcab、helper 與 stage 都不建任何 denoiser／suppressor／comfort noise／post iFFT。McabConfig 與 helper 參數沒有 RES／NR／CNG／level 欄位;auto_vad_* 欄位照常驗證(本範例走 process_with_activity(),不用內建 energy VAD)。pre-stage 欄位(delay_*／capture_proxy_channel／max_delay_ms)照常生效;lane 的 filter_length 是 lane 的 AecConfig(本範例經 mcab_sample_flow 用 mcab_lane_config() 的預設)。

stage 與 flow 的 grid 必須一致:4ch/alignulcnet/tests/test_4ch_ulcnet.c 的 test_example_unit_config_grid 檢查 unit config 的 grid、enable_post = 0、fuse 被拒,以及另一個格點的單元可以建立但接不上 stage。

6. layout_version 對整合者的意義

函式庫物件目前版本
4ch_aec_bf_nr_res(4ch flow,mcab.h;只描述 mcab 自己的 pool)MCAB_LAYOUT_VERSION = 26
DFN2 stage／rate bridgeDFN_RES_STAGE_LAYOUT_VERSION = 6、DFN_RATE_BRIDGE_LAYOUT_VERSION = 6
mono(Aec、AnrDenoiser、AcIstft)、ULCNet stage、DfnHop沒有 descriptor、沒有 layout version(函式庫物件只提供大小查詢;stage／hop／helper 為範例碼)

規則:pool 大小、carve 順序或 descriptor 內容任一改變,該模組的版本加一。

版本一動,任何持久化的 descriptor 都必須丟棄重查。build_flags_hash 不含 sizeof／byte count,control block 只是長大而 carve 結構沒變時 hash 不會動,所以 layout_version 是唯一訊號;descriptor 的 bytes 比較只是下界,擋不住等量語意變更,其他版本的 descriptor 即使快取的 byte 數仍涵蓋現行 pool 也必須被拒絕。

7. DEBUG:出貨板上還剩什麼

出貨板上唯一還活著的診斷面是「主動 poll 的結構化狀態快照」;事件式(log／trace)與時間式(stage timing)觀測在 release 組態下歸零,assert() 仍是活的,mono pipeline 沒有 finite 守衛。Release build 的 nm 實測、可照抄的板端監看迴圈與完整盲點表收在 整合層級與程式骨架;新增哪些 DEBUG 資訊的提案見 docs/debug_observability_zh_TW.md。

8. 整合檢查清單

  • sample rate、frame/FFT、hop 是同一個合法 grid,且三個 lib 對得上(照抄 mono 的 grid agreement guard)。
  • mic/ref 同 sample rate、同 clock;ref 是實際 speaker render reference。
  • 每次呼叫恰好傳一個 hop。
  • 所有 pool 以 resolved config 查 size(每個函式庫各自查、各自對齊後加總),base 至少 16-byte 對齊;descriptor 與大小都不可跨版本快取。
  • stream boundary 同時 reset DSP instance(Aec／mcab＋helper、AnrDenoiser、AcIstft、stage)與 caller 自己的 ring/WOLA state;任何一步被拒,三者一起 reset。
  • borrowed context/gain pointer 沒有跨下一次 process 保存。
  • AEC 的 r2／comfort_noise 是 int16² 尺度:mono_nr_gain()／mcab_sample_anr_gain() 與 aec_cng_fill() 內部已換算(÷32768²);自寫 stage 要自己換算。
  • 接 NN 時 descriptor 非 NULL,且其 D 與 graph 一致(這條沒有任何自動檢查)。
  • application 與三個 archive 使用相同 backend、SIMD、FP flags。
  • 最終 float→PCM 前做 saturating conversion;limiter 只放在整條 chain 最後。
  • 完整應用優先跑 pipeline tests,而不只跑各 library 的 unit test。

板端監看與 MCAB 時序

4. mcab 的 front／fuse 呼叫序列

4.1 front 半的呼叫序列(重點在 far-FFT 共用)

1. skn_all_finite_f32(mic_interleaved, hop*4) && skn_all_finite_f32(ref, hop)   ← 唯一的輸入 NaN gate
2. de-interleave proxy channel → mic_lane
3. update_shared_delay(...)          ← duty 決策 + matched filter + ERLE watchdog
4. align_render(ref, delay)  → aligned_ref
5. if (delay.changed) 四 lane 各跑 aec_apply_external_realign(lanes[ch], delta)
6. for ch in 0..3:
     de-interleave lane ch
     ch==0 : aec_process_context(lanes[0], mic_lane, aligned_ref)
     ch!=0 : aec_process_context_shared_far_from(lanes[ch], mic_lane, aligned_ref, lanes[0])
     aec_get_res_context(lanes[ch], &context)
     bind_lane_view(&snapshots[ch], &context)          ← 借指標,不複製
7. front-valid 旗標置位(mcab_fuse 的序列閘)
四條 lane 這一 hop 看到同一個 aligned_ref 指標,所以其他三條可借用 lane 0 的 far 頻譜 → 4 次 far-FFT/hop 變成 1 次(混合 warm／soft realign 的 hop 改為各 lane 自算,見 四聲道 參數與診斷)。這是 aec_process_context_shared_far_from() 存在的理由,也是它嚴格的 same-hop/same-reference 前提的由來。

4.2 fuse 半

1. front-valid 檢查                         ← 序列協定
2. mcab_weights_valid():逐元 isfinite + Σ|.| > 1e-12
3. fuse_contexts():coherent projection,四 lane far_power 一致性檢查,投影結果與 beamformed 頻譜的有限檢查
   (失敗 → MCAB_DSP_ERROR,mcab 已 reset)
   → 填 McabFrame(e/y/x/r2/cn/far_hop/formed_hop/max_dt/max_sat/all_converged/delay 旗標)

7.2 可以直接照抄的板端監看迴圈

/* 每秒一次即可;三個 API 都是免費的(只讀引擎已維護的欄位) */
AecDebugStatus      a;  aec_debug_status(aec, &a);
AnrDebugStatus  n;  anr_debug_status(nr, &n);   /* nr = 你自己 anr_init() 的物件; NULL = 沒有降噪器 */

log("delay=%d conf=%.1f upd=%d erle=%.1fdB usable=%d conv=%d "
    "near=%.4f out=%.4f duty=%llu/%llu | nr_init=%d gain=%.1f/%.1fdB "
    "spp=%.2f noise=%.1fdB",
    a.delay_samples, a.delay_confidence, a.delay_updates,
    a.erle_windowed_db, a.usable_linear, a.filter_converged,
    a.near_power, a.out_power, a.duty_hops_run, a.duty_hops_total,
    n.initialized, n.mean_gain_db, n.min_gain_db, n.mean_spp, n.noise_floor_db);
讀到這樣通常代表
delay=-1 一直不變從未鎖定。檢查 ref 是否真的是送往喇叭的訊號、電平是否過低
erle 低但 conv=1濾波器收斂了但 echo 仍在 → 懷疑鎖到錯的 delay(早期反射),或非線性失真超出線性模型
duty_run/duty_total 接近 1.0 且長時間不降duty-cycle 未啟用(delay_est_period_s = 0,預設),或已啟用但 delay 一直不穩定而從未進入抽樣
nr_init=0 持續還在啟動 pass-through(前 num_init_frames 個 frame),此時完全不降噪是正常的
mean_spp 長期接近 0判定沒有語音 → 檢查電平或噪聲底是否估過高
noise_floor_db 隨語音一起爬升噪聲估計正在吸收語音 → 檢查 delta_db／alpha_d
三個常見誤判,先看這裡再懷疑演算法:
  • aec_get_last_timing() 回全 0 不代表很快——代表沒有用 PROFILE=1 建 library。而且函式不會告訴你它沒被啟用。
  • delay_updates 是 matched-filter 的更新總數,不區分「同一值重複確認」與「跳到新值」,不能當成 lock 穩定度指標。
  • near_power／out_power 是逐樣本的 EMA(alpha = 0.95^(16000/取樣率),16 kHz 為 0.95),不是瞬時值;duty_* 會被 reset() 清零。
