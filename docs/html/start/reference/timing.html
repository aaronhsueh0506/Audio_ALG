Audio_ALG / 建置與第一次執行

逐 hop 時序與 reset

本頁目錄
  • 1. mono:Aec + AnrDenoiser + AcIstft
  • 2. 4ch:array(共用 delay、4 lane、融合與增益級)+ sample helper(SRP-PHAT、BF)
  • 3. 4ch:array + 外部 beamformer(產品自己的波束器,不用 helper)
  • 4. 錯誤與 reset:誰重設什麼
  • 5. 接 NN 後級的 hop 骨架(摘要)

概要

4 聲道的線性 AEC 前端是 Aec 的 array instance(AecConfig.n_mics = 4:四條 lane、共用 estimator、融合與增益級在同一塊 pool 內),SRP-PHAT／BF 在 sample helper array_sample_beam。其餘 stage(降噪器、合成;mono 與 4ch 的 RES 都在 AEC 呼叫內)都是獨立函式庫,各有 *_get_mem_size() 與 *_init(),初始化、逐 hop 串接、錯誤後的 reset 順序都是整合者(應用)的責任,範例 main 就是參考寫法。本頁用時序圖把三件事畫在一起:建立(一次)、每 hop 的呼叫順序、被拒絕或換串流時的 reset。圖中的箭頭標的都是真實函式名;「借用」代表回傳的指標指向函式庫內部 buffer,只到下一次處理呼叫或 reset 之前有效,不可寫入。

責任誰擁有
pool 記憶體(16-byte 對齊的一塊或多塊)應用:每個函式庫先 *_get_mem_size()(0 = 設定無效),應用配置並 carve 成 16-byte 對齊的子區塊,*_init() 在上面建構;*_destroy() 不釋放 caller pool
格點與 config 的一致性應用:AEC、NR、合成都用同一個 grid.fft_size 導出 config(三者 n_freqs／hop 對不上不會被偵測,會在頻域靜默錯位)
輸入守衛(是否有限)mono:沒有(aec_process_linear() 與 anr_process_gain_with_residual_psd() 不檢輸入);4ch:aec_process_linear() 拒非有限樣本(AEC_ERR_ARG)。輸出守衛由應用做(skn_all_finite_f32();mono 的 main.c 本身不做,example_board_adapter.c 有做)
RES(殘留回音增益)mono:在 aec_process_residual() 內算,經 aec_get_residual() 的 v.res_gain 交出;4ch:在 array 的 aec_process_residual(&AecBeam) 內對融合後的頻譜算一次(residual = FULL),helper 不算;兩者都由 aec_apply_gain() 套用
reset 的範圍函式庫只 reset 自己;任何一步被拒,應用把所有 stage 一起 reset(見第 4 節)

1. mono:Aec + AnrDenoiser + AcIstft

   │═ ④ 結束 ══════════════════════════════════════════════════════════════════════

mono_nr_gain() 只在 use_r2、v.r2 非 NULL 且 v.usable_linear 非零時才把 r2/32768² 折進噪聲底,否則等於純降噪。--aec-only:只建 Aec,每 hop aec_process_linear()、aec_process_residual() 後把 aec_get_linear() 的 linear_hop 複製到 out(0-hop lag)。逐 hop 的 swimlane 與延遲見 Mono · AEC／NR／RES。

3. 4ch:array + 外部 beamformer(產品自己的波束器,不用 helper)

波束器在別處時不需要 helper:aec_process_residual(a, &AecBeam{weights, beamformed_error}) 就是外部權重的入口,RES 增益由 array 的增益級(residual = FULL)算。範例:4ch_external_static.c(權重為每個 bin 皆 1/4 的等權佔位)。

 │   front.lane_error_spec[4] / lane_formed_hop[4] / aligned_ref / delay(delay.changed 非零 ⇒ 外部 STFT/OLA 歷史須清)

4. 錯誤與 reset:誰重設什麼

呼叫回傳／情況函式庫自己做了什麼應用要做什麼
aec_process_linear()／array_sample_beam_process_front()AEC_ERR_ARG(NULL 或非有限樣本)不動 adaptive state;非有限樣本時 array 完全不動(上一個 hop 的視圖仍可讀、待處理的 linear 保留),helper 則不再有 pending beam(NULL 引數則維持原狀)修正輸入後重送;不需 reset
同上AEC_ERR_DSP(lane 拒絕該 hop,或對齊環無法服務目前 delay)array 已 reset(lane＋estimator＋增益級);helper 的 SRP、BF、fallback VAD 與 frame_index 不動reset 自己的後級(NR、合成、handled)
array_sample_beam_process_beam()AEC_ERR_SEQUENCE(沒有 pending linear,或本 hop 的 beam 已跑);AEC_ERR_ARG(NULL、flag 不是 0／1、他格點的 front)不改動修正呼叫順序
array_sample_beam_fuse()AEC_ERR_ARG(NULL)、AEC_ERR_SEQUENCE(本 hop 沒有 beam)、AEC_ERR_MODE(array 是 STATE)不改動修正呼叫
同上其餘非 OK(含 array 因權重或 beamformed 頻譜非有限回的 AEC_ERR_ARG、lane far 頻譜不一致或頻譜非有限回的 AEC_ERR_DSP)依 array_sample_beam.c:整個 helper reset(array、SRP、BF、VAD、frame_index)後回傳reset 自己的後級
aec_process_residual()(直接用 array)AEC_ERR_ARG(權重全零或非有限,或 beamformed_error 含非有限值)linear 保持可用修正權重後可重試同一 hop
同上AEC_ERR_SEQUENCE(沒有 linear,或 FULL 同一 hop 第二次);AEC_ERR_MODE(STATE);AEC_ERR_DSP(lane far 頻譜不一致、lane 頻譜非有限或投影溢位)前兩者不改動;後者 array 已 reset後者 reset 自己的後級
NR 增益(mono:mono_nr_gain();4ch:array_sample_anr_gain())／aec_apply_gain()／aec_apply_cng()回 NULL／非 AEC_OKNR 該 hop 被拒,或 AEC 缺增益(AEC_ERR_MODE／AEC_ERR_SEQUENCE)視為該 hop 被拒,所有 stage 一起 reset:mono CLI 把該 hop 輸出填 0 後繼續;4ch 範例 reset 後回傳該碼並結束該次執行
輸出非有限(skn_all_finite_f32() 為 0)——array／helper／Aec 與後級一起 reset(範例 static_hop()／raw_post() 的寫法)
4ch 的後級物件(AnrDenoiser、AcIstft)與你記的 post_reset_serial 都不在 array／helper 裡,array_sample_beam_reset() 與 aec_reset() 不會動它們;comfort-noise 產生器是 array 自己的,aec_reset() 會重設它。array 的 reset 一併重置四條 lane、estimator 與增益級(level 設定保留)。mono 的 mono/aec_nr_res/main.c(同一份原始碼建出 aec_nr_pipeline_static 與 -DAEC_NR_POOL_SPLIT=1 的 aec_nr_pipeline)在 process_hop() 回 −1 時呼叫 rig_reset() 並把該 hop 輸出填 0;這支 CLI 本身不做輸出有限檢查,example_board_adapter.c 與 4ch 的 static_hop()／raw_post() 才有。

5. 接 NN 後級的 hop 骨架(摘要)

NN 後級把一個 hop 拆開,加速器夾在開幀與收幀之間(ULCNet:ulcnet_stream_pre_process_freq 與 ulcnet_stream_post_process_freq;DFN2:dfn_hop_nn_begin 與 dfn_hop_nn_end);細節與 fail-open 規則在 串接範例 第 5 節、Mono · Align-ULCNet／Mono · DFN2。

應用            Aec 或 4ch(array＋helper)  模型串流(stream)            NN runtime／加速器
 │── (Aec: aec_process_linear + aec_process_residual + aec_get_residual／aec_get_linear) 或 (4ch: array_sample_beam_process_front/beam[/fuse]) ►│
 │── ac_stft_push_planar(far[, err]) ►│ 應用端分析 err／far
 │── ulcnet_stream_pre_process_freq(stream,err,far,delay,&io)  (dfn: dfn_hop_begin + dfn_hop_nn_begin) ►│ 回 1=有一幀、0=本 hop 無模型幀
 │── board_run_npu(io.inputs, io.outputs) ───────────────────────────────►│ mask 已預填 NaN,必須寫滿
 │── ulcnet_stream_post_process_freq(stream,rc,out_re,out_im)  (dfn: dfn_hop_nn_end + dfn_hop_end) ►│ rc≠0 或 mask／輸出非有限 ⇒ identity(fail-open)
 │── ac_istft_push_planar(out_re,out_im) ►│ 應用端合成 → out[hop]

DFN2、DeepVQE-S、Align-ULCNet 的 lib 只有逐 frame 函式（pre_frame／views／validate_run／post_frame／zero_state），每包的呼叫順序在它們的 stream 裡（上圖）。DFN3、GTCRN、RNNoise-ERB 沒有 stream 層，應用端直接用 <pfx>_prepost 類別（下圖是 DFN3）：framing 由應用端用 audiolib 做，類別只收發頻譜；遞迴 state 由應用端登錄（float host）或留在加速器（板端）。各類別的引數差異見 ONNX 邊界與 calibration。

應用            AcStft/AcIstft(audiolib)   DFN3 prepost 類別(頻域)     加速器
 │── ac_stft_push_planar(stft,hop_in,re,im) ►│
 │── pre_process_freq(p,re,im…) ───────────────────────►│ 1 = 這一 hop 要推論(前 M 個 hop 回 0:沒有 job、不開幀、加速器不跑、state 與 generation 不動;DFN2 N=1 的 stream 同理)
 │── frame_open(p,&in,&out) ───────────────────────────►│ view:特徵視窗 + 登錄的 state(板端 NULL);heads 預填 NaN
 │── 推論(in,out) ─────────────────────────────────────────────────────►│ 每個 state 輸出寫回同名輸入的位址
 │── frame_finish(p) ──────────────────────────────────►│ 0 = 提交;−1 = 登錄 state 歸零、generation+1、幀維持開啟 → frame_bypass(p)
 │── post_process_freq(p,out_re,out_im…) ──────────────►│ 增強後頻譜(valid = 0 時為零頻譜,可每 hop 照 push)
 │── ac_istft_push_planar(istft,out_re,out_im,hop_out) ►│ hop_out[hop]
 │ state_generation 與上次不同(reset、被拒的 frame_finish)⇒ 板端以量化後的零重填加速器的 state 輸入
