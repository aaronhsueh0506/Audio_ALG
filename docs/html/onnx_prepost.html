ONNX / NPU 邊界與 calibration

所有 production export 都是 stateless accelerator graph。GRU hidden、 convolution cache、attention/KV ring 都是明確 input/output，由應用端持有：float host 把緩衝登錄進 C 類別的 config， 板端不登錄、由加速器自己保存；函式庫不知道這些 state 的 shape。STFT／ISTFT 也由應用端用 audiolib 的 AcStft／AcIstft 做，C 函式庫只收發頻譜；linear AEC 與輸出頻譜的建構同樣留在 graph 外。 複數一律以 real/imag pair 表示。

Align-ULCNet、DeepVQE-S、DFN2、DFN3、GTCRN 與 RNNoise-ERB 的每個 state 輸入與 *_out 輸出 shape 相同，綁到同一個位址，沒有複製路徑。 C 端的 reset、暖機幀與被拒的 frame_finish／validate 只歸零登錄的 host state，加速器那份定點 state 看不到，所以每個函式庫各有一個 state generation 計數器； runtime 發現數值與上次看到的不同，就把自己的 state tensor 填成量化後的零（下方「遞迴 state」）。

使用者入口

每個模型從自己的目錄提供 graph 匯出與 calibration 入口。下例為 DFN2/DFN3；AIAEC 模型使用 --checkpoint，其餘模型請依自己的 --help 選參數：

python3 export_onnx.py --model checkpoint.pth --output output/model.onnx --verify
python3 inference.py calib --model checkpoint.pth ... --format bin --output calib/model

inference.py calib 會在同一 process、同一 model instance 一併匯出並 parity-check calibration tensors 所綁定的 graph（預設 <output>.onnx， --onnx 可改路徑），兩個部署產物不可能 drift；export_onnx.py 保留給只要 graph 的情境。

BIN calibration layout 為 tensor/tensor_0000.bin、tensor/tensor_0001.bin 等 （零填充、0-based，寬度超過 10000 幀自動增加，字典序即幀序），每個 tensor 每個 frame 一個檔；manifest.json 記錄 dtype、shape、 grid 與 state contract。--format npz 產生 NumPy archive 與 同名 JSON report。

C pre/post 類別（四個模型共用的形狀）

Align-ULCNet、DeepVQE-S、DFN2、DFN3 各有一個 pre/post 類別，把「頻譜 ↔ 加速器張量」之間的一切收進一個物件： 特徵前後端、feature window／ring、frame 狀態機。類別只處理頻域：framing（AcStft／AcIstft、FFT handle、window） 由應用端用 audiolib 建立並呼叫，類別不持有；遞迴 state 同樣由應用端持有。 四個類別的 API 形狀相同，只是前綴 <pfx> 不同（ulcnet / deepvqe / dfn2 / dfn3）：

<lib>_grid_make(&grid, &spec);                  /* 執行期 grid；spec 是匯出模型定下的值（DFN2／DFN3 含 lookahead pair） */
<pfx>_prepost_config_defaults(&cfg, &grid);        /* grid 複製進 cfg；DFN2／DFN3 再設 cfg.erb_fwd／erb_inv */
float host：cfg 登錄 state 緩衝（指標＋元素數，全登或全不登）；板端：不登錄
<pfx>_prepost_get_mem_size(&cfg, &req);            /* reject-first：壞參數回 −1、req 不動 */
p = <pfx>_prepost_init(pool, req.bytes, &cfg);       /* 或 _init_ex(pool, bytes, &cfg, &expected)；host 工具：_create(&cfg) */
每 hop：
  ac_stft_push_planar(stft, hop_in, re, im);      /* 應用端 framing */
  n = <pfx>_prepost_pre_process_freq(p, 頻譜…);   /* 這一 hop 的推論次數 */
  if (n == 1) {
      <pfx>_prepost_frame_open(p, &in, &out);   /* pool 內的 view；非 state 輸出預填 NaN；state 為登錄的緩衝（板端 NULL） */
      加速器填 out                                /* 每個 state 輸出綁到同名輸入的位址（先讀完 state 輸入再寫輸出） */
      if (<pfx>_prepost_frame_finish(p) != 0) <pfx>_prepost_frame_bypass(p);
  }
  <pfx>_prepost_post_process_freq(p, out_re, out_im[, &valid]);
  ac_istft_push_planar(istft, out_re, out_im, hop_out);   /* AC_OLA_ACCUMULATE：每 hop 都 push，valid 只是資訊 */
其餘：_reset（應用端的 AcStft／AcIstft 要一併 reset）／_destroy／_hop_size／_num_bins／_state_generation（見下）

一 hop = 一次推論：pre_process_freq 回傳這一 hop 需要的加速器呼叫次數（−1 = 引數為 NULL 或上一幀還開著）。 Align-ULCNet（引數 err_re, err_im, far_re, far_im）與 DeepVQE-S（mic_re, mic_im, far_re, far_im）從 hop 0 起恆為 1，post_process_freq 不帶 valid； DFN2（N = 1）與 DFN3（引數 re, im）也每 hop 回 1；前 M 個 hop（M = mask_lookahead；graph 的視窗是 [t−(2−M), …, t+M]，右鄰居還沒到；出貨 M = 1 即第一個 hop）是暖機幀：加速器照跑，heads 由 frame_finish／frame_bypass 丟棄、登錄 state 歸零，音訊不變。post_process_freq 的 valid 為 0 時輸出是零頻譜。 M 與 df_lookahead D 是 DFN2GridSpec／DFN3GridSpec 的欄位（15 組合法 pair，出貨 1/1；圖本身與 pair 無關，metadata 記錄 pair；見 ainr_dfn2_detail）。 DFN2 另可匯出每次 invocation N 個 frame 的 graph（--frames-per-call N，輸入 N+2 個 feature frame、輸出 N 個 frame 的 heads）： N 是 DFN2GridSpec.frames_per_call（1..64），pre_process_freq 改為每 N 個 hop 回 1 一次（N>1 無暖機幀），dfn2_prepost_latency_frames() = M + D + N − 1；pipelines 固定 N=1。

pipeline 層的對應：四個應用（mono_alignulcnet、4ch_alignulcnet、mono_aec_dfn_res、4ch_aec_bf_dfn_res）把同一個 hop 拆成 begin → 取 job → 呼叫端在 NPU 上推論 → 回報 rc → end。 DFN2 應用用 dfn/dfn_hop.h：dfn_hop_begin() → while (dfn_hop_nn_begin() > 0) { 推論; dfn_hop_nn_end(rc) } → dfn_hop_end()，job 是 DfnResStageJob（DFN2PrepostInputs/Outputs 視圖）。 ULCNet 應用用 ulcnet/ulcnet_nn_stage.h：ulcnet_nn_stage_begin()／_begin_complex()／_begin_time() → ulcnet_nn_stage_nn_begin()（回 1 並交出 UlcnetNnJob；回 0 表示本 hop 無模型幀）→ 推論 → ulcnet_nn_stage_nn_end(rc) → ulcnet_nn_stage_end()。 兩者都是：rc==0 且輸出有限才提交，否則該幀走 identity（等同 _frame_bypass 的語意）；輸出預填 NaN；合成剛好一個 hop。 DFN 應用經 rate bridge 時一個 native hop 可能有 0..2 個幀，所以 dfn_hop_nn_begin() 放在迴圈裡。 逐步呼叫序列與時序圖見「相關檔案」，另見 pipelines/README.md 的 Call flow。

frame 狀態機：frame_open 只把非 state 的輸出 （heads：output／taps／erb_mask／coefs／alpha， Align-ULCNet 的 output）預填 NaN，state 不預填。frame_finish 是純驗證： heads 與（有登錄時）state 都有限才成功，之後 CCM ring／enhance_spectrum／輸出暫存照常前進，本身不複製任何 state。 state 已被加速器就地覆寫、無法回滾，所以遇到任何一處非有限值時所有登錄的遞迴 state 歸零（冷啟動）、state generation 加一、 CCM ring／輸出暫存不前進、幀維持開啟、回 −1 （Align-ULCNet：key／value／logit 三個 window 與 h_gru 共四個 state；DFN2、DFN3：h_gru 與 df_convp_history 兩個遞迴張量；DeepVQE-S：16 個 state）， 呼叫端再選 frame_bypass 或用新的 frame_open 從冷 state 重跑加速器。 frame_bypass 該幀取 identity（DeepVQE-S 為靜音）、遞迴 state 維持原樣（加速器寫完的樣子；回報失敗的 runtime 視為沒有寫入）；DFN2、DFN3 的 frame clock 照常前進，DeepVQE-S 的 CCM ring 不前進。 frame_finish 沒有 frame_open 就回 −1，heads 預填 NaN，所以「加速器根本沒跑」不會被當成結果收下；幀還開著時再呼叫 pre_process_freq 回 −1。

遞迴 state：就地綁定，由應用端持有。每個 state 張量只有一個 buffer、位址在實例壽命內不變，沒有交替的 bank、沒有指標交換、沒有複製路徑。 float host 把 buffer（指標與元素數，不是 byte）登錄在 config：DFN2／DFN3 的 gru_hidden／df_convp_history、Align-ULCNet 的 key_history／value_history／logit_history／h_gru、 DeepVQE-S 的 state[16]、GTCRN 的 state[8]、RNNoise-ERB 的 h1／h2／h3；init 與 reset 歸零它們，frame_finish（GTCRN 為 state_validate）掃過每個 buffer 的全部元素， 舊格子裡殘留的非有限值也會被拒。板端不登錄（view 回 NULL 與 0），state 由加速器的 buffer 保存。登錄規則一律「全登或全不登」，只給指標或只給元素數會被拒； 登錄的 buffer 不在 pool 大小與 hash 裡，生命期由應用端負責。 runtime 把每個 *_out 綁到同名輸入的同一個位址，先讀完所有 state 輸入、才寫輸出（做不到的 runtime 要自己用暫存區暫存讀取）；維護者的板端驗證確認 NPU 以這個順序工作。 graph 回每個 state 的完整下一個 window，shape 與輸入完全相同：位移在 graph 內，用輸入端的 Slice 切掉一幀、 再把新一幀 Concat 上去（time-ordered window 取 frame 1..N−1 再接在後面；newest-first 的 K/V 與 attention ring 取 slot 0..D−2 再接在前面）， Concat 的結果就是輸出，沒有 state 輸出由 Slice 產生；被丟掉的那一格只讓輸入與輸出 shape 相同。 匯出時 validate_inplace_state_graph()（AINR/onnx_streaming_contract.py，AIAEC 匯出器經 validate_inplace_state_contract 呼叫同一份實作）逐檔檢查這個結構，metadata 帶 state_binding = in_place_same_address， 並為每個 window 宣告丟哪一端（AINR 的 state_slicing 內 drop、AIAEC 的 state_window_drop：time-ordered window 為 first，newest-first ring 為 last），驗證器只接受那一端的 Slice 範圍。RNNoise-ERB 的匯出器只寫 state_layout_version，不寫 state_binding，也不跑這項檢查。

state generation：<pfx>_prepost_state_generation()（DFN2、DFN3、Align-ULCNet 的 *_model_io_state_generation() 與 ulcnet_accelerator_adapter_state_generation() 依同一規則）、 gtcrn_process_state_generation()、rnnoise_state_generation() 數 C 端把 state 重啟的次數：reset、DFN2／DFN3 的每個暖機幀與被拒絕的 frame_finish／validate 各加一，有沒有登錄 state 都照算。 pipelines 的 dfn_res_stage_state_generation()／dfn_rate_bridge_state_generation() 同理（stage／bridge 不登錄 state，state 在模型 callback 手上）。 板端 sample 比較這個值，與上次看到的不同就用量化後的 0 重填 state 輸入。 起始值不同（DFN2、DFN3、GTCRN、RNNoise-ERB 的 init 後為 1，Align-ULCNet、DeepVQE-S 為 0），所以只比較「是否變動」，不假設起始值。

生命週期兩條（audiolib/common/include/fft_wrapper.h「Static memory support」）： 板端 _init／_init_ex 建構在 caller pool 上，host 工具用 _create／_destroy（GTCRN、RNNoise-ERB 沒有）。_init_ex 多收一個 MemReq （32 byte：descriptor_version、layout_version、必為 0 的 reserved0、build_flags_hash、alignment、reserved、bytes； RNNoise-ERB 為 24 byte、沒有 reserved 欄）當陳舊 pool 閘：build_flags_hash（FNV-1a-32）折入 grid、layout 與 carve 版號 （Align-ULCNet、DeepVQE-S 另折入 D；pool 大小與 D 無關，hash 仍隨 D 變）：為別的 grid／D／build 量出來的 pool 會被拒絕，不會被重新解讀。_destroy 對 _init 實例是真正的 no-op、可重複呼叫；_create 實例只能毀一次。

為什麼各自是獨立的 TU：ulcnet_prepost.c、deepvqe_prepost.c 各是一個 TU，使用 ulcnet_model_io.c、deepvqe_process.c， 後兩者維持各自可獨立連結（AIAEC/Makefile 註解）；AINR 的 dfn2_process.c、gtcrn_process.c 也單獨連結進 test_nn_kernels。

Build

兩個 repo 的靜態庫都依組態編碼：物件與封存檔放在 build/simd<N>-<sig>/（sig 由 CC/AR/CFLAGS/CPPFLAGS/SIMD/WERROR 算出）， 每個目錄記下自己的 payload，簽章相撞會被拒絕而不是重新解讀， make print-lib-path 印出該組態封存檔的絕對路徑。

make -C AIAEC lib && make -C AIAEC print-lib-path   # libaiaec_prepost.a
make -C AINR  lib && make -C AINR  print-lib-path   # libainr_prepost.a
make -C AIAEC test                                  # 建庫 + pytest

libaiaec_prepost.a 成員：ulcnet_process、 ulcnet_model_io、ulcnet_prepost、 ulcnet_accelerator_adapter、aiaec_process、 deepvqe_process、deepvqe_prepost。 libainr_prepost.a 成員：dfn2_process、dfn2_model_io、 dfn2_prepost、dfn3_process、dfn3_model_io、dfn3_prepost、gtcrn_process、rnnoise_process （RNNoise-ERB 的 process.c；它自己的測試由 RNNoise-ERB/Makefile 建）。 AINR 成員會呼叫 audiolib（n_fft 檢查、skn_* 核心），連結時要一併帶 audiolib 的封存檔。

Calibration signal seam

AINR calibration 的 WAV 是 noisy speech。AIAEC E2E models 使用 mic + far。Align-ULCNet 使用已產生的 error + raw far（或 --primary-is-mic 餵 raw mic，由凍結 PBFDKF 現算 linear error 並 把衍生檔存於 artifact 旁）； manifest 會另外記錄產品部署輸入(raw far)，避免把校正資料來源與 board wiring 混為一談。

Batch-1 圖整理（onnx_batch1_optimizer.py）

串流圖固定 batch 1、每次呼叫 T 幀（單幀圖 T=1，--frames-per-call N 時 T=N；版面為 [1,C,T,F]，T 在 axis 2、不進 batch 軸），追蹤器因此產生大量只增減大小為 1 的軸的 op，以及 5～6 維的中間 tensor（目標平台量化工具鏈要求 rank-4）。onnx_batch1_optimizer.py（放在 Audio_ALG/PTQ，不屬於任何單一模型；測試在 AIAEC/tests/test_onnx_batch1_optimizer.py）不屬於任何匯出器：匯出、契約檢查、 等價比對與量化一致檢查都在未整理的圖上完成，最後才對匯出的 .onnx 單獨執行下列指令，產出可上板的圖。它可用在任何靜態形狀的 ONNX：

python3 PTQ/onnx_batch1_optimizer.py model.onnx -o model_b1.onnx --verify

三道 pass 都只重新標記軸、不改任何算術，因此結果必須與原圖在 onnxruntime 逐位元相同 （--verify 要求差 0）。唯一例外是下面 lower_rank 的多幀分組線性層：算的是同樣的內積， 但 onnxruntime 對 T 列與 1 列可能選不同的矩陣乘法 kernel，float32 加總順序不同，輸出會差在捨入等級 （本機差 0，其他機器或 onnxruntime 版本可能不為 0）。含這種 MatMul 的圖改用容許值比對： 每個輸出的差不得超過 REGROUP_RTOL（1e-4）乘上該輸出的最大絕對值（至少取 1）； 報告會註明「tolerance」與重排的層數，其餘的圖仍須完全相同。

  • fold_frequency_pad_into_conv：餵給單一 Conv 的頻率軸零 Pad 折進 Conv 的 pads （時間軸不 pad；ConvTranspose 不動）。
  • merge_views：Squeeze／Unsqueeze／Flatten／Reshape、只搬動大小為 1 的軸的 Transpose、 作用在大小為 1 的軸上的 Gather 都視為 view，連續的 view 併成一個 Reshape，進出形狀相同者直接移除。
  • lower_rank：高於 4 維的 tensor 以去掉最前面的大小為 1 的軸降到 4 維（逐元素 op、Transpose、 MatMul、ReduceSum/Mean/Max/Min、Softmax；其他 op 會列在 blocked），再由 merge_views 抵消成對的 Reshape。多幀圖（--frames-per-call N）的分組線性層 [1,T,G,1,K] @ [G,K,O] 沒有多餘的大小為 1 的軸可去，去掉最前面那個會讓 T 落在 axis 0 （加速器讀成 batch）；此時改把 T 放進 MatMul 的列軸（[1,G,T,K] @ [G,K,O]，前後各一個 Transpose），全程維持 rank 4、batch 1，每個輸出元素是同一個內積。axis 0 仍不為 1 的 tensor 會列在報告的 batch_axis_left。

整理前後的節點數與是否仍有 rank > 4 的 tensor 隨模型而定，以 --verify 的輸出為準（各模型的實測數字待量測）。 這些 op 在目標平台上是否有成本、rank-4 限制是否涵蓋中間 tensor，尚待工具鏈的算子報告確認。 改變算式的重寫（例如把 attention 的 Mul＋ReduceSum 改成 MatMul）不在此工具範圍，由各模型的匯出器決定。

Release checks

  1. ONNX checker 與 ONNX Runtime multi-step state parity 通過。
  2. 每個 state output 都有明確 next-input mapping，reset 不留下舊資料。
  3. BIN 檔數、dtype、shape 與 graph descriptor 一致。
  4. 非有限 input/state fail closed，不提交部分 state。
  5. C scalar/SIMD 測試通過。
