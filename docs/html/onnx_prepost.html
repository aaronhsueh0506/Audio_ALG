ONNX / NPU 邊界與 calibration

所有 production export 都是 stateless accelerator graph。GRU hidden、 convolution cache、attention/KV ring 都是明確 input/output，由 CPU 或 driver 保存並在下一次 invocation 送回。STFT、WOLA、linear AEC 與 output composition 留在 graph 外。複數一律以 real/imag pair 表示。

使用者入口

每個模型只從自己的目錄提供兩個入口：

python3 export_onnx.py --checkpoint checkpoint.pth --output output/model.onnx --verify
python3 inference.py calib --checkpoint checkpoint.pth ... --format bin --output calib/model

inference.py calib 會在同一 process、同一 model instance 一併匯出並 parity-check calibration tensors 所綁定的 graph（預設 <output>.onnx， --onnx 可改路徑），兩個部署產物不可能 drift；export_onnx.py 保留給只要 graph 的情境。

BIN calibration layout 為 tensor/tensor_0000.bin、tensor/tensor_0001.bin 等 （零填充、0-based，寬度超過 10000 幀自動增加，字典序即幀序），每個 tensor 每個 frame 一個檔；manifest.json 記錄 dtype、shape、 grid 與 state contract。--format npz 產生 NumPy archive 與 同名 JSON report。

C pre/post 類別（三個模型共用的形狀）

三個模型各有一個 pre/post 類別，把「caller 音訊 ↔ 加速器張量」之間的一切收進一個物件： framing、特徵前後端、recurrent ring／state bank。整合者不再自己把兩個 TU 接起來。 三個類別的 API 形狀相同，只是前綴 <pfx> 不同（ulcnet / deepvqe / dfn2）：

<pfx>_config_defaults(&cfg, io_mode[, delay_depth]);   /* 本 build 的 grid 預設值 */
<pfx>_get_mem_size(&cfg, &req);                       /* reject-first：壞參數時 req 不動 */
<pfx>_init(pool, bytes, &cfg) | _init_ex(pool, bytes, &cfg, &expected) | _create(&cfg)
每 hop：
  n = <pfx>_pre_process(p, hop…);      /* 或 _pre_process_freq()：這一 hop 的推論次數 */
      <pfx>_frame_inputs(p, &in, &out); /* pool 內的 view；每個可寫輸出預填 NaN */
      加速器填 out
      <pfx>_frame_commit(p);            /* 或 <pfx>_frame_skip(p) */
  <pfx>_post_process(p, out_hop, &written);   /* 或 _post_process_freq() */
其餘：_reset / _destroy / _hop_size / _num_bins / _io_mode / _descriptor

io_mode 在 init 固定（它決定 pool 大小，不是可切換的旗標）： *_IO_TIME hop 進 hop 出，framing／加窗／overlap-add 由類別做，但呼叫的是 caller 自己的 FftHandle 與 window 表（借用，類別不建也不毀）； *_IO_FREQ 頻譜進頻譜出、完全不做 transform，fft/window 可為 NULL，是串接用的模式（Align-ULCNet 的 accelerator adapter 就是開一個 FREQ 實例）。

一 hop = 一次推論：pre_process 回傳這一 hop 需要的加速器呼叫次數。 Align-ULCNet 與 DeepVQE-S 從 hop 0 起恆為 1；DFN2 在第一個 hop 回 0（它的 graph 要 [t−1, t, t+1]，hop 0 沒有右鄰居，不可以呼叫），之後每 hop 1 次。

交易式 frame 狀態機：frame_inputs 把每個可寫輸出預填 NaN； frame_commit 先驗證加速器把每個輸出都寫成有限值，之後才讓任何東西移動。 驗證失敗時什麼都不動——persistent state 位元不變、幀維持開啟、回 −1，呼叫端再選 frame_skip 或用新的 frame_inputs 重跑加速器。commit 必須有 frame_inputs 墊背（prepared 閂，三個類別皆然），所以「加速器根本沒跑」 不可能把未動過的緩衝區當成結果收下；幀還開著時再呼叫 pre_process 回 −1。

生命週期兩條（audio_common/include/fft_wrapper.h「Static memory support」）： 板端 _init／_init_ex 建構在 caller pool 上，host 工具用 _create／_destroy。_init_ex 多收一個 32-byte MemReq 當陳舊 pool 閘（descriptor_version、layout_version、 io_mode、build_flags_hash（grid+io_mode+D 的 FNV-1a-32）、 alignment、reserved、bytes）：為別的 io_mode／D／build 量出來的 pool 會被拒絕，不會被重新解讀。_destroy 對 _init 實例是真正的 no-op、可重複呼叫；_create 實例只能毀一次。

為什麼各自是第三個 TU：被組合的兩個檔（ulcnet_process.c + ulcnet_model_io.c；aiaec_process.c + deepvqe_process.c； dfn2_process.c + dfn2_model_io.c）必須維持各自可獨立連結——它們的 parity 測試各自只編其中一個。把類別塞進任一邊，就會在另一邊的 parity build 留下未定義符號。 三個類別都是純組合，被組合的檔一行沒改。

Build

兩個 repo 的靜態庫都依組態編碼：物件與封存檔放在 build/simd<N>-<sig>/（sig 由 CC/AR/CFLAGS/CPPFLAGS/SIMD/WERROR 算出）， 每個目錄記下自己的 payload，簽章相撞會被拒絕而不是重新解讀， make print-lib-path 印出該組態封存檔的絕對路徑。

make -C AIAEC lib && make -C AIAEC print-lib-path   # libaiaec_prepost.a
make -C AINR  lib && make -C AINR  print-lib-path   # libainr_prepost.a
make -C AIAEC test                                  # 建庫 + pytest

libaiaec_prepost.a 成員：ulcnet_process、 ulcnet_model_io、ulcnet_prepost、 ulcnet_accelerator_adapter、aiaec_process、 deepvqe_process、deepvqe_prepost。 libainr_prepost.a 成員：dfn2_process、dfn2_model_io、 dfn2_prepost、gtcrn_process——RNNoise-ERB 不在裡面：它有自己的 Makefile、沒有封存檔，板端要用就把它的 process.c 直接加進自己的 build。

Calibration signal seam

AINR calibration 的 WAV 是 noisy speech。AIAEC E2E models 使用 mic + far。Align-ULCNet 使用已產生的 error + raw far（或 --primary-is-mic 餵 raw mic，由凍結 PBFDKF 現算 linear error 並 把衍生檔存於 artifact 旁）； manifest 會另外記錄產品部署輸入是 aligned far，避免把校正資料來源與 board wiring 混為一談。

Release checks

  1. ONNX checker 與 ONNX Runtime multi-step state parity 通過。
  2. 每個 state output 都有明確 next-input mapping，reset 不留下舊資料。
  3. BIN 檔數、dtype、shape 與 graph descriptor 一致。
  4. 非有限 input/state fail closed，不提交部分 state。
  5. C scalar/SIMD 與 KISS/NE10 測試通過。
