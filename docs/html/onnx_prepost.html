ONNX / NPU 邊界現況（AINR + AIAEC 全模型）

概要

「ONNX 邊界」= 匯出圖（NPU 跑的部分）裡有什麼、C 前後處理做什麼、 runtime 要替模型跨呼叫保存哪些顯式 states。現況（對照當前程式碼）：

  • 已有 C 前後處理：AINR 四個模型全部 （dfn2_process.c / dfn3_process.c / gtcrn_process.c / RNNoise-ERB process.c）+ AIAEC 的 Align-ULCNet（ulcnet_process.c）。
  • 尚無 C 前後處理：Align-CRUSE、DeepVQE-S、CAGCRN（純 Python）； GTCRN-AENR（STFT/ISTFT 可直接重用 AINR 的 gtcrn_process.c，同 grid 且該 C 無模型特定 state）；DFN-AENR（需 dfn2_process 的雙倍 state 擴充，見下）。
  • in-repo ONNX 匯出腳本有兩個：RNNoise-ERB 的 export_onnx.py，與 Align-ULCNet 的 AIAEC/Align_ULCNet/export_streaming_onnx.py （stateless one-frame graph;K/V/logit/GRU state 皆顯式 I/O,見下方 Align-ULCNet 列）。其餘模型的 explicit-state NPU 匯出屬後續工作（readiness 文件 §5 的 Phase 4）；六個 AIAEC 候選已有 create_stream_state()/ forward_stream() Python frame-by-frame reference + streaming.py CLI，定義 state/I-O contract。
