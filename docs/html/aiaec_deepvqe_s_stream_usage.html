DeepVQE-S PCM stream：stream/aiaec/deepvqe_s/deepvqe_stream.h

驗證範圍：本頁描述的行為已用主機端、替身加速器對照板端 sample 的逐 hop 流程驗證（逐樣本 PCM、逐 hop trace 比對；另以一個從零建的 AC_OLA_ACCUMULATE 對照組證明 AC_OLA_ENV_NORM 這個設定本身有可觀測的影響，不只是對齊問題）。未經實板、未經真實 NPU graph 驗證。

概要

這是 DeepVQE-S 模型給板端 sample 用的單一標頭入口：把 lib/aiaec/deepvqe_s/deepvqe_prepost.h 的頻域 frame_open／finish／bypass 生命週期、兩路（mic、far）analysis AcStft 與一路 synthesis AcIstft（AC_OLA_ENV_NORM）包成「int16 PCM 進、int16 PCM 出，一 hop 一次呼叫」的介面。沒有 HPF（板端 sample 本身就沒有）、沒有檔案載入入口（這個模型沒有 ERB 矩陣這種需要外部檔案的東西）。

這個模型從第 0 個 hop 就「有一幀可用」——沒有 DFN2 那種暖機拍概念。真正的啟動行為來自兩處：CCM ring（原始 mic 歷史）起始全零，前 DEEPVQE_TIME_ORDER-1 個 hop 的 tap 套用是在部分零的歷史上跑（模型自身的啟動行為，不是 stream 的人為限制）；以及 AC_OLA_ENV_NORM 本身的合成行為——重置後第一次 push 不吐出任何樣本，這一拍由 post_process 回報一個明確的 0。

API 用法

ctx = deepvqe_stream_init(&cfg, pool, pool_bytes);
while (有一個 hop 的 int16 mic_in, far_in) {
    DeepVqeHopIO io;
    if (deepvqe_stream_pre_process(ctx, mic_in, far_in, &io) != 1) break;   // -1 是契約錯誤
    device_state_sync(io.state_generation);      // generation 若變了就把加速器自己的 state 拷貝
                                                  // 重填量化零——不是可省的步驟
    int ai_rc = run_accelerator(&io.inputs, &io.outputs);                  // 0 = taps + 每個 state 都寫了
    if (ai_rc != 0) device_state_refill_zero();  // 這次跑可能已經寫了「部分」state 才失敗；
                                                  // 現在就重填零，不要等下一拍的 sync
    if (deepvqe_stream_post_process(ctx, ai_rc, pcm_out) < 0) break;
    // pcm_out 永遠是完整一個 hop
}

device_state_sync／device_state_refill_zero 不是這層 stream 自己的函式，道理跟 DFN2 stream 一樣（這層只追蹤並回報 io.state_generation，碰不到加速器記憶體）；這個模型預設沒有登錄任何 state（DeepVqeStreamConfig.state[]/state_elements[] 全留 NULL，加速器自己持有 state），但若呼叫端確實登錄了，這兩步仍不可省。

Bypass 是關閉式（fail CLOSED），不是直通：這個模型的主輸入是原始麥克風、前面沒有線性消除器，所以一旦 ai_rc != 0 或 frame_finish 自己的有限性檢查拒收，這個保證是頻域層級的——本拍模型對增強頻譜的貢獻歸零，不是把 mic_in 原樣放過去（跟 Align-ULCNet 的 fail-OPEN 正好相反）。但 AC_OLA_ENV_NORM 的合成仍會疊加前一拍的真實輸出，所以單獨一拍 bypass 的 pcm_out不是全零（實測：正常一拍之後接一拍強制失敗，256 個樣本仍有約 254 個非零，數值從上一拍殘留衰減下來）；要連續兩拍 bypass（50% overlap 的那一拍重疊歷史排空）才會真正輸出靜音。呼叫端不能假設單一 bypass 拍的 pcm_out 是靜音。CCM ring 與任何登錄的 state 在 ai_rc != 0 的 bypass 上維持原狀（兩者都不動）；frame_finish 自己的非有限值拒收則不同：只歸零「登錄的 state」（CCM ring 不動，「ring 不推進」），generation 推進，然後本層照常呼叫 frame_bypass 把這拍關掉。
