DFN2 pipeline 細節 — 入口語意、rate bridge pool 與測試內容

概要

本頁收兩條 DFN2 pipeline(mono、4ch)會把單頁撐過 30 KB 的細節:(1) 兩個 wrapper 的公開入口逐項語意與 stage／bridge 的 reject-first 清單,(2) 16 kHz／8 kHz 原生格點才存在的 DfnRateBridge pool 逐項說明(兩個 wrapper 共用同一份 bridge),(3) 各測試檔實際檢查的內容。API 範例、block diagram、泳道圖、I/O 表、State 表主表、延遲與 warm-up、檔案清單仍各自留在原頁。

mono wrapper:入口語意(mono_aec_dfn_res_*)

入口語意
_get_mem_requirementsReject-first:NULL、host.sample_rate 不是 8000/16000/48000、aec_only≠0、enable_nr≠0、enable_res≠1、非有限 atten_lim_db、48 kHz 時 fft_size 不是 0/1024,以及 host、stage 或 bridge 的任何拒絕都回 -1。build_flags_hash 摺入 host 與「stage 或 bridge」的 layout/hash,任一端 carve 改變即作廢。
_init / _init_ex在呼叫端記憶體建構;_init_ex 多一道 8 點 stale-pool gate。_destroy 只釋放 _create 配置的記憶體。
_process_begin要求 phase 0。audio_pipeline_process_spec() 取得 SeSpecFrame,再 sk_min_f32(unity 與 g_res_ctx)→ sk_capply_gain_f32 →(enable_cng 時)aec_cng_fill() 組出 P,交給 stage(48 kHz)或 bridge(8/16 kHz)。任一步失敗即整條 pipeline reset 並回 -1。
_nn_begin / _nn_endnn_begin 回 1(job 已開,*job 借用到 nn_end)、0(本 hop 沒有了)或 -1;一個 job 開著時不得再 nn_begin。nn_end(rc):rc=0 且輸出寫滿、有限才提交,否則該幀走 identity,時鐘照樣各前進一次。48 kHz 每 hop 最多 1 個 job,原生格點經 bridge 最多 2 個,所以用迴圈。
_process_end沒被取走或沒被關閉的 job 走 identity(fail-open),然後合成剛好一個 host hop(48 kHz 走 audio_pipeline_synthesize(),原生格點走 dfn_rate_bridge_finish(),bridge 自己合成)。
_process上面四個呼叫的序列,模型由 cfg.model.infer(dfn_res_stage_infer())執行。
_set_aec_preset / _set_atten_lim執行期強度:host 的 AEC preset dB 域 ramp、stage 的 DFN2 attenuation limit(非有限值回 -1)。只能在 hop 之間。
_get_host / _get_aec / _get_stage / _get_bridge唯讀診斷 handle(audio_pipeline_get_last_timing、aec_get_res_context、dfn_res_stage_get_counters、dfn_rate_bridge_get_counters/_added_delay_samples);_get_bridge() 在 48 kHz 回 NULL。不可經由它們 reset/destroy。
_hop_size / _lookahead_sampleshost hop / 總演算法延遲:48 kHz 為 512 與 1536(=3 hop);原生格點為 hop 與「hop + bridge added delay」(16 k/256 = 128 與 800)。NULL 回 -1。

Stage 的 reject-first 清單(dfn_res_stage.h、.c):非 48000、fft_size 非 0/1024、缺 ERB 矩陣、erb_inv 不是 partition of unity、非有限 atten_lim_db、有 infer 卻沒 descriptor(或被 dfn2_model_io_descriptor_validate() 拒絕)、以及不是從 pipelines/Makefile 建置(backend id 0)。unity 檢查照 df_common_expand_mask 的展開順序逐 band 累加後逐位元比對 1.0f——fail-open identity 的精確性就建立在此(dfn_res_stage.c)。Bridge 另有拒絕列:取樣率非 8000/16000、該取樣率沒有的 fft_size,以及 stage 的任何拒絕(dfn_rate_bridge.h)。

4ch wrapper:入口語意(four_aec_dfn_res_*)

入口語意
_get_mem_requirementsReject-first:sample_rate 不是 16000/48000(含 8 kHz)、48 kHz 時 fft_size 非 0/1024、enable_post≠1、enable_res≠1、enable_nr≠0、非有限 atten_lim_db,以及核心、stage 或 bridge 的任何拒絕。build_flags_hash 摺入核心與「stage 或 bridge」的 layout/hash。
_init / _init_ex / _create / _destroy同房規:_init_ex 多一道 8 點 stale-pool gate;destroy 只釋放 create 配置的記憶體。
_front_process轉呼叫前端的 four_aec_front_process(),交出借用的 FourAecFront。out->delay.changed 回報給外部 STFT/OLA 的 far-end 消費者;stage 與 bridge 都不消費 far-end,所以不因此 reset。
_process_begin要求 phase 0(否則 SEQUENCE_ERROR)。four_aec_fuse() → se_res_stage_gain() → sk_min_f32 → sk_capply_gain_f32 →(enable_cng 時)aec_cng_fill() 組出 P,再交給 stage(48 kHz)或 bridge(16 kHz)。beamformed_error 為 NULL 時由權重重建;非 NULL 時採用它(契約同 four_aec_fuse())。前端回 DSP_ERROR、stage 或 bridge 拒絕,都會 reset 整個 wrapper 並回 FOUR_AEC_NR_RES_DSP_ERROR。
_nn_begin / _nn_endnn_begin 回 1(job 已開,*job 借用到 nn_end)、0(本 hop 沒有了)或負的狀態碼;一個 job 開著時不得再 nn_begin。nn_end(rc):rc=0 且輸出寫滿、有限才提交,否則該幀走 identity,時鐘照樣各前進一次。48 kHz 每 hop 最多 1 個 job,16 kHz 經 bridge 最多 2 個,所以用迴圈。
_process_end沒被取走或沒被關閉的 job 走 identity(fail-open),然後合成剛好一個 hop(48 kHz 本應用的 ac_istft_push()、16 kHz dfn_rate_bridge_finish())。輸出含非有限值則 reset 並回 DSP_ERROR。
_process上面四個呼叫的序列,模型由 cfg.model.infer(dfn_res_stage_infer())執行。
_set_aec_preset / _set_atten_lim執行期強度:核心的 AEC preset dB 域 ramp,以及 stage 的 DFN2 attenuation limit。只能在 hop 之間。
_hop_size / _lookahead_samples核心 hop / 總演算法延遲:48 kHz 為 512 與 1536(=3 hop);16 kHz 為 hop 與「hop + bridge added delay」(fft 256 → 128 與 800)。NULL 回 -1。
_get_front_end / _get_stage / _get_bridge唯讀診斷 handle(核心的結構稽核 *_count()、duty census、dfn_res_stage_get_counters()、dfn_rate_bridge_get_counters());_get_bridge() 在 48 kHz 回 NULL。不可經由它們 reset 或 destroy。

Stage 的 reject-first 清單(pipelines/dfn_res_stage.h)在這裡一字不差地適用,其中最容易踩到的是 erb_inv 必須是 partition of unity:檢查照 df_common_expand_mask 的展開順序(band 外、bin 內)逐 band 累加後逐位元比對 1.0f,因為 fail-open identity 的精確性建立在這個性質上(pipelines/dfn_res_stage.c)。

DfnRateBridge pool 逐項(原生格點才存在)

兩個 wrapper 在 8/16 kHz 核心時都 carve 整個 DfnRateBridge pool(pipelines/dfn_rate_bridge.{h,c}),stage 的 pool 含在其中;48 kHz 沒有 bridge。dfn_rate_bridge_reset() 連同 stage 一起清乾淨並重新預填。

4ch wrapper:估計用 E、套用在 P

E = frame.e(SeSpecFrame):beamformed 線性誤差頻譜(由 weights 重建的 coherent projection,或呼叫端交出的 beamformed_error),也就是 RES gain 據以估計的那個 pre-RES 頻譜,只送進網路做估計。P = 本應用的 post 緩衝:E * min(1, G_res) + comfort noise,才是三個 head 套用的對象。理由與 mono 相同:DFN2 是以未經處理的 noisy speech 訓練的,不能讓它看見 RES 挖出的頻譜洞;像語音的 far-end 殘留由 DFN 保留、留給 RES 處理,不像語音的兩級都壓。本應用的 comfort-noise fill(front_end.enable_cng)是開關但預設關閉:關閉時 E 與 P 逐 bin 同相位,複數 deep-filter tap 不會相位錯配;開啟時 CNG 在 RES 挖掉的 bin 改變 P 的相位,estimate/apply 一致性在那裡不成立(dfn_res_stage.h 開頭)。開啟時它包在 P 裡、過同一張 mask,atten_lim_db 限制任何一個 bin 最多被壓多少。

4ch wrapper:fail-open 等值

Fail-open = 傳統核心的等值(延後)。沒有模型、infer() 回非 0、或輸出有未寫/非有限值時,該幀走 dfn2_prepost_frame_skip()(unit ERB mask 經 partition-of-unity 的 erb_inv 展開成 unit bin gain、zero taps、alpha 0),輸出即「enable_nr=0 的傳統核心延後兩個 hop」,comfort noise 一併保留。這是本 wrapper 的 backbone gate,48 kHz 由 C 測試在權重重建／trusted 兩種來源 × CNG 關/開共四輪逐 byte 釘死;16 kHz 因為多了 resampler 往返,gate 改為「延後 added delay 後的通帶容差」。
