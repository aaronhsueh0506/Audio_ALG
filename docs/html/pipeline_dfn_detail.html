DFN2 pipeline 細節 — 呼叫語意、rate bridge pool 與測試內容

概要

本頁收兩條 DFN2 pipeline(mono、4ch)會把單頁撐過 30 KB 的細節:(1) samples/dfn_hop.h 的呼叫語意(兩個範例共用)與 stage／bridge 的 reject-first 清單,(2) 16 kHz／8 kHz 原生格點才存在的 DfnRateBridge pool 逐項說明(兩個範例共用同一份 bridge),(3) 各測試檔實際檢查的內容。API 範例、block diagram、泳道圖、I/O 表、State 表主表、延遲與 warm-up、檔案清單仍各自留在原頁。兩個範例都沒有 wrapper 函式庫:各函式庫(mono 的 Aec、4ch 的 AudioPipeline4Ch 單元、stage 或 bridge)各自查大小與 init,整合者在 main.c 串接;DfnHop 是 header-only 範例碼,沒有 layout version 或 descriptor。

呼叫語意(samples/dfn_hop.h,mono 與 4ch 共用)

入口語意
形成 P(dfn_hop 之前)mono:aec_process_context() → se_frame_from_aec() → main.c 自寫(sk_min_f32(unity 與 g_res_ctx)→ sk_capply_gain_f32 →(CNG 開時)aec_cng_fill())。4ch:audio_pipeline_4ch_process() → audio_pipeline_4ch_fuse()(frame.g_res_ctx 是單元自己的 RES 增益)→ 同樣三行(dfn_form())。P 必須在 dfn_hop_begin() 之前形成。
dfn_hop_init_stage / dfn_hop_init_bridge接線,非擁有指標:48 kHz 是 stage 加呼叫端的 AcIstft 與 [513] 輸出頻譜,其餘取樣率是 DfnRateBridge(stage 在其內)。stage 路徑可把 check_finite 設 1,讓 dfn_hop_end() 拒絕非有限的 stage 輸出或 hop。
dfn_hop_begin要求 phase 0(否則 DFN_HOP_SEQUENCE_ERROR)。NULL 引數、stage／bridge 拒絕(含 E、P 非有限)回 DFN_HOP_INVALID。48 kHz:dfn_res_stage_begin(stage, E, P, &job);原生格點:dfn_rate_bridge_begin(bridge, E, P)。
dfn_hop_nn_begin / dfn_hop_nn_endnn_begin 回 1(job 已開,*job 借用到 nn_end)、0(本 hop 沒有了)或負的狀態碼;一個 job 開著時不得再 nn_begin(phase 檢查)。nn_end(rc):rc=0 且輸出寫滿、有限才提交,否則該幀走 identity,時鐘照樣各前進一次。48 kHz 每 hop 最多 1 個 job,原生格點經 bridge 最多 2 個,所以用迴圈。
dfn_hop_end沒被取走或沒被關閉的 job 走 identity(fail-open),然後合成剛好一個 hop(48 kHz 走呼叫端 AcIstft 的 ac_istft_push(),原生格點走 dfn_rate_bridge_finish(),bridge 自己合成)。
dfn_hop_process上面四個呼叫的序列,模型由 stage 設定的 model.infer(dfn_res_stage_infer())執行。
dfn_hop_reset / dfn_hop_stagereset:phase 歸零,stage 或 bridge(連同其 stage)reset,48 kHz 路徑另 reset 合成並清空輸出頻譜;model.reset 隨 stage reset 呼叫。dfn_hop_stage() 給 dfn_res_stage_set_atten_lim() 與計數器用。
整合者的失敗處理任何負的回傳,或 RES 增益(g_res_ctx)為 NULL,整合者要把前端(mono 的 aec_reset()、4ch 的 audio_pipeline_4ch_reset())、CNG RNG(回 SE_CNG_RNG_SEED)與 DfnHop(dfn_hop_reset())一起 reset。範例:mono_aec_dfn_res/main.c 的 rig_reset()、4ch_aec_bf_dfn_res/main.c 的 dfn_reset()。
執行期強度mono:aec_set_preset()(lane 的 RES 增益地板,dB 域 ramp);4ch:aec_res_set_preset(audio_pipeline_4ch_res(unit), …);兩者:dfn_res_stage_set_atten_lim(dfn_hop_stage(&hop), db)(非有限值回 -1)。只能在 hop 之間。
演算法延遲範例 main.c 自己印:48 kHz 為 hop 與 hop * (DFN_RES_STAGE_LOOKAHEAD_FRAMES + 1)(512 與 1536,=3 hop);原生格點為 hop 與「hop + dfn_rate_bridge_added_delay_samples()」(16 k/256 = 128 與 800)。

Stage 的 reject-first 清單(dfn_res_stage.h、.c):非 48000、fft_size 非 0/1024、缺 ERB 矩陣、erb_inv 不是 partition of unity、非有限 atten_lim_db、有 infer 卻沒 descriptor(或被 dfn2_model_io_descriptor_validate() 拒絕)、以及不是從 pipelines/Makefile 建置(backend id 0)。unity 檢查照 df_common_expand_mask 的展開順序逐 band 累加後逐位元比對 1.0f——fail-open identity 的精確性就建立在此(dfn_res_stage.c)。Bridge 另有拒絕列:取樣率非 8000/16000、該取樣率沒有的 fft_size,以及 stage 的任何拒絕(dfn_rate_bridge.h)。

4ch 範例:單元與核心的拒絕與序列語意

入口語意
audio_pipeline_4ch_get_mem_requirementsReject-first:sample_rate 不是 16000/48000(含 8 kHz)、fft_size 不在核心的格點清單內、res_preset 不合法,以及核心 config 的任何拒絕。範例另在 dfn_plan() 拒絕非有限 atten_lim_db、48 kHz 時 fft_size 非 0/1024,並把 stage 或 bridge 的拒絕原樣回傳。單元 layout 20、核心 layout 24。
audio_pipeline_4ch_process四條 lane、SRP-PHAT、BF。info.delay.changed 回報給外部 STFT/OLA 的 far-end 消費者;stage 與 bridge 都不消費 far-end,所以不因此 reset。
audio_pipeline_4ch_fuse要求本 hop 已有 beam(否則 SEQUENCE_ERROR,什麼都沒改)。用單元自己的權重與 beamformed 頻譜做 four_aec_fuse(),再把 frame->g_res_ctx 設為 RES 增益。其他拒絕(含 RES 拒絕 frame 的 DSP_ERROR)會 reset 整個單元(核心、SRP、BF、RES)並回傳,呼叫端自己的後級要自己 reset。
dfn_hop_*見上表。範例 dfn_process() 在任何一步失敗時呼叫 dfn_reset():audio_pipeline_4ch_reset()、CNG RNG 回種子、dfn_hop_reset()。

Stage 的 reject-first 清單(pipelines/dfn_res_stage.h)在這裡一字不差地適用,其中最容易踩到的是 erb_inv 必須是 partition of unity:檢查照 df_common_expand_mask 的展開順序(band 外、bin 內)逐 band 累加後逐位元比對 1.0f,因為 fail-open identity 的精確性建立在這個性質上(pipelines/dfn_res_stage.c)。

DfnRateBridge pool 逐項(原生格點才存在)

兩個範例在 8/16 kHz 核心時都建整個 DfnRateBridge pool(pipelines/dfn_rate_bridge.{h,c}),stage 的 pool 含在其中;48 kHz 沒有 bridge。dfn_rate_bridge_reset() 連同 stage 一起清乾淨並重新預填。

3 顆 audio_resampler;原生 AcIstft ×2、48 kHz AcStft ×2 與 AcIstft ×1;兩個 FFT handle、兩張窗表;48 kHz FIFO ×2各自 pool;2×AcIstft(fft_n)+ 3×1024 點物件;FIFO48_CAP = 1,536 float ×2bridge poolE、P 各一顆升頻(→ 48 kHz)、共用一顆降頻(每顆自帶相位與 FIR 歷史)。synth_e/synth_p 各走一份 host 同款 sqrt-Hann WOLA 還原成時域;fifo_e/fifo_p(FIFO48_CAP:只放未湊滿 512 的餘量加一個 hop 的升頻量,每消耗一幀就左移 512;分析歷史由 stft_e/stft_p 持有)。五個 STFT/ISTFT 物件借用 bridge 的兩支 FFT handle 與兩張窗表（win_n、win48）,bridge 以「自帶 FFT 與窗的物件大小減去那兩段」估算借用物件大小

4ch 範例在 16 kHz／fft 256 的 bridge pool 小計同為 349,888 B(ne10)(已含 stage 的 pool)。bridge 另有一個 phase 欄位供 begin/nn_begin/nn_end/finish 序列閘使用(struct 大小不變)。

4ch 範例:估計用 E、套用在 P

E = frame.e(SeSpecFrame):單元的 beamformed 線性誤差頻譜(BF 權重的 coherent projection),也就是 RES gain 據以估計的那個 pre-RES 頻譜,只送進網路做估計。P = dfn_form() 的輸出:E * min(1, G_res) + comfort noise,才是三個 head 套用的對象。理由與 mono 相同:DFN2 是以未經處理的 noisy speech 訓練的,不能讓它看見 RES 挖出的頻譜洞;像語音的 far-end 殘留由 DFN 保留、留給 RES 處理,不像語音的兩級都壓。comfort-noise fill(--cng)是開關但預設關閉:關閉時 E 與 P 逐 bin 同相位,複數 deep-filter tap 不會相位錯配;開啟時 CNG 在 RES 挖掉的 bin 改變 P 的相位,estimate/apply 一致性在那裡不成立(dfn_res_stage.h 開頭)。開啟時它包在 P 裡、過同一張 mask,atten_lim_db 限制任何一個 bin 最多被壓多少。

4ch 範例:fail-open 等值

Fail-open = 傳統鏈的等值(延後)。沒有模型、infer() 回非 0、或輸出有未寫/非有限值時,該幀走 dfn2_prepost_frame_skip()(unit ERB mask 經 partition-of-unity 的 erb_inv 展開成 unit bin gain、zero taps、alpha 0),輸出即「手寫傳統鏈(conv_chain_4ch.h,降噪器關;餵單元的 beam 權重與 beamformed 頻譜)延後兩個 hop」,comfort noise 一併保留。這是本範例的 backbone gate,48 kHz 由 C 測試在 CNG 關/開兩輪逐 byte 釘死;16 kHz 因為多了 resampler 往返,gate 改為「延後 added delay 後的通帶容差」。

測試檔檢查內容
pipelines/mono_aec_dfn_res/tests/test_mono_dfn.c48 kHz backbone gate:對手寫傳統鏈(conv_chain_mono.h,降噪器關)延後兩個 hop 逐 byte 相同(CNG 與 phased 序列各列),CNG 關與開各一輪,且跨一次真實的 delay 改變;另檢查 min G_res < 0.9(否則 P≡E、estimate/apply 對調無法被看見)、計數器 frames=64 / commits=0 / skips=63、拒絕列。現查兩輪皆 identity over 64 hops, 1 delay change(s), min G_res 0.040。另有 phased 列(process_begin／nn_begin／nn_end／process_end 序列對 process() 逐位元相同,含失敗模型、未取走的 job、序列錯誤)。另有三個原生格點閘(16 k/256、16 k/512、8 k/256):排程、累計幀數、脈衝釘住的 added delay(672/629/330)、對 NR-off 輸出的通帶容差
