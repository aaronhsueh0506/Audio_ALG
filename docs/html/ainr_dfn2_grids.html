AINR DeepFilterNet2：grid 由應用端於執行期給定

概要

DFN2 函式庫不持有任何 grid：取樣率、FFT 大小、ERB 帶數、deep filter 的 bin 數與階數、lookahead pair、每次呼叫的 frame 數、兩組正規化器設定都不是函式庫的常數，沒有 preset、沒有預設值。應用端把模型固定的值填成 DFN2GridSpec，用 dfn2_grid_make() 得到 DFN2Grid，傳給它建立的每一個物件（DFN2State、DFN2ModelIOState、model-I/O descriptor、DFN2Prepost）；同一個 binary 跑任何 grid，記憶體由 get_mem_size 依 grid 在執行期算出。grid、訓練好的模型、它的 ERB 矩陣三者必須屬於同一組；出貨 checkpoint 的 grid 是 48 kHz、FFT 1024、32 個 ERB band、df_bins 96、lookahead 1／1。

(sample rate, FFT size) 對應 n_erb、df_bins 與 lookahead pair 的表是模型的性質，由應用端持有（板端 sample 有自己的表，見下）；函式庫只驗證應用端傳入的值。框化（AcStft／AcIstft）也是應用端的，尺度由 grid 給（stft_scale／stft_unscale）。模型本身（cascade、I/O、State）見 ainr_dfn2，呼叫順序見 ainr_dfn2_usage。

本頁的大小為本機（64 位元主機、-ffp-contract=off）量測；非出貨 grid 的音質與板端行為待量測。DFN2 的 grid 與 pool 版號的詳細規則另見 AINR/DeepFilterNet2/README.md 的 "Choosing the grid"。

API 用法

  1. 應用端依模型的 config.ini（[signal] sr／n_fft、[model] n_erb／df_bins／df_order／mask_lookahead／df_lookahead、[feature] 的正規化器）填 DFN2GridSpec，呼叫 dfn2_grid_make()；回傳 DFN2_GRID_OK（grid 已寫入）或第一個失敗的檢查（grid 不動）。dfn2_grid_status_text() 給 log 用的短字串。
  2. 把 &grid 交給 dfn2_state_mem_size()／dfn2_state_init()、dfn2_model_io_mem_size()／dfn2_model_io_init()、dfn2_model_io_descriptor_default()／_validate()、dfn2_prepost_config_defaults()；DFN2PrepostConfig 按值持有一份，dfn2_prepost_grid(p) 回傳實例的那份。
  3. 每個收 grid 的入口先跑 dfn2_grid_validate()，無效的 grid 回 -1（size 函式回 0）；手改過的衍生欄位（hop、ring、scale、alpha）也會被擋（DFN2_GRID_ERR_INCONSISTENT）。
DFN2GridSpec spec = {                 /* config.ini 的值(出貨 48 kHz 模型) */
    .sample_rate = 48000, .n_fft = 1024, .n_erb = 32, .df_bins = 96, .df_order = 5,
    .mask_lookahead = 1, .df_lookahead = 1, .frames_per_call = 1,
    .erb_norm_tau_sec = 1.0f, .erb_norm_init_lo_db = -60.0f, .erb_norm_init_hi_db = -90.0f,
    .erb_norm_scale_db = 40.0f, .spec_norm_tau_sec = 1.0f,
    .spec_norm_init_lo = 0.001f, .spec_norm_init_hi = 0.0001f };
DFN2Grid grid;
int status = dfn2_grid_make(&grid, &spec);
if (status != DFN2_GRID_OK) { fprintf(stderr, "%s\n", dfn2_grid_status_text(status)); return -1; }

DFN2PrepostConfig cfg;
dfn2_prepost_config_defaults(&cfg, &grid);       /* 按值複製 grid */
cfg.erb_fwd = erb_fwd;  cfg.erb_inv = erb_inv;   /* 應用端載入的 ERB 矩陣 */
DFN2PrepostMemReq req;
dfn2_prepost_get_mem_size(&cfg, &req);           /* 48 kHz 1/1：92,608 bytes */

給定量與推導量

DFN2GridSpec 的 15 個欄位是訓練好的模型所固定的（dfn2_grid.h）；其餘由公式推導：

給定欄位出貨值來源（config.ini）
sample_rate、n_fft48000、1024[signal]
n_erb、df_bins、df_order32、96、5[model]
mask_lookahead、df_lookahead1、1[model]；pair 規則見 ainr_dfn2_detail
frames_per_call1匯出的 graph（--frames-per-call）
erb_norm_tau_sec、erb_norm_init_lo_db、erb_norm_init_hi_db、erb_norm_scale_db1.0 s、−60 dB、−90 dB、40 dB[feature]
spec_norm_tau_sec、spec_norm_init_lo、spec_norm_init_hi1.0 s、0.001、0.0001[feature]
推導欄位公式
hop、n_binsn_fft／2、n_fft／2 + 1（組幀固定為 50 % overlap、sqrt-Hann、不補零，audiolib audio_stft.h）
input_framesframes_per_call + DFN2_MODEL_INPUT_FRAMES（3）− 1 = N + 2
stft_scale、stft_unscalefloat32 的 1／√n_fft 與 √n_fft（torch.stft(normalized=True) 的尺度與其反向；float32 的除法與開根號是正確捨入，各編譯器結果相同）。train.py 的 analysis_scale() = 2·hop／win²·√n_fft，win = n_fft、hop = n_fft／2 時恰為同一值，它作用在餵給正規化器的拷貝；應用端的 AcStft／AcIstft 以這兩個值做 spec_scale／ispec_scale
erb_norm_alpha、spec_norm_alphadfn2_norm_alpha(sample_rate, hop, tau_sec) = train.py 的 make_norm_alpha：exp(−(hop／sr)／tau) 取到小數第三位（若進位到 1.0 就多一位）。tau = 1.0 s 時，hop 512 @ 48 kHz 得 0.989（0x3f7d2f1b）；hop 128 @ 16 kHz 與 hop 256 @ 32 kHz 的 hop／sr 都是 8 ms，得 0.992（0x3f7df3b6）。alpha 是推導值、不能給；tau 不同的模型改 spec 的 tau 欄位，alpha 須在 (0, 1)
df_history、ringdf_order − df_lookahead − 1 個過去 tap；ring 深度 max(df_order, mask + df + 1)，mask-only 為 mask + 1

合法性規則與狀態碼

dfn2_grid_make() 依下表順序檢查，回第一個失敗的狀態碼；-8 未指派、不重用。

狀態碼規則
DFN2_GRID_ERR_NULL（-1）指標為 NULL
DFN2_GRID_ERR_SAMPLE_RATE（-2）sample_rate > 0
DFN2_GRID_ERR_N_FFT（-3）audiolib 組幀建得出的大小（ac_stft_get_mem_size() 不為 0：2 的次方、[16, 8192]），且 n_bins ≤ 65535（ERB 範圍表是 16 位元）
DFN2_GRID_ERR_N_ERB（-4）正且為 4 的倍數（ERB kernel 四個 band 一組、encoder 的 band 軸兩次 stride-2 只需要 %4；train.py 的 validate_signal_config 也只要求 %4），且每個 band 至少兩個 bin：2 × n_erb ≤ n_bins（檢查不會溢位：n_erb = 1<<30、0x7ffffffc 乾淨地回這個狀態碼，UBSan 下也是）
DFN2_GRID_ERR_DF_BINS（-5）[2, n_bins)；-DDFN2_MASK_ONLY 可到 n_bins（高於 deep filter 的 bin 保留 masked 頻譜，所以完整版至少留一個；df_bins = 1 會讓正規化器起點的 linspace 除以零）
DFN2_GRID_ERR_DF_ORDER（-10）[1, DFN2_GRID_DF_ORDER_MAX = 16]；mask-only 接受 [0, 16]，存成 0
DFN2_GRID_ERR_MASK_LOOKAHEAD（-6）[0, DFN2_GRID_MASK_LOOKAHEAD_MAX = 2]
DFN2_GRID_ERR_DF_LOOKAHEAD（-7）[0, df_order − 1]；mask-only 必須為 0（沒有 deep filter 可以 look ahead）
DFN2_GRID_ERR_FRAMES_PER_CALL（-11）[1, DFN2_MODEL_MAX_FRAMES_PER_CALL = 64]
DFN2_GRID_ERR_ERB_NORM（-12）／_SPEC_NORM（-13）tau 有限且 > 0，起點有限（spec 的起點與 ERB 的 scale 須 > 0），且它給出的 alpha（float32）嚴格在 0 與 1 之間：取樣率或 tau 讓 alpha 取整後到 0 或 1 的被拒絕，所以 dfn2_grid_make() 接受的 grid，dfn2_grid_validate() 一定接受
DFN2_GRID_ERR_INCONSISTENT（-9）（dfn2_grid_validate()）衍生欄位與 dfn2_grid_make() 推導的不同

本機以 dfn2_grid_status_text() 驗證：n_erb 30 回 DFN2_GRID_ERR_N_ERB；n_erb 36、df_bins 100、n_fft 2048、2／4 這組 pair（ring 7）、frames_per_call 64 都接受；df_order 17 回 _DF_ORDER、frames_per_call 65 回 _FRAMES_PER_CALL、erb_norm_tau_sec 1e-6 回 _ERB_NORM。

連結符號與 pool 身分

  • 連結符號只有 variant：dfn2_process.c 定義 dfn2_variant_full 或 dfn2_variant_mask_only，dfn2_model_io.c、dfn2_prepost.c 與任何執行 DFN2_REQUIRE_VARIANT_LINK() 的應用單元引用它。一部分單元帶 -DDFN2_MASK_ONLY 的物件連結失敗；grid、pair 與 frames_per_call 都不在符號裡——一個 build 服務所有 grid，grid 或 pair 不符由執行期的 descriptor、pool hash 與 grid 檢查拒絕。
  • 在 .c → .o 規則下，不同旗標（mask-only）編出的物件同名：每組旗標用自己的物件資料夾，或在切換之間清除；殘留的舊物件會以 dfn2_variant_* 未定義而連結失敗。make -C AINR lib 本來就一組旗標一個資料夾。dfn 與 dfn-lite 兩個板端 sample 也是如此。
  • pool 身分：DFN2_PREPOST_CARVE_VERSION = 11；build_flags_hash（FNV-1a-32）對每一個 grid 都折入整個 grid：sr、n_fft、hop、n_bins、n_erb、df_bins、df_order、兩個 lookahead、df_history、ring、frames_per_call、input_frames、兩個時間常數與 alpha、兩個 scale、四個正規化起點與 erb_norm_scale_db，加上 variant、layout 與 carve 版號、graph 的輸入 frame 數、feature 版本。別的 build 或別的 grid 查到的 pool 大小與 DFN2PrepostMemReq 會被 dfn2_prepost_init_ex() 拒絕，請重新查詢。state 登錄不在 hash 裡，它不改變 pool 的任何位元組。

uvc_audio_live2a.c同樣只有 48 kHz、沒有旗標、同一列 dfn2_grid_make()；grid 放進 DfnResStage／DfnRateBridge 的 config、model-I/O descriptor 與 tensor 表（host 在模型的取樣率，或經 bridge）
pipeline 範例 main（mono_aec_dfn_res、4ch_aec_bf_dfn_res）--ai-sample-rate、--ai-fft-size（--sample-rate 是 host 的）；grid 放進 DfnResStageConfig.grid，輸出「model grid …」一行。規則同 alg_ai3_aec_dfn.c，bridge 不能服務時 pool 查詢被拒、結束碼 1

板端 sample 不登錄遞迴 state（加速器持有）：h_gru [1,5,1,256]（mask-only [1,3,1,256]）與 df_convp_history [1,64,5,df_bins] 的形狀是 sample 自己的常數；每次加速器執行前比對 dfn2_prepost_state_generation()（由 stage 或 bridge 託管時用 dfn_res_stage_state_generation()／dfn_rate_bridge_state_generation()）與上次看到的值，不同就把 state 輸入 buffer 重填量化零；載入的模型回報的元素數與 sample 的表不符時 sample 拒絕啟動。

所有 DFN2 板端 sample 的 ERB 矩陣都讀 /mnt/sd/dfn2_blobs/fb_<sr>_<n_erb>.bin（例如 fb_48000_32.bin；<sr> 是模型 grid 的取樣率，不是 host 的），一套部署檔共用。這個檔是匯出器的 erb_matrix.bin（export_erb_matrix.py --output-dir DIR，--format bin 或預設的 all）依 grid 以上述檔名存放，內容為：int32 n_bins、int32 n_bands、float32 正向矩陣 [n_bins][n_bands]、float32 反向矩陣 [n_bins][n_bands]，little-endian，兩個矩陣都是 bin-major，大小為 8 + 2 × n_bins × n_erb × 4 bytes（48 kHz 為 131,336）。板端 sample 先核對標頭的 n_bins、n_bands 等於 grid 的，讀入兩個矩陣，init 時自己把反向矩陣轉置成函式庫要的 band-major，再把兩個指標交給函式庫。它不是 --runtime-bins DIR 寫的 erb_fwd.bin（bin-major）與 erb_inv.bin（band-major）那一對（兩個 raw 檔，各 n_bins × n_erb 個 float32，另有 erb_matrices.json）；pipeline 範例 main 讀的是這一對：--erb-fwd FILE 與 --erb-inv FILE（兩個一起給或都不給；都不給時用 unit ERB partition，只供 fail-open 的冒煙跑，並印出提示）。板端實跑待量測。

  • 測試在建置時用自己的標頭選 grid，不經函式庫；pipeline 與範例 main 不用：AINR/tests/dfn2_test_grid.h 與 pipelines/dfn/tests/dfn_test_grid.h（-DDFN2_GRID_KHZ=16|32|48，或 -DDFN2_SR／-DDFN2_N_FFT／-DDFN2_N_ERB／-DDFN2_DF_BINS，加上 -DDFN2_MASK_LOOKAHEAD／-DDFN2_DF_LOOKAHEAD；dfn2_test_grid()／dfn_test_grid() 回傳 const DFN2Grid *）。它們提供測試自己的固定陣列用的大小巨集並掃 grid 與 pair；preset 預設的 pair 是 1／1，不是上表 16、32 kHz 的 0／0，所以它們證明程式在那個 grid 上跑得對，不是在驗上表的某一列。
  • pipeline 的 dfn_res_stage、dfn_rate_bridge、dfn_hop 沒有建置期的 grid：DfnResStageConfig.grid 由應用端給（dfn_res_stage_default_config(&grid)），stage 的尺度取 grid.stft_scale／stft_unscale（出貨 grid 為 2-5／25），延遲取 dfn_res_stage_lookahead_frames(&grid)。dfn_rate_bridge_default_config(sample_rate, &model_grid) 的 resolve() 在 stage 的 grid 不是 48000／1024 時回 -1：bridge 的重取樣倍率、每 hop 推論排程、prefill 校準與延遲算式都是為 48 kHz 模型寫的。兩支 DFN2 pipeline 與 dfn2_stage.py 只以出貨 grid 驗證；stage、bridge、hop 的 C 測試另在 16、32 kHz 的測試 grid 上跑（make test-dfn-grids）。

切 grid 的流程

  1. 訓練端：config.ini [signal] 的 sr／n_fft／win_len／hop_len 與 [model] 的 n_erb／df_bins／兩個 lookahead 改成該 grid（hop_len = n_fft／2；n_erb 為 4 的倍數）；alpha 與 analysis scale 由 train.py 推導，不是設定值。
  2. 匯出：export_onnx.py 與 export_erb_matrix.py；pipeline 範例以 --erb-fwd／--erb-inv 讀 --runtime-bins DIR 的 erb_fwd.bin／erb_inv.bin（各 n_bins × n_erb 個 float32；48 kHz 是 513 × 32 × 4 = 65,664 bytes，16 kHz 是 129 × 24 × 4 = 12,384 bytes）；板端 sample 讀以 fb_<sr>_<n_erb>.bin 存放的 erb_matrix.bin（上一節）。
  3. 應用端：用同一組值填 DFN2GridSpec、呼叫 dfn2_grid_make()，載入該 grid 的 model 與 ERB 矩陣。DFN2ModelIoDescriptor 的外部欄位（sample_rate、fft_size、hop_size、spectrum_bins、erb_bands、df_bins、df_order、兩個 lookahead、input_frames）取自傳入的 grid，執行期擋掉對著另一組幾何匯出的圖。
