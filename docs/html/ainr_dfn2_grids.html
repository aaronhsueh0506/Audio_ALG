AINR DeepFilterNet2：grid 於建置時選擇

概要

DFN2 的訊號 grid（取樣率、FFT 大小、ERB 帶數、deep filter 的 bin 數、兩個 EMA 係數）是建置期契約：C 函式庫、訓練好的模型、它的 ERB 矩陣三者必須屬於同一個 grid。出貨 grid 是 48 kHz、FFT／win／hop = 1024／1024／512、32 個 ERB band、df_bins 96，不帶任何旗標就是它；其他 grid 在建置時選擇。常數集中在 AINR/DeepFilterNet2/dfn2_grid.h（由 dfn2_process.h 引入），不再散落各檔。

出貨 grid 的行為不變：預設建置的六個物件（完整版與 -DDFN2_MASK_ONLY 各三個）的機器碼、常數段與符號和加入此標頭之前逐位元相同，DFN2_IO_FREQ pool 仍是 219,536 bytes、hash d2d3bc45，layout 與 carve 版號都不變。模型本身（cascade、I/O、State）見 ainr_dfn2，呼叫順序見 ainr_dfn2_usage。

本頁的大小為本機（64 位元主機、-ffp-contract=off）以對應旗標編譯後量測；非出貨 grid 的音質與板端行為待量測。lookahead pair、DFN2_MASK_ONLY、DFN2_FRAMES_PER_CALL 是獨立的建置選擇，與 grid 無關。

DF 截止 = df_bins × sr／n_fft（df_bins 在三組都是 96，所以截止頻率隨 bin 間距變）。DFN2_GRID_KHZ 不是 16、32、48 即 #error。preset 是完整的一組：只定義其中一個值（例如 -DDFN2_GRID_KHZ=16 -DDFN2_N_ERB=20）會 #error，要改請改用下一節的外部定義。

B. 外部定義的 grid

為另一個 grid 訓練的模型，在建置參數定義下列巨集（或用 -DDFN2_GRID_HEADER='"my_grid.h"' 指定一個定義它們的標頭，標頭先於檢查被引入）。外部定義時不給任何預設（DF_ORDER 固定為 5，不在此列），避免悄悄套用別的 grid 的值：缺任何一個必填巨集，#error 會點名它。

巨集意義與規則訓練端對應
DFN2_SR取樣率 Hz，須為正；它存在就代表走外部定義，不可再帶 DFN2_GRID_KHZconfig.ini [signal] sr必填
DFN2_N_FFT2 的次方，16..8192[signal] n_fft必填
DFN2_N_ERBERB band 數，正且為 4 的倍數[model] n_erb必填
DFN2_DF_BINSdeep filter 負責的 bin 數，[2, n_bins]；完整版須 < n_bins[model] df_bins必填
DFN2_ERB_NORM_ALPHAERB 特徵 EMA 係數（float 字面值，如 0.992f）make_norm_alpha(sr, hop, tau)必填
DFN2_SPEC_NORM_ALPHA複數特徵 EMA 係數同上必填
DFN2_DF_ORDERdeep filter 的 tap 數，固定 5（graph 的 pathway window 與狀態版面都為 5 建立）；外部定義它會 #error[model] df_order固定，不可定義
# 例：24 kHz、n_fft 512、24 個 ERB band（測試用的外部 grid，不是出貨 grid）
GRID='-DDFN2_SR=24000 -DDFN2_N_FFT=512 -DDFN2_N_ERB=24 -DDFN2_DF_BINS=96 -DDFN2_ERB_NORM_ALPHA=0.989f -DDFN2_SPEC_NORM_ALPHA=0.989f'
make -C AINR lib CFLAGS="-O2 -std=c11 $GRID"
# preset 同理：CFLAGS 帶 -DDFN2_GRID_KHZ=16。CFLAGS 進組態簽章，不同 grid 的 archive 各落在自己的 build 資料夾

#error 守門（編譯期）

條件原因
缺 DFN2_N_FFT／_N_ERB／_DF_BINS／_ERB_NORM_ALPHA／_SPEC_NORM_ALPHA（已定義 DFN2_SR）外部 grid 無預設，訊息點名缺的巨集
DFN2_GRID_KHZ 與 DFN2_SR 同時定義；preset 之外又定義 DFN2_N_FFT／_N_ERB／_DF_BINS／alphapreset 與外部定義不可混用
n_fft 不是 2 的次方或不在 [16, 8192]audiolib audio_stft.h 的組幀範圍
n_erb ≤ 0 或不是 4 的倍數C 的 ERB kernel 四個 band 一組，encoder 的 band 軸兩次 stride-2 只需要 %4；train.py 的 validate_signal_config 也只要求 %4（不再沿用上游 DeepFilterNet 的 %8）
2 × n_erb > n_bins每個 ERB band 至少兩個 bin
df_bins < 2 或 > n_bins；完整版 df_bins ≥ n_binsdf_bins = 1 會讓正規化器起點的 linspace 除以零；高於 deep filter 的 bin 保留 masked 頻譜，所以完整版至少留一個 bin（-DDFN2_MASK_ONLY 不受後一條限制）
DFN2_SR ≤ 0取樣率須為正
外部定義 DFN2_DF_ORDERgraph 的 pathway window 與狀態版面都為 5 個 tap 建立，所以不是 grid 的選項

推導量與常數來源

  • 由 n_fft 推導，不是設定值：DFN2_N_BINS = n_fft／2 + 1、DFN2_WIN_LEN = n_fft、DFN2_HOP_LEN = n_fft／2、DFN2_OVL_LEN = WIN − HOP（組幀固定為 50 % overlap、sqrt-Hann、不補零）。
  • DFN2_NORMALIZED_STFT_SCALE／_UNSCALE = float32 的 1／√n_fft 與 √n_fft（torch.stft(normalized=True) 的尺度與其反向）。由 n_fft 計算（float32 的除法與開根號是正確捨入，各編譯器結果相同），新 grid 不必補表：1024 為 0.03125／32，512 為 0.044194173／22.627417，256 為 0.0625／16。頻譜進出 DFN2_IO_FREQ 的換算用它（出貨 grid 是 1／32 與 32）。
  • DFN2_ANALYSIS_SCALE：train.py 的 analysis_scale() = 2·hop／win²·√n_fft；win = n_fft、hop = n_fft／2 時恰為 1／√n_fft，所以它直接定義為上一項的 SCALE，不能另外覆寫。兩者數值相同、意義不同：它只作用在餵給正規化器的那份拷貝，不是頻譜進出的換算。
  • 兩個 alpha = make_norm_alpha(sr, hop, tau)：exp(−(hop／sr)／tau) 取到小數第三位（若進位到 1.0 就多一位），tau = 1.0 s（[feature] erb_norm_tau_sec／spec_norm_tau_sec）。hop 512 @ 48 kHz 得 0.989；hop 128 @ 16 kHz 與 hop 256 @ 32 kHz 的 hop／sr 都是 8 ms，得 0.992。它們寫成字面常數、不由編譯器計算；與 train.py 的對拍在 AINR/tests/test_dfn2_grid.py。改 tau 就要重算並同步改這裡與 checkpoint。
  • 正規化器的起點（DFN2_ERB_NORM_INIT_LO_DB／_HI_DB／DFN2_ERB_NORM_SCALE_DB、DFN2_SPEC_NORM_INIT_LO／_HI）是 libDF 的常數、與 grid 無關，仍在 dfn2_process.h，但可由建置參數覆寫（#ifndef）；用了其他起點的模型要在建置參數定義，該建置即使在 48k preset 上也不再是出貨 grid。

連結符號與 pool 身分

  • 連結符號：dfn2_process.c 定義一個 variant 符號，dfn2_model_io.c、dfn2_prepost.c 與任何執行 DFN2_REQUIRE_LOOKAHEAD_PAIR_LINK() 的應用單元引用它。出貨 grid（內建的 48k preset）維持原名 dfn2_variant_full／dfn2_variant_mask_only；其他 grid 附加 _s<sr>_f<n_fft>_e<n_erb>_d<df_bins>，例如 dfn2_variant_full_s16000_f256_e24_d96，所以不同 grid 的物件無法連結（雙向都驗過）。四個值須是單純十進位整數。
  • 應用端與庫不同 grid 也連不起來：只在應用自己的檔案裡寫 -D 不會影響已編好的庫物件；應用在 main() 呼叫 DFN2_REQUIRE_LOOKAHEAD_PAIR_LINK()，不一致就變成連結錯誤。切 grid 時庫與應用的每個編譯單元要用同一組旗標。只引用常數、沒執行該巨集的單元不會被擋。在 .c → .o 規則下，不同旗標（另一個 grid、lookahead pair 或 variant）編出的物件同名：每組旗標用自己的物件資料夾，或在切換之間清除；殘留的舊物件會以 dfn2_variant_* 或 dfn2_lookahead_* 未定義而連結失敗。make -C AINR lib 本來就一組旗標一個資料夾。
  • pool 身分：build_flags_hash 本來就蓋 sr、n_fft、hop、n_erb、df_bins、df_order、pair 與 layout／carve 版號；非出貨 grid 另外折入 7 個 float 的 bit（兩個 alpha、五個正規化起點），所以同樣的整數但 tau 或起點不同的兩個模型，pool 也不互換。出貨 grid 不折入這 7 個值，hash 與以前相同。
  • 「出貨 grid」指內建的 48k preset 本身，且建置參數沒有覆寫任何正規化起點。覆寫了起點的建置，以及在建置參數定義的 grid（即使整數與出貨相同），都不是出貨 grid：alpha 與起點由定義者決定，所以有自己的符號名與 pool hash（test_dfn2_grid.py 驗證）。

切 grid 的流程與板端 sample

  1. 訓練端：config.ini [signal] 的 sr／n_fft／win_len／hop_len 與 [model] 的 n_erb／df_bins 改成該 grid（hop_len = n_fft／2；n_erb 為 4 的倍數）；alpha 與 analysis scale 由 train.py 推導，不是設定值。
  2. 匯出：export_onnx.py 與 export_erb_matrix.py --runtime-bins DIR；erb_fwd.bin／erb_inv.bin 各 n_bins × n_erb 個 float32（48 kHz 是 513 × 32 = 65,664 bytes，16 kHz 是 129 × 24 = 12,384 bytes）。
  3. 建置：函式庫與應用用同一組 grid 旗標編譯；板端 sample 部署的 model.bin 與 erb_matrix.bin 也要換成該 grid 的。DFN2ModelIoDescriptor（sample_rate、fft_size、hop_size、spectrum_bins、erb_bands、df_bins、df_order）在執行期仍會擋掉對著另一組幾何匯出的圖。

板端 sample alg_ai3_dfn.c（audio_sample/，不在本 repo）不再重述 48 kHz 的常數：HOP_SIZE、FFT_SIZE、N_ERB、SAMPLE_RATE 等都是 DFN2_* 的別名，所以輸入 PCM 的取樣率就是該 build 的 DFN2_SR；main() 呼叫 DFN2_REQUIRE_LOOKAHEAD_PAIR_LINK() 並印出 grid（sr、fft、hop、bins、ERB 數、deep filter bins × taps、lookahead），--help 註明 grid 在建置時決定。切 16 kHz：庫物件與該 sample 都加 -DDFN2_GRID_KHZ=16，並換成 16 kHz 的 model 與 ERB 檔；板端實跑待量測。

pipelines 與其他限制

  • pipelines/dfn/dfn_res_stage.h 的 DFN_RES_STAGE_IN_SCALE／_OUT_SCALE 現在是 DFN2_NORMALIZED_STFT_SCALE／_UNSCALE（出貨 grid 仍是 2-5／25，數值不變）；stage 的 sample_rate 只收 DFN2_SR、fft_size 只收 0 或 DFN2_N_FFT。
  • pipelines/dfn/dfn_rate_bridge.c 的 resolve() 在 DFN2_SR != 48000 或 DFN2_N_FFT != 1024 時回 -1：bridge 的重取樣倍率、每 hop 推論排程、prefill 校準與延遲算式都是為 48 kHz 模型寫的，非 48 kHz 模型明確拒絕，不會悄悄用錯。bridge 的 host 端只有 8k／fft256、16k／fft256、16k／fft512。
  • 兩支 DFN2 pipeline 與 dfn2_stage.py 只以出貨 grid 驗證，非出貨 grid 的 pipeline 組合未驗證。
  • 32 kHz preset 是暫定值：尚無 32 kHz 模型；28 個 band 在 C 端與 train.py 都合法。
  • mask-only（stage 1）用同一支板端 sample alg_ai3_dfn.c（audio_sample/，不在本 repo）：sample 與函式庫的每個編譯單元都加 -DDFN2_MASK_ONLY，就綁 I/O layout 9（輸入 erb, spec, h_gru、輸出 erb_mask, h_gru_out），模型放 dfn2_lite/，輸出到 DFN2_LITE/，同樣吃 build 的 grid；不需要額外的 .c／.h。與完整版的物件互相連不起來（dfn2_variant_mask_only）；兩種 build 要各用自己的物件資料夾（見「連結符號與 pool 身分」一節）。
