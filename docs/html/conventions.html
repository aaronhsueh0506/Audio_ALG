全鏈 grid / window / framing 慣例

概要

整條鏈的共同格點規則：frame == FFT、hop = fft/2（50% overlap）、無 transform zero-padding、bins = fft/2+1。各層各有自己的預設與白名單， 本頁把它們放在同一張表；另外收錄三件跨模組最容易踩的 framing 事實： 重建路徑一律 periodic sqrt-Hann、PBFDKF 線性路徑的矩形窗例外、 centered 與串流（center=False）framing 在穩態逐 bit 等價。

視窗慣例：重建路徑一律 periodic sqrt-Hann

所有「會被合成回時域」的路徑（分析與合成兩側）用同一個公式，denominator = block 長度 N（periodic，非 symmetric）：

w[k] = sqrtf(0.5 * (1 - cos(2*pi*k / N)))     k = 0..N-1
使用點程式碼
AEC RES 分析窗（error_spec_windowed 用） pbfdkf.c pbfdaf_fill_windows()（denom = block_size）
AEC3 post 合成窗（16k/512 grid 表格化 = sin(πk/512)） aec3_balanced_config.h AEC3B_SYNTH_WINDOW[512]（per-rate 表）
mono pipeline 合成窗pipelines/mono_aec_nr_res/audio_pipeline.c:395（synth_win）
4ch pipeline 合成窗pipelines/4ch_aec_bf_nr_res/4aec_nr_res.c:728、 pipelines/4ch_alignulcnet/audio_pipeline_4ch_ulcnet.c:579-582
ULCNet C 分析+合成（共用一張表） ulcnet_process.c ulcnet_make_window()（與 Python 逐 bit 同 @f32）
DFN2/DFN3/GTCRN 分析+合成 AINR/dfn_process_common.h df_common_make_root_hann()

sqrt-Hann 分析 × sqrt-Hann 合成 = Hann，在 50% overlap 下滿足 COLA， 合成端不需 window-envelope 除法（dfn3_synthesis() 註解明文）。 例外是 torch.istft 語意的 ULCNet WOLA：它照 torch 做窗平方包絡正規化 （UlcnetSynthesis.env），結果相同、簿記不同。

PBFDKF far_spec 矩形窗例外

線性濾波路徑沒有分析窗。PBFDAF/PBFDKF 是 overlap-save 結構： far/near 的 block（= 2×hop 原始樣本）直接進 RFFT—— pbfdkf.c:458 rfft_padded(p, p->far_buffer, blk, p->far_spec)、 :450 同樣的 near_spec——等效矩形窗。輸出取 echo_time[hop:block] 有效半段、error_spec 由 zero-pad 的有效 hop 重建 （:542-545），全程無窗。sqrt-Hann 只出現在供 RES/後級分析用的 error_spec_windowed（:552-553：sqrt-Hann×near − echo_spec）。 另有 td_window（IR 時域約束窗：causal taps 全 1 + hop/4 非因果 fade），作用在濾波器係數不是訊號。

ULCNet centered framing vs AEC/DFN 串流（center=False）framing

兩種 framing 並存是刻意的：AINR DFN2/DFN3 的 C 是 center=False 串流 （dfn2_process.h parity 限制 (1)），Align-ULCNet 的 C 重現 torch center=True timing（ulcnet_process.h 檔頭 + docs/align_ulcnet_embedded_streaming_design_zh_TW.md 第 7 節決策）。

穩態幀為何重合（逐 bit）：本 grid 下 win = n_fft、hop = win/2、同一 sqrt-Hann 窗。centered 第 k 幀以樣本 k·hop 為中心，覆蓋 [k·hop − win/2, k·hop + win/2) = [(k−1)·hop, (k+1)·hop)； non-centered 第 k−1 幀覆蓋 [(k−1)·hop, (k−1)·hop + win)——同一段樣本、 同一張窗 → 頻譜逐 bit 相同，差別只剩幀編號。因此：

  • 兩種 framing 的 STFT→NN→ISTFT 鏈穩態 I/O 延遲都是同一個 1 hop （WOLA 收尾本來就要等下一幀；centered 的半窗 lookahead 藏在其中）。 改 past-only framing 拿不到任何延遲收益。
  • 真實差異只有 (a) 串流開頭第一幀：reflect 前綴 vs 零填冷啟動（影響 recurrent-state start transient）；(b) 檔案級評測的幀數/邊界；(c) 幀時間戳 語意。checkpoint 的 feature-time contract 因此不能靜默改 framing——換 framing 是輸入分佈變更，須 A/B。
  • C 實作佐證：ulcnet_analysis_push() 的排程是 push#0→0 幀、 push#1→2 幀（frame0 含 reflect 前綴 + frame1）、之後每 push 1 幀；輸出端 frame#0→0 樣本（半窗 trim）、之後每幀 256 樣本——與 dfn2 的 center=False 串流輸出排程逐 hop 相同。

Wall-clock authoring grid 註記

  • AEC 的時間常數多以 legacy 10 ms hop（hop=160@16k）撰寫，於 aec_carve()/aec3_growth_rehop() 對實際 grid 即時 retime （aec.h 各欄位註解）；不要在程式碼裡寫入已 retime 的字面值。
  • NR 有兩個 authoring 基準並存：10 ms 參考（mmse_lsa_retime_alpha） 與 16 ms 撰寫（mmse_lsa_retime_alpha_ref(..., 0.016)，如 alpha_xi=0.92、L=32、strength overlay 的 alpha_d/g/attack/decay）。 從錯的基準 retime 會 double-correct（mmse_lsa_types.h 註解）。
  • 換 grid（如 16k 256↔512）時這些機制讓行為以 wall-clock 不變； 但 alpha 值本身會不同，比對常數要先問「authoring grid 是哪個」。
