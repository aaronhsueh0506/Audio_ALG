全鏈 grid / window / framing 慣例

概要

整條鏈的共同格點規則：frame == FFT、hop = fft/2（50% overlap）、無 transform zero-padding、bins = fft/2+1。各層各有自己的預設與白名單， 本頁把它們放在同一張表；另外收錄三件跨模組最容易踩的 framing 事實： 重建路徑一律 periodic sqrt-Hann、PBFDKF 線性路徑的矩形窗例外、 centered 與串流（center=False）framing 在穩態逐 bit 等價。

視窗慣例：重建路徑一律 periodic sqrt-Hann

所有「會被合成回時域」的路徑（分析與合成兩側）用同一個公式，denominator = block 長度 N（periodic，非 symmetric）：

w[k] = sqrtf(0.5 * (1 - cos(2*pi*k / N)))     k = 0..N-1
使用點程式碼
AEC RES 分析窗（error_spec_windowed 用） pbfdkf.c pbfdaf_fill_windows()（ac_window_build(),denom = block_size）

sqrt-Hann 分析 × sqrt-Hann 合成 = Hann，在 50% overlap 下滿足 COLA， 合成端不需 window-envelope 除法（dfn2_process.h 的 dfn2_synthesis() 註解明文）。 例外是 torch.istft 語意的 ULCNet WOLA：它照 torch 做窗平方包絡正規化 （AC_OLA_ENV_NORM 的 env 累加器），結果相同、簿記不同。

STFT／ISTFT 組幀家族（audio_stft.h）

上表所有呼叫點都經 audiolib 的 AcStft／AcIstft；差別只在兩個旋鈕： 分析的 center（0 = 每次 push 恰一幀、零歷史起算；1 = torch center=True、reflect 前綴）與合成的 ola 模式（AC_OLA_ACCUMULATE = acc += ifft×w、每幀吐一個 hop；AC_OLA_ENV_NORM = 另累加 w×w、除以包絡、第一幀不吐）。頻譜縮放由 DFN2/DFN3 用（spec_scale = 1/32、ispec_scale = 32，皆 2 的冪， 乘法不進位）；縮放恰為 1.0f 時略過乘法。

家族呼叫點分析合成FFT／窗
Amono／4ch 各 main 的 ac_istft_push()（在 AEC 內，非本物件）ACCUMULATE物件自帶 FFT 與窗
B → Adfn_rate_bridge.c、dfn2_process.c、gtcrn_process.ccenter 0（bridge 48 kHz 兩路、DFN2、GTCRN）ACCUMULATE（bridge 三路、DFN2、GTCRN）借用呼叫端／bridge 的 FFT handle 與窗
Culcnet_prepost、deepvqe_prepost、兩條 ULCNet pipelinecenter 0（出貨路徑）；center 1 只剩 Python parity 測試ENV_NORM借用 pipeline／呼叫端的 FFT handle 與窗

AC_OLA_ACCUMULATE 把每幀累加進已歸零的 acc 再吐出；若另一個實作改成「前一幀尾巴直接 copy」，兩者數值只可能差在零的符號 （-0.0 對 +0.0），其他位元相同。窗公式 sqrtf(0.5f - 0.5f*cosf(...)) 與 sqrtf(0.5f*(1.0f - cosf(...))) 在 float 下逐 bit 相同 （0.5f 的乘法是精確的縮放）。

PBFDKF far_spec 矩形窗例外

線性濾波路徑沒有分析窗。PBFDAF/PBFDKF 是 overlap-save 結構： far/near 的 block（= 2×hop 原始樣本）直接進 RFFT—— pbfdkf.c 的 rfft_padded(p, p->far_buffer, blk, p->far_spec) 與同樣的 near_spec——等效矩形窗。輸出取 echo_time[hop:block] 有效半段、error_spec 由 zero-pad 的有效 hop 重建，全程無窗。sqrt-Hann 只出現在供 RES/後級分析用的 error_spec_windowed（sqrt-Hann×near − echo_spec）。 另有 td_window（IR 時域約束窗：在 [0, hop) 為 1、[hop, fft_size) 為 0，保留每個 partition 的因果半、清掉其餘，避免 wrap-around 能量漏進下一個 valid hop），作用在濾波器係數不是訊號。

centered framing 與串流（center=False）framing

AINR DFN2 的 C 是 center=False 串流（dfn2_process.h parity 限制 (1)）， Align-ULCNet 的 C 出貨路徑也是 center=False rolling 分析，與 torch center=True 的穩態幀逐 bit 重合（ulcnet_process.h 檔頭 + docs/align_ulcnet_embedded_streaming_design_zh_TW_01_state_wola_delay.md §7）。

穩態幀為何重合（逐 bit）：本 grid 下 win = n_fft、hop = win/2、同一 sqrt-Hann 窗。centered 第 k 幀以樣本 k·hop 為中心，覆蓋 [k·hop − win/2, k·hop + win/2) = [(k−1)·hop, (k+1)·hop)； non-centered 第 k−1 幀覆蓋 [(k−1)·hop, (k−1)·hop + win)——同一段樣本、 同一張窗 → 頻譜逐 bit 相同，差別只剩幀編號。因此：

  • 兩種 framing 的 STFT→NN→ISTFT 鏈穩態 I/O 延遲都是同一個 1 hop （WOLA 收尾本來就要等下一幀；centered 的半窗 lookahead 藏在其中）。 改 past-only framing 拿不到任何延遲收益。
  • 真實差異只有 (a) 串流開頭第一幀：reflect 前綴 vs 零填冷啟動（影響 recurrent-state start transient）；(b) 檔案級評測的幀數/邊界；(c) 幀時間戳 語意。checkpoint 的 feature-time contract 因此不能靜默改 framing——換 framing 是輸入分佈變更，須 A/B。
  • C 實作佐證：AcStft（center 1）的排程是 push#0→0 幀、 push#1→2 幀（frame0 含 reflect 前綴 + frame1）、之後每 push 1 幀；輸出端 AcIstft（ENV_NORM）frame#0→0 樣本（半窗 trim）、之後每幀 256 樣本——與 dfn2 的 center=False 串流輸出排程逐 hop 相同。

ULCNet 的兩種分析排程並存，出貨路徑分兩派。 AcStft 的 center 0（ulcnet_framing_config(…, center = 0)， AIAEC/Align_ULCNet/ulcnet_process.c）是 rolling 分析： 從第一次 push 起每次恰好一幀（第一幀的前半段是被歸零的 history）， 且與 center 1 對同一個 pushed hop 所發的 最後一幀逐 bit 相同——centered 排程只是多了開頭那個 reflect 前綴幀。 上面的穩態等價性因此原封不動地成立，換掉的只是幀編號與串流開頭。 同一個 AcStft 不可混用兩種 center（center 在建立時固定）。

  • 用 center 0：三支前後處理 class （ulcnet_prepost／deepvqe_prepost／dfn2_prepost 本來就是 center=False）、4ch ULCNet pipeline 的 far 分支，以及 mono ULCNet pipeline 兩路皆是 （pipelines/ulcnet/ulcnet_nn_stage.c 的 ac_stft_push_planar(err_analysis / far_analysis, …)）——因為它們要和 AEC/BF seam 自己的頻譜（一 hop 一幀、從 hop 0 起）配對，一手已經是那種幀時， 另一手就得用同一個排程才對得上 hop；mono 的 error/far 兩路本來就同 hop 推入，換成 rolling 排程後兩者天生 hop-locked，不需再靠 centered 排程的 0/2/1 發射對齊。
  • 用 center 1：只剩 Python parity gate （AIAEC/tests/test_ulcnet_process_c.py）與 test_ulcnet_prepost_c.py 的 equiv 案例，兩者都需要 0/2/1 排程本身作為比對基準，不代表任何出貨 pipeline。

Wall-clock authoring grid 註記

  • AEC 的時間常數多以 10 ms hop（hop=160@16k）為基準撰寫，於 aec_carve()/aec_growth_rehop() 對實際 grid 即時 retime （aec.h 各欄位註解）；不要在程式碼裡寫入已 retime 的字面值。
  • NR 有兩個 authoring 基準並存：10 ms 參考（anr_retime_alpha／anr_retime_frames，如 alpha_s=0.95、alpha_p=0.2、alpha_decay=0.88、num_init_frames=20） 與 16 ms 撰寫（anr_retime_alpha_ref(..., 0.016)／anr_retime_frames_ms，如 alpha_xi=0.92、alpha_d_speech=0.95、alpha_attack=0.15、L=32 frames = 512 ms）。 從錯的基準 retime 會 double-correct（anr_types.h 註解）。
  • 換 grid（如 16k 256↔512）時這些機制讓行為以 wall-clock 不變； 但 alpha 值本身會不同，比對常數要先問「authoring grid 是哪個」。
  • 獨立 RES 級 aec_res（AEC RES 級）用與 lane 相同的建構函式， 所以抑制器設定（含上述 retime）逐位元相同；輸入尺度：error_spec/near_spec 為 audio 尺度， r2/comfort_noise 為 int16² 尺度，render 在內部乘 32768 換算。
