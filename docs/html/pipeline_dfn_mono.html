audio_pipeline_dfn — mono AEC(linear) → RES → DeepFilterNet2 後級

概要

pipelines/mono_aec_dfn_res/audio_pipeline_dfn.{h,c}:不是另一條 pipeline,而是一層 wrapper——它內含傳統 mono pipeline(mono_aec_nr_res/audio_pipeline.h)並組成 enable_nr=0 / enable_res=1,再把 DeepFilterNet2 插在「host 的 post-RES 頻譜」與「host 自己的合成」之間;傳統 MMSE-LSA 整個不建構。插入點是 host 的兩個公開入口:audio_pipeline_process_spec() 交出當前 hop 的 SeSpecFrame,audio_pipeline_synthesize() 用 host 自己那組 sqrt-Hann iFFT/OLA 收尾。wrapper 自己擁有增益暫存、unity 向量、P 緩衝與 comfort-noise 狀態,明寫 sk_min_f32 → sk_capply_gain_f32 → aec_cng_fill。中間那一段由共用的 pipelines/dfn_res_stage.{h,c} 負責,4ch 變體用同一份。

Host 跑產品自己的取樣率(預設 16 kHz),只有 DFN2 stage 在 48 kHz。host.sample_rate 接受 8000 / 16000 / 48000;48 kHz 時 stage 直接吃 host 的頻譜,8/16 kHz 時 wrapper 改 carve 一個 DfnRateBridge 負責兩個格點之間的來回,每個 native hop 進一個、出一個。AEC、RES、CNG 一律留在產品取樣率,呼叫端不再需要在 API 之外把訊號 resample 到 48 kHz。

為什麼「估計用 E、套用在 P」

DFN2 是以未經處理的 noisy speech 訓練的,RES 挖出的頻譜洞不在它的訓練分佈裡,所以 stage 把兩件事拆開(dfn_res_stage.h):E = frame.e(線性 AEC 誤差,即 RES gain 當初據以估計的 pre-RES 頻譜)只用來估計(ERB/複數特徵、[t-1,t,t+1] 視窗、三個 head);P = wrapper 的 post 緩衝(= E * min(1, G_res) + CNG,傳統 pipeline 本來就會合成的那一個)才是三個 head 套用的對象(ERB mask、deep filter、alpha blend、atten limit)。分工是:像語音的 far-end 殘留由 DFN 保留、交給 RES 處理;不像語音的兩級都壓。

Comfort-noise fill 關閉時 E 與 P 逐 bin 同相位(G_res 是實數),deep-filter tap 不會相位錯配;開啟時 comfort noise 恰好在 RES 挖得最兇的 bin 改變 P 的相位,estimate/apply 一致性在那裡不成立(實數的 ERB mask 不敏感得多)。所以本變體預設關閉 host 的 fill(enable_cng=0),只留為產品 A/B 開關;雙輸入拓樸仍是產品假說,C 端 gate 只證明結構正確。

API 用法

呼叫順序:default_config() → 填 ERB 矩陣與 model callback → get_mem_requirements() → init_ex() → 每 hop 一次 process() → destroy()。每次 process() 吃剛好一個 host hop 的 mic 與 ref、寫出同樣長度(mono_aec_dfn_res_hop_size():16 k/256 預設 128、16 k/512 為 256、8 k/256 為 128、48 k/1024 為 512)。

#include "audio_pipeline_dfn.h"

MonoAecDfnResConfig cfg = mono_aec_dfn_res_default_config();
/* 預設:host = audio_pipeline_default_config(16000)(fft 256 / hop 128)、
 * enable_nr=0、enable_res=1、enable_cng=0(preset/delay 沿用 host:BALANCED、
 * MATCHED、n=5);atten_lim_db=0、無矩陣、identity model。MonoAecDfnResConfig
 * 直接內含整份 AudioPipelineConfig host,沒有攤平欄位
 * (audio_pipeline_dfn.h、.c) */
cfg.host.sample_rate = 16000;     /* 8000 / 16000 / 48000;< 48 k 走 rate bridge */
cfg.host.delay_num_filters = 5;   /* host 的欄位直接改;wrapper 只釘 seam 不變量 */
cfg.erb_fwd = erb_fwd;   /* bin-major [513][32];erb_inv 為 band-major [32][513], */
cfg.erb_inv = erb_inv;   /* 必須是 partition of unity。兩者 borrowed */
cfg.atten_lim_db = 0.0f;
DFN2ModelIoDescriptor descriptor;          /* 板端應從匯出的模型 metadata 填 */
dfn2_model_io_descriptor_default(&descriptor);
cfg.model.user = board_ctx;
cfg.model.infer = board_run_dfn2_graph;    /* 回 0 = 已寫滿每個輸出 */
cfg.model.reset = board_reset_runtime;     /* 可為 NULL */
cfg.model.io_descriptor = &descriptor;     /* 有 infer 就必須發布 */

MonoAecDfnResMemReq req;
if (mono_aec_dfn_res_get_mem_requirements(&cfg, &req) != 0) { /* reject */ }
void *pool = platform_alloc((size_t)req.bytes, req.alignment);   /* 16-byte 對齊 */
MonoAecDfnRes *p = mono_aec_dfn_res_init_ex(pool, (size_t)req.bytes, &cfg, &req);
while (stream) {   /* mic/ref/out 各 mono_aec_dfn_res_hop_size() 個 float */
    /* (a) 一次完成:模型由 cfg.model.infer 執行(沒設就是 identity) */
    if (mono_aec_dfn_res_process(p, mic, ref, out) != 0) { /* 已自行 reset */ }

    /* (b) 或自己在中間跑加速器(板端):phased API */
    DfnResStageJob job;
    mono_aec_dfn_res_process_begin(p, mic, ref);           /* AEC、RES、P、stage 輸入 */
    while (mono_aec_dfn_res_nn_begin(p, &job) > 0) {      /* 每 hop 0..2 次 */
        int rc = board_run_dfn2_graph_on_npu(&job);     /* 0 = 每個輸出都寫滿 */
        mono_aec_dfn_res_nn_end(p, rc);                    /* rc≠0 → 該幀走 identity */
    }
    mono_aec_dfn_res_process_end(p, out);                  /* 合成剛好一個 host hop */
}
mono_aec_dfn_res_set_aec_preset(p, AEC_PRESET_AGGRESSIVE, 200.0f);  /* hop 之間 */
mono_aec_dfn_res_set_atten_lim(p, 12.0f);                           /* hop 之間 */
DfnRateBridge *b = mono_aec_dfn_res_get_bridge(p);  /* 48 kHz 時 NULL */
mono_aec_dfn_res_reset(p);      /* host + stage/bridge + model->reset 一起 */
mono_aec_dfn_res_destroy(p);    /* 不釋放 caller pool */

公開入口(_get_mem_requirements、_init_ex、_process_begin／_nn_begin／_nn_end／_process_end、_process、_set_aec_preset／_set_atten_lim、_get_*、_hop_size／_lookahead_samples)的逐項語意,以及 stage 與 bridge 的 reject-first 清單(其中最容易踩到的是 erb_inv 必須是 partition of unity),收在 pipeline_dfn_detail。任一步失敗即整條 reset 並回 -1。

訊號泳道圖

48 kHz host 的泳道很短:每 hop 一次推論,第 0 幀因為沒有右鄰居而不呼叫加速器,stage 前兩個 hop 輸出全零頻譜,之後第 p 個 hop 的輸出就是「傳統 pipeline 的 hop#(p-2) 輸出」,合計 3 hop 純延遲(見「延遲與 warm-up」)。原生格點則多了 bridge 的兩個時鐘:

E 與 P 一路都是兩個指標。它們從 SeSpecFrame 與 wrapper 的 post 緩衝出來就分開,在 dfn2_process.c 內部也踩互斥的狀態(est 走特徵/視窗,app 走 noisy ring);est == app 時 ..._freq_dual() 等同dfn2_prepost_pre_process_freq()。命名為 est/app 而非 a/b,是因為兩個同型別的 pair 最容易對調(dfn2_prepost.h)。Bridge 內也維持這個分離:E、P 各有自己的原生 AcIstft、升頻器、48 kHz FIFO 與 48 kHz AcStft(分析歷史在物件內),只有降頻器與 48 kHz 合成物件是一份,因為 stage 只輸出一條訊號。

延遲與 warm-up

端到端演算法延遲 = host 的 1 hop WOLA + DFN2 段的延遲(mono_aec_dfn_res_lookahead_samples())。48 kHz 時 DFN2 段就是 2 hop 模型 lookahead(DFN2_MASK_LOOKAHEAD + DFN2_DF_LOOKAHEAD = 1+1,cascade 串聯相加而非取 max);原生格點時是 bridge 的 added delay:

host 格點hopprefillbridge added delay總演算法延遲
16 kHz / fft 256(預設)128128672(42.0 ms)800 samples = 50.0 ms
16 kHz / fft 51225685629(39.3 ms)885 samples = 55.3 ms
8 kHz / fft 25612842330(41.3 ms)458 samples = 57.3 ms
48 kHz / fft 1024512—(無 bridge)—1536 samples = 32.0 ms(3 hop)
  • added delay = prefill + 升頻群延遲 + 1536×sr/48000 + 降頻群延遲;兩個群延遲在每個支援格點都各是 16 個原生樣本,測試即以 prefill + 16 + 1536*sr/48000 + 16 釘死。1536 = stage 自己的 1 個分析/合成 hop 加兩個 lookahead hop。
  • prefill 不是寫死的常數:init 用真正的 resampler 在靜音上走一遍排程,量出「吐出 − 產生」的最大缺口,_process() 因此永遠拿得到完整 hop。
  • 原生格點不是逐位元等值:訊號走過兩顆 FIR resampler,通帶響應被套用兩次,測試因此用容差而非 memcmp——延遲本身則由脈衝精確釘住。單元測試閘 < 5e-3(現查 7.4e-05 / 9.6e-05 / 1.2e-04);pipeline 測試把兩路都過 0.35 fs 低通後比對,閘 < 1e-3(現查 8.7e-06 / 4.5e-06 / 6.9e-06)。
  • Warm-up:開頭的輸出是全零(48 kHz 兩個 hop;原生格點為 added delay,來自預填的 out FIFO)。dfn_res_stage_process() 暖機時回 0 並寫滿零頻譜,呼叫端可以無條件合成,延遲是純延遲而非條件分支。第 0 幀 不呼叫加速器(分析是 center=False、一個 hop 一幀,但 graph 吃 [t-1,t,t+1],第 0 幀沒有右鄰居);之後 48 kHz 每 hop 恰好一次推論,原生格點照泳道圖的排程,一個 hop 可能 0、1 或 2 次。
  • AEC delay 改變不 reset stage/bridge。它們不消費 far-end,delay 改變後兩個輸入仍然連續;reset 會白付暖機並讓遞迴狀態重來。只有 mono_aec_dfn_res_reset() 才會連帶 reset stage/bridge 與 model.reset(dfn_res_stage.h 開頭)。收尾 flush 要再推兩個全零 hop(原生格點推滿 added delay)才吐得出最後的 source frame,那幾拍加速器也要照跑。
