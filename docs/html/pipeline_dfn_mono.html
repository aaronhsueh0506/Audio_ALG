mono AEC(linear) → RES → DeepFilterNet2 後級(Aec + dfn_hop)

概要

pipelines/dfn/mono_aec_dfn_res/main.c:沒有 DFN wrapper 函式庫,也沒有 mono unit——範例直接組合獨立的函式庫:lib/aec 的 Aec(aec_process_context())→ aec_get_res_context()(AecResContext)→ main.c 的 rig_process() 自己形成 P(只取 AEC 自己的 RES 增益 res_gain:sk_min_f32 對 unity 取 min、sk_capply_gain_f32 套在 E 上,預設不做 CNG,--cng 才呼叫 aec_cng_fill)→ dfn/dfn_hop.h 把 DeepFilterNet2 插在「post-RES 頻譜」與「合成」之間;傳統 MMSE-LSA 整個不建構。每個物件(Aec、DfnResStage／DfnRateBridge、48 kHz 路徑的 AcIstft)各有自己的 mem_size 與 init,由 main.c 加總並切塊;DfnHop 只是非擁有指標的 phase 機器。中間那一段由共用的 pipelines/dfn/dfn_res_stage.{h,c} 負責,4ch 變體用同一份。

Host 跑產品自己的取樣率(預設 16 kHz),只有 DFN2 stage 在 48 kHz。--sample-rate 接受 8000 / 16000 / 48000;48 kHz 時 stage 直接吃 host 的頻譜,8/16 kHz 時範例改建一個 DfnRateBridge(dfn_hop_init_bridge())負責兩個格點之間的來回,每個 native hop 進一個、出一個。AEC、RES、CNG 一律留在產品取樣率,呼叫端不再需要在 API 之外把訊號 resample 到 48 kHz。

為什麼「估計用 E、套用在 P」

DFN2 是以未經處理的 noisy speech 訓練的,RES 挖出的頻譜洞不在它的訓練分佈裡,所以 stage 把兩件事拆開(dfn_res_stage.h):E = error_spec(線性 AEC 誤差,即 RES gain 當初據以估計的 pre-RES 頻譜)只用來估計(ERB/複數特徵、[t-(2-M)..t+M] 視窗、三個 head);P = rig_process() 組出的頻譜(= E * min(1, G_res) + CNG,傳統鏈本來就會合成的那一個)才是三個 head 套用的對象(ERB mask、deep filter、alpha blend、atten limit)。分工是:像語音的 far-end 殘留由 DFN 保留、交給 RES 處理;不像語音的兩級都壓。

Comfort-noise fill 關閉時 E 與 P 逐 bin 同相位(G_res 是實數),deep-filter tap 不會相位錯配;開啟時 comfort noise 恰好在 RES 挖得最兇的 bin 改變 P 的相位,estimate/apply 一致性在那裡不成立(實數的 ERB mask 不敏感得多)。所以本變體預設關閉 comfort-noise fill(--cng 才開),只留為產品 A/B 開關;雙輸入拓樸仍是產品假說,C 端 gate 只證明結構正確。

API 用法

呼叫順序:derive_lane()(aec_resolve_signal_grid() 加 aec_config_from_level())→ 填 ERB 矩陣與 model callback → 各物件 mem_size → 切塊 init → 每 hop 一次(aec_process_context、aec_get_res_context、自寫的 P 形成、dfn_hop_process)→ destroy。每次吃剛好一個 host hop 的 mic 與 ref、寫出同樣長度(16 k/256 預設 128、16 k/512 為 256、8 k/256 為 128、48 k/1024 為 512)。完整範例(含 48 kHz 與 phased 變體)、流程時序圖與參數表收在 pipeline_dfn_usage、pipeline_dfn_sequence 與 pipeline_dfn_params。每 hop 的核心如下:

AecResContext c;
aec_process_context(aec, mic, ref);                          /* 剛好一個 host hop */
aec_get_res_context(aec, &c);
if (!c.error_spec || !c.res_gain) { /* 被拒: aec + rng + hop 一起 reset */ }
sk_min_f32(gain, unity, c.res_gain, n_freqs);                /* P 必須在 dfn_hop_begin 之前形成 */
sk_capply_gain_f32(post, c.error_spec, gain, n_freqs);       /* P = E * min(1, G_res) */
if (cng_on && c.comfort_noise)                               /* 預設關: E 與 P 要同相位 */
    aec_cng_fill(&rng, post, c.comfort_noise, c.res_gain, unity, CNG_NR_GAIN_FLOOR, n_freqs);

dfn_hop_process(&hop, c.error_spec, post, out);                       /* (a) 一次完成:模型由 model.infer 執行(沒設就是 identity) */
/* (b) 或自己在中間跑加速器:dfn_hop_begin → while (dfn_hop_nn_begin() > 0) { 跑 NPU; dfn_hop_nn_end(rc) } → dfn_hop_end(&hop, out) */

各 stage 與 bridge 的 reject-first 清單(其中最容易踩到的是 erb_inv 必須是 partition of unity),以及入口的逐項語意,收在 pipeline_dfn_detail。任一步失敗,整合者要把 Aec、CNG RNG 與 DfnHop 一起 reset(main.c 的 rig_reset())。

訊號泳道圖

48 kHz host 的泳道很短:每 hop 一次推論,前 M 幀因為沒有右鄰居而不呼叫加速器,stage 前 L 個 hop 輸出全零頻譜,之後第 p 個 hop 的輸出就是「傳統 pipeline 的 hop#(p-L) 輸出」(出貨 pair:M=1、L=2,合計 3 hop 純延遲,見「延遲與 warm-up」)。原生格點則多了 bridge 的兩個時鐘:

E 與 P 一路都是兩個指標。它們從 AecResContext 與 P 緩衝出來就分開,在 dfn2_process.c 內部也踩互斥的狀態(est 走特徵/視窗,app 走 noisy ring);est == app 時 ..._freq_dual() 等同dfn2_prepost_pre_process_freq()。命名為 est/app 而非 a/b,是因為兩個同型別的 pair 最容易對調(dfn2_prepost.h)。Bridge 內也維持這個分離:E、P 各有自己的原生 AcIstft、升頻器、48 kHz FIFO 與 48 kHz AcStft(分析歷史在物件內),只有降頻器與 48 kHz 合成物件是一份,因為 stage 只輸出一條訊號。

延遲與 warm-up

端到端演算法延遲 = host 的 1 hop WOLA + DFN2 段的延遲(範例 main.c 以 hop 加 dfn_rate_bridge_added_delay_samples() 或 hop * (DFN_RES_STAGE_LOOKAHEAD_FRAMES + 1) 印出)。48 kHz 時 DFN2 段就是 L = M + D 個 hop 的模型 lookahead(DFN2_MASK_LOOKAHEAD + DFN2_DF_LOOKAHEAD,cascade 串聯相加而非取 max;出貨 pair 1/1 → L = 2);原生格點時是 bridge 的 added delay。下表與數字都是出貨 pair 1/1(其餘 pair 的規則見 pipeline_dfn_detail「lookahead pair」):

host 格點hopprefillbridge added delay總演算法延遲
16 kHz / fft 256(預設)128128672(42.0 ms)800 samples = 50.0 ms
16 kHz / fft 51225685629(39.3 ms)885 samples = 55.3 ms
8 kHz / fft 25612842330(41.3 ms)458 samples = 57.3 ms
48 kHz / fft 1024512—(無 bridge)—1536 samples = 32.0 ms(L+1 = 3 hop)
  • added delay = prefill + 升頻群延遲 + (L+1)×512×sr/48000 + 降頻群延遲(整數除法);兩個群延遲在每個支援格點都各是 16 個原生樣本,測試即以此釘死。(L+1)×512 = stage 自己的 1 個分析/合成 hop 加 L 個 lookahead hop;出貨 pair 為 1536。L+1 不是 3 的倍數時 stage 延遲含小數個原生樣本,向下取整。
  • prefill 不是寫死的常數:init 用真正的 resampler 在靜音上走一遍排程,量出「吐出 − 產生」的最大缺口,_process() 因此永遠拿得到完整 hop。
  • 原生格點不是逐位元等值:訊號走過兩顆 FIR resampler,通帶響應被套用兩次,測試因此用容差而非 memcmp——延遲本身則由脈衝精確釘住。bridge 測試閘 < 5e-3(現查 7.4e-05 / 9.6e-05 / 1.2e-04);test_mono_dfn 把兩路都過 0.35 fs 低通後比對,閘 < 1e-3(現查 8.73e-06 / 8.91e-06 / 1.30e-05)。
  • Warm-up:開頭的輸出是全零(48 kHz 為 L 個 hop;原生格點為 added delay,來自預填的 out FIFO)。dfn_res_stage_end() 暖機時回 0 並寫滿零頻譜,呼叫端可以無條件合成,延遲是純延遲而非條件分支。前 M 幀 不呼叫加速器(graph 的視窗是 [t-(2-M)..t+M],前 M 幀還湊不齊右鄰居;出貨 M=1 即第 0 幀);之後 48 kHz 每 hop 恰好一次推論,原生格點照泳道圖的排程,一個 hop 可能 0、1 或 2 次。
  • AEC delay 改變不 reset stage/bridge。它們不消費 far-end,delay 改變後兩個輸入仍然連續;reset 會白付暖機並讓遞迴狀態重來。只有整合者的 reset(dfn_hop_reset() 連帶 reset stage/bridge 與 model.reset)(dfn_res_stage.h 開頭)。收尾 flush 要再推 L 個全零 hop(原生格點推滿 added delay)才吐得出最後的 source frame,那幾拍加速器也要照跑。
