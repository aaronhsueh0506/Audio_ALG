mono AEC(linear) → RES → DeepFilterNet2 後級(Aec + 範例鏈 + dfn_hop)

概要

pipelines/mono_aec_dfn_res/main.c:沒有 DFN wrapper 函式庫,也沒有 mono unit——範例直接組合獨立的函式庫:lib/aec 的 Aec(aec_process_context())→ se_frame_from_aec() → 範例鏈 samples/se_sample_chain.h(只取 AEC 自己的 RES 增益:enable_nr=0、with_synthesis=0,預設 enable_cng=0)形成 P → samples/dfn_hop.h 把 DeepFilterNet2 插在「post-RES 頻譜」與「合成」之間;傳統 MMSE-LSA 整個不建構。每個物件(Aec、SeSampleChain、DfnResStage／DfnRateBridge、48 kHz 路徑的 AcIstft)各有自己的 mem_size 與 init,由 main.c 加總並切塊;DfnHop 只是非擁有指標的 phase 機器。中間那一段由共用的 pipelines/dfn_res_stage.{h,c} 負責,4ch 變體用同一份。

Host 跑產品自己的取樣率(預設 16 kHz),只有 DFN2 stage 在 48 kHz。--sample-rate(SeRequest.sample_rate)接受 8000 / 16000 / 48000;48 kHz 時 stage 直接吃 host 的頻譜,8/16 kHz 時範例改建一個 DfnRateBridge(dfn_hop_init_bridge())負責兩個格點之間的來回,每個 native hop 進一個、出一個。AEC、RES、CNG 一律留在產品取樣率,呼叫端不再需要在 API 之外把訊號 resample 到 48 kHz。

為什麼「估計用 E、套用在 P」

DFN2 是以未經處理的 noisy speech 訓練的,RES 挖出的頻譜洞不在它的訓練分佈裡,所以 stage 把兩件事拆開(dfn_res_stage.h):E = frame.e(線性 AEC 誤差,即 RES gain 當初據以估計的 pre-RES 頻譜)只用來估計(ERB/複數特徵、[t-1,t,t+1] 視窗、三個 head);P = se_sample_chain_form() 的輸出(= E * min(1, G_res) + CNG,傳統鏈本來就會合成的那一個)才是三個 head 套用的對象(ERB mask、deep filter、alpha blend、atten limit)。分工是:像語音的 far-end 殘留由 DFN 保留、交給 RES 處理;不像語音的兩級都壓。

Comfort-noise fill 關閉時 E 與 P 逐 bin 同相位(G_res 是實數),deep-filter tap 不會相位錯配;開啟時 comfort noise 恰好在 RES 挖得最兇的 bin 改變 P 的相位,estimate/apply 一致性在那裡不成立(實數的 ERB mask 不敏感得多)。所以本變體預設關閉鏈的 fill(enable_cng=0;--cng 才開),只留為產品 A/B 開關;雙輸入拓樸仍是產品假說,C 端 gate 只證明結構正確。

Fail-open = 傳統鏈的等值(延後)。沒有模型(model.infer == NULL)、infer() 回非 0、或輸出有未寫/非有限值時,該幀走 dfn2_prepost_frame_skip():unit ERB mask 經 partition-of-unity 的 erb_inv 展開成 unit bin gain、zero taps、alpha 0,是精確的 identity;遞迴 state 維持加速器寫完的樣子,輸出非有限時已歸零(commit 讓 state generation 加 1)(dfn_res_stage.h、.c)。48 kHz 輸出就是「手寫傳統鏈(tests/conv_chain_mono.h,降噪器關)延後兩個 hop」(CNG 也一樣),由 C 測試逐 byte 釘死;8/16 kHz 因為多了 resampler 往返,gate 改為「延後 added delay 後的通帶容差」。

API 用法

呼叫順序:se_derive() → 填 ERB 矩陣與 model callback → 各物件 mem_size → 切塊 init → 每 hop 一次(aec_process_context、se_frame_from_aec、se_sample_chain_form、dfn_hop_process)→ destroy。每次吃剛好一個 host hop 的 mic 與 ref、寫出同樣長度(16 k/256 預設 128、16 k/512 為 256、8 k/256 為 128、48 k/1024 為 512)。

#include "aec.h"
#include "common/se_config.h"
#include "samples/dfn_hop.h"
#include "samples/se_sample_chain.h"

/* 1. lane: 格點 + AecConfig(mono rules; 8 kHz 可) */
static const SeRules rules = { .allow_8k = 1, .spatial_context = SE_CONTEXT_PRESET };
SeRequest req = {0};  req.sample_rate = 16000;  req.delay_mode = AEC_DELAY_MATCHED;
req.delay_num_filters = 5;  req.fixed_delay_samples = -1;  req.aec_preset = AEC_PRESET_BALANCED;
SeGrid grid;  AecConfig aec_cfg;
se_derive(&req, &rules, &grid, &aec_cfg);

/* 2. 鏈: 只取 AEC 自己的 RES 增益, 不降噪, 不合成(DFN hop 合成); E 與 P 必須同相位, 故 CNG 預設關 */
SeSampleChainConfig sc = se_sample_chain_default_config(16000, grid.fft_size);
sc.res = SE_SAMPLE_RES_FRAME_GAIN;  sc.enable_nr = 0;  sc.enable_cng = 0;  sc.with_synthesis = 0;

/* 3. DFN2: 48 kHz 直接用 stage(+ 呼叫端的 AcIstft); 其餘格點用 rate bridge */
DfnRateBridgeConfig bc = dfn_rate_bridge_default_config(16000);
bc.stage.erb_fwd = erb_fwd;   /* bin-major [513][32];erb_inv 為 band-major [32][513], */
bc.stage.erb_inv = erb_inv;   /* 必須是 partition of unity。兩者 borrowed */
bc.stage.atten_lim_db = 0.0f;
DFN2ModelIoDescriptor descriptor;          /* 板端應從匯出的模型 metadata 填 */
dfn2_model_io_descriptor_default(&descriptor);
bc.stage.model.user = board_ctx;
bc.stage.model.infer = board_run_dfn2_graph;    /* 回 0 = 已寫滿每個輸出 */
bc.stage.model.reset = board_reset_runtime;     /* 可為 NULL */
bc.stage.model.io_descriptor = &descriptor;     /* 有 infer 就必須發布 */

/* 4. 各自查大小、切塊、init(每塊 16-byte 對齊) */
size_t aec_b = aec_get_mem_size(&aec_cfg), chain_b = se_sample_chain_mem_size(&sc);
DfnRateBridgeMemReq breq;  dfn_rate_bridge_get_mem_requirements(&bc, &breq);
void *pool = platform_alloc(ALIGN16(aec_b) + ALIGN16(chain_b) + (size_t)breq.bytes, 16);
Aec *aec = aec_init(pool, aec_b, &aec_cfg);
SeSampleChain *chain = se_sample_chain_init((uint8_t*)pool + ALIGN16(aec_b), chain_b, &sc);
DfnRateBridge *bridge = dfn_rate_bridge_init((uint8_t*)pool + ALIGN16(aec_b) + ALIGN16(chain_b),
                                             (size_t)breq.bytes, &bc);
DfnHop hop;  dfn_hop_init_bridge(&hop, bridge);

while (stream) {   /* mic/ref/out 各 grid.hop_size 個 float */
    SeSpecFrame f;  const Complex *P;
    aec_process_context(aec, mic, ref);
    se_frame_from_aec(aec, &f);
    P = se_sample_chain_form(chain, &f);                 /* P 必須在 dfn_hop_begin 之前形成 */

    /* (a) 一次完成:模型由 model.infer 執行(沒設就是 identity) */
    if (!P || dfn_hop_process(&hop, f.e, P, out) != 0) { /* 被拒: aec + chain + hop 一起 reset */ }

    /* (b) 或自己在中間跑加速器(板端):phased API */
    DfnResStageJob job;
    dfn_hop_begin(&hop, f.e, P);                           /* stage 輸入 */
    while (dfn_hop_nn_begin(&hop, &job) > 0) {          /* 每 hop 0..2 次 */
        int rc = board_run_dfn2_graph_on_npu(&job);       /* 0 = 每個輸出都寫滿 */
        dfn_hop_nn_end(&hop, rc);                        /* rc≠0 → 該幀走 identity */
    }
    dfn_hop_end(&hop, out);                               /* 合成剛好一個 host hop */
}
aec_set_preset(aec, AEC_PRESET_AGGRESSIVE, 200.0f);                      /* hop 之間 */
dfn_res_stage_set_atten_lim(dfn_hop_stage(&hop), 12.0f);               /* hop 之間 */
aec_reset(aec);  se_sample_chain_reset(chain);  dfn_hop_reset(&hop);   /* 一起 reset(model->reset 隨 stage reset) */
dfn_rate_bridge_destroy(bridge);  se_sample_chain_destroy(chain);  aec_destroy(aec);   /* 不釋放 caller pool */

各 stage 與 bridge 的 reject-first 清單(其中最容易踩到的是 erb_inv 必須是 partition of unity),以及入口的逐項語意,收在 pipeline_dfn_detail。任一步失敗,整合者要把 Aec、鏈與 DfnHop 一起 reset(main.c 的 rig_reset())。

訊號泳道圖

48 kHz host 的泳道很短:每 hop 一次推論,第 0 幀因為沒有右鄰居而不呼叫加速器,stage 前兩個 hop 輸出全零頻譜,之後第 p 個 hop 的輸出就是「傳統 pipeline 的 hop#(p-2) 輸出」,合計 3 hop 純延遲(見「延遲與 warm-up」)。原生格點則多了 bridge 的兩個時鐘:

E 與 P 一路都是兩個指標。它們從 SeSpecFrame 與鏈的 P 緩衝出來就分開,在 dfn2_process.c 內部也踩互斥的狀態(est 走特徵/視窗,app 走 noisy ring);est == app 時 ..._freq_dual() 等同dfn2_prepost_pre_process_freq()。命名為 est/app 而非 a/b,是因為兩個同型別的 pair 最容易對調(dfn2_prepost.h)。Bridge 內也維持這個分離:E、P 各有自己的原生 AcIstft、升頻器、48 kHz FIFO 與 48 kHz AcStft(分析歷史在物件內),只有降頻器與 48 kHz 合成物件是一份,因為 stage 只輸出一條訊號。

延遲與 warm-up

端到端演算法延遲 = host 的 1 hop WOLA + DFN2 段的延遲(範例 main.c 以 hop 加 dfn_rate_bridge_added_delay_samples() 或 hop * (DFN_RES_STAGE_LOOKAHEAD_FRAMES + 1) 印出)。48 kHz 時 DFN2 段就是 2 hop 模型 lookahead(DFN2_MASK_LOOKAHEAD + DFN2_DF_LOOKAHEAD = 1+1,cascade 串聯相加而非取 max);原生格點時是 bridge 的 added delay:

host 格點hopprefillbridge added delay總演算法延遲

  • added delay = prefill + 升頻群延遲 + 1536×sr/48000 + 降頻群延遲;兩個群延遲在每個支援格點都各是 16 個原生樣本,測試即以 prefill + 16 + 1536*sr/48000 + 16 釘死。1536 = stage 自己的 1 個分析/合成 hop 加兩個 lookahead hop。
  • prefill 不是寫死的常數:init 用真正的 resampler 在靜音上走一遍排程,量出「吐出 − 產生」的最大缺口,_process() 因此永遠拿得到完整 hop。
  • 原生格點不是逐位元等值:訊號走過兩顆 FIR resampler,通帶響應被套用兩次,測試因此用容差而非 memcmp——延遲本身則由脈衝精確釘住。單元測試閘 < 5e-3(現查 7.4e-05 / 9.6e-05 / 1.2e-04);test_mono_dfn 把兩路都過 0.35 fs 低通後比對,閘 < 1e-3(現查 8.73e-06 / 8.91e-06 / 1.30e-05)。
  • Warm-up:開頭的輸出是全零(48 kHz 兩個 hop;原生格點為 added delay,來自預填的 out FIFO)。dfn_res_stage_process() 暖機時回 0 並寫滿零頻譜,呼叫端可以無條件合成,延遲是純延遲而非條件分支。第 0 幀 不呼叫加速器(分析是 center=False、一個 hop 一幀,但 graph 吃 [t-1,t,t+1],第 0 幀沒有右鄰居);之後 48 kHz 每 hop 恰好一次推論,原生格點照泳道圖的排程,一個 hop 可能 0、1 或 2 次。
  • AEC delay 改變不 reset stage/bridge。它們不消費 far-end,delay 改變後兩個輸入仍然連續;reset 會白付暖機並讓遞迴狀態重來。只有整合者的 reset(dfn_hop_reset() 連帶 reset stage/bridge 與 model.reset)(dfn_res_stage.h 開頭)。收尾 flush 要再推兩個全零 hop(原生格點推滿 added delay)才吐得出最後的 source frame,那幾拍加速器也要照跑。
