Align-ULCNet（linear AEC → RES+NR post-filter，paper reference）

概要

Shetu et al.（EUSIPCO 2025, arXiv:2410.13620）兩級混合式殘響/殘迴聲 + 噪音抑制器的重建。 task（dataset_gen/model_views.py 的 MODEL_TASKS）= linear_aec_postfilter_res_nr_dereverb：輸入是凍結 PBFDKF linear AEC 的 error（linear_error = mic_postclip − D_hat，不是 oracle residual；由 context-only frontend 產生，與板端 pipeline 同一條 seam，含 over-output capture guard——被判 unusable 的 hop 送的是 mic 本身，見 AIAEC/dataset_gen/README.md）與 未對齊 far-end（far_render）；target 是共同的 near_target（去噪、去迴聲、early/dereverb 近端語音）。

兩組編譯期 grid（唯一支援的兩組；export_onnx.py 的 SUPPORTED_GRIDS 拒絕其他組合，ulcnet_model_io.h 對其他組合 直接 #error）。下表每個寬度都由 n_fft 導出，沒有任何一個是寫死的：

gridn_fft/win/hopK（bins）C-SamFR 每通道寬attention ta_binshop 時長
16 kHz512/512/256257522616.00 ms
48 kHz1024/1024/5125131045210.67 ms

alignment 深度 D 在 16 kHz 固定 64（論文 Dmax）。D 不能跨 grid 沿用：它數的是 hop， 而兩個 grid 的 hop 長度不同。深度 D 往回搆到 (D−1) 個 hop，所以 D=8 在 16 kHz 是 112 ms、在 48 kHz 只剩 74.7 ms；要在 48 kHz 搆到同樣的 112 ms 需要 D=12。 而「由一個物理秒導出 D」這條路在 48 kHz 走不通： SignalGrid.delay_frames(1.0) 在該 grid 給出 94，超過 export_onnx.py 的 MAX_DELAY_DEPTH 與 C 端 ULCNET_MODEL_IO_MAX_D 共同的 D ≤ 64 上限——這種 run 會訓練成功、 到 export 才失敗。因此 48 kHz 必須在 [model] max_delay_frames 明寫 D； 出貨的 config.ini 寫的是 8，不受影響。 參數量實測 672,441 trainable（16k grid；README 記 ~0.67 M，落在論文 0.69 M class）。stream_output_delay = 0。

ONNX / NPU graph boundary（export 腳本已交付：AIAEC/Align_ULCNet/export_onnx.py 匯出 stateless one-frame graph，K/V/logit/GRU state 全部顯式 I/O， boundary 標記為 stateless_one_frame_delta_state；D 由 checkpoint 的 max_delay_frames 決定並在 export 當下固定進 ONNX shape，見下方 D 覆寫段）：graph 內 = ChannelSampledReorientation（C-SamFR reshape）、separable conv + ELU + MaxPool、 FrameDelayAttention（softmax over D）、FrequencyGRU （頻率軸 bidirectional GRU 32×2，逐幀、免 state）、兩個 2 層 128-unit 時間軸 GRU、FC + sigmoid + PReLU、stage-2 CNN complex mask。所有 recurrent state 是顯式 I/O tensor，由 CPU/DSP caller-owned pool 逐次傳入/傳回；加速器本身無隱藏 state。graph 外（C 前後處理）= PBFDKF linear AEC 與 delay 對齊（AEC C 端 seam）、centered sqrt-Hann STFT/ISTFT 與 complex↔RI 轉換 （C 實作 ulcnet_process.c；Python reference StreamSTFT/StreamISTFT）， 以及 layout v5 起的固定前後端（C 實作封在 ulcnet_model_io.c 的 prepare/commit；Python reference export_onnx.stream_features/host_output）： _signed_power（signed pow(0.3) 壓縮）、兩路 magnitude、 atan2/cos/sin（壓縮域相位——對 0.3 次方後分量取角，板端不可用原始相位替代）， graph 綁五個特徵輸入 error_mag/far_mag/error_cos/error_sin（各 [1,1,K]）＋壓縮域 error_ri（[1,1,K,2]）， 各自持量化 scale；graph 輸出為壓縮域 estimate，host 做逆冪還原。以上是 出貨的 host/split 這一對；另外三對見下節。

far branch 契約：checkpoint contract 的 far_input_mode 只記錄訓練 provenance（legacy 預設 raw_far）。production 固定使用 AEC aligned-far seam；未取得 alignment 時 seam 暫時承載 raw far，模型仍執行，取得後切成 aligned far 並 reset recurrent state。export_onnx.py 因此分開寫 training_far_input_mode 與部署用 far_input_mode=aligned_far。C descriptor 只接受 ALIGNED；production pipeline 沒有 runtime far-mode setter。raw/aligned 比較僅保留在 sweep 工具。
PTQ calibration：可直接使用訓練域的 linear_error + raw_far；calibration report 會將 calibration_far_input_mode=raw_far 與 production deployment_far_input_mode=aligned_far 分開記錄。D 不改權重， 但會改 K/V history shape 與 host RAM，因此 calibration 的 D 必須和該份 ONNX export 相同。
既有匯出必須全部重跑：model-I/O layout 現為 v8 （v3 = far branch RAW → ALIGNED；v4 = tensor 更名；v5 = 固定前後端搬到 host；v8 = 兩顆 GRU hidden 由 rank-3 改為 rank-4 NCHW，與三個 attention cache 同一慣例；3–7 一律退役不得重用），此前產出的每一份 ONNX/JSON descriptor 在 ulcnet_model_io_descriptor_validate() 卡在 layout_version（v3 之前另卡 far_input_mode）， ulcnet_accelerator_adapter_init() 回 NULL。修法只有「重新 export graph」一項：checkpoint 與 dataset 不需要重新訓練或重新生成， 權重未變，exporter 會把 checkpoint 原本的 training far_input_mode 與固定的 aligned-far deployment 值分開寫入。 4/6/7 是被佔用不是空號（另外三對 boundary），下一次真正 bump ULCNET_MODEL_IO_LAYOUT_VERSION 要跳到 8。

ONNX graph boundary：兩軸開關

boundary 是一對互相獨立的開關，version 屬於這一對、不屬於任何一半， 表在 export_onnx.py 的 LAYOUT_VERSIONS。 inference.py calib 收同樣兩個旗標，且在同一個 process 用同一個 model instance 匯出對應 graph，不必為了換 layout 匯出兩次。

--feature-layout＝固定前後端跑在哪裡。host 把 signed pow(0.3) 壓縮、兩路 magnitude、壓縮域相位 cos/sin 留在 graph 外 （stream_features；C ulcnet_model_io_prepare），回程逆冪也在外 （host_output；C ulcnet_model_io_commit）。graph 改綁兩個 raw RI 頻譜，把同一份固定數學搬回 graph 內——除了 recurrent state 的 rank 之外，這重現了固定前後端搬到 host 之前的 boundary， 因此它自帶版本號，而不是沿用那個 boundary 當年、如今已退役的號碼。

差別在量化不在算術：host 讓五個特徵各持自己的 scale，且 sqrt/atan2/pow 這些非學習運算不進量化域；graph 少綁 tensor、 host 端不需要前端，代價是那些運算進了量化域，且 error_cos/error_sin 共用編譯器替它們推出來的同一個 scale。實測 graph 多出的非學習運算為 Sign×6、Abs×6、Pow×6、Sqrt×2、 Atan/Cos/Sin 各 1（另有隨之增加的 elementwise 與索引節點）；經 onnxoptimizer + 常數摺疊後節點數 121 → 177。

--gru-state-layout＝兩顆 subband GRU hidden 怎麼呈現。 split 出 h_gru0/h_gru1，各 (1, GRU_LAYERS, 1, GRU_HIDDEN)；combined 沿 dim 1 （dim 0 是 singleton N）疊成單一 h_gru (1, 2*GRU_LAYERS, 1, GRU_HIDDEN)（h_gru0 在前，沿 channel 軸堆疊）， 輸出也併成一個 h_gru_out。三個 attention cache （key_history/value_history/logit_history） 在兩種 layout 都維持獨立：它們是結構性歷史而不是 recurrent hidden state， 也不與 hidden 共用分布。combined 存在的目的就是量「共用一個量化 scale 要付多少代價」。

python3 AIAEC/Align_ULCNet/export_onnx.py --checkpoint ckpt.pth \
    --max-delay-frames 8 --feature-layout graph --gru-state-layout combined \
    --output output/align_ulcnet_d8_graph_combined.onnx --verify
四對 boundary 逐幀互跑位元相同（rtol=0, atol=0；test test_every_layout_pair_computes_the_same_frames）。C 端只綁 host/split，板端拿到另外三對會在 layout_version 被擋掉——這是刻意的。換 layout 屬合約變更不是旗標切換： ulcnet_model_io.h、其 prepare/commit API 與 graph I/O 表 （Align_ULCNet/README.md、設計文件 §10.2）要一起搬。

API 用法

from AIAEC.Align_ULCNet.inference import load_model
from AIAEC.aiaec_streaming import StreamSTFT, StreamISTFT

model, grid, linear_contract = load_model("ckpt.pth", "cpu")  # max_delay_frames=8 可覆寫 D
state = model.create_stream_state()          # {"align", "subband_gru0", "subband_gru1"}
H = grid.hop_len                                          # 16k: 256、48k: 512
stft_err = StreamSTFT(grid.n_fft, H, window)              # window = sqrt-Hann n_fft
stft_far = StreamSTFT(grid.n_fft, H, window)
istft    = StreamISTFT(grid.n_fft, H, window)
for s in range(0, n, H):
    for e, f in zip(stft_err.push(err[:, s:s+H]), stft_far.push(far[:, s:s+H])):
        out = model.forward_stream(linear_error=e.unsqueeze(1),
                                   far_end=f.unsqueeze(1), state=state)
        samples = istft.push(out.enhanced[:, 0])          # 穩態每幀 H samples
python3 AIAEC/Align_ULCNet/inference.py checkpoint.pth mic.wav far.wav out.wav \
    [--verify] [--input-is-linear-error] [--max-delay-frames N] [--device cpu]

inference.py 只有一條路徑：逐幀 forward_stream 排程 （實作在 _streaming.py，entry 不會退回整段 model(...)——test： test_inference_entry_uses_streaming_schedule）。D 覆寫 （--max-delay-frames）：checkpoint contract 記錄的是訓練時的 D（training provenance）；權重 D-agnostic（D=64 checkpoint 可 strict-load 進 D=8），但輸出跨 D 不數值相同（fixture 實測 enhanced max-abs 差 8.9e-6）。部署閘不是 checkpoint contract 而是 graph descriptor：板端 比對的是 ONNX metadata／calibration report／C UlcnetModelIoDescriptor 三方的 D 與 state_layout_version，訓練 D 與部署 D 不同不構成拒絕理由。

K = n_fft/2+1（16k: 257、48k: 513）；TA = ceil(K/10)（16k: 26、48k: 52）；
HOP = n_fft/2（16k: 256、48k: 512）；D = max_delay_frames（出貨 config 為 8）。
joint2 之後的 [B,96,1,7] 與 fgru 之後的 [B,64,1,7] 是 16 kHz 的值；48 kHz 因 TA 加倍
而變成 [B,96,1,13] / [B,64,1,13]（TA 之後再兩次 ceil-halving：26→13→7、52→26→13）。
subband 切法 split = (ceil(w/2), w//2)，兩個 GRU 各輸出 128，concat 後恆為 256——
所以 mask_fc1/fc2 的輸入寬度與 grid 無關，只有輸出寬度是 K。

延遲與 warm-up

  • NN 演算法 lookahead = 0 hop；zero-init history ≡ offline 左零 padding， 從 reset 開始的 stream 與 whole-utterance forward 等價，無 warm-up 特例。 實測 stream-vs-offline 最差差異：enhanced 4.1e-8 / mask 1.2e-7 / magnitude_mask 6.0e-8 / delay 4.0e-7（test 檔頭記載；tolerances 以 ~10x headroom 釘在 5e-7 / 2e-6 / 1e-6 / 5e-6）。
  • Framing：center=True 契約 → 半窗 1 個 hop 的 lookahead；C 端端到端演算法 延遲 = HOP samples（ulcnet_process.h 明文）＝16 kHz 256 smp（16 ms）、 48 kHz 512 smp（10.67 ms）。hop 數兩個 grid 相同，毫秒數不同。
  • C 前後處理 vs Python：float-ULP 級（實測 ~2e-5 絕對值，KISS f32 FFT vs torch double twiddles），非 bit-exact（test_ulcnet_process_c.py 檔頭）。
