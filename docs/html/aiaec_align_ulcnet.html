Align-ULCNet（linear AEC → RES+NR post-filter，selected）

概要

如何呼叫、流程時序圖、外部／內部參數表：aiaec_align_ulcnet_usage。

Shetu et al.（EUSIPCO 2025, arXiv:2410.13620）兩級混合式殘響/殘迴聲 + 噪音抑制器的重建。 task（dataset_gen/model_views.py 的 MODEL_TASKS）= linear_aec_postfilter_res_nr_dereverb：輸入是凍結 PBFDKF linear AEC 的 error（linear_error = mic_postclip − D_hat，不是 oracle residual；由 context-only frontend 產生，與板端 pipeline 同一條 analysis seam（formed_hop），是每個 hop 真實選定的線性殘差；output guard 只選 rendering base、不改這個輸入，guard hop 上它可能大於 capture，見 AIAEC/dataset_gen/README.md）與 未對齊 far-end（far_render）；target 是共同的 near_target（去噪、去迴聲、early/dereverb 近端語音）。

兩組編譯期 grid（唯一支援的兩組；export_onnx.py 的 SUPPORTED_GRIDS 拒絕其他組合，ulcnet_model_io.h 對其他組合 直接 #error）。下表每個寬度都由 n_fft 導出，沒有任何一個是寫死的：

alignment 深度 D：建構子預設在 16 kHz 為 64（論文 Dmax），出貨 16 kHz 訓練 config.ini 的 max_delay_frames 為 32；部署 D 是匯出時另定的值。D 不能跨 grid 沿用：它數的是 hop， 而兩個 grid 的 hop 長度不同。深度 D 往回搆到 (D−1) 個 hop，所以 D=8 在 16 kHz 是 112 ms、在 48 kHz 只剩 74.7 ms；要在 48 kHz 搆到同樣的 112 ms 需要 D=12。 「由一個物理秒導出 D」在 48 kHz 走不通： SignalGrid.delay_frames(1.0) 在該 grid 給出 94，超過 MAX_DELAY_DEPTH ／ULCNET_MODEL_IO_MAX_D 共同的 D ≤ 64 上限——這種 run 訓練成功、到 export 才失敗，因此 48 kHz 必須在 [model] max_delay_frames 明寫 D（16 kHz 出貨 config.ini 為 32；沒有 48 kHz 出貨 config）。 參數量實測 672,441 trainable（16k grid；落在論文 0.69 M class）。stream_output_delay = 0。

ONNX / NPU graph boundary（Align_ULCNet/export_onnx.py 匯出 stateless one-frame graph，key_history/value_history/logit_history/h_gru 四個 state 全部顯式 I/O：輸入是完整 window，各回同 shape 的完整下一個 window（位移在 graph 內：輸入端 Slice 加 Concat，Concat 的結果就是輸出），boundary 標記 stateless_one_frame_full_state、state_binding: in_place_same_address、cpu_delta_state_update: false；D 由 checkpoint 的 max_delay_frames 決定，export 當下固定進 ONNX shape）：graph 內 = ChannelSampledReorientation（C-SamFR reshape）、separable conv + ELU + MaxPool、 FrameDelayAttention（softmax over D）、FrequencyGRU （頻率軸 bidirectional GRU 32×2，逐幀、免 state）、兩個 2 層 128-unit 時間軸 GRU、FC + sigmoid + PReLU、stage-2 CNN complex mask（state 見 State 表）。graph 外（C 前後處理）= PBFDKF linear AEC 與 delay 對齊（AEC C 端 seam）、sqrt-Hann STFT/ISTFT 與 complex↔RI 轉換 （C 實作 ulcnet_process.c，出貨 seam 走 center=False 逐 hop 一幀，見下方 「C pre/post 類別」；Python reference StreamSTFT/StreamISTFT）， 以及 host layout 的固定前後端（C 實作封在 ulcnet_model_io.c 的 prepare/commit；Python reference export_onnx.stream_features/host_back_end）： _signed_power（signed pow(0.3) 壓縮）、兩路 magnitude、 atan2/cos/sin（壓縮域相位——對 0.3 次方後分量取角，板端不可用原始相位替代）， graph 綁四個特徵輸入 error_mag/far_mag/error_cos/error_sin（各 [1,1,K]），各自持量化 scale。graph 止於 complex_mask 1×1 Conv， output 是學到的複數 mask（planar [1,2,1,K]，plane 0 實部、plane 1 虛部）； host（commit()）用 prepare() 留在 state 的壓縮域 error 頻譜乘上 mask， 再逆冪還原。以上是唯一的 boundary（layout 18）。

far branch 契約:production 固定用 caller 的 raw far,C descriptor 只接受 ULCNET_FAR_RAW,export_onnx.py 分開寫 training_far_input_mode 與 far_input_mode(兩者皆為 raw_far);PTQ calibration 的 D 必須和該份 ONNX export 相同。model-I/O layout 是 v18(ULCNET_MODEL_IO_LAYOUT_VERSION = 18;RETIRED_LAYOUT_VERSIONS = 3–17,不得重用),其他 layout 的 ONNX/JSON descriptor 會在 ulcnet_model_io_descriptor_validate() 卡在 layout_version。三項的完整說明收在 aiaec_align_ulcnet_detail。
訓練前端契約:metadata 另帶 linear_aec_contract_version、aec_behavior_hash(取自 checkpoint)與 error_input_seam = analysis_formed;整合端在 ulcnet_accelerator_adapter_init() 之前要拿前者比對 ULCNET_MODEL_IO_FRONTEND_CONTRACT(aiaec-linear-error-v4),不符就不綁定。這不是 layout 升版(仍是 18)。

ONNX graph boundary（layout 18）

boundary 只有一種：四個 host 特徵輸入加四個 rank-4 state，每個 state 都有同 shape 的 *_out。 版本號在 export_onnx.py 的 LAYOUT_VERSION，與 ulcnet_model_io.h 的 ULCNET_MODEL_IO_LAYOUT_VERSION 互鎖（test_c_descriptor_constants_match_export_contract）。 inference.py calib 與匯出用同一個 wrapper，同一個 process 匯出。

graph 輸入shape內容
error_mag/far_mag/error_cos/error_sin(1,1,K) 各一host 前端產生（stream_features；C ulcnet_model_io_prepare）
key_history/value_history(1,32,D,TA)newest-first：slot 0 是最新一幀，slot d 是 t−d
logit_history(1,32,5,D)oldest-first：frame 4 是最新一幀；score conv 的 5 幀輸入
h_gru(1,4,1,128)subband GRU 0 的兩層，接著 subband GRU 1 的兩層（沿 dim 1 疊；dim 0 是 singleton N，不是疊的軸）

輸出是 output（planar mask (1,2,1,K)）加四個 *_out，每個與同名輸入 shape 完全相同。位移在 graph 內、用輸入端的 Slice 再把新一幀 Concat 進去（K/V 放前面、logit 放後面），沒有 state 輸出由 Slice 產生，所以 runtime 可把每個 *_out 綁到同名輸入的位址、CPU 不搬不複製;export_graph 以 validate_inplace_state_contract（AIAEC/_onnx_contract.py）檢查,任何一項不成立匯出直接失敗。Slice 參數與檢查項目逐條收在 aiaec_align_ulcnet_detail。

python3 AIAEC/Align_ULCNet/export_onnx.py --checkpoint ckpt.pth \
    --max-delay-frames 8 --output output/align_ulcnet_d8.onnx --verify
boundary 沒有可選開關：前後端固定在 host，GRU hidden 固定併成單一 h_gru， export 與 calibration CLI 都沒有 layout 旗標。C 端把 state 清零（reset 或拒絕一幀）時，定點 accelerator 自己的 state 緩衝不會跟著變，所以板端 sample 要追蹤 ulcnet_accelerator_adapter_state_generation()（見下節）， 值一變就用量化後的 0 重填 state。第一個 hop 的 state 全為 0（reset 值）；定點 runtime 的「0」是否等於量化後的 0 由量化工具鏈確認，尚未驗證。

API 用法

from AIAEC.Align_ULCNet.inference import load_model
from AIAEC.aiaec_streaming import StreamSTFT, StreamISTFT

model, grid, linear_contract = load_model("ckpt.pth", "cpu")  # max_delay_frames=8 可覆寫 D
state = model.create_stream_state()          # {"align", "subband_gru0", "subband_gru1"}
H = grid.hop_len                                          # 16k: 256、48k: 512
stft_err = StreamSTFT(grid.n_fft, H, window)              # window = sqrt-Hann n_fft
stft_far = StreamSTFT(grid.n_fft, H, window)
istft    = StreamISTFT(grid.n_fft, H, window)
for s in range(0, n, H):
    for e, f in zip(stft_err.push(err[:, s:s+H]), stft_far.push(far[:, s:s+H])):
        out = model.forward_stream(linear_error=e.unsqueeze(1),
                                   far_end=f.unsqueeze(1), state=state)
        samples = istft.push(out.enhanced[:, 0])          # 穩態每幀 H samples
python3 AIAEC/Align_ULCNet/inference.py checkpoint.pth mic.wav far.wav out.wav \
    [--verify] [--input-is-linear-error] [--max-delay-frames N] [--device cpu]

inference.py 只有一條路徑：逐幀 forward_stream 排程（實作在 _streaming.py，entry 不會退回整段 model(...)——test test_inference_entry_uses_streaming_schedule）。D 覆寫 （--max-delay-frames）：checkpoint contract 記的是訓練時的 D；權重 D-agnostic （D=64 checkpoint 可 strict-load 進 D=8），但輸出跨 D 不數值相同（fixture 實測 enhanced max-abs 差 8.9e-6）。部署閘不是 checkpoint contract 而是 graph descriptor：板端比對 ONNX metadata／calibration report／C UlcnetModelIoDescriptor 三方的 D 與 state_layout_version，訓練 D 與部署 D 不同不構成拒絕理由。

C pre/post 類別（ulcnet_prepost.c/h）

板端整合點：一個物件包住 caller 音訊與加速器張量之間的一切（framing、壓縮域前端、 recurrent state）。它組合 ulcnet_process.c ＋ ulcnet_model_io.c， 兩個被組合的檔各自保有獨立的 parity 測試。生命週期、32-byte MemReq 陳舊 pool 閘、交易式 frame 狀態機與「為何是第三個 TU」是三個模型共用的形狀，寫在 onnx_prepost；以下只記 Align-ULCNet 自己的部分。

UlcnetPrepostConfig cfg;  UlcnetPrepostMemReq req;
ulcnet_prepost_config_defaults(&cfg, ULCNET_IO_TIME, /*D=*/8);  /* D 須等於 export 的 D */
cfg.fft = fft;  cfg.window = window;      /* caller-owned 借用；本類別不建也不毀 */
cfg.istft = istft;   /* TIME 必填：應用端用 ulcnet_framing_config(&sc, fft, window, 0) + ac_istft_init() 建的 AcIstft */
ulcnet_prepost_get_mem_size(&cfg, &req);
UlcnetPrepost *p = ulcnet_prepost_init_ex(pool, req.bytes, &cfg, &req);  /* 或 _init / _create */
每 hop：
  ulcnet_prepost_pre_process(p, err_hop, far_hop);   /* 恆回 1；_pre_process_freq 為頻域孿生 */
  ulcnet_prepost_frame_inputs(p, &in, &out);         /* pool 內的 view；只有 output 預填 NaN */
  my_npu_run(&in, &out);                         /* 每個 out.*_out 綁 in 的同名位址；先讀完 state 輸入再寫輸出 */
  ulcnet_prepost_frame_commit(p);                    /* 失敗改呼叫 ulcnet_prepost_frame_skip(p) */
  ulcnet_prepost_post_process(p, out_hop, &written); /* _post_process_freq 為頻域孿生 */
其餘：_reset / _destroy / _hop_size / _num_bins / _io_mode / _descriptor / _state_generation

一 hop 進、一次推論、一 hop 出——從 hop #0 起、兩種模式皆然，呼叫端不必迴圈。 io_mode 在 init 固定（它決定 pool 大小）：ULCNET_IO_TIME hop 進 hop 出， 分析 framing 由類別做、呼叫的是 caller 的 FftHandle 與 window 表，合成是應用端持有的 AcIstft（cfg.istft，borrowed；frame_commit 對它 push、reset 一併清它）； ULCNET_IO_FREQ 頻譜進頻譜出、不做任何 transform（合成由應用端對 post_process_freq 的頻譜自己呼叫 ac_istft_push_planar），fft/window/istft 可為 NULL，這是串接（AEC seam 或 4ch 路徑的 beamformed 頻譜）用的模式。

四個 state 就地綁定：key_history/value_history/logit_history/ h_gru 在 caller pool 各一份，graph 回每個 state 的完整下一個 window（shape 同輸入，位移在 graph 內）， runtime 把每個 *_out 綁到 frame_inputs() 回傳的同名位址，先讀完所有 state 輸入才寫輸出； 沒有複製路徑，也沒有 ping-pong。frame_inputs 只對 output 預填 NaN；commit 不更新任何 state，先驗證： output（mask）、h_gru 全部，以及每個 channel 的 K/V slot 0 與 logit 最後一幀皆有限才成功 （較舊的格子與被丟掉的那一格不重查，殘留的非有限值會在下一幀進到 output 被擋下）； 遇非有限值無法回滾，四個 state 全部歸零、幀維持開啟、回 −1。 frame_skip 在本模型 = identity——error 頻譜原樣通過、state 維持原樣、 framing 照常前進（stream 0 已是 linear-AEC error，不需 mute；DeepVQE-S 必須 mute）。這個 error 是未經 guard 的 analysis residual （formed_hop／AecResContext.error_spec，每個 hop 都是真實選中的線性殘差），在 lib/aec 渲染 guard 作用的 hop 上可能大於 capture；guard 只決定渲染 base，不改這個輸入。寫一半只有非有限值才偵測得到。

state generation：ulcnet_prepost_state_generation()（adapter 與 model-I/O 層各有同語意的 *_state_generation()）是 C 端清零 state 的次數計數器：reset 與被拒絕的 commit 各加一， 新建的實例為 0，成功的 commit、skip 與再次呼叫被拒的 commit 都不動它。定點 accelerator 的 state 緩衝在 C 清零時不會 跟著變，板端 sample 比較這個值，變了就用量化後的 0 重填 state 輸入。

rolling 分析:出貨 seam 的 AcStft 用 center 0(ulcnet_framing_config()),第一次 push 起每次恰一幀;與 centered(center 1)對同一個 hop 吐出的最後一幀位元相同(test_ulcnet_prepost_c.py 的 equiv 案例實測),自第二個 hop 起對得起來。完整說明收在 aiaec_align_ulcnet_detail。

adapter 驅動類別：ulcnet_accelerator_adapter.c 開一個 ULCNET_IO_FREQ 實例（不 carve framing state、完全不牽涉 FftHandle/window，framing 時鐘歸呼叫端）；adapter pool = 類別 FREQ pool + 32 B header。 Build：make -C AIAEC lib 產出 libaiaec_prepost.a，放在依組態 編碼的 build/simd<N>-<sig>/（sig = CC/AR/CFLAGS/CPPFLAGS/SIMD/WERROR 的 cksum）；make -C AIAEC print-lib-path 印出該組態封存檔的絕對路徑， make -C AIAEC test = 建庫 + pytest。

延遲與 warm-up

  • NN 演算法 lookahead = 0 hop；zero-init history ≡ offline 左零 padding， 從 reset 開始的 stream 與 whole-utterance forward 等價，無 warm-up 特例。 實測 stream-vs-offline 最差差異：enhanced 4.1e-8 / mask 1.2e-7 / magnitude_mask 6.0e-8 / delay 4.0e-7（test 檔頭記載；tolerances 以 ~10x headroom 釘在 5e-7 / 2e-6 / 1e-6 / 5e-6）。
  • Framing：類別與 AEC seam／4ch 路徑用 center=False、每 hop 一幀的 rolling 分析；centered push 只剩 Python parity gate 使用（mono 範例 pipelines/ulcnet/mono_alignulcnet/main.c 用同一套排程）。端到端 演算法延遲仍是 HOP samples＝16 kHz 256 smp（16 ms）、48 kHz 512 smp（10.67 ms），但它來自 synthesis 的半窗 trim、不是分析排程（ulcnet_prepost.h 明文）。
  • C 前後處理 vs Python：float-ULP 級（實測 ~2e-5 絕對值，NE10 f32 FFT vs torch double twiddles），非 bit-exact（test_ulcnet_process_c.py 檔頭）。
