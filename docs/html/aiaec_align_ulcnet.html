Align-ULCNet（linear AEC → RES+NR post-filter，paper reference）

概要

Shetu et al.（EUSIPCO 2025, arXiv:2410.13620）兩級混合式殘響/殘迴聲 + 噪音抑制器的重建。 task（dataset_gen/model_views.py 的 MODEL_TASKS）= linear_aec_postfilter_res_nr_dereverb：輸入是凍結 PBFDKF linear AEC 的 error（linear_error = mic_postclip − D_hat，不是 oracle residual；由 context-only frontend 產生，與板端 pipeline 同一條 seam，含 over-output capture guard——被判 unusable 的 hop 送的是 mic 本身，見 AIAEC/dataset_gen/README.md）與 未對齊 far-end（far_render）；target 是共同的 near_target（去噪、去迴聲、early/dereverb 近端語音）。

兩組編譯期 grid（唯一支援的兩組；export_onnx.py 的 SUPPORTED_GRIDS 拒絕其他組合，ulcnet_model_io.h 對其他組合 直接 #error）。下表每個寬度都由 n_fft 導出，沒有任何一個是寫死的：

alignment 深度 D 在 16 kHz 固定 64（論文 Dmax）。D 不能跨 grid 沿用：它數的是 hop， 而兩個 grid 的 hop 長度不同。深度 D 往回搆到 (D−1) 個 hop，所以 D=8 在 16 kHz 是 112 ms、在 48 kHz 只剩 74.7 ms；要在 48 kHz 搆到同樣的 112 ms 需要 D=12。 而「由一個物理秒導出 D」這條路在 48 kHz 走不通： SignalGrid.delay_frames(1.0) 在該 grid 給出 94，超過 MAX_DELAY_DEPTH ／ULCNET_MODEL_IO_MAX_D 共同的 D ≤ 64 上限——這種 run 會訓練成功、到 export 才失敗，因此 48 kHz 必須在 [model] max_delay_frames 明寫 D（出貨 config.ini 寫 8，不受影響）。 參數量實測 672,441 trainable（16k grid；README 記 ~0.67 M，落在論文 0.69 M class）。stream_output_delay = 0。

ONNX / NPU graph boundary（Align_ULCNet/export_onnx.py 匯出 stateless one-frame graph，K/V/logit/GRU state 全部顯式 I/O，boundary 標記 stateless_one_frame_delta_state；D 由 checkpoint 的 max_delay_frames 決定，export 當下固定進 ONNX shape）：graph 內 = ChannelSampledReorientation（C-SamFR reshape）、separable conv + ELU + MaxPool、 FrameDelayAttention（softmax over D）、FrequencyGRU （頻率軸 bidirectional GRU 32×2，逐幀、免 state）、兩個 2 層 128-unit 時間軸 GRU、FC + sigmoid + PReLU、stage-2 CNN complex mask（recurrent state 全部是顯式 I/O tensor， 加速器本身無隱藏 state，見 State 表）。graph 外（C 前後處理）= PBFDKF linear AEC 與 delay 對齊（AEC C 端 seam）、sqrt-Hann STFT/ISTFT 與 complex↔RI 轉換 （C 實作 ulcnet_process.c，出貨 seam 走 center=False 逐 hop 一幀，見下方 「C pre/post 類別」；Python reference StreamSTFT/StreamISTFT）， 以及 layout v5 起的固定前後端（C 實作封在 ulcnet_model_io.c 的 prepare/commit；Python reference export_onnx.stream_features/host_output）： _signed_power（signed pow(0.3) 壓縮）、兩路 magnitude、 atan2/cos/sin（壓縮域相位——對 0.3 次方後分量取角，板端不可用原始相位替代）， graph 綁五個特徵輸入 error_mag/far_mag/error_cos/error_sin（各 [1,1,K]）＋壓縮域 error_ri（[1,1,K,2]）， 各自持量化 scale；graph 輸出為壓縮域 estimate，host 做逆冪還原。以上是 出貨的 host/split 這一對；另外三對見下節。

far branch 契約：checkpoint contract 的 far_input_mode 只記錄訓練 provenance（legacy 預設 raw_far）。production 固定用 AEC aligned-far seam；未取得 alignment 時 seam 暫時承載 raw far，模型仍執行，取得後切成 aligned far 並 reset recurrent state。export_onnx.py 因此分開寫 training_far_input_mode 與部署用 far_input_mode=aligned_far；C descriptor 只接受 ALIGNED，production pipeline 沒有 runtime far-mode setter，raw/aligned 比較只留在 sweep 工具。
PTQ calibration：可直接用訓練域的 linear_error + raw_far； report 會把 calibration_far_input_mode=raw_far 與 deployment_far_input_mode=aligned_far 分開記錄。D 不改權重，但會改 K/V history shape 與 host RAM，所以 calibration 的 D 必須和該份 ONNX export 相同。
既有匯出必須全部重跑：model-I/O layout 現為 v8 （v3 = far branch RAW → ALIGNED；v4 = tensor 更名；v5 = 固定前後端搬到 host；v8 = 兩顆 GRU hidden 由 rank-3 改為 rank-4 NCHW，與三個 attention cache 同一慣例；RETIRED_LAYOUT_VERSIONS = 3–7，不得重用），此前產出的每一份 ONNX/JSON descriptor 會在 ulcnet_model_io_descriptor_validate() 卡在 layout_version（v3 之前另卡 far_input_mode）， ulcnet_accelerator_adapter_init() 回 NULL。修法只有「重新 export graph」一項： 權重未變，checkpoint 與 dataset 不需要重新訓練或重新生成。 9/10/11 被另外三對 boundary 佔用，下一次真正 bump ULCNET_MODEL_IO_LAYOUT_VERSION 要跳到 12。

ONNX graph boundary：兩軸開關

boundary 是一對互相獨立的開關，version 屬於這一對、不屬於任何一半， 表在 export_onnx.py 的 LAYOUT_VERSIONS。 inference.py calib 收同樣兩個旗標，且在同一個 process 用同一個 model instance 匯出對應 graph，不必為了換 layout 匯出兩次。

--feature-layout＝固定前後端跑在哪裡。host 把 signed pow(0.3) 壓縮、兩路 magnitude、壓縮域相位 cos/sin 留在 graph 外 （stream_features；C ulcnet_model_io_prepare），回程逆冪也在外 （host_output；C ulcnet_model_io_commit）。graph 改綁兩個 raw RI 頻譜、把同一份固定數學搬回 graph 內；除了 recurrent state 的 rank 之外它重現了前後端搬到 host 之前的 boundary，所以自帶版本號而不是沿用已退役的舊號。

差別在量化不在算術：host 讓五個特徵各持自己的 scale，且 sqrt/atan2/pow 這些非學習運算不進量化域；graph 少綁 tensor、 host 端不需要前端，代價是那些運算進了量化域，且 error_cos/error_sin 共用編譯器替它們推出來的同一個 scale。實測 graph 多出的非學習運算為 Sign/Abs/Pow 各 6、Sqrt×2、Atan/Cos/Sin 各 1（加上隨之 增加的 elementwise 與索引節點）；經 onnxoptimizer + 常數摺疊後節點數 121 → 177。

--gru-state-layout＝兩顆 subband GRU hidden 怎麼呈現。split 出 h_gru0/h_gru1，各 (1, GRU_LAYERS, 1, GRU_HIDDEN)； combined 沿 dim 1（dim 0 是 singleton N）把 h_gru0 排在前疊成單一 h_gru (1, 2*GRU_LAYERS, 1, GRU_HIDDEN)，輸出也併成一個 h_gru_out。 三個 attention cache（key_history/value_history/logit_history） 在兩種 layout 都獨立：它們是結構性歷史而非 recurrent hidden state，也不與 hidden 共用分布。 combined 存在就是為了量「共用一個量化 scale 要付多少代價」。

python3 AIAEC/Align_ULCNet/export_onnx.py --checkpoint ckpt.pth \
    --max-delay-frames 8 --feature-layout graph --gru-state-layout combined \
    --output output/align_ulcnet_d8_graph_combined.onnx --verify
四對 boundary 逐幀互跑位元相同（rtol=0, atol=0；test test_every_layout_pair_computes_the_same_frames）。C 端只綁 host/split，板端拿到另外三對會被 layout_version 擋掉。 換 layout 屬合約變更不是旗標切換：ulcnet_model_io.h、其 prepare/commit API 與 graph I/O 表要一起搬。

API 用法

from AIAEC.Align_ULCNet.inference import load_model
from AIAEC.aiaec_streaming import StreamSTFT, StreamISTFT

model, grid, linear_contract = load_model("ckpt.pth", "cpu")  # max_delay_frames=8 可覆寫 D
state = model.create_stream_state()          # {"align", "subband_gru0", "subband_gru1"}
H = grid.hop_len                                          # 16k: 256、48k: 512
stft_err = StreamSTFT(grid.n_fft, H, window)              # window = sqrt-Hann n_fft
stft_far = StreamSTFT(grid.n_fft, H, window)
istft    = StreamISTFT(grid.n_fft, H, window)
for s in range(0, n, H):
    for e, f in zip(stft_err.push(err[:, s:s+H]), stft_far.push(far[:, s:s+H])):
        out = model.forward_stream(linear_error=e.unsqueeze(1),
                                   far_end=f.unsqueeze(1), state=state)
        samples = istft.push(out.enhanced[:, 0])          # 穩態每幀 H samples
python3 AIAEC/Align_ULCNet/inference.py checkpoint.pth mic.wav far.wav out.wav \
    [--verify] [--input-is-linear-error] [--max-delay-frames N] [--device cpu]

inference.py 只有一條路徑：逐幀 forward_stream 排程（實作在 _streaming.py，entry 不會退回整段 model(...)——test test_inference_entry_uses_streaming_schedule）。D 覆寫 （--max-delay-frames）：checkpoint contract 記的是訓練時的 D；權重 D-agnostic （D=64 checkpoint 可 strict-load 進 D=8），但輸出跨 D 不數值相同（fixture 實測 enhanced max-abs 差 8.9e-6）。部署閘不是 checkpoint contract 而是 graph descriptor：板端比對 ONNX metadata／calibration report／C UlcnetModelIoDescriptor 三方的 D 與 state_layout_version，訓練 D 與部署 D 不同不構成拒絕理由。

C pre/post 類別（ulcnet_prepost.c/h）

板端整合點：一個物件包住 caller 音訊與加速器張量之間的一切（framing、壓縮域前端、 recurrent ring）。它組合 ulcnet_process.c ＋ ulcnet_model_io.c， 兩個被組合的檔都沒有改。生命週期、32-byte MemReq 陳舊 pool 閘、交易式 frame 狀態機與「為何是第三個 TU」是三個模型共用的形狀，寫在 onnx_prepost；以下只記 Align-ULCNet 自己的部分。

UlcnetPrepostConfig cfg;  UlcnetPrepostMemReq req;
ulcnet_prepost_config_defaults(&cfg, ULCNET_IO_TIME, /*D=*/8);
cfg.fft = fft;  cfg.window = window;      /* caller-owned 借用；本類別不建也不毀 */
ulcnet_prepost_get_mem_size(&cfg, &req);
UlcnetPrepost *p = ulcnet_prepost_init_ex(pool, req.bytes, &cfg, &req);  /* 或 _init / _create */
每 hop：
  ulcnet_prepost_pre_process(p, err_hop, far_hop);   /* 恆回 1；_pre_process_freq 為頻域孿生 */
  ulcnet_prepost_frame_inputs(p, &in, &out);         /* pool 內的 view；out 全 NaN 預填 */
  my_npu_run(&in, &out);
  ulcnet_prepost_frame_commit(p);                    /* 失敗改呼叫 ulcnet_prepost_frame_skip(p) */
  ulcnet_prepost_post_process(p, out_hop, &written); /* _post_process_freq 為頻域孿生 */
其餘：_reset / _destroy / _hop_size / _num_bins / _io_mode / _descriptor

一 hop 進、一次推論、一 hop 出——從 hop #0 起、兩種模式都成立，呼叫端沒有可變幀數要迴圈。 io_mode 在 init 固定（它決定 pool 大小）：ULCNET_IO_TIME hop 進 hop 出， framing／加窗／overlap-add 由類別做、但呼叫的是 caller 的 FftHandle 與 window 表； ULCNET_IO_FREQ 頻譜進頻譜出、不做任何 transform，fft/window 可為 NULL，這是串接（AEC/GSC seam）用的模式。frame_commit 驗證失敗時 什麼都不動、幀維持開啟；frame_skip 在本模型 = identity——error 頻譜 原樣通過、recurrent state 不推進、framing 排程照常前進（stream 0 是 linear-AEC error 而不是原始 mic，所以放行是安全的；DeepVQE-S 同一個位置必須 mute）。

rolling 分析 ulcnet_analysis_push_frame()（ulcnet_process.h； aiaec_process.h 有同語意的 aiaec_analysis_push_frame()）：center=False， 第一次 push 起每次恰一幀（首幀前半段是歸零的歷史），與 centered ulcnet_analysis_push() 對同一個 hop 吐出的最後一幀位元相同——這個幾何下 （win = n_fft、hop = n_fft/2、共用同一張 sqrt-Hann 表）centered 第 k 幀與 non-centered 第 k−1 幀 蓋的是同一段樣本、同一個窗，centered 排程只是在開頭多發一幀 reflect 前綴。 test_ulcnet_prepost_c.py 的 equiv 案例逐 hop memcmp 釘住這件事 （400 hop，真的跑 0/2/1 排程），所以是實測；hop 0 的 centered 排程 0 幀，兩者自第二個 hop 起對得起來。同一個 state 上不可混用兩個 push 函式（共用歷史、不共用排程）。 centered push 仍在 ulcnet_process.c：mono ULCNet wrapper （pipelines/mono_alignulcnet/audio_pipeline_ulcnet.c）與 Python parity gate （test_ulcnet_process_c.py）都還走它。

adapter 改為驅動類別：ulcnet_accelerator_adapter.c 不再自己接 per-frame transaction，而是開一個 ULCNET_IO_FREQ 實例（不 carve framing state、完全不牽涉 FftHandle/window，framing 時鐘歸呼叫端）；adapter pool = 類別 FREQ pool + 32 B header。 Build：make -C AIAEC lib 產出 libaiaec_prepost.a，放在依組態 編碼的 build/simd<N>-<sig>/（sig = CC/AR/CFLAGS/CPPFLAGS/SIMD/WERROR 的 cksum）；make -C AIAEC print-lib-path 印出該組態封存檔的絕對路徑， make -C AIAEC test = 建庫 + pytest。

PBFDKF / delay 對齊—AEC C 端 static pool

Python reference 把全部 state 存在 create_stream_state() 回傳的 host dict； D 只進 ring/score 史的形狀，不進權重形狀。上表 h_gru0/h_gru1 是出貨的 split layout，combined 只是在 boundary 上併成單一 h_gru (1, 4, 1, 128)（總量與 host RAM 不變，三個 attention cache 仍獨立，C 端不綁）。

延遲與 warm-up

  • NN 演算法 lookahead = 0 hop；zero-init history ≡ offline 左零 padding， 從 reset 開始的 stream 與 whole-utterance forward 等價，無 warm-up 特例。 實測 stream-vs-offline 最差差異：enhanced 4.1e-8 / mask 1.2e-7 / magnitude_mask 6.0e-8 / delay 4.0e-7（test 檔頭記載；tolerances 以 ~10x headroom 釘在 5e-7 / 2e-6 / 1e-6 / 5e-6）。
  • Framing：類別與 AEC/GSC seam 用 center=False、每 hop 一幀的 rolling 分析（centered push 仍供 mono wrapper 與 Python parity gate 使用，兩者自第二個 hop 起位元相同）。端到端演算法 延遲仍是 HOP samples＝16 kHz 256 smp（16 ms）、48 kHz 512 smp（10.67 ms），但它來自 synthesis 的半窗 trim、不是分析排程（ulcnet_prepost.h 明文）。
  • C 前後處理 vs Python：float-ULP 級（實測 ~2e-5 絕對值，KISS f32 FFT vs torch double twiddles），非 bit-exact（test_ulcnet_process_c.py 檔頭）。
