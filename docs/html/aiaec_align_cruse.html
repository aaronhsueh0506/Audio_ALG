Align-CRUSE（end-to-end AEC+RES+NR，selected）

概要

Indenbom et al.（arXiv:2208.11308）的 cross-attention 對齊 CRUSE 重建。task （dataset_gen/model_views.py）= end_to_end_aec_res_nr_dereverb： 輸入是未對齊的 microphone 與 far-end 複數頻譜（mic_postclip / far_render，前面沒有任何 matched filter 或 linear AEC）；target 是 near_target。輸出為 real magnitude mask 乘在 mic 頻譜上（保留 mic 相位）。 本候選早期的 AEC-only 路線已裁撤併入此共同 task。

16k grid 下 max_delay_frames = 63（delay_frames(1.0)=ceil(62.5)）。 參數量實測 710,513 trainable（論文 ~0.75 M class）。stream_output_delay = 0。 alignment 有兩個 mode：部署預設 causal_running（逐幀 D[B,T,63]， 只用過去證據）；paper_global（整段一個 D[B,63]）為整段非因果， create_stream_state() 直接 ValueError 拒絕串流。

ONNX / NPU graph boundary（由 AIAEC/Align_CRUSE/export_onnx.py 匯出）： graph 內 = log_power_feature（square+clamp+log）、causal conv + BatchNorm + ELU（mic1..mic4 / far1..far2）、alignment 的 MaxPool(1,4) + Linear query/key + softmax（作用在 cumsum 積分 score 上）、 GRU(192)、頻率 stride-2 的 ConvTranspose2d(1,3) 解碼、sigmoid mask 與 mask_gain clamp。graph 外（C 前後處理）= centered sqrt-Hann STFT/ISTFT 與 complex↔RI（Python reference StreamSTFT/StreamISTFT）。 所有 recurrent state（conv 史、K/V ring、score 積分、GRU h、幀計數）為顯式 state， 由 runtime 逐次傳入傳回。

產品風險（readiness §3.2）：causal_running 的 delay score 是無衰減 cumsum 積分器（無限記憶）——長通話下 delay 分佈會凍結、追不上 echo path 變化；streaming 化本身可行，但長時行為需上板前決策。

API 用法

from AIAEC.Align_CRUSE.inference import load_model
from AIAEC.aiaec_streaming import StreamSTFT, StreamISTFT

model, grid = load_model("ckpt.pth", "cpu")
state = model.create_stream_state()   # mic1..4 / far1..2 / align / gru
mic_stft = StreamSTFT(grid.n_fft, grid.hop_len, window)  # sqrt-Hann 512
far_stft = StreamSTFT(grid.n_fft, grid.hop_len, window)
synth    = StreamISTFT(grid.n_fft, grid.hop_len, window)
for s in range(0, n, grid.hop_len):
    for m, f in zip(mic_stft.push(mic[:, s:s+256]), far_stft.push(far[:, s:s+256])):
        out = model.forward_stream(m.unsqueeze(1), f.unsqueeze(1), state)
        samples = synth.push(out.enhanced[:, 0])

延遲與 warm-up

  • NN 演算法 lookahead = 0 hop；framing 半窗 256 samples（16 ms）。
  • T ≥ D caveat（forward_stream docstring 明文）：offline 用最終 utterance 長度 T 做 arange(D) < T 的 observable mask，stream 無法預知 T，因此假設 T ≥ D。utterance ≥ 63 hops（1 s @16k）時每一幀（含前 63 幀）精確等價：實測 T=90 全幀 stream-vs-offline enhanced 4.9e-7 / mask 1.8e-7 / delay 3.3e-7（ATOL 釘 5e-6）。 整段 < 63 幀的短檔刻意發散：專屬測試 T=30 差 > 1e-3 （test_short_utterance_below_delay_window_differs；readiness 實測 1.18e-2）。
  • paper_global checkpoint 不可串流，必須以 causal_running 重訓。
  • startup 前 D 幀的 softmax 含未觀測（score=0）delay 候選——這是 offline 訓練語意 本身，非 streaming 造成（readiness §3.2）。
