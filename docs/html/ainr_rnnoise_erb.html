AINR RNNoise-ERB (16 kHz ERB band-gain 模型)

概要

RNNoise v0.2 方向(Conv+GRU)的輕量 16 kHz 降噪模型:網路輸出 22 個實數 ERB band gain(sigmoid ∈ [0,1]),由 C 端經 partition-of-unity 反向三角矩陣展開為 257 個 bin gain 後套在頻譜上。出貨設定為純 ERB (use_complex_input=false):complex 分支程式仍在,但網路不建、也不吃 spec_input 的內容(ONNX 簽名仍保留該輸入以固定合約)。

項目值(以現行程式碼為準)
取樣率 / grid16000 Hz;FFT/win/hop = 512/512/256(RNNOISE_N_FFT/RNNOISE_HOP_LEN)
頻譜 bins / ERB 帶257 / 22(RNNOISE_N_BANDS,每帶 ≥ 2 bins greedy-forward 保證)
模型容量cond_size=64、gru_size=128、3 層 GRU;參數 321,110(以出貨 config 實際建構量測)
Lookaheadlookahead_frames=1:conv 3-tap 窗 [t−2,t−1,t] 的 gain 屬於 spectrum t−1(RNNOISE_CONV_DELAY=1)
feature versionlog_erb_dfn_mean_cplx_unit_0_4k_v8(v8 = 以本專案 16 k 語料校準 EMA init)
正規化 EMAtau = 1.0 s → α = 0.984;ERB init −20/−45 dB、spec init 0.04/0.008、eps 1e-12

公式推導、v4–v8 演進與純 ERB 的表達力限制見 README.md;此頁不重複。

API 用法

注意:rnnoise_analysis() 吃的是完整 WIN_LEN=512 窗 (呼叫端自己維護 256-hop 滑動窗,與 DFN/GTCRN 的「只給新樣本」不同); 且 lookahead=1 之下,呼叫端必須把 spectrum 延遲一框再套 gain。

#include "RNNoise-ERB/process.h"

RNNoiseState st;                    /* 15,328 bytes, 呼叫端配置 */
rnnoise_state_init(&st);            /* 表格為編譯期常數, 無執行期初始化 */

float win[512];                     /* 呼叫端滑動窗 (每 hop 移入 256 新樣本) */
float prev_re[257], prev_im[257];   /* 呼叫端: 延遲一框的 spectrum */
for (each hop of 256 new samples) {
    rnnoise_analysis(&st, win, spec_re, spec_im);
    int ready = rnnoise_compute_features(&st, spec_re, spec_im,
                                         erb3 /*[3][22]*/,
                                         spec3 /*[3][2][129]*/);
    if (ready) {                    /* 已累積 3 框 (oldest -> newest) */
        /* 模型: (erb3, spec3, h1,h2,h3) -> band_gains[22], h1..h3 更新 */
        run_model(erb3, spec3, h, band_gains);
        rnnoise_apply_atten_lim(band_gains, atten_lim_db); /* 可選, <=0 = no-op */
        rnnoise_expand_gains(band_gains, bin_gains /*[257]*/);
        /* gain 屬於 t-1: 套在延遲一框的 prev_re/prev_im 上 */
        rnnoise_synthesis(&st, prev_re, prev_im, bin_gains, out256);
    }
    save prev_re/prev_im = spec_re/spec_im;   /* 1-hop spectrum 延遲 */
}

Python 離線:denoise.py --config config.ini --model output/rnnoise_best.pth --input in.wav --output out.wav (offline 以 F.pad(pad_left=2−LOOKAHEAD, pad_right=LOOKAHEAD) 一次過整段)。 ONNX 匯出:python export_onnx.py --config config.ini --model output/rnnoise_best.pth --output rnnoise.onnx。

延遲與 warm-up

  • 演算法延遲 = 1 hop = 256 samples = 16 ms(lookahead_frames=1: 3-tap conv 窗置中,gain 對應中間框 t−1;RNNOISE_CONV_DELAY = 2 − LOOKAHEAD = 1)。
  • WOLA 重疊結構延遲:win−hop = 256 samples = 16 ms。
  • Warm-up:rnnoise_compute_features() 前 2 框回 0(3-frame conv 窗未滿), 此期間無模型輸出、無音訊輸出。
  • EMA 正規化 warm-up:tau = 1.0 s(α=0.984,3·tau ≈ 187.5 框);v8 的 init 校準 (−20/−45 dB、0.04/0.008,量測自本專案 16 k 語料)把 3 秒片段殘留 init 成分壓到 ~4.9% (config.ini [feature] 有完整紀錄)。
  • C 特徵測試實證:stationary 輸入下 ERB mean 特徵收斂到 0、complex 特徵在 4096 框後 仍可觀測(test_rnnoise_features PASS 訊息原文)。
