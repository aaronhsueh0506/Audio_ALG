Audio_ALG

模型開發與部署

PCM SDK（stream/）負責窗函數、STFT／ISTFT 與每包的呼叫流程（選圖、StreamWork、輸入範圍檢查、N 個 frame 的迴圈），每包交給呼叫端執行加速器。模型的前後處理本身在 lib/ainr/、lib/aiaec/：DFN2、DeepVQE-S、Align-ULCNet 是逐 frame 函式加模型 state（pre_frame／views／validate_run／post_frame／zero_state），呼叫流程由各自的 stream 負責；DFN3、GTCRN、RNNoise-ERB 沒有 stream 層，沿用 pre_process／frame_open／frame_finish 一類。已經拿到頻譜的應用，可直接用 lib 內的 model core。

AINR

模型C 入口訊號
DeepFilterNet2ainr.h（PCM、PCM → 頻譜、頻譜 → 頻譜）、頻域 coreint16 語音 → 增強 PCM；客戶只設 sr、fft、hop_in，full 或 lite 由產品綁定。
DeepFilterNet3頻域 core原始低頻深濾波與高頻 ERB mask，在同一頻譜輸出。
GTCRN頻域 core單路複數頻譜 → ERB 特徵 → 複數 mask。
RNNoise-ERB頻域 core單路頻譜 → 三幀特徵窗 → ERB gains，對齊延遲頻譜。

AIAEC

模型C 入口訊號
Align-ULCNetaiaec.h（PCM、頻譜 → 頻譜）、頻域 core線性 AEC 的 float 殘差、原始 far 與對齊事件 → 增強 PCM；16 kHz／256／N=1 與 16 kHz／512／N=1 有登錄的 graph。
DeepVQE-Saiaec.h（PCM、頻譜 → 頻譜）、頻域 core原始 mic 和 far PCM → 複數濾波 → 增強 PCM；16 kHz／256／N=1 與 16 kHz／512／N=1 有登錄的 graph。
CAGCRN無（沒有 C 程式碼）原始 mic 和 far。只有 Python 串流與 ONNX 匯出。
Align-CRUSE無（沒有 C 程式碼）原始 mic 和 far。只有 Python 串流與 ONNX 匯出。

ONNX 張量邊界、state、匯出與 PTQ calibration

DFN2、DeepVQE-S、Align-ULCNet 的客戶介面（stream/ainr/ainr.h、stream/aiaec/aiaec.h）以主機和替身加速器驗證，各模型首頁列出組態與驗證狀態。沒有交付 graph 的組態在 init 被拒絕。目標板上的真實 graph、量化、cache／DMA 與每 hop 耗時，需在部署時另外核對。

三個模型的 init 都回 0 或負的錯誤碼，並填一份精簡的 info：圖路徑，DFN2 另有延遲欄位 queue_frames（DeepVQE-S 與 Align-ULCNet 只回圖路徑）。stream 函式庫不描述圖的埠：客戶只設 sr、fft、hop_in，N = hop_in / (fft / 2) 由 sample 從 config 算；每個已交付 graph 的訊號、head 與 state 的 shape 放在各函式庫旁的模型設定（stream/ainr/graph_io_dfn2.h、stream/aiaec/graph_io_deepvqes.h、stream/aiaec/graph_io_alignulcnet.h，只有標頭，ainr.h／aiaec.h 不引用），共用的接線程式是 stream/common/graph_io.h。圖的埠順序是同一條規則：輸入為訊號再接 state、輸出為 head 再接 state，所以 sample 依位置綁埠並以 SDK 無關的檢查器 stream_check_ports()（stream/common）檢查，細節見板端整合。

客戶標頭與 include 路徑

三個模型的產品路徑（ainr.h／aiaec.h）用下列本庫標頭。直接用頻域 core 的應用另外 include 各模型首頁所列的 lib/ainr/、lib/aiaec/ 標頭。

標頭用途
stream/ainr/ainr.hDFN2 產品介面
stream/ainr/bridge/ainr_bridge.h8／16 kHz host 經取樣率 bridge 接 48 kHz 模型
stream/aiaec/aiaec.hDeepVQE-S 與 Align-ULCNet 產品介面
stream/aiaec/front/aiaec_front.h沒有自己 AEC 的 Align-ULCNet 獨立 sample
stream/common/graph_io.h 與 stream/ainr/graph_io_dfn2.h、stream/aiaec/graph_io_deepvqes.h、stream/aiaec/graph_io_alignulcnet.hgraph 接線表與埠檢查（只有標頭）
stream/common/stream_bind.h埠綁定；sample 另編譯 stream/common/stream_bind.c
stream/common/stream_run.hStreamWork（區塊的 tensor、action 與 state generation）與 run status（STREAM_RUN_OK／NOT_STARTED／FAILED）；ainr.h／aiaec.h 會引用它，只有標頭、與 SDK 無關
stream/common/stream_mem.hStreamMemReq（ainr.h／aiaec.h 已引用）與 stream_saturate_s16()

include 路徑：所用標頭各自的目錄、stream/common、audiolib 的 common/（stream_mem.h 引用 utility/mem_align.h）；用 ainr_bridge.h 時再加 audiolib 的 common/include（fft_wrapper.h）。例：cc app.c -Istream/aiaec -Istream/common -I$AUDIOLIB/common …，完整建置指令見各模型首頁。make -C stream/common check-public-headers（包含在 make -C stream/common test）只用這些 include 路徑，把整組標頭當成一個 C99（-Wpedantic -Werror）與 C++11 的編譯單元編譯（DFN2 full 與 lite 各一次），並確認每個宣告的函式都是 C linkage（沒有被 mangle）。
