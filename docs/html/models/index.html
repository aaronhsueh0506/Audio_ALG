Audio_ALG

模型開發與部署

PCM SDK 負責窗函數、STFT／ISTFT 及模型前後處理，每 hop 交給呼叫端執行加速器。已經拿到頻譜的應用，可直接用 lib/ainr/ 或 lib/aiaec/ 內的 model core。

AINR

模型C 入口訊號
DeepFilterNet2ainr.h（PCM、PCM → 頻譜、頻譜 → 頻譜）、頻域 coreint16 語音 → 增強 PCM；客戶只設 sr、fft、hop_in，full 或 lite 由產品綁定。
DeepFilterNet3頻域 core原始低頻深濾波與高頻 ERB mask，在同一頻譜輸出。
GTCRN頻域 core單路複數頻譜 → ERB 特徵 → 複數 mask。
RNNoise-ERB頻域 core單路頻譜 → 三幀特徵窗 → ERB gains，對齊延遲頻譜。

AIAEC

模型C 入口訊號
Align-ULCNetaiaec.h（PCM、PCM → 頻譜、頻譜 → 頻譜）、頻域 core線性 AEC 的 float 殘差、原始 far 與對齊事件 → 增強 PCM；目前沒有交付的 graph。
DeepVQE-Saiaec.h（PCM、PCM → 頻譜、頻譜 → 頻譜）、頻域 core原始 mic 和 far PCM → 複數濾波 → 增強 PCM；只有 16 kHz／512／N=1 有登錄的 graph。
CAGCRNmask 合成 helper原始 mic 和 far。Python 串流與匯出，C 提供複數 mask 合成。
Align-CRUSEmask 合成 helper原始 mic 和 far。Python 串流與匯出，C 提供實數 mask 合成。

ONNX 張量邊界、state、匯出與 PTQ calibration

DFN2、DeepVQE-S、Align-ULCNet 的客戶介面（stream/ainr/ainr.h、stream/aiaec/aiaec.h）以主機和替身加速器驗證，各模型首頁列出組態與驗證狀態。沒有交付 graph 的組態在 init 被拒絕。目標板上的真實 graph、量化、cache／DMA 與每 hop 耗時，需在部署時另外核對。

三個模型的 init 都回 0 或負的錯誤碼，並填一份精簡的 info：圖路徑、trim_samples、queue_frames、tail_zero_blocks。stream 函式庫不描述圖的埠：客戶只設 sr、fft、hop_in，N = hop_in / (fft / 2) 由 sample 從 config 算；每個已交付 graph 的訊號、head 與 state 的 shape 放在各函式庫旁的模型設定（stream/ainr/ai3_model_io_dfn2.h、stream/aiaec/ai3_model_io_deepvqes.h、stream/aiaec/ai3_model_io_alignulcnet.h，只有標頭，ainr.h／aiaec.h 不引用），共用的接線程式是 stream/common/ai3_model_io.h。圖的埠順序是同一條規則：輸入為訊號再接 state、輸出為 head 再接 state，所以 sample 依位置綁埠並以 SDK 無關的檢查器 stream_check_ports()（stream/common）檢查，細節見板端整合。
