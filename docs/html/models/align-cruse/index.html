Align-CRUSE

概要

Align-CRUSE 是端到端 AEC+RES+NR：輸入是未對齊的 mic 與 far 複數頻譜（前面沒有 linear AEC），輸出是 real magnitude mask，乘在 mic 頻譜上（保留 mic 相位）。目前沒有對應的 C pre/post 類別（ONNX 邊界與 calibration 的缺口表有一列）：可執行、有測試的呼叫路徑是 Python 參考實作與 ONNX 匯出／校正工具；C 端現有的零件只有 audiolib 的 AcStft／AcIstft 與 align_cruse_process.h 的 aiaec_apply_real_mask()。模型內容、I/O 表、State 表、warm-up 的 T ≥ D 限制見 Align-CRUSE 頻域與模型契約。

如何呼叫使用

A. Python 串流參考（逐 hop，已測試）

  1. load_model(checkpoint, device) 回 (model, grid)：grid、alignment 設定全由 checkpoint 內的 contract 還原，不讀 config.ini，所以推論不會悄悄偏離訓練設定。
  2. model.create_stream_state()：新的一段串流＝新的全零 state（alignment_mode="paper_global" 的 checkpoint 會直接 ValueError，因為整段非因果）。
  3. 每個 hop 把 mic／far 各推入 StreamSTFT，對每個吐出的框呼叫 forward_stream(microphone, far_end, state)，把 res.enhanced[:, 0] 推入 StreamISTFT。第一個 hop 的 STFT 不吐框、ISTFT 輸出 0 個樣本（centered 排程的 reflect 前綴）。
import soundfile as sf
import torch
from AIAEC.Align_CRUSE.inference import load_model
from AIAEC.aiaec_streaming import StreamSTFT, StreamISTFT

model, grid = load_model("checkpoint.pth", "cpu")   # grid/D 全部取自 checkpoint contract
state = model.create_stream_state()                 # 新的一段串流 = 新的全零 state
window = grid.window(device="cpu")                  # sqrt-Hann, 長度 n_fft
H = grid.hop_len                                    # 16 kHz: 256
mic_stft = StreamSTFT(grid.n_fft, H, window)
far_stft = StreamSTFT(grid.n_fft, H, window)
synth = StreamISTFT(grid.n_fft, H, window)

mic, sr = sf.read("mic.wav", dtype="float32")       # 單聲道, 取樣率須等於 checkpoint 的 sr
far, _ = sf.read("far.wav", dtype="float32")
mic, far = torch.from_numpy(mic)[None], torch.from_numpy(far)[None]

pieces = []
with torch.no_grad():
    for s in range(0, mic.shape[1] - H + 1, H):
        for m, f in zip(mic_stft.push(mic[:, s:s + H]), far_stft.push(far[:, s:s + H])):
            res = model.forward_stream(m.unsqueeze(1), f.unsqueeze(1), state)
            pieces.append(synth.push(res.enhanced[:, 0]))   # 輸出頭一個 hop 為 0 個樣本
sf.write("out.wav", torch.cat(pieces, dim=1)[0].numpy(), sr)

片語已用隨機權重的模型代入 load_model 實際跑過（1 秒、16 kHz 輸入得到 15,616 個輸出樣本＝少第一個 hop）。命令列等價形式：python3 AIAEC/Align_CRUSE/inference.py checkpoint.pth mic.wav far.wav out.wav [--device cpu] [--verify]，或目錄模式 --mic-dir D [--ref-dir D2] --out-dir D3（沒給 --ref-dir 則 reference 為靜音，等同純降噪）；輸出沿用輸入樹，*_mic.wav 寫成 *_ours.wav。取樣率不同的 WAV 會先重取樣到 checkpoint 的 rate；兩路必須描述同一條時間軸。--verify 只列印差異、不改變結束碼。

B. 匯出與 PTQ 校正（給目標平台工具鏈）

python3 AIAEC/Align_CRUSE/export_onnx.py --checkpoint checkpoint.pth \
    --output output/align_cruse.onnx [--max-delay-frames D] [--opset 17] --verify
python3 AIAEC/Align_CRUSE/inference.py calib --checkpoint checkpoint.pth \
    --primary-dir /path/to/microphone --far-dir /path/to/far \
    --frames 8192 --format bin --output calib/align_cruse

校正需要一條不中斷的錄音（拼接短檔會讓 score_sum 在每個接縫歸零）；state_align_score_sum 是 float32_no_ptq、state_align_frame_index 是 int64_no_ptq，不可整數量化。

C. 部署契約（以現有零件組成；沒有對應的 C 類別與測試）

  1. graph 輸入：mic、far（各 [1,1,257,2]，未正規化 RI 頻譜）加 11 個 state；輸出：output（[1,1,257] mask）與 11 個 *_out，每個與同名輸入同 shape，由 runtime 綁在同一個位址。
  2. host 前端：應用端以 audiolib 建立的 AcStft（sqrt-Hann，512/512/256）把 mic 與 far 轉成頻譜，排成 [bin][re,im] 餵圖；圖內自己做 log-power，C 端不做壓縮。
  3. host 後端：aiaec_apply_real_mask(mic_re, mic_im, mask, out_re, out_im, n_bins)，再經 AcIstft 合成。
  4. 匯出 metadata 沒有 state_layout_version 與 c_descriptor（缺席就是「C 端沒有綁定這個模型」）；state_binding 為 in_place_same_address。
