Audio_ALG / 模型開發與部署

DeepFilterNet2

單路 int16 PCM 進、同樣長度的 PCM 出。客戶只設三個值：sr、fft、hop_in。一個產品只含一種 DFN2（full 或 lite）；stream 由這三個值決定模型 hop（fft / 2）、每包張數 N（hop_in / 模型 hop）與要開的 graph。介面在 stream/ainr/ainr.h。開圖、送張量、執行與讀回是板端 sample 自己的程式，見板端整合。

stream 只選圖並做 host 端的前後處理，不描述圖的埠。圖的埠順序只有一條規則，埠表在 stream/ainr/ai3_model_io_dfn2.h，sample 依位置綁埠、不比對名稱（見下方「Graph 接線」）。

full16000 / 2561024（N=8）AINR_OK10241

lite 只有 48 kHz／1024／N=1，沒有 16 kHz，也沒有 N>1。full 與 lite 的 archive 分開建置，不可混連。「可啟動」只表示登錄表有這一列；graph 的實際交付狀態見「驗證狀態」。

Graph 接線

ainr_init() 只回報選出的圖（AinrInfo.graph_path）與尾端長度，不回報埠表，函式庫也沒有任何只為 graph 接線存在的 state 尺寸常數。每個已交付 graph 的完整接線——訊號與 head 的數量及 shape、state 的 shape——放在 stream/ainr/ai3_model_io_dfn2.h：full 與 lite 共用一份，依 -DDFN2_MASK_ONLY 選產品，每個登錄的 (產品, sr, fft, N) 一列，列旁註明所對應的匯出器。共用的接線程式 stream/common/ai3_model_io.h（由 make -C stream/common test-model-io 測試）把一列展開成 StreamWiring，並做 state 配對、開圖後的埠檢查、input buffer 大小與送件前的核對（見「初始化與每包呼叫」）。兩者都與 SDK 無關、只有標頭，ainr.h 不引用，函式庫不含接線；sample 加 -I stream/common -I stream/ainr 並編譯 stream/common/stream_bind.c。沒有對應列的組態，或與 init 選出的 graph 不符，由 sample 的啟動檢查在任何 SDK 呼叫之前拒絕。

所有轉出的圖都照同一條規則排埠：輸入 = 訊號輸入，再接 state 輸入；輸出 = head 輸出，再接 state 輸出。第 k 組 state 是輸入 signal_in_count + k 與輸出 head_out_count + k，兩端形狀相同。sample 依數量迴圈處理，full 與 lite 用同一段程式。訊息以位置稱呼埠，例如 input 3 (state 0)。

初始化與每包呼叫

啟動做一次，之後每包三步：ainr_preprocess()、板端 sample 自己的 AI3 執行、ainr_postprocess()。每次成功的 pre 都對應一次加速器執行與一次 post，沒有「這拍不推論」的分支。

/* 啟動（一次） */
AinrConfig cfg = { sr, fft, hop_in };              /* 例：{ 48000, 1024, 512 } */
int n = cfg.hop_in / (cfg.fft / 2);                /* N；整除與支援範圍由 ainr_init() 檢查 */
StreamMemReq req;
if (ainr_get_mem_size(&cfg, &req) != AINR_OK) return -1;   /* 未登錄的組態在此被拒 */
void *pool = alloc_aligned(req.alignment, req.bytes);
AinrCtx *ctx;
AinrInfo info;                                     /* graph_path、trim_samples、queue_frames、tail_zero_blocks */
int rc = ainr_init(&cfg, pool, req.bytes, &ctx, &info);   /* 0 或負的 AINR_ERR_*；尚未呼叫 SDK */
if (rc != AINR_OK) { log(ainr_status_text(rc)); return -1; }

/* sample 的模型設定：這個產品、這個 grid 與 N 的接線列；沒有列就在開圖前拒絕 */
Ai3ModelIoConfig model;
if (ai3_model_io_dfn2_find(AI3_MODEL_IO_DFN2_PRODUCT, cfg.sr, cfg.fft, n, &model) != AI3_MODEL_IO_OK) return -1;

/* 板端：開圖、逐埠描述、與模型設定比對，再把 state 同步起點設為目前的 generation */
open_graph(info.graph_path);
char msg[160];
if (ai3_model_io_check_ports(&model, din, n_in, dout, n_out, msg, sizeof msg) != STREAM_PORT_OK) return -1;
unsigned seen = ainr_state_generation(ctx);

/* 每包（剛好 hop_in 個樣本） */
while (read_block(pcm_in, hop_in)) {
    AinrWork work;
    if (ainr_preprocess(ctx, pcm_in, &work) != AINR_OK) return -1;   /* 1. 成功回 0 */
    int ai_rc = -1, chk;
    AI3_MODEL_IO_CHECK_WORK(chk, &model, &work);               /* work 的數量與 shape 必須等於這一列 */
    if (chk == AI3_MODEL_IO_OK) ai_rc = run_ai3(&work);          /* 2. 板端 sample 自己的 AI3；不符就不送件 */
    if (ainr_postprocess(ctx, ai_rc, pcm_out) != AINR_OK) return -1; /* 3. ai_rc != 0 也要呼叫 */
    write_block(pcm_out, hop_in);
}
  • 步驟 2 的 run_ai3() 把 work.inputs 依位置填進加速器、執行、把 work.outputs 讀回。state 留在加速器的 buffer，由 sample 依 work.state_generation 與失敗紀錄重載量化零，細節與範例在板端整合。
  • 送件前的核對失敗（數量或 shape 與模型設定的列不同）代表 stream 與接線資料不一致：該包不呼叫 AI3，ai_rc 填非零，照常呼叫 ainr_postprocess()。每次成功的 pre 仍恰好對應一次 post。
  • 執行或讀回失敗時，ai_rc 填非零並照常呼叫 ainr_postprocess()：當拍走近恆等直通（單位 mask、alpha 0），不是靜音，pcm_out 仍有 hop_in 個有效樣本。
  • ainr.h 沒有 destroy 函式，pool 由呼叫端釋放。介面是檔案模式：ERB 表在 ainr_init() 從產品設定的路徑載入；沒有 stdio 的板子改用較低階的 dfn2_stream.h。
  • AinrInfo 只有 graph_path、trim_samples、queue_frames、tail_zero_blocks 四欄；N 與 hop_in 不在其中，sample 由 config 算 N = hop_in / (fft / 2)。三個家族（PCM、_spec、_freq）對同一組態填出相同的內容。

延遲與檔案尾端

trim_samples 是輸出相對輸入的總延遲，以最終 PCM 的樣本數計（_spec、_freq 是外部 ISTFT 之後）：(queue_frames + 1) × 模型 hop，那個 +1 是 stream 自己的一個 STFT／OLA hop。queue_frames 是模型佇列單獨保存的 frame 數：mask_lookahead + df_lookahead + N − 1。三個家族對同一組態的值相同。下表單位：trim_samples 為樣本，queue_frames 為 frame（本庫 host 建置讀出的 AinrInfo）。

組態模型 hopqueue_framestrim_samplestail_zero_blocks
full 16 kHz／256／N=112801281
full 16 kHz／256／N=8128710241
full 48 kHz／1024／N=1512215363
lite 48 kHz／1024／N=1512110242

tail_zero_blocks = ceil(trim_samples / hop_in)。N>1 時，每包的 N 個 hop 在同一次加速器執行中算完。

輸出與輸入等長的做法（離線處理）：

  1. 最後一包不足 hop_in 時補零成完整一包，真實樣本數 total_in 另外記下。
  2. 再用同一組 pre／AI3／post 送 info.tail_zero_blocks 包全零。
  3. 輸出串流前端丟掉 info.trim_samples 個樣本，總長只留 total_in，補零與排尾包多出來的部分不輸出。

輸入為空時沒有真實樣本，不需要推任何包。

衰減上限（--atten-lim）

ainr_set_atten_lim(ctx, dB)（_spec、_freq 家族各有同名函式）設定抑制量上限，預設 0 dB（關閉）。只能在兩包之間呼叫：pre 之後、post 之前回 AINR_ERR_SEQUENCE，NaN 或 Inf 回 AINR_ERR_NONFINITE_INPUT，NULL 回 AINR_ERR_NULL。它不改 pool 大小、不改 layout、不動 state；ainr_reset() 保留設定值。N > 1 時新值從下一個完整區塊起生效。

PCM 進、頻譜出（外接 ISTFT）與頻譜進、頻譜出

已有自己的合成器時用 _spec 家族：ainr_get_mem_size_spec()、ainr_init_spec()、ainr_preprocess_spec()、ainr_postprocess_spec()。邊界、登錄表、AinrInfo 與 AinrWork 都與 PCM 家族相同，只有交換的資料不同：ainr_preprocess_spec() 收 hop_in 個 PCM 樣本，ainr_postprocess_spec() 輸出這包 N 個 hop 的增強頻譜（audio 尺度、frame-major、最舊在前；out_re、out_im 各 N * (fft / 2 + 1) 個 float），交給外部的 AcIstft（AC_OLA_ACCUMULATE、ispec_scale 為 1）。頻譜進、頻譜出用 _freq 家族（ainr_preprocess_freq() 收估計頻譜 E 與套用頻譜 P，E 與 P 同指標即單頻譜）。

_freq 的輸入檢查：ainr_preprocess_freq() 在任何一個 frame 進入模型之前，先掃整包 N 個 frame 的 E 與 P；只要有一個 bin 是 NaN 或 Inf（有限但功率會溢位的 bin 同樣算），整包以 AINR_ERR_NONFINITE_INPUT 拒絕。拒絕時特徵正規化器、frame 佇列與 state generation 都沒有動，也沒有開啟的 block：sample 不要跑加速器，也不要呼叫 ainr_postprocess_freq()（會回 AINR_ERR_SEQUENCE），該包輸出由 sample 自己補，下一包照常呼叫，仍是「一次成功的 pre 對一次 post」。模型沒看過被拒絕的那一包，仍在佇列中的 frame 會晚一包出來，直到佇列深度（AinrInfo.queue_frames）過去才回到原本的對齊。沒有這個檢查時，一個壞 bin 會讓特徵正規化器永久帶 NaN，之後每一包的 ERB／spec 視窗都是 NaN，直到 ainr_reset_freq()。uvc_audio_live2a 經 rate bridge 轉出的 E／P 走的是同一個入口，適用同一個合約。PCM 與 _spec 家族的輸入是 int16，不會有這個狀況。

檔案尾端的半個視窗

DFN2 以 AC_OLA_ACCUMULATE 合成，沒有 flush：一個 hop 的輸出是這個 frame 合成的前半加上前一個 frame 的後半。最後一段真實樣本落在「從最後一個真實 hop 開始」的分析 frame 裡，要再多一個 hop 的輸入，這個 frame 才完整。

  • stream 這邊的佇列（queue_frames）比 PCM 家族的總延遲少一個 hop，但外部合成器的 OLA 還要再一個 hop 才吐出最後一段，所以 trim_samples 與 PCM 家族相同；_spec 的 info.tail_zero_blocks 是同一個值。
  • 先把最後一包補成完整 hop_in，再用同一組 pre／AI3／post 推 tail_zero_blocks 包全零，每包的輸出頻譜都推給外部 ISTFT；輸出前端去掉上表的 trim_samples，保留輸入長度。
  • 只推 queue_frames 個全零 hop、再多給外部 ISTFT 一個零頻譜，會漏掉最後一個 hop（含最後真實樣本的那個 frame 沒被分析）。在 stream/ainr/tests/test_ainr_tail.c 的 bypass 測項中，最後一個樣本設為 16000：照上述排程時，PCM、_spec、_freq 三個家族都取回 16000（PCM 家族在 48 kHz 為 15999）；錯誤的排程在 full 16 kHz／N=1 取回 2.4，在 48 kHz 的 full 與 lite 取回 0.2。
  • 使用 AC_OLA_ACCUMULATE 時 ac_istft_flush() 回 0（只有 AC_OLA_ENV_NORM 會回資料），不能靠它補尾；改照上述排程推全零 hop（或全零頻譜）。
  • _freq：上游分析器要先吐出含最後真實樣本的 E／P frame（對它餵同樣的全零 PCM 包），之後模型佇列再用同樣數量的全零包排空。

PyTorch 與 ONNX Runtime 欄的範圍，以 AINR/tests/test_dfn2_inference_frames_per_call.py 為準：

  • 測試用隨機權重的小 checkpoint（48 kHz／1024／hop 512，與 full 的 48 kHz 產品同 grid）。一般 WAV 的 inference.py --frames-per-call 路徑在 PyTorch 上逐包串流，N=1 與 N=8 的輸出彼此一致、也與整檔一次跑一致，長度與輸入相同；mask-only（lite 的圖）同樣比對。這條路徑不經 ONNX Runtime。
  • ONNX Runtime 在這個檔案裡只執行校正流程（calib --frames-per-call 8）匯出的 N=8 full 與 mask-only 圖，逐包串流後與 PyTorch 比對。
  • 這個 N=8 圖的 grid 是 48 kHz／1024，而 stream 對 48 kHz／1024 的 N>1 回 AINR_ERR_LOOKAHEAD_BLOCK_UNSUPPORTED（-5），所以它不對應上表任何一列，不能當作 full 16 kHz／256／N=8 的證據。
  • AINR/tests 內另有兩個測試檔也有 ONNX Runtime 的串流比對，用的是 16 kHz／512 的隨機小模型，上表不引用它們。

上表的「未驗」代表本庫沒有對應的測試或實跑紀錄，不代表已知失敗。
