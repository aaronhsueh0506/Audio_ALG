用途與位置

主機（AEC、RES、波束、舒適噪聲，或只做 STFT／ISTFT 的 sample）跑在 8 或 16 kHz，模型跑在 48 kHz／1024／hop 512 的 grid 時，AinrBridge（stream/ainr/bridge/ainr_bridge.{h,c}）負責兩個格點之間的來回：主機的 estimate／apply 兩路頻譜經原生 WOLA 還原成時域、升頻到 48 kHz、做 sqrt-Hann 1024/512 分析，交給呼叫端的模型，再把模型回的 48 kHz 頻譜做 WOLA、降頻，每個主機 hop 剛好吐出一個 hop。

橋接器不內嵌模型。呼叫端在「取出 48 kHz 頻譜」與「放回」之間自己跑：模型可以是 dfn2_stream_*_freq或 ainr_*_freq，DFN3（同為 48 kHz／1024）也能接；兩支桌面 DFN2 pipeline 經 pipelines/dfn/dfn_hop.h 接的是 dfn2_stream_*_freq，板端 sample alg_ai3_aec_dfn.c（開 graph_io_dfn2.h 該列的 graph 檔，沒有 --quant8／--quant16_8）、uvc_ai_nr_stream.c、uvc_audio_live2a.c 接的是 ainr_*_freq。它放在 stream/ 而不在 lib/：橋接器本身用 audiolib 的 AcStft／AcIstft／resampler，lib/ 的模型核心不含框化（pipelines/scripts/audit_no_transform_in_models.sh 把關，它不掃 stream/）。

呼叫順序

AinrBridgeConfig cfg = ainr_bridge_default_config(host_rate, lookahead_frames);   /* 8000 或 16000 */
AinrBridgeMemReq req;
ainr_bridge_get_mem_requirements(&cfg, &req);            /* 失敗 = 取樣率、fft、lookahead 不在支援範圍 */
AinrBridge *b = ainr_bridge_init_ex(pool, req.bytes, &cfg, &req);

/* 每個主機 hop */
ainr_bridge_begin(b, E, P);                              /* 主機頻譜 → WOLA → 升頻 */
AinrBridgeFrame f;
while (ainr_bridge_model_begin(b, &f) > 0) {          /* 0..2 個 48 kHz frame */
    run_model(f.estimate_spec, f.apply_spec, f.out_spec); /* 513 bin；out_spec 開啟時全零 */
    ainr_bridge_model_end(b);                            /* out_spec → WOLA → 降頻 */
}
ainr_bridge_finish(b, out_hop);                          /* 剛好一個主機 hop */

每個 frame 都要以完整的 out_spec 回覆：橋接器不跳過、不重複 frame。模型失敗時要放回什麼（例如 apply 路頻譜的延遲 L 幀）由呼叫端的模型層決定；沒寫的 out_spec 是零。模型層拒絕一個已開的 frame（沒有東西可放回）時，呼叫端讓該 hop 輸出零，並呼叫 ainr_bridge_reset() 與模型自己的 reset：重置會清掉開著的 frame，下一個 hop 從全新狀態開始。48 kHz 頻譜用 audiolib 預設尺度（1）；需要正規化頻譜的模型（DFN2 的 dfn2_stft_scale）由呼叫端乘進去、乘出來。

契約

項目內容
主機格點8 kHz／256、16 kHz／256、16 kHz／512（hop = fft / 2），其他回 -1
模型格點48000／1024／512／513 bin，是 AINR_BRIDGE_MODEL_* 常數（FIFO 容量、排程與 prefill 校正照它寫）；改成由呼叫端傳入是之後的一步
排程16 kHz／hop 128：每 4 hop 的 frame 數 0,1,1,1；16 kHz／hop 256 與 8 kHz／hop 128：1,2
錯誤使用begin 重複、model_begin 在 frame 開著時、model_end 沒有 frame、finish 在 frame 開著或有到期未取的 frame 時都回 -1 且不改狀態；開著的 frame 無法回覆時，用 ainr_bridge_reset() 離開
重置ainr_bridge_reset() 清 resampler、FIFO、overlap-add 與 prefill（模型是呼叫端的）。ainr_bridge_reset_synthesis() 只清兩個原生格點合成物件的尾巴（AEC 硬重置事件，在該 hop 的 begin 之前呼叫；hop 進行中回 -1），added delay 不變
診斷ainr_bridge_get_counters()（48 kHz frame 總數與最近一 hop 的數量）、ainr_bridge_get_host_hops()（原生格點合成出的 E／P hop）

延遲

增加的延遲 = prefill + 升頻群延遲 + (L + 1)×512×sr/48000 + 降頻群延遲，單位是主機 sample，L = lookahead_frames（模型把 frame t − L 的頻譜交回；橋接器看不到，由呼叫端在 config 給）。ainr_bridge_added_delay_samples() 取整，ainr_bridge_added_delay_exact() 回精確的分子（分母固定為 6）。L = 2：16 kHz／hop 128 為 672、16 kHz／hop 256 為 629、8 kHz／hop 128 為 330；L = 0..3 的全部數字由 test_ainr_bridge 現查（例如 L = 1 在 16 kHz／hop 128 為 501 2/6）。兩顆 FIR resampler 往返不是恆等，通帶內的容差見測試。

記憶體與版號

靜態 pool 加 32 位元組 descriptor（AinrBridgeMemReq），16 byte 對齊，init 之後沒有 heap、沒有 stdio。16 kHz／fft 256 的 pool 約 117,856 B（本機現查；不含模型：pipeline 範例另配 freq_only 的模型串流 84,272 B 與換算緩衝 12,312 B）。AINR_BRIDGE_LAYOUT_VERSION 在 pool 大小、carve 順序或 descriptor 內容任一改變時加一；descriptor 的雜湊折入主機格點、lookahead、FIFO 容量與兩個 resampler 的 pool 大小，其他格點或 lookahead 的 pool 會被 init_ex 拒絕。

呼叫端

上述板端 sample 編 stream/ainr/bridge/ainr_bridge.c（-I stream/ainr/bridge -I stream/common），在 ainr_bridge_model_begin()／ainr_bridge_model_end() 之間呼叫 ainr_preprocess_freq()、AI3 執行、ainr_postprocess_freq()，lookahead_frames 給 AinrInfo.queue_frames。兩支桌面 pipeline 範例（mono_aec_dfn_res、4ch_aec_bf_dfn_res）經 pipelines/dfn/dfn_hop.h，直接在 ainr_bridge_model_begin()／ainr_bridge_model_end() 之間跑模型串流（pipelines/dfn/tests/test_dfn_hop.c 把它與手寫的配方逐位元對拍）。pool 的逐項與大小見 AinrBridge pool 逐項。

限制

  • 模型格點寫死為 48 kHz／1024；主機只有 8／16 kHz。
  • 板端 RAM、板端執行未驗。
  • 模型無法回覆一個已開的 frame 時（例如模型串流拒絕該 frame），橋接器停在該 frame，直到 ainr_bridge_reset()。
