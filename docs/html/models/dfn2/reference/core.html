dfn2_prepost 類別(建議整合入口)

把「呼叫端頻譜 ↔ 加速器張量」之間的每一件事收進一個物件:ERB/複數特徵前端、deep-filter ring、遞迴 state 的有限性檢查都不再由整合者直接碰;框化與 FFT 仍是應用端的 audiolib。它是第三個 TU(dfn2_prepost.c),組合 dfn2_process.c 與 dfn2_model_io.c 而兩者都不改(它們必須各自可獨立連結)。

DFN2PrepostConfig cfg;                            /* dfn2_prepost.h */
dfn2_prepost_config_defaults(&cfg, &grid);        /* 複製 grid */
cfg.erb_fwd = erb_fwd;  cfg.erb_inv = erb_inv;    /* 必填,借用 */
cfg.atten_lim_db = 0.0f;                          /* 0 = 關閉 */
cfg.gru_hidden = gru;  cfg.gru_hidden_elements = 5 * 256;                    /* 浮點 host:登錄自己的 state; */
cfg.df_convp_history = convp;  cfg.df_convp_history_elements = 64 * 5 * 96;  /* 板端:四個欄位留 NULL／0 */

DFN2PrepostMemReq req;
dfn2_prepost_get_mem_size(&cfg, &req);        /* 48 kHz 1/1: 92,608 bytes */
DFN2Prepost *p = dfn2_prepost_init_ex(pool, req.bytes, &cfg, &req);
unsigned seen = dfn2_prepost_state_generation(p); /* 上次看到的 state generation */
my_npu_fill_state_with_quantized_zero();          /* 板端:啟動時先填量化後的零 */

for (each hop of grid.hop samples) {
    ac_stft_push_planar(stft, hop_in, re, im);
    dfn2_prepost_pre_process_freq(p, re, im);          /* N=1:每 hop 回 1;前 M 拍是暖機幀 */
    DFN2PrepostInputs in; DFN2PrepostOutputs out;
    dfn2_prepost_frame_open(p, &in, &out);          /* 指向本實例 pool 與登錄 state 的 view;位址固定 */
    if (dfn2_prepost_state_generation(p) != seen) {   /* reset、暖機幀或被拒的 commit 清了 state */
        my_npu_fill_state_with_quantized_zero();      /* 板端:加速器自己那份定點 state 也要歸零 */
        seen = dfn2_prepost_state_generation(p);
    }
    if (my_npu_run(&in, &out) != 0 ||              /* state 輸入與 *_next 綁同一個位址,就地寫入 */
        dfn2_prepost_frame_finish(p) != 0)
        dfn2_prepost_frame_bypass(p);                 /* 原頻譜直通,保住 framing 節奏 */
    dfn2_prepost_post_process_freq(p, out_re, out_im, NULL);   /* 前 M+D 拍輸出零頻譜 */
    ac_istft_push_planar(istft, out_re, out_im, out_hop);      /* 每 hop 都 push */
}

_state_generation(p)遞迴 state 被函式庫歸零的次數計數:init 後為 1,每次 _reset、每個暖機幀與每次被拒的 _frame_finish 加 1;NULL 回 0。有自己一份定點 state 的 runtime 在啟動時先填成量化後的零,之後每發現數值變了就再填一次;沒有登錄 state 時函式庫只計數
_hop_size / _num_bins
_layout_version / _model_lookahead_frames / _grid		查詢,失敗 -1(_grid:NULL)。_layout_version = DFN2_MODEL_IO_LAYOUT_VERSION;_model_lookahead_frames = dfn2_prepost_latency_frames() = M+D+N-1 框(出貨 2);_grid = 實例的 grid
_pre_process_freq(p, re, im)吃已分析好的一框(見下方尺度警告),回這一拍需要的加速器呼叫次數:N=1 每拍 1(前 M 拍暖機);N>1 見細節頁。NULL／frame 仍開著 → -1
_pre_process_freq_dual(p, est_re, est_im, app_re, app_im)雙輸入:est 餵估計分支(ERB/複數特徵、EMA 正規化器、[t-(2-M)..t+M] 圖視窗,即 heads),app 餵套用分支(mask／deep filter／atten-lim 作用的 noisy ring)。同一個 frame clock,兩者踩互斥的狀態,所以 est == app 時恰等於 _pre_process_freq()。回傳同 _pre_process_freq
_frame_open(p, &in, &out)公開本框加速器邊界;三個 head 預填 NaN,state 不預填(登錄的 buffer 原址、未登錄為 NULL／0)。無開啟的 frame → -1
_frame_finish(p)驗證每個 head 與登錄的 state 有限(純驗證,不複製)→ 建構增強頻譜(ERB 展開、deep filter、alpha blend、atten-lim)。暖機幀不看 heads:state 歸零、generation +1、回 0
_frame_bypass(p)本框取 identity:unit ERB mask + alpha 0;遞迴 state 維持原樣(就地路徑為加速器寫完的樣子;回報失敗的 runtime 視為沒有寫入),framing 與合成時鐘照走;暖機幀同 finish(歸零、+1)
_post_process_freq(p, re, im, &valid)輸出頻譜與輸入同一個 normalized=True 尺度;前 M+D 拍 *valid = 0 且頻譜為零(valid 只是資訊,可為 NULL),之後 1;frame 仍開著 → -1
_output_frame_index(p, &frame)最近一次輸出屬於哪個 source frame(自 reset 起算);尚未輸出或 NULL → -1
_set_erb_matrices(p, fwd, inv) / _set_atten_lim(p, db)只能在 hop 之間呼叫,保證邊界見 DeepFilterNet2 頻域與模型契約

Transaction 規則

  • frame_open 對三個 head 預填 NaN,「加速器只寫了一半」會在 finish 被抓到。
  • frame_finish 是純驗證:head 與登錄的 state 皆有限才進合成。就地路徑遇非有限值時 state 已被覆寫、無法回滾, 登錄的遞迴張量歸零、state generation 加 1(沒有登錄 state 時只加 generation,由應用端重填加速器的 state),合成不執行、framing／feature window 不動、frame 維持開啟、回 -1; 接著只有兩條路:frame_bypass(),或 frame_open() 從冷 state 重跑。寫一半而仍有限者偵測不到。
  • finish 前一定要有一次 frame_open(prepared 閂鎖):沒跑過的加速器不能把 沒被碰過的 buffer 當結果。frame 開著時 pre_process_freq 回 -1。
  • bypass 是精確的 identity,不是近似:erb_inv 須是 partition of unity,匯出與 host 都會擋(見細節頁)。
  • pre_process_freq 回的是次數不是布林:圖吃 [t-(2-M), .., t+M],前 M 拍(出貨 M=1:第 0 拍)是暖機幀:加速器照跑,heads 丟棄、state 歸零、generation +1,音訊不變;N=1 每拍 1,N>1 與 M=0 不變。

⚠ 頻譜尺度

本類別收發的頻譜是 torch.stft(normalized=True):sqrt-Hann 加窗後 grid.n_fft 區塊的 rfft 再乘 1/√n_fft(grid.stft_scale,出貨 grid 為 1/32;由應用端 AcStft 的 spec_scale 套上、AcIstft 的 ispec_scale = grid.stft_unscale 還原)。AIAEC 模型與 pipeline 的 AEC seam 交出的都是未正規化(audio-scale)的 rfft, 直接餵進來會剛好過驅動 √n_fft 倍(出貨 grid 32 倍),反向欠驅動同倍;兩邊都偵測不到——都是量綱合法的 float 頻譜, ERB 特徵又是 EMA 正規化的,mask 仍看起來合理,只有輸出電平是錯的。跨這個邊界必須自己換算 (出貨 grid × 1/32 進、× 32 出;一般用 grid.stft_scale／stft_unscale)。

兩支 DFN2 pipeline 的 stage 收 audio-scale 頻譜,以 DfnResStageConfig.grid 的 stft_scale／stft_unscale（出貨 grid 為 2-5／25）自行換算,其 AcStft／AcIstft 留 scale 1。 特徵分支內部另有一次同值的縮放(libDF wnorm 殘留), 只作用在餵給正規化器的那份拷貝,從不碰 masking/ISTFT 路徑上的頻譜。

延遲與 warm-up

  • 演算法延遲(模型側)= M+D hops(出貨 1/1:2 hops = 1024 samples = 21.33 ms @48 kHz):DFN2 是 cascade——DF 的未來 tap 需要「已套 mask 的 t+D」,mask(t+D) 又需要 feat(t+D+M),所以 mask_lookahead + df_lookahead 框,相加而非取 max。
  • STFT framing 結構延遲:win−hop = 512 samples = 10.67 ms(WOLA 重疊)。
  • Warm-up:dfn2_enhance_spectrum_stream() 前 M+D 次呼叫回 0(無輸出,不送 ISTFT); 右端 flush 須再推 M+D+1 個全零 hop(含 ISTFT 重疊 1 個),加速器照跑;N 個 frame 時再加 N-1。
  • 正規化器 EMA warm-up:tau = 1.0 s(α=0.989,有效 tau 0.9644 s ≈ 90.4 框,3·tau ≈ 271 框);init 用 libDF linspace 值。
  • 對齊守衛:tests/test_c_prepost.c: test_dfn_stream_alignment() 用逐框變動的 mask/coefs 驗證 output_frame_index 與逐 bin 3e-6 一致性,off-by-one 的配對無法以「輸出有限」矇混過關。

頻域 API

如何呼叫使用

  1. 建立 grid：把模型的值填成 DFN2GridSpec，dfn2_grid_make(&grid, &spec)（欄位見 DFN2 grid 與 ERB），回 DFN2_GRID_OK 才往下，同一個 grid 交給每個物件。
  2. 準備應用端的物件：ERB 矩陣由應用端載入並持有，erb_fwd（bin-major）、erb_inv（band-major），各 n_bins × n_erb 個 float32（48 kHz 為 65,664 bytes；函式庫不讀檔、不複製）；框化：ac_stft_config_default(&sc, grid.n_fft)，設 spec_scale = grid.stft_scale、ispec_scale = grid.stft_unscale，建 AcStft／AcIstft（大小見 DFN2 grid 與 ERB）；浮點 host 另備兩塊遞迴 state buffer。
  3. dfn2_prepost_config_defaults(&cfg, &grid) 後填 erb_fwd／erb_inv（必填）與 atten_lim_db；浮點 host 再登錄遞迴 state（gru_hidden／df_convp_history 與各自的 *_elements，出貨模型 1,280 與 30,720 個 float），板端四欄留 NULL／0，由加速器持有。
  4. dfn2_prepost_get_mem_size(&cfg, &req)：req.bytes 是整個 pool，req.alignment = 16；48 kHz 1/1 為 92,608 bytes（本機量測；不含應用端的 AcStft／AcIstft、ERB 矩陣與登錄的 state；其他 grid 見 DFN2 grid 與 ERB）。板端把 pool 放進靜態 arena，host 工具可改用 dfn2_prepost_create(&cfg)／_destroy()。
  5. dfn2_prepost_init_ex(pool, req.bytes, &cfg, &req)：起始即 reset，state_generation = 1。傳入查詢時的 req 可擋下「別的 build／grid 查出來的陳舊 pool 大小」。
  6. 每個 hop 同一條流程（frames_per_call N = 1）：ac_stft_push_planar → pre_process_freq（回 1）→ frame_open → 加速器 → frame_finish（或 frame_bypass）→ post_process_freq → ac_istft_push_planar；valid 只是資訊（可傳 NULL），AC_OLA_ACCUMULATE 下每 hop 都 push，零頻譜得零 hop。前 M 個 hop 是暖機幀：加速器照跑，heads 被丟棄、登錄 state 歸零、generation 加 1，所以首個真幀從零 state 開始，音訊不變；M = 0 沒有暖機幀，N > 1 維持舊流程（見 DeepFilterNet2 頻域與模型契約）。
  7. 加速器那份定點 state 在啟動時填成量化後的 0，之後每次 state_generation 變了就重填（reset、每個暖機幀、被拒的 commit；M 個暖機幀各重填一次，串流開頭多 M 次加速器呼叫，見時序圖）。串流結尾：再餵全零 hop 並照常跑加速器才能排出尾端：M+D 個只排出最後一個頻譜框，PCM 要多 1 個（ISTFT 重疊），共 M+D+1 個（出貨 pair 3 個；identity 實跑確認）。
  8. 重新開始一段串流：dfn2_prepost_reset(p)，並 reset 自己的 AcStft／AcIstft，然後把加速器 state 重填量化零；結束：dfn2_prepost_destroy(p)（對 _init 實例是 no-op）。

  • 遞迴 state:登錄或不登錄,只有就地綁定:兩個 state tensor(h_gru (1,5,1,256) 與 df_convp_history (1,64,5,96), 共 32,000 float = 128,000 bytes)各只有一份 buffer、位址固定。浮點 host 把它們登錄在 DFN2PrepostConfig(gru_hidden／df_convp_history 與各自的 *_elements;四欄全設或全空,指標配 0 個元素、元素數配 NULL 都被拒,-DDFN2_MASK_ONLY 只有 h_gru 一對):函式庫在 init 與 reset 歸零、每次 frame_finish 檢查有限、被拒時歸零,並把同一個位址交給加速器。板端不登錄(四欄 NULL／0):加速器持有 state,函式庫只計 state generation。登錄的 buffer 不在 pool 大小與 build_flags_hash 內,須與 pool 同壽命。 每個 state 的輸入與 *_out 輸出 shape 完全相同並綁到同一個位址,下一次呼叫的輸入就是這次的輸出,沒有第二份 buffer 也沒有複製。runtime 必須先讀完所有 state 輸入、才寫同位址的輸出 (目標平台已確認 NPU 先讀完所有輸入再寫輸出)。DFN2PrepostOutputs 的 *_next 指標就是輸入的同一個位址。
  • ERB 特徵與 mask 展開只走矩陣的非零範圍:dfn2_set_erb_matrices() 依矩陣內容記下每個 bin／band 的非零區間 (DFN2State.erb_fwd_lo/hi、erb_inv_lo/hi,以及正向矩陣每個 band 的 bin 範圍 erb_fwd_k0/k1),出貨矩陣 16,416 格正反向各只有 995 格非零(model.py 的 _build_erb_fb(1024, 48000, 32) 量測)。被略過的項都是「有限值 × ±0」, 累加器從 +0 開始、加 ±0 不改變任何值(含 Inf/NaN),保留的項順序不變,所以結果與完整矩陣乘法逐位元相同; 某個 bin 的 power 或某個 band 的 gain 非有限時(x × 0 會是 NaN),只有那一列走完整範圍。 power 全有限時正向和依 erb_fwd_k0/k1 逐 band 算(相鄰四個 band 並行、暫存器累加,band 內仍是 bin 遞增順序,逐位元不變)，任何 power 非有限時退回逐 bin 走法。 dfn2_state_init() 之後矩陣為 NULL、範圍為完整。就地改寫矩陣內容後必須再呼叫一次 set_erb_matrices; 回歸測試 AINR/tests/test_c_prepost.c 的 test_dfn_erb_spans_exact 逐位元比對稀疏與完整兩種算法(含溢位、NaN、非有限 mask、含 NaN 的矩陣)。
  • 框化是應用端的:窗、FFT 與 STFT 物件都不在函式庫內,窗與尺度的契約寫在 dfn2_process.h 檔頭(見 DeepFilterNet2 頻域與模型契約);ERB 矩陣是借用的,從不建立或銷毀。
  • 32-byte DFN2PrepostMemReq 七欄:descriptor_version(=1)、layout_version (DFN2_MODEL_IO_LAYOUT_VERSION)、reserved0(必須為 0,_init_ex 拒絕其他值)、build_flags_hash (FNV-1a-32 蓋整個 grid(含 df_order、兩個 lookahead、frames_per_call、input_frames)、variant、model_io layout 與 carve 版號、feature version,加上兩個正規化 alpha(erb_norm_alpha、spec_norm_alpha,由取樣率與 hop 推算)與兩個 STFT scale(dfn2_stft_scale()／dfn2_stft_unscale(),由 n_fft 推算;固定的 tau／初始值／scale 常數在 dfn2_grid.h,不是 grid 欄位,不折入 hash))、alignment(16)、reserved、bytes。

Setter 的保證邊界

_set_erb_matrices()(換另一組 ERB 矩陣,borrowed 不複製)與 _set_atten_lim() 都是 hop 之間限定:frame 開著時回 -1,換手不會落在同一筆交易中間。

這買到的是 per-hop atomicity,不是 per-source-frame consistency:hop t 展開的 mask 屬於 source frame t−1、特徵視窗又橫跨三拍,一次被接受的換手仍會有幾拍同時踩到新舊矩陣。 要 per-source-frame 一致就先 reset 再換。

遞迴 state 的圖邊界

  • h_gru (1,5,1,256):五列 GRU hidden——encoder 第 0 列、ERB decoder 第 1–2 列、DF decoder 第 3–4 列(圖的合約;列序與形狀常數由應用端定義,函式庫不含)。每顆 GRU 用輸入上dim 1 的 Slice取自己的列再 squeeze 成 nn.GRU 的 (layers,1,hidden),下一個 state 以一個 Concat(dim 1)接回;ONNX 沒有 stacked GRU op,兩層的 stack 仍是兩個 GRU node,共 5 個 GRU node。 三顆 GRU 共用同一個輸入 tensor,因此共用同一個量化 scale(inference.py calib 的 gru_state_slices 報告每顆 GRU 在共用 max-abs int8 scale 下損失的位元數)。
  • df_convp_history (1,64,5,96):pathway 卷積(kernel 5)的完整因果 window。圖在輸入上做一個 Slice(axes=[2]、starts=[1]、ends=[5]、step 1,end 是明確整數)丟掉最舊一幀, 接上新的一幀,卷積,並把整個 5 幀 Concat 結果當作 df_convp_history_out。輸入只有這一個 consumer,沒有任何 state 輸出由 Slice 產生。

AINR/onnx_streaming_contract.py 的 validate_inplace_state_graph() 把上述條件逐條檢查(兩支 exporter 匯出時呼叫), AINR/check_state_quantization.py 可在量化後對圖與量化報告再檢查一次:state 輸入與輸出的 dtype／scale／zero point／shape 任一不同就中止。 版本 4–7 已退役(RETIRED_LAYOUT_VERSIONS),合約測試擋下誤 bump。int8 下 window 一列 96 byte,axis-2 Slice 起於第 1 列,對齊由量化工具鏈決定,尚未在板上驗證。

加速器 callback 邊界:DFN2Model

host 不擁有 runtime,只擁有四個指標;邊界放在 prepost 而非 dfn2_process.h,因為 dfn2_process.c 必須能單獨編給 parity build。

typedef struct DFN2Model {
    void *user;
    int (*infer)(void *user, const DFN2PrepostInputs *inputs,
                 DFN2PrepostOutputs *outputs);   /* 回 0 = 每個輸出都寫了 */
    void (*reset)(void *user);                   /* 可選;hosting stage reset 時呼叫 */
    const DFN2ModelIoDescriptor *io_descriptor;  /* NULL = 未發布 */
} DFN2Model;

int dfn2_model_run_frame(const DFN2Model *model, DFN2Prepost *p);

dfn2_model_run_frame()(io_descriptor 為 NULL 或不通過 dfn2_model_io_descriptor_validate() 時回 -1,且不呼叫 infer())把一個已開啟的 frame 走完:frame_open()(head 預填 NaN)→ infer() → frame_finish();infer() 回非 0 或 finish 被拒時改走 frame_bypass(), 所以 framing 與合成兩個時鐘永遠恰好前進一次(N=1 的暖機幀上 infer() 成功也回 1,雖然它的 heads 被丟棄)。有限性規則不在這裡重寫一份——那是 frame_finish() 的責任。回 1 = heads 已 commit、0 = 該幀被 bypass、-1 = 契約錯誤(model/instance 為 NULL、 沒有 infer、或沒有開啟中的 frame)。與 AIAEC 的 identity 政策不同:被 bypass 的幀仍然吐出 M+D 拍前的 source frame ——identity 是在 cascade 內部套用的,時序從不改變。

有 infer 就必須發布 descriptor。DFN2ModelIoDescriptor是 18 個欄位(72 bytes)的圖合約,分兩組。12 個外部欄位:layout_version、sample_rate、fft_size、hop_size、 spectrum_bins、erb_bands、df_bins、df_order、mask_lookahead、 df_lookahead、input_frames、state_tensor_count(2;mask-only 為 1)。6 個內部欄位:encoder_gru_layers、erb_gru_layers、 df_gru_layers、gru_hidden、encoder_channels、df_pathway_window——應用端記帳用,_descriptor_default 填 0、validate 不讀。input_frames = grid.input_frames = N+2(N=1 時 3),N 由 input_frames - 2 得出,descriptor 沒有另外的 N 欄位。_descriptor_default(grid, &d) 填外部欄位,_descriptor_validate(grid, &d) 逐欄位比對外部欄位(不是 memcmp,padding 不得參與決定),不合即 -1(grid 無效也是 -1)。幾何與兩個 lookahead 取自傳入的 grid,layout_version 與 state_tensor_count 是本 build 的常數,所以 validate(grid, default(grid))==0 恆真,它的工作是擋掉對著另一個 layout 版本、另一組幾何或另一個 lookahead pair 匯出的圖——那正是 NaN 預填看不見的一類錯誤(抓得到「沒寫」,抓不到「形狀不對」)。

實際消費者:pipelines/dfn/dfn_res_stage.c。它在 get_mem_requirements() 就把 「有 infer 卻沒 descriptor」「descriptor 被 validate() 拒絕」「有 reset／descriptor 卻沒 infer」三種組合一併拒掉,再由 mono 與 4ch 兩支 DFN2 pipeline 使用;它們走的是雙輸入入口(估計用 pre-RES 頻譜、 套用在 post-RES 頻譜)。

Lookahead pair(M／D)

  • 延遲多 N-1 hop。輸出落後輸入 1 + M + D + N - 1 hops(dfn2_prepost_latency_frames(grid) = M+D+N-1,dfn2_prepost_model_lookahead_frames() 回這個值;valid = 0 的暖機拍數也是這個值)。出貨 pair 配 N=8 為 10 hops = 106.7 ms。flush 要持續推零 hop 並執行加速器,直到最後一個真實 hop 被吐出。finish 被拒時登錄的 state 就地歸零一次,並把 N 個 frame 都走 identity。

  • pipelines 固定 N=1。pipelines/dfn 的 stage(以及其上的 rate bridge)拒絕 grid.frames_per_call != 1;make test／test-simd 的驅動跑 N=1。
  • 尚未量測。目標平台工具鏈對 seq_len>1 的 GRU 的支援、N-frame graph 的量化精度,沒有量過;等價性只用隨機初始化模型與替身加速器證明(N-frame graph 分塊串流等於一個 frame graph 逐 frame 串流,torch 與 ONNX Runtime 數值一致)。N>5 時 c0(餵給下一層卷積)是兩段分別算出的 tensor 的 Concat,量化工具可能給兩個 scale。N>1 時合成在 finish 才跑,所以 set_atten_lim 與反向 ERB 矩陣的更換對下一次 finish 的 N 個 frame 一併生效,包含更換之前就已推入的 frame。

bypass identity 的 partition of unity 檢查

  • bypass 是精確的 identity,不是近似:erb_inv 是 partition of unity (每個 bin 的 band 權重和為 1),unit band mask 展開後就是 unit bin gain,noisy 頻譜原樣穿過 cascade。 匯出時檢查:export_erb_matrix.py 的 --runtime-bins 在寫檔前、一般輸出在寫檔後呼叫 require_partition_of_unity()(後者被拒時檔案已寫出)——照 df_common_expand_mask 的順序逐 band 以 float32 累加後逐位元比對 1.0f(一般路徑另印 inverse_unity_max_error)。C 側 host (pipelines/dfn/dfn_res_stage.c)在 get_mem_requirements() 再驗一次,所以載到一份 inverse 不是 partition of unity 的 ERB 矩陣會被 init 擋下,而不是讓 identity 悄悄變成近似。
