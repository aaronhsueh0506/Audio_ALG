DFN2 板端整合

給負責 AI3 接線的人。ainr.h 在 host 端算好 pool、選出要開的圖與尾端長度；state generation 由 ainr_state_generation() 給；圖的埠表（數量、shape、state 配對）、開圖、送張量、執行、讀回與 state 重載是板端 sample 的程式與它的模型設定。產品首頁列組態與每包三步，這一頁補啟動後的細節。

Pool

ainr_get_mem_size() 回 StreamMemReq（bytes 與 alignment 兩欄，定義在 stream/common/stream_mem.h，與接線型別無關；ainr.h 只引用它）。呼叫端配 bytes 個位元組、對齊 alignment（AINR_ALIGNMENT = 16），交給 ainr_init()。init 自己重算所需大小：pool 小於它或沒有對齊就回 AINR_ERR_POOL（pool 不會被寫入）；較大的 pool 可以。

三個家族（PCM、_spec、_freq）的 pool 都含完整的內層 stream，也就是 STFT 與 ISTFT；不跑 ISTFT 的家族不會縮小。_spec、_freq 另外多一份跨 hop 的暫存，所以 N>1 時三者大小不同。

下表是在本庫 host 建置（arm64 macOS、SIMD=1、BACKEND=ne10）以 ainr_get_mem_size()、_spec()、_freq() 實際讀出的值，單位 bytes。目標板的值隨指標寬度與編譯設定而異，請在板上呼叫同一組函式取得。

組態PCMPCM → 頻譜（_spec）頻譜 → 頻譜（_freq）
full 16 kHz／256／N=1103728103728105792
full 16 kHz／256／N=8160896166336168400
full 48 kHz／1024／N=1361424361424369632
lite 48 kHz／1024／N=1301056301056309264

AinrInfo 與 sample 模型設定

ainr_init()（_spec、_freq 同）填 AinrInfo，只有四欄：

  • graph_path：這個組態要開的圖，由產品的發布資料決定，客戶不必也不應自己拼檔名。
  • trim_samples、queue_frames、tail_zero_blocks。

N 與 hop_in 不在 AinrInfo：客戶的三欄設定已經帶有它們，sample 自己算 N = cfg.hop_in / (cfg.fft / 2)。state 的起始 generation 也不在其中：sample 在 init 之後、第一次 ainr_preprocess() 之前呼叫 ainr_state_generation(ctx) 取得（reset 之後同樣用它）。函式庫不描述圖的埠，也不保存 state 的尺寸。

圖的接線在兩個無 SDK 標頭：stream/ainr/ai3_model_io_dfn2.h 是 DFN2 的固定表（只有標頭，ainr.h 不引用），每個登錄的 (產品, sr, fft, N) 一列，列出每個訊號輸入、每個 head 與每個 state 的 [b,c,h,w]，註明所對應的匯出器；stream/common/ai3_model_io.h（由 make -C stream/common test-model-io 測試）是四支 sample（與另兩款模型）共用的程式：把一列展開成 StreamWiring、用數量迴圈算 state 配對、依 shape 算 input buffer 大小、呼叫埠檢查，以及送件前核對 AinrWork 的數量與 shape（AI3_MODEL_IO_CHECK_WORK）。sample 加 -I stream/common -I stream/ainr 並編譯 stream/common/stream_bind.c。查不到列（AI3_MODEL_IO_ERR_NO_ROW）的組態在開圖前拒絕。

埠順序是一條規則：輸入 = 訊號輸入，再接 state 輸入；輸出 = head 輸出，再接 state 輸出；第 k 組 state 是輸入 signal_in_count + k 與輸出 head_out_count + k，每組兩端同形狀。DFN2 的 signal_in_count 恆為 2（erb 視窗、spec 視窗）。各列的 shape 見產品首頁的表。

產品輸入位置輸出位置
full（signal_in_count 2、head_out_count 3）0 erb、1 spec、2 state 0（h_gru [1,5,1,256]）、3 state 1（df_convp_history [1,64,5,96]）0 erb_mask、1 df_coefs、2 df_alpha、3 state 0、4 state 1
lite（2、1）0 erb、1 spec、2 state 0（h_gru [1,3,1,256]）0 erb_mask、1 state 0

括號與表中的名稱是匯出器的 ONNX 名稱，只用來讀表；C 端不保存名稱，sample 不比對名稱。AinrWork.inputs[i] 是圖的輸入 i（只有兩個訊號輸入），AinrWork.outputs[j] 是圖的輸出 j（full 三個 head，lite 一個），索引與模型設定的 signal i、head j 一致。

開圖後的埠檢查

開圖後、第一次執行前，把 SDK 回報的每個埠填成 StreamDeviceDesc（軸 w, h, c, b、elem_bits、is_float、scale_ratio／zero_point、line_ofs／channel_ofs／batch_ofs、capacity_bytes），依 SDK 的埠順序交給 ai3_model_io_check_ports(&model, in, n_in, out, n_out, msg, sizeof msg)，它呼叫 stream_check_ports()。StreamWiring、StreamDeviceDesc 與 stream_check_ports() 在 stream/common/stream_bind.{h,c}：SDK 無關的 sample 端檢查器，只由 sample 連結；libainr.a 不含它。回傳 STREAM_PORT_OK 或下列負值，並在 msg 給一行原因，以位置稱呼埠（例如 input 2 (state 0)）；不符就不要啟動，不會誤讀。

回傳意義
STREAM_PORT_ERR_NULL（-101）參數為 NULL，或 wiring 本身不合規則（埠數、state 形狀）
STREAM_PORT_ERR_IN_COUNT（-102）／STREAM_PORT_ERR_OUT_COUNT（-103）輸入或輸出埠數不對；埠數先於所有索引檢查
STREAM_PORT_ERR_AXES（-104）軸與 ONNX 邏輯形狀不符；大小為 1 的軸不比，兩個大小大於 1 的軸對調即使元素數相同也拒絕
STREAM_PORT_ERR_FORMAT（-105）不支援的元素格式
STREAM_PORT_ERR_SCALE（-106）定點埠的 scale_ratio 為 0 或非有限值（float 埠不看 scale）
STREAM_PORT_ERR_STRIDE（-107）有 padding 或不連續；只接受連續張量，因為 sample 以連續搬運
STREAM_PORT_ERR_CAPACITY（-108）裝置 buffer 小於張量
STREAM_PORT_ERR_STATE_PAIR（-109）state 輸入與輸出的格式、scale_ratio、軸或 stride 不一致
STREAM_PORT_ERR_STATE_ZERO_POINT（-110）定點 state 埠（任一端）的 zero_point 不是 0；float 的 state 埠不看 zero_point

每個埠依序檢查格式、scale、軸、stride、容量；最後檢查每個 state 輸入與它的輸出。這條規則對 DFN2、DeepVQE-S 與 Align-ULCNet 相同：state 的清零是對 buffer 填位元組 0，只有 zero_point 為 0 時才等於量化後的 0。主機端的 stream/common 的 test_stream_bind 以替身描述涵蓋這條路徑；真實的 descriptor 值要在取得正式 bin 後於板上核對。

送件前的核對是另一道：每個成功的 pre 之後，AI3_MODEL_IO_CHECK_WORK 比對 work.input_count／work.output_count 與每個 tensor 的元素數、[b,c,h,w] 和資料指標是否等於模型設定的列。不符回 AI3_MODEL_IO_ERR_COUNT／_ERR_SHAPE／_ERR_NULL（共用程式的回傳碼範圍為 -301..-306）：不呼叫 AI3，該包以失敗交給 ainr_postprocess()（近恆等直通），仍是一次 pre 對一次 post。

State 與失敗後的回復

  • recurrent state（h_gru、full 另有 df_convp_history）留在加速器的 buffer，不經 host。每對 state 輸入與輸出綁同一塊 buffer：輸入 signal_in_count + k 與輸出 head_out_count + k；shape 取自模型設定，函式庫不保存。
  • 定點 state 埠兩端的 zero_point 都必須是 0（清零用位元組填 0，只有 zero_point 0 時才等於量化後的 0）；不為 0 的 graph 在第一次送件前被埠檢查（stream_check_ports()）以 STREAM_PORT_ERR_STATE_ZERO_POINT（-110）拒絕，float 的 state 埠不看 zero_point。
  • 每拍 ainr_preprocess() 之後，work.state_generation 與 sample 上次同步的值不同，就在這次執行前把 state 輸入 buffer 重載量化零。generation 在 ainr_reset()、暖機拍，以及 post 拒絕這拍的 head（例如 head 不是有限值）時前進。
  • 呼叫端自己通報的失敗（infer_status != 0）本身不推進 generation。但失敗的執行或讀回可能已經寫過 state，所以 sample 還要自己記一個「待回復」旗標：在 AI3 開始執行前設起，執行與全部 head 讀回都成功才清除；下一次送件前，generation 不同或旗標仍設著，就重載量化零。
static void state_generation_sync(unsigned int generation)
{
    if (generation == g_state_gen_seen && !g_state_pending_recovery) return;
    state_refill_zero();                 /* 每個 state 輸入 buffer 寫量化零並 flush cache */
    g_state_gen_seen = generation;
    g_state_pending_recovery = 0;
}

/* 每拍：pre 之後、執行之前 */
state_generation_sync(work.state_generation);
g_state_pending_recovery = 1;            /* 從這裡起，加速器可能就地改寫 state */
ret = run_and_read_back(&work);          /* 執行 + 讀回全部 head */
if (ret == OK) g_state_pending_recovery = 0;
ainr_postprocess(ctx, ret == OK ? 0 : -1, pcm_out);

起始時 sample 先載入一次量化零，再把 g_state_gen_seen 設成 ainr_state_generation(ctx)。失敗的那一拍輸出近恆等直通，不是靜音；回復發生在下一次送件前。

板端 sample 的接線

板端 sample 是本庫以外的檔案（audio_sample），本庫沒有建置它們，也沒有目標板 SDK。AI3 的接線程式——開圖、設定緩衝、加速器執行呼叫、讀回、cache flush——是板端負責人的程式，原版不改；我方只加模型設定與共用接線（stream/ainr/ai3_model_io_dfn2.h、stream/common/ai3_model_io.h）這一側。本庫提供 ainr_* 與 SDK 無關的檢查器 stream_check_ports()。四支 sample 的 stream 端接線一致：

sample使用的入口啟動
alg_ai3_dfn.c（full）ainr_*（PCM）一個 host 端初始化函式依序做 size、pool、ainr_init()，由 config 算 N，查 stream/ainr/ai3_model_io_dfn2.h 的列；開圖後埠檢查，再用 ainr_state_generation() 設同步起點；組態被拒或查無列時結束碼 1，未執行加速器
alg_ai3_dfn_lite.c（lite）同上同上；只登錄 48000／1024／512
uvc_ai_nr_stream.cainr_*（PCM）固定 48000／1024／512；模型設定查不到該列時拒絕；開圖後埠檢查
uvc_audio_live2a.cainr_*_freq（E／P 頻譜）固定 48000／1024／512；同樣查列；開圖後埠檢查

四支 sample 共用同一份 DFN2 模型設定，按位置把 work.inputs[i]、work.outputs[j] 對到 SDK 的第 i 個輸入與第 j 個輸出，state 對依 signal_in_count／head_out_count 之後的位置綁同一塊 buffer，都有「待回復」旗標（見上節），也都沒有 job_ready 分支：每次成功的 pre 都接一次 AI3 執行與一次 post。保留 full 的 alpha 對應與既有的數值處理。

本庫未驗證的部分：正式量化後的 model.bin、目標板 SDK 的建置、板上的 descriptor 實值、音訊與每 hop 耗時。
