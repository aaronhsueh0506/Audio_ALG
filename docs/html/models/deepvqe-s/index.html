DeepVQE-S

輸入是原始 mic 與 far 的 int16 PCM，兩路長度皆為一個模型 hop。SDK 做雙路分析，模型輸出複數濾波 taps，套在 mic 的頻譜歷史，再合成單路 int16 PCM。

建置與初始化

make -C stream/aiaec/deepvqe_s lib
make -s -C stream/aiaec/deepvqe_s print-lib-path

依模型建立 grid 與 config，用 deepvqe_stream_get_mem_size() 查詢 pool 大小與對齊，再配置 pool。以同一目標工具鏈建置並連結模型 archive 和 audiolib 的 libaudio_common.a。裝置 runtime 載入與 grid 相符的模型檔，負責每次 NPU 推論。

每 hop 呼叫

範例中的讀寫、run_accelerator 與 device_state_* 由呼叫端實作。裝置第一次使用或 generation 改變時，把 recurrent state 還原為模型的量化零值。推論已開始後回錯，也立刻清掉可能部分寫入的裝置 state。

DeepVqeStream *ctx = deepvqe_stream_init(&cfg, pool, bytes);
if (!ctx) return -1;
while (read_hops(mic_in, far_in)) {
    DeepVqeHopIO io;
    if (deepvqe_stream_pre_process(ctx, mic_in, far_in, &io) != 1) return -1;
    device_state_sync(io.state_generation);
    int rc = run_accelerator(&io.inputs, &io.outputs);
    if (rc != 0) device_state_refill_zero();
    if (deepvqe_stream_post_process(ctx, rc, pcm_out) < 0) return -1;
    write_hop(pcm_out);
}

模型從 hop 0 起每拍推論，CCM ring 初始為零。init／reset 後第一次 ISTFT push 尚未吐出樣本，post 回 0 並輸出一整拍零 PCM。正式幀推論失敗時，當拍增強頻譜歸零。50% overlap 的 ISTFT 仍疊加上一拍尾端，因此若前拍已有音訊，需連續兩拍零頻譜才保證 PCM 全零。
