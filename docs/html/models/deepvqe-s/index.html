Audio_ALG / 模型開發與部署

DeepVQE-S

輸入是原始 mic 與 far 的 int16 PCM，兩路每次各 hop_in 個樣本。SDK 做雙路分析，模型輸出複數濾波 taps，套在 mic 的頻譜歷史，再合成單路 int16 PCM。客戶只設三個值：sr、fft、hop_in。每包張數 N = hop_in / (fft / 2)，grid、graph 與其餘參數由產品登錄表決定；介面在 aiaec.h。

支援的組態

sr / ffthop_in → N正式登錄表測試登錄表（僅主機測試）
16000 / 512256 → 1有登錄的 graph，接受可建構
16000 / 5122048 → 8無 graph，init 拒絕無，init 拒絕
16000 / 256128 → 1無 graph，init 拒絕可建構
16000 / 2561024 → 8無 graph，init 拒絕可建構

沒有交付 graph 的組態在 aiaec_get_mem_size()／aiaec_init() 被拒絕（AIAEC_ERR_FRAMES_PER_CALL），不會呼叫任何 SDK。測試登錄表只存在於主機測試用的測試建置，不在交付的 archive 裡，以佔位路徑讓主機測試走完整個 API，不代表有 graph。表外的 (sr, fft) 回 AIAEC_ERR_GRID；不是模型 hop 倍數的 hop_in（例如 129）回 AIAEC_ERR_IN_HOP。FFT 512 與 256 使用同一個迴圈。

建置與連結

DeepVQE-S 的單模型產品用 AIAEC_MODEL=deepvqe 建置，連結 libaiaec.a、該款 backend libdeepvqe_stream.a 與 audiolib 的 libaudio_common.a（與本庫同一目標工具鏈建置）。路徑一律用 print-lib-path 查，且查詢要帶與建置相同的 AIAEC_MODEL、SIMD、CC、EXTRA_CFLAGS；不帶 AIAEC_MODEL 會查到預設 both 版的路徑。

AUDIOLIB=/path/to/audiolib
COMMON_LIB="$(make -s -C $AUDIOLIB/common lib print-lib-path | tail -1)"
make -C stream/aiaec AIAEC_MODEL=deepvqe COMMON_DIR=$AUDIOLIB/common COMMON_LIB="$COMMON_LIB" lib
make -C stream/aiaec/deepvqe_s COMMON_DIR=$AUDIOLIB/common COMMON_LIB="$COMMON_LIB" lib
cc app.c -Istream/aiaec \
   "$(make -s -C stream/aiaec AIAEC_MODEL=deepvqe COMMON_DIR=$AUDIOLIB/common COMMON_LIB="$COMMON_LIB" print-lib-path)" \
   "$(make -s -C stream/aiaec/deepvqe_s COMMON_DIR=$AUDIOLIB/common COMMON_LIB="$COMMON_LIB" print-lib-path)" \
   "$COMMON_LIB" -lm -o app

漏掉 libdeepvqe_stream.a 會缺 deepvqe_stream_*。預設 AIAEC_MODEL=both 的 libaiaec.a 同時引用兩款 backend，只連 DeepVQE-S 的 backend 會缺 ulcnet_stream_*。

Graph 接線

aiaec_init() 只回報選出的圖（AiaecInfo.graph_path）與尾端長度，不回報埠表。每個已交付 graph 的完整接線——訊號與 head 的 shape、16 組 state 的 shape——放在 stream/aiaec/ai3_model_io_deepvqes.h，每個登錄的 (sr, fft, N) 一列，列旁註明所對應的匯出器；共用的接線程式 stream/common/ai3_model_io.h（由 make -C stream/common test-model-io 測試）負責列的展開、state 配對、開圖後的埠檢查、input buffer 大小與送件前的核對。兩者與 SDK 無關、只有標頭，aiaec.h 不引用，函式庫不含接線；sample 加 -I stream/common -I stream/aiaec並編譯 stream/common/stream_bind.c。沒有對應列的組態，或與 init 選出的 graph 不符，由 sample 的啟動檢查在任何 SDK 呼叫之前拒絕。

圖的埠順序只有一條規則：輸入 = 訊號輸入，再接 state 輸入；輸出 = head 輸出，再接 state 輸出；第 k 組 state 是輸入 signal_in_count + k 與輸出 head_out_count + k，兩端同形狀。DeepVQE-S：signal_in_count 2（mic、far）、head_out_count 1（CCM taps）、16 組 state，所以輸入 18 個、輸出 17 個，N=1 與 N>1 相同。sample 依數量迴圈處理，不比對名稱。N 改變 mic／far 與 CCM head 的時間軸，不改埠順序；state 的 shape 隨 grid 與延遲深度 D = ceil(0.5 s / hop) 而變：

組態mic、far（輸入 0、1）CCM taps（輸出 0）state
16k／256／N=1[1,2,1,129][1,1,129,18]16 組，D = 63
16k／256／N=8[1,2,8,129][1,8,129,18]16 組，D = 63
16k／512／N=1[1,2,1,257][1,1,257,18]16 組，D = 32

AiaecWork.inputs[0..1] 與 outputs[0] 的 shape 與元素數就是上表同一列；state 不在 AiaecWork 裡。state 的順序是匯出器的順序（align_key_ring、align_value_ring、align_score_history、ccm_up_history、far1_history、far2_history、h_gru、mic1_history … mic4_history、res2_history、res3_history、up1_history … up3_history；ONNX 名稱除 h_gru 外都帶 state_ 前綴），各自的 shape 見模型設定的列。

初始化與每包呼叫

一次 init（aiaec_get_mem_size() → aiaec_init()）備好 pool，並填 AiaecInfo：圖路徑、trim_samples、queue_frames、tail_zero_blocks 四欄。N 不在其中，sample 由 config 算 N = hop_in / (fft / 2)。起始 generation 由 aiaec_state_generation() 取得。sample 的演算法入口只有 init／pre／post；AI3 的開圖、送張量、執行、讀回與 state 緩衝是 sample 自己的。每包 pre／post 只交換這一包的特徵（work.inputs[0..1] 為 mic、far 的特徵）與模型 head（work.outputs[0]，CCM taps）。

AiaecConfig cfg = { sr, fft, hop_in };             /* 例：{ 16000, 512, 256 } */
StreamMemReq req;
if (aiaec_get_mem_size(&cfg, &req) != AIAEC_OK) return -1;   /* 未登錄組態在此被拒 */
void *pool = alloc_aligned(req.alignment, req.bytes);
AiaecCtx *ctx;
AiaecInfo info;                                    /* graph_path、trim_samples、queue_frames、tail_zero_blocks */
int rc = aiaec_init(&cfg, pool, req.bytes, &ctx, &info);   /* 0 或負的 AIAEC_ERR_* */
if (rc != AIAEC_OK) { log(aiaec_status_text(rc)); return -1; }

/* sample 的模型設定：這個 grid 與 N 的接線列；沒有列就在開圖前拒絕 */
int n = ai3_model_io_frames(cfg.fft, cfg.hop_in);  /* N = hop_in / (fft / 2) */
Ai3ModelIoConfig model;
if (ai3_model_io_deepvqes_find(cfg.sr, cfg.fft, n, &model) != AI3_MODEL_IO_OK) return -1;

open_graph(info.graph_path);                       /* sample 的 AI3 */
char msg[160];
if (ai3_model_io_check_ports(&model, din, n_in, dout, n_out, msg, sizeof msg) != STREAM_PORT_OK) return -1;

unsigned seen = aiaec_state_generation(ctx);

while (read_blocks(mic, far, hop_in)) {
    AiaecInput in = { .kind = AIAEC_INPUT_DEEPVQE_S, .samples = hop_in };
    in.u.deepvqe_s.mic_in = mic;
    in.u.deepvqe_s.far_in = far;
    AiaecWork work;
    if (aiaec_preprocess(ctx, &in, &work) != AIAEC_OK) return -1;
    int ai_rc = 0;
    if (work.action == AIAEC_SUBMIT) {             /* DeepVQE-S 每包都是 SUBMIT */
        int chk;
        AI3_MODEL_IO_CHECK_WORK(chk, &model, &work);   /* work 的數量與 shape 必須等於這一列 */
        if (chk != AI3_MODEL_IO_OK) ai_rc = -1;    /* 不符：不送件，仍呼叫 post */
        else {
            if (work.state_generation != seen) { clear_state_buffers(); seen = work.state_generation; }
            ai_rc = run_ai3(&work);                /* 填 work.inputs，執行，讀回 work.outputs */
        }
        if (ai_rc != 0) clear_state_buffers_before_next_run();
    }
    if (aiaec_postprocess(ctx, ai_rc, pcm_out) != AIAEC_OK) return -1;   /* 失敗也呼叫 */
    write_block(pcm_out, hop_in);
}

aiaec_init() 回 0 或負的 AIAEC_ERR_*，pool 小於 aiaec_get_mem_size() 的位元組數或未對齊時回 AIAEC_ERR_POOL，較大的 pool 可以。aiaec_preprocess() 成功回 AIAEC_OK（0），是否要跑加速器看 work.action。開圖後、第一次執行前，共用接線程式的 ai3_model_io_check_ports()（內部呼叫 SDK 無關的檢查器 stream_check_ports()，在 stream/common，libaiaec.a 不含它）檢查每個埠的格式、軸、stride、容量與 state 配對；每包送件前 AI3_MODEL_IO_CHECK_WORK 再核對 work 的數量與 shape。

pool 大小（本庫 host 建置讀出，單位 bytes；16k／256 兩列只存在於測試登錄表）：

組態PCM_spec_freq
16k／512／N=1124096124096124096
16k／256／N=1641926419264192
16k／256／N=8167024172464172464

State

  • recurrent state 留在 AI3 的 buffer。每對 state 輸入與輸出依位置（輸入 signal_in_count + k 與輸出 head_out_count + k）綁同一塊 buffer；DeepVQE-S 有 16 對。
  • 定點 state 埠兩端的 zero_point 都必須是 0（清零用位元組填 0，只有 zero_point 0 時才等於量化後的 0）。5/5、0/5、5/0 都在第一次送件前被埠檢查（stream_check_ports()）以 STREAM_PORT_ERR_STATE_ZERO_POINT（-110）拒絕；float 的 state 埠不看 zero_point。
  • init 時每塊 state buffer 清零一次（memset 加 cache flush）。正常連續推論不碰 state，每包只交換特徵與 head。
  • 函式庫只在 reset 與加速器輸出非有限時動 state 並讓 work.state_generation 改變；sample 看到 generation 改變就清。回報失敗（infer_status 非 0）的一包只旁路該包，state 與 generation 都不動，所以 sample 在任何失敗的一包之後，也要在下一次實際送件前自行再清一次。

失敗語義與延遲

  • 執行失敗或加速器輸出非有限時為 fail-closed：當拍自己的頻譜貢獻歸零，不是直通。pcm_out 仍可能有非零樣本，因為 overlap-add 會加上前一包已提交的結果。失敗那一批 N 個 frame 的頻譜全為零：失敗那包的最後一個 hop 只剩前一個 frame 的 overlap（半個窗），下一包的前 N − 1 個 hop 恰為零，下一包的最後一個 hop 又只有半個窗，再往後恢復正常；N=1 時受影響的是失敗的 hop 與下一個 hop，各只有半個窗。
  • N>1 時第一包開頭的 (N − 1) × 模型 hop 個樣本依設計為零。
  • trim_samples = N × 模型 hop（含 stream 自己的一個 STFT／ISTFT hop），三個家族相同；queue_frames = N − 1 個 frame（模型佇列單獨保存的部分）。
  • 檔案尾端：最後一包補成完整 hop_in，再送 info.tail_zero_blocks（恆為 1）包全零，輸出去掉 info.trim_samples 個樣本，保留輸入長度。

有自己合成器的應用可用 aiaec_*_spec（PCM 進、頻譜出）或 aiaec_*_freq（頻譜進、頻譜出）家族；邊界與 AiaecInfo 相同，延遲與尾端規則見 aiaec.h 的 "Tail" 一節。AC_OLA_ACCUMULATE 的 ac_istft_flush() 回 0，外部 ISTFT 要照常推全零頻譜。

驗證狀態

目前所有驗證都在主機上：SDK 替身加速器（stream/aiaec/tests）與隨機權重的 ONNX。沒有正式量化 graph 的符合性驗證，沒有廠商 SDK 建置，沒有板端執行。

組態主機替身ONNX Runtime正式 bin板端
16k／512／N=1正式登錄表與測試登錄表都已測已驗：匯出圖與 PyTorch 逐項比對（隨機權重）；未經 C 家族逐包執行有登錄路徑；交付與符合性未驗未驗
16k／256／N=1僅測試登錄表已驗：匯出圖在 ONNX Runtime 逐包串流，與 N=8 的輸出一致（隨機權重）；未經 C 家族逐包執行無 graph，init 拒絕未驗
16k／256／N=8僅測試登錄表同上（N=8 封包圖，每包一次呼叫）無 graph，init 拒絕未驗
16k／512／N=8不存在，init 拒絕不適用不適用不適用
  • work 對匯出圖（不跑推論）：AIAEC/tests/test_aiaec_bind_info_pin.py 以隨機權重匯出 16k／256 N=1、N=8 與 16k／512 N=1，依位置比對三個家族真實 aiaec_preprocess*() 給出的 AiaecWork（mic、far 與 CCM taps 的 shape 與元素數）和匯出圖的訊號輸入、head 輸出，並檢查匯出器的 ONNX 名稱順序符合上述規則（訊號輸入在前、state 在後；head 在前、state 輸出 = 輸入名稱加 _out、state 兩端同 shape）。函式庫不保存 state 的 shape；模型設定各列（ai3_model_io_deepvqes.h）同一個測試用 make -C stream/aiaec model-io-dumper 傾印，逐列比對全新匯出的圖（layout 版本、埠數與順序、各輸入輸出 shape、state 名稱與順序、兩端同 shape），列集合恰為匯出的案例；C 端的列對 AiaecWork 由 test-aiaec-model-io 檢查。
  • ONNX Runtime：AIAEC/tests/test_deepvqe_frames_per_call.py 匯出 16k／512 的 N=1、2、4，驗 state 就地契約並以 ONNX Runtime 對 PyTorch 驗證；test_deepvqe_inference_frames_per_call.py 在 16k／256 匯出 N=1 與 N=8 兩張圖，在 ONNX Runtime 串流同一段輸入，CCM taps 最大差小於 5e-5，加速器呼叫數分別為 hop 數與 hop 數除以 8 進位。兩者都不經 C 的 aiaec_* 家族。
