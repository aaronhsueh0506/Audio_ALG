Audio_ALG / 模型開發與部署

DeepVQE-S

輸入是原始 mic 與 far 的 int16 PCM，兩路每次各 hop_in 個樣本。SDK 做雙路分析，模型輸出複數濾波 taps，套在 mic 的頻譜歷史，再合成單路 int16 PCM。客戶只設三個值：sr、fft、hop_in。每包張數 N = hop_in / (fft / 2)，grid 與其餘參數由產品的 catalog 決定，graph 檔由 sample 的 graph_io 表決定；介面在 aiaec.h。

支援的組態

sr / ffthop_in → Ngraph 檔（graph_io_deepvqes.h）
16000 / 256128 → 1deepvqes_16k_fft256_n1.bin
16000 / 2561024 → 8沒有列；函式庫接受，sample 在開圖前拒絕
16000 / 512256 → 1deepvqes_16k_fft512_n1.bin
16000 / 5121024 → 4deepvqes_16k_fft512_n4.bin
16000 / 5122048 → 8沒有列；函式庫接受，sample 在開圖前拒絕
48000 / 1024512 → 1deepvqes_48k_fft1024_n1.bin
48000 / 10241024 → 2deepvqes_48k_fft1024_n2.bin

函式庫接受模型 stream 收的任何 N（1..64），N 超出範圍回 AIAEC_ERR_FRAMES_PER_CALL；哪個 N 有 graph 是 sample 的 graph_io_deepvqes.h 表：沒有列的組態（GRAPH_IO_ERR_NO_ROW）由 sample 在任何 SDK 呼叫之前拒絕。表外的 (sr, fft) 回 AIAEC_ERR_GRID；不是模型 hop 倍數的 hop_in（例如 16 kHz／256 的 129）回 AIAEC_ERR_IN_HOP。FFT 512、1024 與 256 使用同一個迴圈。48 kHz 的 AEC 前端格點是 48k／1024（AEC 產品格點）。

板端 graph 檔：每列一個檔，名稱如上表，sample 開 SAMPLE_MODEL_DIR "/" cfg.file（預設 /mnt/sd/audio_model/16x16；量化資料夾是 sample 的選擇），SD 卡上的檔名要與表一致。每個檔只能在它自己的 grid 與 N 跑：另一個 grid 的 graph 在開圖後被 sample 的 graph_io_check_ports() 拒絕，不會執行任何推論。sample alg_ai3_deepvqes.c 的預設命令列（不帶選項，等於 --sample-rate 16000 --fft-size 256 --hop-in 128）是 16 kHz／fft 256／hop_in 128（N=1，129 bins，D = 63）；--fft-size 512 選 16 kHz／512／256，--fft-size 512 --hop-in 1024 選 16 kHz／512 的 N=4（一包 1024 點）。16 kHz／256 只有 N=1 的列：--hop-in 1024 在 fft 256 是 N=8，沒有列，sample 在開圖前拒絕。

建置與連結

DeepVQE-S 的單模型產品用 AIAEC_MODEL=deepvqe 建置，連結 libaiaec.a、該款 backend libdeepvqe_stream.a 與 audiolib 的 libaudio_common.a（與本庫同一目標工具鏈建置）。路徑一律用 print-lib-path 查，且查詢要帶與建置相同的 AIAEC_MODEL、SIMD、CC、EXTRA_CFLAGS；不帶 AIAEC_MODEL 會查到預設 both 版的路徑。

AUDIOLIB=/path/to/audiolib
COMMON_LIB="$(make -s -C $AUDIOLIB/common lib print-lib-path | tail -1)"
make -C stream/aiaec AIAEC_MODEL=deepvqe COMMON_DIR=$AUDIOLIB/common COMMON_LIB="$COMMON_LIB" lib
make -C stream/aiaec/deepvqe_s COMMON_DIR=$AUDIOLIB/common COMMON_LIB="$COMMON_LIB" lib
cc app.c -Istream/aiaec -Istream/common -I$AUDIOLIB/common \
   "$(make -s -C stream/aiaec AIAEC_MODEL=deepvqe COMMON_DIR=$AUDIOLIB/common COMMON_LIB="$COMMON_LIB" print-lib-path)" \
   "$(make -s -C stream/aiaec/deepvqe_s COMMON_DIR=$AUDIOLIB/common COMMON_LIB="$COMMON_LIB" print-lib-path)" \
   "$COMMON_LIB" -lm -o app

漏掉 libdeepvqe_stream.a 會缺 deepvqe_stream_*。預設 AIAEC_MODEL=both 的 libaiaec.a 同時引用兩款 backend，只連 DeepVQE-S 的 backend 會缺 ulcnet_stream_*。

Graph 接線

aiaec_init() 不回報任何東西（沒有檔名、沒有埠表）。每個已交付 graph 的完整接線——訊號與 head 的 shape、16 組 state 的 shape——放在 stream/aiaec/graph_io_deepvqes.h，每個登錄的 (sr, fft, N) 一列，列旁註明所對應的匯出器，並帶中性的 graph 檔名（GraphIoConfig.file）；共用的接線程式 stream/common/graph_io.h（由 make -C stream/common test-graph-io 測試）負責列的展開、state 配對、開圖後的埠檢查、input buffer 大小與送件前的核對。兩者與 SDK 無關、只有標頭，aiaec.h 不引用，函式庫不含接線；sample 加 -I stream/common -I stream/aiaec並編譯 stream/common/stream_bind.c。沒有對應列的組態，或開圖後埠與該列不符，由 sample 的啟動檢查在任何 SDK 呼叫之前拒絕。

圖的埠順序只有一條規則：輸入 = 訊號輸入，再接 state 輸入；輸出 = head 輸出，再接 state 輸出；第 k 組 state 是輸入 signal_in_count + k 與輸出 head_out_count + k，兩端同形狀。DeepVQE-S：signal_in_count 2（mic、far）、head_out_count 1（CCM taps）、16 組 state，所以輸入 18 個、輸出 17 個，N=1 與 N>1 相同。sample 依數量迴圈處理，不比對名稱。N 改變 mic／far 與 CCM head 的時間軸，不改埠順序；state 的 shape 隨 grid 與延遲深度 D = ceil(0.5 s / hop) 而變：

組態mic、far（輸入 0、1）CCM taps（輸出 0）state
16k／256／N=1[1,2,1,129][1,1,129,18]16 組，D = 63
16k／512／N=1[1,2,1,257][1,1,257,18]16 組，D = 32
16k／512／N=4[1,2,4,257][1,4,257,18]16 組，D = 32
48k／1024／N=1[1,2,1,513][1,1,513,18]16 組，D = 47
48k／1024／N=2[1,2,2,513][1,2,513,18]16 組，D = 47

16k／256 那一列的 state 依 AIAEC/DeepVQE_S/config_16k_256.ini 的 [model]（similarity_channels 8、score_kernel 9,5、gru_hidden 256）：align_key_ring [1,8,63,33]、align_score_history [1,8,9,63]、h_gru [1,1,1,256]。其餘列依建構子預設（sim 通道 4、score window 5、GRU 192）。16k／256 的 graph 要用 config_16k_256.ini 訓練的 checkpoint 匯出；以建構子預設訓練的 16k／256 graph 在開圖後被 graph_io_check_ports() 拒絕。三個 grid 各有一份自足的訓練 config（config_16k_256.ini、config_16k_512.ini、config_48k.ini），train.py 的 --config 必填。

StreamWork.inputs[0..1] 與 outputs[0] 的 shape 與元素數就是上表同一列；state 不在 StreamWork 裡。state 的順序是匯出器的順序（align_key_ring、align_value_ring、align_score_history、ccm_up_history、far1_history、far2_history、h_gru、mic1_history … mic4_history、res2_history、res3_history、up1_history … up3_history；ONNX 名稱除 h_gru 外都帶 state_ 前綴），各自的 shape 見模型設定的列。

初始化與每包呼叫

一次 init（aiaec_get_mem_size() → aiaec_init()）備好 pool，不回報其他東西。N 由 sample 從 config 算：N = hop_in / (fft / 2)。起始 generation 由 aiaec_state_generation() 取得。sample 的演算法入口只有 init／pre／post；AI3 的開圖、送張量、執行、讀回與 state 緩衝是 sample 自己的。每包 pre／post 只交換這一包的特徵（work.inputs[0..1] 為 mic、far 的特徵）與模型 head（work.outputs[0]，CCM taps）。

AiaecConfig cfg = { sr, fft, hop_in };             /* 例：{ 16000, 256, 128 } */
StreamMemReq req;
if (aiaec_get_mem_size(&cfg, &req) != AIAEC_OK) return -1;   /* 未登錄組態在此被拒 */
void *pool = alloc_aligned(req.alignment, req.bytes);
AiaecCtx *ctx;
int rc = aiaec_init(&cfg, pool, req.bytes, &ctx);   /* 0 或負的 AIAEC_ERR_* */
if (rc != AIAEC_OK) { log(aiaec_status_text(rc)); return -1; }

/* sample 的模型設定：這個 grid 與 N 的接線列；沒有列就在開圖前拒絕 */
int n = graph_io_frames(cfg.fft, cfg.hop_in);  /* N = hop_in / (fft / 2) */
GraphIoConfig model;
if (graph_io_deepvqes_find(cfg.sr, cfg.fft, n, &model) != GRAPH_IO_OK) return -1;

open_graph(path_of(SAMPLE_MODEL_DIR, model.file));   /* sample 的 AI3 */
char msg[160];
if (graph_io_check_ports(&model, din, n_in, dout, n_out, msg, sizeof msg) != STREAM_PORT_OK) return -1;

unsigned seen = aiaec_state_generation(ctx);

while (read_blocks(mic, far, hop_in)) {
    AiaecInput in = { .kind = AIAEC_INPUT_DEEPVQE_S, .samples = hop_in };
    in.u.deepvqe_s.mic_in = mic;
    in.u.deepvqe_s.far_in = far;
    StreamWork work;
    if (aiaec_preprocess(ctx, &in, &work) != AIAEC_OK) return -1;
    int run_status = STREAM_RUN_NOT_STARTED;
    if (work.action == STREAM_WORK_SUBMIT) {             /* DeepVQE-S 每包都是 SUBMIT */
        int chk;
        GRAPH_IO_CHECK_WORK(chk, &model, &work);   /* work 的數量與 shape 必須等於這一列 */
        if (chk != GRAPH_IO_OK) run_status = STREAM_RUN_NOT_STARTED;    /* 不符：不送件，仍呼叫 post */
        else if (work.state_generation != seen && zero_state_buffers() != 0) run_status = STREAM_RUN_NOT_STARTED;   /* 清零失敗：seen 不更新，下一包再清 */
        else {
            seen = work.state_generation;
            /* 填 work.inputs，執行，讀回 work.outputs；net_proc 之前的失敗回 STREAM_RUN_NOT_STARTED，
             * 之後的失敗回 STREAM_RUN_FAILED，全部讀回才是 0 */
            run_status = run_ai3(&work);
        }
    }
    if (aiaec_postprocess(ctx, run_status, pcm_out) != AIAEC_OK) return -1;   /* 失敗也呼叫 */
    write_block(pcm_out, hop_in);
}

aiaec_init() 回 0 或負的 AIAEC_ERR_*，pool 小於 aiaec_get_mem_size() 的位元組數或未對齊時回 AIAEC_ERR_POOL，較大的 pool 可以。aiaec_preprocess() 成功回 AIAEC_OK（0），是否要跑加速器看 work.action。開圖後、第一次執行前，共用接線程式的 graph_io_check_ports()（內部呼叫 SDK 無關的檢查器 stream_check_ports()，在 stream/common，libaiaec.a 不含它）檢查每個埠的格式、軸、stride、容量與 state 配對；每包送件前 GRAPH_IO_CHECK_WORK 再核對 work 的數量與 shape。

輸入檢查：PCM 入口是 int16，不可能非有限，沒有掃描。aiaec_preprocess_freq() 在 kind、size、NULL 檢查之後、任何 frame 進入 stream 之前，檢查四個平面（mic 與 far 的實部、虛部，各 N × n_bins 個 float）；任何一個 NaN 或 Inf 都讓整包以 AIAEC_ERR_NONFINITE_INPUT（-10）被拒絕。這個檢查屬於 stream：deepvqe_stream_pre_process_packet_freq() 對同一個條件回 DEEPVQE_STREAM_ERR_RANGE（-2），在任何狀態變動之前。拒絕時 stream、分析器與 state generation 都沒有動，也沒有開啟的 block：sample 不要跑加速器，也不要呼叫 post，同一個 ctx 直接接下一包，輸出與從未收到這包相同。有限的 bin（到 FLT_MAX 為止）照常處理，送進加速器的特徵都是有限值；有限的 tap 乘上接近 FLT_MAX 的 mic 頻譜若溢位成 Inf，函式庫拒收該批（同加速器輸出非有限），輸出靜音、generation +1，不會輸出 Inf。

pool 大小（本庫 host 建置讀出，單位 bytes）：

組態PCM_freq
16k／512／N=111776031504
16k／512／N=4197920105488
16k／256／N=16092816144
48k／1024／N=123142462224
48k／1024／N=2284752111440

_freq 的 pool 不含 FFT、STFT／ISTFT 與 PCM 暫存（呼叫端自己做分析與合成），所以比 PCM 小。

State

  • recurrent state 留在 AI3 的 buffer。每對 state 輸入與輸出依位置（輸入 signal_in_count + k 與輸出 head_out_count + k）綁同一塊 buffer；DeepVQE-S 有 16 對。
  • 定點 state 埠兩端的 zero_point 都必須是 0（清零用位元組填 0，只有 zero_point 0 時才等於量化後的 0）。5/5、0/5、5/0 都在第一次送件前被埠檢查（stream_check_ports()）以 STREAM_PORT_ERR_STATE_ZERO_POINT（-110）拒絕；float 的 state 埠不看 zero_point，清零仍是填位元組 0，不受 FLOAT_IN／FLOAT_OUT 影響（見Float I/O 模式）。
  • init 時每塊 state buffer 清零一次（memset 加 cache flush）。正常連續推論不碰 state，每包只交換特徵與 head。
  • 函式庫在 reset、加速器輸出非有限、以及回報失敗而 state 可能已髒時動 state 並讓 work.state_generation 改變；sample 看到 generation 改變就在下一次送件前清（上面的範例）。狀態值 0 是全部寫完；STREAM_RUN_NOT_STARTED（0x4E53）是加速器沒動 state，只旁路該包，generation 不動；其他值都算 state 可能已髒，generation +1。

失敗語義與延遲

  • 執行失敗、加速器輸出非有限、或有限的輸出算出非有限的增強頻譜時為 fail-closed：當拍自己的頻譜貢獻歸零，不是直通。pcm_out 仍可能有非零樣本，因為 overlap-add 會加上前一包已提交的結果。失敗那一批 N 個 frame 的頻譜全為零，正是失敗那一包自己的 N 個 hop：第一個 hop 只剩前一個 frame 的 overlap（半個窗），其餘 N − 1 個 hop 恰為零，下一包的第一個 hop 又只有半個窗，再往後恢復正常；N=1 時受影響的是失敗的 hop 與下一個 hop，各只有半個窗。
  • 延遲：輸出比輸入晚一個模型 hop（stream 自己的 STFT／ISTFT hop，fft / 2 個樣本），與 N 無關，兩個家族相同；每一包的輸出就是這一包 N 個 frame 的合成，沒有跨包的佇列。
  • 函式庫不修剪也不補尾：每一包照常 pre → AI3 → post，輸出與輸入逐包對應，起點晚上述延遲。

有自己分析與合成器的應用可用 aiaec_*_freq（頻譜進、頻譜出）家族；邊界與 PCM 家族相同，延遲同為一個模型 hop（呼叫端自己的 ISTFT 之後），見 aiaec.h。AC_OLA_ACCUMULATE 沒有 flush（ac_istft_flush() 回 0）。
