ONNX graph boundary（layout 18）

boundary 只有一種：四個 host 特徵輸入加四個 rank-4 state，每個 state 都有同 shape 的 *_out。 版本號在 export_onnx.py 的 LAYOUT_VERSION，與 ulcnet_model_io.h 的 ULCNET_MODEL_IO_LAYOUT_VERSION 互鎖（test_c_descriptor_constants_match_export_contract）。 inference.py calib 與匯出用同一個 wrapper，同一個 process 匯出。

graph 輸入shape內容
error_mag/far_mag/error_cos/error_sin(1,1,K) 各一host 前端產生（stream_features；C ulcnet_model_io_prepare）
key_history/value_history(1,32,D,TA)newest-first：slot 0 是最新一幀，slot d 是 t−d
logit_history(1,32,5,D)oldest-first：frame 4 是最新一幀；score conv 的 5 幀輸入
h_gru(1,4,1,128)subband GRU 0 的兩層，接著 subband GRU 1 的兩層（沿 dim 1 疊；dim 0 是 singleton N，不是疊的軸）

輸出是 output（planar mask (1,2,1,K)）加四個 *_out，每個與同名輸入 shape 完全相同。位移在 graph 內、用輸入端的 Slice 再把新一幀 Concat 進去（K/V 放前面、logit 放後面），沒有 state 輸出由 Slice 產生，所以 runtime 可把每個 *_out 綁到同名輸入的位址、CPU 不搬不複製;export_graph 以 validate_inplace_state_contract（AIAEC/_onnx_contract.py）檢查,任何一項不成立匯出直接失敗。Slice 參數與檢查項目逐條收在 Align-ULCNet 頻域與模型契約。

python3 AIAEC/Align_ULCNet/export_onnx.py --checkpoint ckpt.pth \
    --max-delay-frames 8 --output output/align_ulcnet_d8.onnx --verify
boundary 沒有可選開關：前後端固定在 host，GRU hidden 固定併成單一 h_gru， export 與 calibration CLI 都沒有 layout 旗標。C 端把 state 清零（reset 或拒絕一幀）時，定點 accelerator 自己的 state 緩衝不會跟著變，所以板端 sample 要追蹤 ulcnet_accelerator_adapter_state_generation()（見下節）， 值一變就用量化後的 0 重填 state。第一個 hop 的 state 全為 0（reset 值）；定點 runtime 的「0」是否等於量化後的 0 由量化工具鏈確認，尚未驗證。

延遲與 warm-up

  • NN 演算法 lookahead = 0 hop；zero-init history ≡ offline 左零 padding， 從 reset 開始的 stream 與 whole-utterance forward 等價，無 warm-up 特例。 實測 stream-vs-offline 最差差異：enhanced 4.1e-8 / mask 1.2e-7 / magnitude_mask 6.0e-8 / delay 4.0e-7（test 檔頭記載；tolerances 以 ~10x headroom 釘在 5e-7 / 2e-6 / 1e-6 / 5e-6）。
  • Framing：應用端的 AcStft 用 center=False、每 hop 一幀的 rolling 分析（AEC seam／4ch 路徑同）；centered push 只剩 Python parity gate 使用（mono 範例 pipelines/mono/alignulcnet/main.c 用同一套排程）。端到端 演算法延遲仍是 HOP samples＝16 kHz 256 smp（16 ms）、48 kHz 512 smp（10.67 ms），但它來自 synthesis 的半窗 trim、不是分析排程（ulcnet_process.h 明文）。
  • C 前後處理 vs Python：float-ULP 級（實測 ~2e-5 絕對值，NE10 f32 FFT vs torch double twiddles），非 bit-exact（test_ulcnet_process_c.py 檔頭）。

頻域 API

如何呼叫使用

  1. grid 是 run-time 值：填 UlcnetGridSpec（sample_rate、n_fft、delay_depth 取自匯出該模型的設定）→ ulcnet_grid_make(&grid, &spec) 回 ULCNET_GRID_OK 或第一個失敗的 ULCNET_GRID_ERR_*；hop = n_fft/2、n_bins = n_fft/2+1。函式庫接受 audiolib 建得出 framing 的任何 n_fft；匯出器目前只支援 16 kHz／512 與 48 kHz／1024（SUPPORTED_GRIDS）。
  2. D（delay depth）必須等於匯出該 ONNX 時的 --max-delay-frames：C 端只檢查範圍 ULCNET_MODEL_IO_MIN_D(2)…MAX_D(64)，檢查不出與 graph 不符。D 不跨 grid 沿用（D 數的是 hop）。
  3. framing 由應用端做：用 audiolib 建兩個 AcStft（error、raw far）與一個 AcIstft，組態 ac_stft_config_default(&sc, grid.n_fft)（sqrt-Hann、center 0、spec_scale = ispec_scale = 1），合成端另設 sc.ola = AC_OLA_ENV_NORM（契約寫在 ulcnet_process.h）。FftHandle 與窗表可循序共用；函式庫不持有 window、FFT 或 STFT 物件。
  4. recurrent state 歸應用端（key_history、value_history、logit_history、h_gru；形狀見 Align-ULCNet 頻域與模型契約 的 State 表，函式庫不知道這些形狀）：浮點 host 配四塊 float buffer，把四組（指標，元素數）登錄進 cfg——全登錄或全不登錄，init 與 reset 時清零，每次 frame_finish 整塊檢查有限，不計入 pool 大小與 hash；目標平台不登錄，由加速器持有。
  5. ulcnet_prepost_config_defaults(&cfg, &grid)（grid 被複製）→ 登錄 state → ulcnet_prepost_get_mem_size(&cfg, &req)（req.alignment = 16）→ ulcnet_prepost_init_ex(pool, req.bytes, &cfg, &req)；host 工具可用 _create／_destroy。
  6. 每個 hop（從 hop 0 起一次推論，沒有只暖機不推論的拍）：ac_stft_push_planar×2 → pre_process_freq(err, far) 恆回 1 → frame_open → 加速器 → frame_finish（失敗改 frame_bypass）→ post_process_freq → ac_istft_push_planar。
  7. 目標平台：啟動時先載入量化後的 0 並記下 ulcnet_prepost_state_generation()（新建實例為 0）；之後每次它改變（reset、被拒的 frame_finish）就重填加速器自己的 state。
  8. 重新開始：ulcnet_prepost_reset(p)（清登錄的 state、丟掉未結束的 frame、generation +1；config、登錄與 pool 不動），並自行 ac_stft_reset／ac_istft_reset；結束：_destroy（對 _init 實例是 no-op，登錄的 buffer 與 pool 歸應用端）。
#include <stdlib.h>
#include <string.h>
#include "audio_stft.h"
#include "Align_ULCNet/ulcnet_prepost.h"

extern int npu_run(const UlcnetModelIoInputs *in, UlcnetModelIoOutputs *out);

static void *block(size_t n) { return aligned_alloc(16, (n + 15u) / 16u * 16u); }

/* el[0..3] = key_history、value_history、logit_history、h_gru 的元素數（匯出圖的 state shape 乘積）；
 * D 必須等於匯出該 ONNX 時的 --max-delay-frames。 */
int run_ulcnet(int sample_rate, int n_fft, int D, const size_t el[4],
               const float *err, const float *far, float *out, long hops)
{
    const UlcnetGridSpec spec = { sample_rate, n_fft, D };
    UlcnetGrid grid;
    UlcnetPrepostConfig cfg;
    UlcnetPrepostMemReq req;
    AcStftConfig sc;
    int rc = -1;

    if (ulcnet_grid_make(&grid, &spec) != ULCNET_GRID_OK) return -1;
    if (ulcnet_prepost_config_defaults(&cfg, &grid) != 0) return -1;
    cfg.key_history   = calloc(el[0], sizeof(float));  cfg.key_history_elements   = el[0];
    cfg.value_history = calloc(el[1], sizeof(float));  cfg.value_history_elements = el[1];
    cfg.logit_history = calloc(el[2], sizeof(float));  cfg.logit_history_elements = el[2];
    cfg.h_gru         = calloc(el[3], sizeof(float));  cfg.gru_hidden_elements    = el[3];

    ac_stft_config_default(&sc, grid.n_fft);   /* sqrt-Hann、center 0、spec_scale = ispec_scale = 1 */
    sc.ola = AC_OLA_ENV_NORM;                  /* 合成用；分析忽略 */
    size_t an = ac_stft_get_mem_size(&sc), sy = ac_istft_get_mem_size(&sc);
    void *m0 = block(an), *m1 = block(an), *m2 = block(sy);
    AcStft *err_stft = m0 ? ac_stft_init(m0, an, &sc) : NULL;
    AcStft *far_stft = m1 ? ac_stft_init(m1, an, &sc) : NULL;
    AcIstft *istft   = m2 ? ac_istft_init(m2, sy, &sc) : NULL;

    float *buf = calloc(6u * (size_t)grid.n_bins, sizeof(float));
    float *e_re = buf, *e_im = e_re + grid.n_bins, *f_re = e_im + grid.n_bins;
    float *f_im = f_re + grid.n_bins, *o_re = f_im + grid.n_bins, *o_im = o_re + grid.n_bins;
    void *pool = NULL;
    UlcnetPrepost *p = NULL;
    if (ulcnet_prepost_get_mem_size(&cfg, &req) == 0 && (pool = block(req.bytes)))
        p = ulcnet_prepost_init_ex(pool, (size_t)req.bytes, &cfg, &req);

    if (p && err_stft && far_stft && istft && buf) {
        rc = 0;
        for (long h = 0; h < hops && rc == 0; ++h) {
            UlcnetModelIoInputs xin;
            UlcnetModelIoOutputs xout;
            float *dst = out + h * grid.hop;
            /* err：linear AEC 的 error hop；far：同一輸入 hop 的原始 far（未對齊） */
            ac_stft_push_planar(err_stft, err + h * grid.hop, e_re, e_im);   /* center 0：恆 1 幀 */
            ac_stft_push_planar(far_stft, far + h * grid.hop, f_re, f_im);
            if (ulcnet_prepost_pre_process_freq(p, e_re, e_im, f_re, f_im) != 1 ||
                ulcnet_prepost_frame_open(p, &xin, &xout) != 0) { rc = -1; break; }
            if (npu_run(&xin, &xout) != 0 || ulcnet_prepost_frame_finish(p) != 0)
                ulcnet_prepost_frame_bypass(p);                    /* error 頻譜原樣通過 */
            if (ulcnet_prepost_post_process_freq(p, o_re, o_im) != 0) { rc = -1; break; }
            if (ac_istft_push_planar(istft, o_re, o_im, dst) == 0)   /* 第一個 hop 無輸出 */
                memset(dst, 0, (size_t)grid.hop * sizeof(float));
        }
    }
    ulcnet_prepost_destroy(p);   /* _init 實例：no-op；登錄的 buffer 與 pool 歸應用端 */
    free(pool); free(buf); free(m0); free(m1); free(m2);
    free(cfg.key_history); free(cfg.value_history); free(cfg.logit_history); free(cfg.h_gru);
    return rc;
}

目標平台形式（加速器持有 state）：config_defaults 之後什麼都不登錄，每個 hop 在 frame_open 之後、加速器執行之前比對 generation：

#include <stdint.h>
#include "audio_stft.h"
#include "Align_ULCNet/ulcnet_prepost.h"

extern int  npu_run(const UlcnetModelIoInputs *in, UlcnetModelIoOutputs *out);
extern void npu_fill_state_with_quantized_zero(void);

/* 目標平台（加速器持有 state）：config_defaults 之後不登錄任何 state，四個 view 為 NULL／0。 */
int board_hop(UlcnetPrepost *p, uint32_t *seen)
{
    UlcnetModelIoInputs xin;
    UlcnetModelIoOutputs xout;
    if (ulcnet_prepost_frame_open(p, &xin, &xout) != 0) return -1;
    if (ulcnet_prepost_state_generation(p) != *seen) {      /* reset 或被拒的 frame_finish */
        npu_fill_state_with_quantized_zero();
        *seen = ulcnet_prepost_state_generation(p);
    }
    if (npu_run(&xin, &xout) != 0 || ulcnet_prepost_frame_finish(p) != 0)
        ulcnet_prepost_frame_bypass(p);
    return 0;
}

入口 B（交給 pipeline 的 callback 邊界）：

#include <stdlib.h>
#include "Align_ULCNet/ulcnet_accelerator_adapter.h"

/* 目標平台 runtime：綁定 inputs 的八個張量與 outputs 的五個張量；
 * 每個 *_out 綁在同名 state 輸入的位址，先讀完所有 state 輸入才寫輸出。成功回 0。 */
extern int run_graph(void *user, const UlcnetModelIoInputs *in, UlcnetModelIoOutputs *out);

/* 給 pipeline 用的 UlcnetModel（callback 邊界）。grid.delay_depth 必須等於匯出該 ONNX 時的
 * --max-delay-frames；descriptor 只做範圍檢查。 */
UlcnetAcceleratorAdapter *make_adapter(const UlcnetGrid *grid, void *runtime, UlcnetModel *model)
{
    UlcnetModelIoDescriptor desc;
    size_t bytes = 0, align = 0;

    if (ulcnet_model_io_descriptor_default(grid, &desc) != 0) return NULL;   /* grid 無效 */
    /* 從 ONNX／JSON metadata 載入的 descriptor 用 ulcnet_model_io_descriptor_validate(grid, &desc) 檢查 */
    if (ulcnet_accelerator_adapter_get_mem_size(&desc, &bytes, &align) != 0) return NULL;

    void *mem = aligned_alloc(align, (bytes + align - 1) / align * align);  /* 板端：靜態 arena */
    if (!mem) return NULL;
    UlcnetAcceleratorAdapter *a = ulcnet_accelerator_adapter_init(
        mem, bytes, &desc, NULL /* 不登錄 state：加速器自己持有 */, run_graph, runtime);
    if (!a) { free(mem); return NULL; }
    *model = ulcnet_accelerator_adapter_model(a);   /* 交給 pipeline；adapter 與 pool 須活得比 pipeline 久 */
    return a;
}

三段程式已在暫存副本以 -std=c11 -Wall -Wextra -Wpedantic -Werror 編譯，並以替身加速器（mask 恆為 1）在 16 kHz／512 與 48 kHz／1024 各跑 40 hop：輸出等於 error 延後一個 hop。npu_run／run_graph／npu_fill_state_with_quantized_zero 由目標平台提供。UlcnetModel.infer 回非 0 或輸出非有限時，pipeline 會改走 identity（輸出 linear error；這是未經 guard 的 analysis residual，即 formed_hop／error_spec，在 lib/aec 渲染 guard 作用的 hop 上可能大於 capture）；io_descriptor 必須發布，且須比 pipeline 活得久（pipeline 只複製 struct）。

Far 分支與校正

far branch 與 PTQ calibration

far branch 契約：production 固定用 caller 的 raw far （PBFDKF 的 aligned 副本只用來形成 linear error，對齊由模型的 TA block 負責）。 export_onnx.py 分開寫 training_far_input_mode 與 far_input_mode，兩者都必須是 raw_far；C descriptor 只接受 ULCNET_FAR_RAW，production pipeline 沒有 runtime far-mode setter，raw/aligned 比較只留在 sweep 工具。
PTQ calibration：可直接用訓練域的 linear_error + raw_far； report 會把 calibration_far_input_mode 與 deployment_far_input_mode（兩者皆為 raw_far）分開記錄。D 不改權重，但會改 K/V window shape 與 host RAM，所以 calibration 的 D 必須和該份 ONNX export 相同。
calibration 的 linear_error 來源與 stamp：校正張量是某一版前端（aiaec-linear-error-v4，AEC 分析 seam）的輸出， 所以 inference.py calib 預設的 --primary-dir linear_error WAV 必須由該前端產生並帶 stamp： 目錄內的 linear_error.contract.json，或其旁、記有契約本體的 linear_error.done.json corpus ledger （只有 fingerprint 的舊 ledger 視為無 stamp；沒有涵蓋目錄內全部 chunk 序列的 ledger＝半新半舊的 corpus，被拒）。 stamp 必須等於 checkpoint 自己的 linear_aec 契約；退役的版本或 aec_behavior_hash、契約不符、 stamp 內部不一致、seam 不是 analysis_formed，都在匯出 graph 與寫 artifact 之前被拒。 完全沒有 stamp 也被拒（訊息含 “carry no front-end stamp”），除非加 --allow-unstamped-linear-error：它只放行這一種情況， 會警告並在 report 記 linear_error_stamp.origin = unstamped_override，且不能與 --primary-is-mic 併用。 --primary-is-mic 是自行 stamp 的路徑：--primary-dir 放 RAW mic WAV，由 checkpoint 對應的 frozen PBFDKF 在同 process 推導，寫入 <output>_linear_error/ 並附最後才寫的 linear_error.contract.json， manifest 記 primary_source = raw_mic_via_frozen_pbfdkf。 calibration report（BIN 的 manifest.json、NPZ 的 <name>.calib.json）帶 linear_aec_contract_version、aec_behavior_hash、linear_aec_contract_hash、error_input_seam 與 linear_error_stamp（sidecar／corpus_ledger／derived_in_process／unstamped_override）； PTQ/calib_analyze.py 在載入與寫出挑選結果時，拒絕 stamp 缺失、契約版本不是目前版本或 hash 已退役的 Align-ULCNet artifact， 修法是重跑 inference.py calib。inference.py --input-is-linear-error 只供評估，不檢查所給 WAV 的來源。 這些檢查都在 Python 端與已提交的測試，C 端不會依前端版本拒絕模型。
訓練前端契約：layout 只描述 tensor/state 邊界，不辨識 checkpoint 是用哪一版前端訓練的。 export_onnx.py 把 checkpoint 的 linear_aec 契約原樣寫進 ONNX/JSON metadata： linear_aec_contract_version、aec_behavior_hash，以及 error_input_seam = analysis_formed（error 輸入是 AEC 的分析 seam：formed_hop／beam.spectrum， 不是 rendering base）。整合端可以把 linear_aec_contract_version 與 ulcnet_model_io.h 的 ULCNET_MODEL_IO_FRONTEND_CONTRACT（aiaec-linear-error-v4）比對或記錄 （例如分辨從已退役的 v3 checkpoint 匯出的圖）；C 端 init 不會依前端拒絕任何圖， 強制檢查在 Python 端（export、inference、calibration）與已提交的測試。這個常數不在 descriptor 內，也不是 layout 升版；測試把它釘在 LINEAR_AEC_CONTRACT_VERSION。沒有 linear_aec 契約的 checkpoint 不能匯出。

layout 18

model-I/O layout 是 v18 （ULCNET_MODEL_IO_LAYOUT_VERSION = 18；四個 state 是完整 window，每個 *_out 就地綁定到輸入位址； RETIRED_LAYOUT_VERSIONS = 3–17，不得重用），其他 layout 產出的每一份 ONNX/JSON descriptor 會在 ulcnet_model_io_descriptor_validate() 卡在 layout_version，ulcnet_accelerator_adapter_init() 回 NULL。 state shape：K/V 是 (1,32,D,TA)、logit 是 (1,32,5,D)、兩顆 GRU hidden 併成單一 h_gru (1,4,1,128)；output 元素數是 2·K，所以版本號是唯一能攔下舊板綁新圖的閘門。 D 不改權重；checkpoint 與 dataset 不因 layout 而需要重新訓練或重新生成， 但 calibration 資料與量化結果要對應該份 graph，加速器程式要對應該份 descriptor。

rolling 分析與 center 0

rolling 分析 AcStft 的 center 0（應用端以 ac_stft_config_default(&sc, grid.n_fft) 建立， 組態寫在 ulcnet_process.h；DeepVQE-S 用同一組態）：center=False， 第一次 push 起每次恰一幀（首幀前半段是歸零的歷史），與 centered center 1 的 AcStft 對同一個 hop 吐出的最後一幀位元相同——這個幾何下 （win = n_fft、hop = n_fft/2、共用同一張 sqrt-Hann 表）centered 第 k 幀與 non-centered 第 k−1 幀 蓋的是同一段樣本、同一個窗，centered 排程只是在開頭多發一幀 reflect 前綴。 test_ulcnet_prepost_c.py 的 equiv 案例逐 hop memcmp 釘住這件事 （400 hop，真的跑 0/2/1 排程），所以是實測；hop 0 的 centered 排程 0 幀，兩者自第二個 hop 起對得起來。排程由建立 AcStft 時的 center 決定，同一個物件不會混用兩種排程。 centered（center 1）沒有出貨 pipeline 使用：pipelines/ulcnet/ulcnet_nn_stage.c （mono 與 4ch 範例共用）以 center 0 的 AcStft 呼叫 ac_stft_push_planar()；只剩上述 parity 測試還在用 center 1 當比對基準。

graph 內位移與就地綁定的驗證

輸出是 output（planar mask (1,2,1,K)）加 key_history_out/value_history_out/ logit_history_out/h_gru_out，每個 *_out 與同名輸入 shape 完全相同。 位移在 graph 內、用輸入端的 Slice：K/V 取輸入的 slot 0..D−2（Slice axis 2，start 0、end D−1，step 1） 再把新一幀 Concat 在前面；logit 取輸入的 frame 1..4（start 1、end 5）再把新的一列 Concat 在後面。 Concat 的結果同時是 attention 的候選與 *_out，沒有任何 state 輸出由 Slice 產生；被丟掉的那一格 （K/V 的 slot D−1、logit 的 frame 0）只用來讓輸入與輸出 shape 相同，graph 不讀它。

因此 runtime 可以把每個 *_out 綁到同名輸入的位址， CPU 不搬、不複製。export_graph 對寫出的檔案呼叫 validate_inplace_state_contract （AIAEC/_onnx_contract.py）：每對 state 的 shape 相同且 rank 為 4、每個 window 輸入恰有一個 Slice 消費者 （axis 2、step 1、end 為窗內整數、保留 N−1 幀）、沒有 state 輸出由 Slice 產生，metadata 帶 state_binding = in_place_same_address；任何一項不成立匯出直接失敗。
