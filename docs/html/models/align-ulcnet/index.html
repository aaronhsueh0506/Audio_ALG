Audio_ALG / 模型開發與部署

Align-ULCNet

輸入是線性 AEC 的 error（殘差）hop、原始 far 參考，以及每個模型 hop 一筆的對齊事件（changed、solid）。殘差與 far 都是滿幅約 1.0 的 float，輸出是 int16 PCM（或頻譜，見下方）。客戶只設三個值：sr、fft、hop_in。每包張數 N = hop_in / (fft / 2)，grid、graph 與其餘參數由產品登錄表決定；介面在 aiaec.h。

支援的組態

sr / ffthop_in → N正式登錄表測試登錄表（僅主機測試）
16000 / 256128 → 1無 graph，init 拒絕可建構
16000 / 2561024 → 8無 graph，init 拒絕可建構（封包 graph）
16000 / 512256 → 1無 graph，init 拒絕可建構
16000 / 5122048 → 8無 graph，init 拒絕無，init 拒絕

正式登錄表下三種可用的 grid 都還沒有交付的 graph，aiaec_get_mem_size()／aiaec_init() 回 AIAEC_ERR_FRAMES_PER_CALL，不會呼叫任何 SDK。測試登錄表只存在於主機測試用的測試建置，不在交付的 archive 裡，以佔位路徑讓主機測試能走完整個 API，不代表有 graph。表外的 (sr, fft) 回 AIAEC_ERR_GRID；不是模型 hop 倍數的 hop_in（例如 16 kHz／256 的 129）回 AIAEC_ERR_IN_HOP。

建置與連結

Align-ULCNet 的單模型產品用 AIAEC_MODEL=align 建置，連結 libaiaec.a、該款 backend libulcnet_stream.a 與 audiolib 的 libaudio_common.a。路徑一律用 print-lib-path 查，且查詢要帶與建置相同的 AIAEC_MODEL、SIMD、CC、EXTRA_CFLAGS，否則得到另一組設定的路徑。

已有自己的線性 AEC 的 pipeline（殘差、raw far、事件直接傳入，不需要前端）：

AUDIOLIB=/path/to/audiolib
COMMON_LIB="$(make -s -C $AUDIOLIB/common lib print-lib-path | tail -1)"
make -C stream/aiaec AIAEC_MODEL=align COMMON_DIR=$AUDIOLIB/common COMMON_LIB="$COMMON_LIB" lib
make -C stream/aiaec/ulcnet COMMON_DIR=$AUDIOLIB/common COMMON_LIB="$COMMON_LIB" lib
cc app.c -Istream/aiaec \
   "$(make -s -C stream/aiaec AIAEC_MODEL=align COMMON_DIR=$AUDIOLIB/common COMMON_LIB="$COMMON_LIB" print-lib-path)" \
   "$(make -s -C stream/aiaec/ulcnet COMMON_DIR=$AUDIOLIB/common COMMON_LIB="$COMMON_LIB" print-lib-path)" \
   "$COMMON_LIB" -lm -o app

獨立 sample（沒有自己的 AEC）另連結前端 libaiaec_front.a 與它依賴的 AEC 函式庫；libaiaec.a 本身不依賴 AEC。每個 make 都帶同一組 COMMON_DIR／COMMON_LIB，使 front、libaiaec.a、backend 與 AEC 的 archive 都對齊同一份 audiolib：

AEC=/path/to/AEC/c_impl
make -C stream/aiaec/front COMMON_DIR=$AUDIOLIB/common COMMON_LIB="$COMMON_LIB" lib
make -C $AEC COMMON_DIR=$AUDIOLIB/common COMMON_LIB="$COMMON_LIB" lib
cc app.c -Istream/aiaec -Istream/aiaec/front \
   "$(make -s -C stream/aiaec/front COMMON_DIR=$AUDIOLIB/common COMMON_LIB="$COMMON_LIB" print-lib-path)" \
   "$(make -s -C stream/aiaec AIAEC_MODEL=align COMMON_DIR=$AUDIOLIB/common COMMON_LIB="$COMMON_LIB" print-lib-path)" \
   "$(make -s -C stream/aiaec/ulcnet COMMON_DIR=$AUDIOLIB/common COMMON_LIB="$COMMON_LIB" print-lib-path)" \
   "$(make -s -C $AEC COMMON_DIR=$AUDIOLIB/common COMMON_LIB="$COMMON_LIB" print-lib-path | tail -1)" \
   "$COMMON_LIB" -lm -o app

archive 的順序是前端、libaiaec.a、backend、AEC、audiolib；前端的 aiaec_front_preprocess() 引用 libaiaec.a 的 aiaec_preprocess()，所以 libaiaec.a 必須排在前端之後。漏掉 libulcnet_stream.a 會缺 ulcnet_stream_*，漏掉 AEC archive 會缺 aec_*。預設 AIAEC_MODEL=both 的 libaiaec.a 同時引用兩款 backend，只連 Align 的 backend 會缺 deepvqe_stream_*。

Graph 接線

aiaec_init() 只回報選出的圖（AiaecInfo.graph_path）與尾端長度，不回報埠表。每個已交付 graph 的完整接線——訊號與 head 的 shape、四組 state 的 shape——放在 stream/aiaec/ai3_model_io_alignulcnet.h：一個描述產生器依 (sr, fft, N) 的 grid 列（bins、ta_bins、延遲深度 D）產生一列，layout 18 與 19 共用同一段邏輯，N=1 四個訊號、N>1 五個。共用的接線程式 stream/common/ai3_model_io.h（由 make -C stream/common test-model-io 測試）負責列的展開、state 配對、開圖後的埠檢查、input buffer 大小與送件前的核對。兩者與 SDK 無關、只有標頭，aiaec.h 不引用，函式庫不含接線；sample 加 -I stream/common -I stream/aiaec並編譯 stream/common/stream_bind.c。沒有對應列的組態，或與 init 選出的 graph 不符，由 sample 的啟動檢查在任何 SDK 呼叫之前拒絕。

圖的埠順序只有一條規則：輸入 = 訊號輸入，再接 state 輸入；輸出 = head 輸出，再接 state 輸出；第 k 組 state 是輸入 signal_in_count + k 與輸出 head_out_count + k，兩端同形狀。sample 依數量迴圈處理，不比對名稱：

Nlayoutsignal_in_counthead_out_count輸入／輸出埠數state 組數
1184（error_mag、far_mag、error_cos、error_sin）1（複數 mask）8 ／ 54
>1195（上列四個，再加最後一個訊號輸入 frame_reset，形狀 [1, 1, 1, N]）19 ／ 54

signal 與 head 的 shape（bins = fft / 2 + 1）：四個特徵訊號 [1,1,N,bins]，N>1 的 frame_reset [1,1,1,N]，複數 mask [1,2,N,bins]。四組 state 依序是 key_history、value_history [1,32,D,ta_bins]、logit_history [1,32,5,D]、h_gru [1,4,1,128]，其中 D = ceil(0.5 s / hop)、ta_bins = (bins + 9) / 10：

組態binsDta_binssignal 數
16k／256／N=112963134
16k／256／N=812963135
16k／512／N=125732264

frame_reset 是 stream 依逐 hop 事件產生的控制值（N 個 0.0／1.0，事件 hop 為 1.0），放在 AiaecWork.inputs[4]；sample 不判斷事件，把它當第五個普通訊號輸入依位置搬進加速器，沒有特例。AiaecWork.inputs[0..3] 與 outputs[0] 的 shape 與元素數就是上表同一列；state 不在 AiaecWork 裡。括號內的名稱是匯出器的 ONNX 名稱，C 端與 sample 不讀名稱。

初始化與每包呼叫

sample 的演算法流程只有一次啟動，之後每包 pre → sample 自己的 AI3 → post。啟動時 aiaec_get_mem_size() → aiaec_init() 備好 pool 並填 AiaecInfo（圖路徑、trim_samples、queue_frames、tail_zero_blocks 四欄；N 由 sample 從 config 算：N = hop_in / (fft / 2)）；起始 generation 由 aiaec_state_generation() 取得。AI3 的開圖、送張量、執行、讀回與 state 緩衝是 sample 自己的。獨立 sample 的線性 AEC 前端與 pre 合成一次呼叫 aiaec_front_preprocess()；前端的延遲策略是內部預設（BALANCED、線上 matched filter、5 組），不是客戶選項。

AiaecConfig cfg = { sr, fft, hop_in };             /* 例：{ 16000, 256, 1024 } */
StreamMemReq req;
if (aiaec_get_mem_size(&cfg, &req) != AIAEC_OK) return -1;   /* 未登錄組態在此被拒 */
void *pool = alloc_aligned(req.alignment, req.bytes);
AiaecCtx *ctx;
AiaecInfo info;                                    /* graph_path、trim_samples、queue_frames、tail_zero_blocks */
int rc = aiaec_init(&cfg, pool, req.bytes, &ctx, &info);   /* 0 或負的 AIAEC_ERR_* */
if (rc != AIAEC_OK) { log(aiaec_status_text(rc)); return -1; }

/* 獨立 sample：線性 AEC 前端只吃同一個 cfg（pipeline 自帶 AEC 時略過，見下） */
int err = AIAEC_OK;
size_t front_bytes = aiaec_front_get_mem_size(&cfg);          /* 0：被拒 */
AiaecFront *front = aiaec_front_init(alloc_aligned(AIAEC_FRONT_ALIGNMENT, front_bytes), front_bytes, &cfg, &err);

/* sample 的模型設定：這個 grid 與 N 的接線列（N=1 四個訊號，N>1 多一個 frame_reset）；沒有列就在開圖前拒絕 */
int n = ai3_model_io_frames(cfg.fft, cfg.hop_in);  /* N = hop_in / (fft / 2) */
Ai3ModelIoConfig model;
if (ai3_model_io_alignulcnet_find(cfg.sr, cfg.fft, n, &model) != AI3_MODEL_IO_OK) return -1;

open_graph(info.graph_path);                       /* sample 的 AI3 */
char msg[160];
if (ai3_model_io_check_ports(&model, din, n_in, dout, n_out, msg, sizeof msg) != STREAM_PORT_OK) return -1;
unsigned seen = aiaec_state_generation(ctx);

while (read_blocks(mic, far, hop_in)) {
    AiaecWork work;
    /* 線性 AEC，再接 pre；mic、far 各 hop_in 個 int16 */
    if (aiaec_front_preprocess(front, ctx, mic, far, &work) != AIAEC_OK) return -1;
    int ai_rc = 0;
    if (work.action == AIAEC_SUBMIT) {
        int chk;
        AI3_MODEL_IO_CHECK_WORK(chk, &model, &work);   /* work 的數量與 shape 必須等於這一列 */
        if (chk != AI3_MODEL_IO_OK) ai_rc = -1;    /* 不符：不送件，仍呼叫 post */
        else {
            if (work.state_generation != seen) { clear_state_buffers(); seen = work.state_generation; }
            ai_rc = run_ai3(&work);                /* 填 work.inputs（含 N>1 的 frame_reset），執行，讀回 work.outputs[0]（複數 mask） */
        }
        if (ai_rc != 0) clear_state_buffers_before_next_run();
    }                                              /* BYPASS：不呼叫加速器 */
    if (aiaec_postprocess(ctx, ai_rc, pcm_out) != AIAEC_OK) return -1;   /* 兩種 action 都剛好呼叫一次 */
    write_block(pcm_out, hop_in);
}

已有自己的線性 AEC 的 pipeline 略過 front，把殘差、raw far 與事件直接填進輸入，再呼叫 aiaec_preprocess()，中間不經 int16：

AiaecAlignEvent ev[N];                             /* 每個模型 hop 一筆，最舊在前 */
AiaecInput in = { .kind = AIAEC_INPUT_ALIGN_ULCNET, .samples = hop_in };
in.u.align_ulcnet.residual_in = residual;          /* 線性 AEC 的 float error hop */
in.u.align_ulcnet.far_in      = raw_far;           /* 同一 hop 的原始 far */
in.u.align_ulcnet.events      = ev;
in.u.align_ulcnet.event_count = N;

aiaec_init() 回 0 或負的 AIAEC_ERR_*，pool 小於 aiaec_get_mem_size() 的位元組數或未對齊時回 AIAEC_ERR_POOL，較大的 pool 可以。aiaec_preprocess() 成功回 AIAEC_OK（0），是否要跑加速器看 work.action。每包 pre／post 只交換這一包的特徵（前四個訊號輸入；N>1 的最後一個訊號輸入是 frame_reset）與模型 head（複數 mask）。開圖後、第一次執行前，共用接線程式的 ai3_model_io_check_ports()（內部呼叫 SDK 無關的檢查器 stream_check_ports()，在 stream/common，libaiaec.a 不含它）檢查每個埠的格式、軸、stride、容量與 state 配對；每包送件前 AI3_MODEL_IO_CHECK_WORK 再核對 work 的數量與 shape。N=8 的每一包恆為一次 SUBMIT；N=1 時事件 hop 是 BYPASS。

State

  • recurrent state 留在 AI3 的 buffer。每對 state 輸入與輸出依位置（輸入 signal_in_count + k 與輸出 head_out_count + k）綁同一塊 buffer；Align-ULCNet 有 4 對。
  • 定點 state 埠兩端的 zero_point 都必須是 0（清零用位元組填 0，只有 zero_point 0 時才等於量化後的 0）。5/5、0/5、5/0 都在第一次送件前被埠檢查（stream_check_ports()）以 STREAM_PORT_ERR_STATE_ZERO_POINT（-110）拒絕；float 的 state 埠不看 zero_point。
  • init 時每塊 state buffer 清零一次（memset 加 cache flush）。正常連續推論不碰 state，每包只交換特徵與 head。
  • 函式庫只在 reset 與輸出被拒（非有限）時讓 work.state_generation 改變；sample 看到 generation 改變就清。回報失敗（infer_status 非 0）的一包只旁路該包，generation 不動，所以 sample 在任何失敗的一包之後，也要在下一次實際送件前自行再清一次。N>1 封包的事件 hop 由 graph 內的 frame_reset 重設模型 state，generation 不變，host 不需要清 buffer。

對齊事件

事件 hop 是 changed 為真，或 solid 由假轉真（前面已有 hop；前一個 hop 的 solid 跨包延續）。事件 hop 的模型 state 重設，該 hop 的輸出是殘差頻譜不變。各入口的行為：

入口N=1N=8（封包 graph）
aiaec_*（PCM → PCM）事件 hop 是 BYPASS，不呼叫加速器；stream 自己的分析與 ISTFT 在該 hop 重啟，該 hop 的 PCM 輸出恰為靜音，前一個輸入 hop 的音訊不輸出。一包恆為一次 SUBMIT，graph 內以 frame_reset（0.0／1.0）重設 state 並直通該 hop；stream 自己的 STFT 分析與 ISTFT 合成在該 hop 重啟，與 N=1 在同一位置。PCM 輸出與同樣事件的 N=1 逐樣本相同，事件 hop 同樣恰為靜音。
_spec（PCM → 頻譜）同 PCM 家族的分析重啟；ISTFT 在呼叫端。重啟的 hop 同樣記在 work.synthesis_restart_mask，外部 ISTFT 要在推入這些 hop 的增強頻譜之前先 ac_istft_reset()，輸出才等於 PCM 家族。分析重啟同 PCM 家族；work.synthesis_restart_mask 的 bit k 是第 k 個 hop（最舊為 0），重設規則同 N=1。
_freq（頻譜 → 頻譜，aiaec）只重啟模型；呼叫端的分析器與 ISTFT 不重啟，overlap 連續。同 N=1：只有模型在 graph 內重設，分析與 ISTFT 的 overlap 連續。不要為此重設 ISTFT。
pipeline stage（mono、4ch、live3 經 ulcnet_nn_stage）只重啟模型；stage 外的分析器與 ISTFT 不重啟，overlap 連續。不適用：stage 只接受一幀一包的 graph，封包 graph（layout 19）在 ulcnet_nn_stage_set_model() 被拒（回 -1）。
  • N=8 的事件由 graph 處理，generation 不變，一包仍是一次 AI3 呼叫。stream 把事件寫成 frame_reset：包內第 3 個 hop 是事件時為 0 0 1 0 0 0 0 0，sample 原樣搬進第五個訊號輸入。24 個 hop、第 3 個 hop 有事件的情境，N=1 送件 23 次（事件 hop 是 BYPASS，不送件，仍呼叫 post），N=8 每個完整包送一次、共 3 次。
  • PCM 入口（aiaec_* PCM 家族，以及 _spec 加上外部 ISTFT 重設）每個事件少一個 hop 的音訊：事件 hop 輸出恰為靜音，前一個輸入 hop 不會輸出。需要連續訊號時改用 _freq 或 pipeline stage；Python 參考實作走的是 _freq 流程。
  • 事件由線性 AEC 的 delay 狀態轉成：CHANGED 同時設 changed 與 solid，LOCKED 只設 solid，UNLOCKED 兩者皆 0。CHANGED 的下一個 hop 是 LOCKED，不會再觸發第二個事件；aiaec_front 與各 pipeline 都用這個對應。
  • 執行失敗或加速器輸出非有限時為 fail-open：線性 AEC 的殘差頻譜不變地通過，模型失敗不會比沒有模型更糟。

Python 的事件重播

C 的事件由線性 AEC 的 delay 狀態逐 hop 給出。Python 的線性 AEC 沒有這個存取器，無法從音訊推出事件，只能從記錄檔重播：inference.py 與 inference.py calib 的 --events PATH，N=1 與 N=8 共用同一條邊緣規則。記錄檔每個真實模型 hop 一筆 (changed, solid)，筆數等於 ceil(樣本數 / hop_len)：

格式內容
.json{"schema": "aiaec-align-events-v1", "events": [[changed, solid], ...]}、單純的 list，或 {"changed": 0, "solid": 1} 項目
.csv標頭 changed,solid（可有從 0 起算的 hop 欄）
.npz一維整數陣列 changed 與 solid

Python 沿用 _freq 的流程：STFT 與 ISTFT 在事件 hop 繼續跑，所以事件 hop 附近的 Python PCM 與 C 的 PCM 家族、_spec 不同；與 C 的 _freq 才是同一個流程。沒有給 --events 時不會有任何事件。格式細節與行為見 alignment.md 與 README。

延遲與檔案尾端

trim_samples 是輸出相對輸入的總延遲，以最終 PCM 的樣本數計（_spec、_freq 是呼叫端自己的 ISTFT 之後），三個家族相同：只有 stream 自己的一個框化 hop（model_hop = fft / 2），與 N 無關。queue_frames 是模型佇列單獨保存的 frame 數，Align-ULCNet 在任何 N 都是 0。

組態model_hoptrim_samplesqueue_framestail_zero_blocks
16 kHz／256／N=112812801
16 kHz／256／N=812812801
16 kHz／512／N=125625601

trim_samples 單位是樣本，queue_frames 單位是 frame。處理檔案時，把最後一包補成完整 hop_in（零補的部分算進送出的包數），再用同一組前端／pre／AI3／post 送 info.tail_zero_blocks 包全零，輸出從頭去掉 info.trim_samples 個樣本，只保留輸入長度。外部 ISTFT 的 AC_OLA_ACCUMULATE 沒有 flush，不能靠 ac_istft_flush() 補尾，照原排程推全零。細節見 aiaec.h 的 "Tail"。

  • 主機替身：make -C stream/aiaec test 涵蓋 catalog 拒絕順序、PCM／_spec／_freq 三個家族、N=8 封包（含事件與 N=1 逐樣本對照）、work 的形狀與 frame_reset 值，以及兩個單模型建置。替身加速器自己實作 frame_reset 語意，不是 AI3 的圖。

  • work 對匯出圖（不跑推論）：AIAEC/tests/test_aiaec_bind_info_pin.py 以隨機權重匯出 16k／256 N=1、N=8 與 16k／512 N=1，依位置比對三個家族真實 aiaec_preprocess*() 給出的 AiaecWork 與匯出圖的訊號輸入、head 輸出（N=1：4 個訊號；N=8：5 個，frame_reset 為最後一個）與形狀，檢查匯出器的 ONNX 名稱順序符合上述規則（含 state 兩端同 shape），並固定 N=8 第 3 個 hop 事件的 frame_reset 為 00100000、N=1 事件 hop 是沒有任何 tensor 的 BYPASS。函式庫不保存 state 的 shape；模型設定各列（ai3_model_io_alignulcnet.h）同一個測試用 make -C stream/aiaec model-io-dumper 傾印，逐列比對全新匯出的圖（layout 版本、埠數與順序、各輸入輸出 shape、state 名稱與順序、兩端同 shape、N>1 時 frame_reset 為最後一個訊號），列集合恰為匯出的案例；C 端的列對 AiaecWork 由 test-aiaec-model-io 檢查。
