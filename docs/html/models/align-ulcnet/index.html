Audio_ALG / 模型開發與部署

Align-ULCNet

輸入是線性 AEC 的 error（殘差）hop、原始 far 參考，以及每個模型 hop 一筆的對齊事件（changed、solid）。殘差與 far 都是滿幅約 1.0 的 float，輸出是 int16 PCM（或頻譜，見下方）。客戶只設三個值：sr、fft、hop_in。每包張數 N = hop_in / (fft / 2)，grid、graph 與其餘參數由產品登錄表決定；介面在 aiaec.h。

支援的組態

sr / ffthop_in → N正式登錄表測試登錄表（僅主機測試）
16000 / 256128 → 1有登錄的 graph，接受可建構
16000 / 2561024 → 8有登錄的 graph，接受可建構（封包 graph）
16000 / 512256 → 1有登錄的 graph，接受可建構
16000 / 5122048 → 8無 graph，init 拒絕無，init 拒絕
48000 / 1024512 → 1有登錄的 graph，接受可建構
48000 / 10241024 → 2有登錄的 graph，接受可建構（封包 graph）

沒有交付 graph 的組態（16 kHz／512 的 N=8、48 kHz／1024 的 N=4 以上等未登錄的 N），aiaec_get_mem_size()／aiaec_init() 回 AIAEC_ERR_FRAMES_PER_CALL，不會呼叫任何 SDK。測試登錄表只存在於主機測試用的測試建置，不在交付的 archive 裡，以佔位路徑讓主機測試能走完整個 API，不代表有 graph。表外的 (sr, fft) 回 AIAEC_ERR_GRID；不是模型 hop 倍數的 hop_in（例如 16 kHz／256 的 129）回 AIAEC_ERR_IN_HOP。

板端 graph 路徑：16k／256（N=1、N=8）、16k／512／N=1 與 48k／1024（N=1、N=2）各列共用 /mnt/sd/audio_model/16x16/alignulcnet/nvt_model.bin（登錄表裡只寫一次）。卡上每個模型只放一張 graph，只能在它自己的 grid 與 N 跑：另一個 grid 的 graph 在開圖後被 sample 的 graph_io_check_ports() 拒絕，不會執行任何推論。sample alg_ai3_alignulcnet.c 的預設命令列（不帶選項，等於 --sample-rate 16000 --fft-size 256 --hop-in 128）是 16 kHz／fft 256／hop_in 128（N=1，129 bins，D = 63）；--fft-size 512 選 16 kHz／512／256（257 bins，D = 32）。

建置與連結

Align-ULCNet 的單模型產品用 AIAEC_MODEL=align 建置，連結 libaiaec.a、該款 backend libulcnet_stream.a 與 audiolib 的 libaudio_common.a。路徑一律用 print-lib-path 查，且查詢要帶與建置相同的 AIAEC_MODEL、SIMD、CC、EXTRA_CFLAGS，否則得到另一組設定的路徑。

已有自己的線性 AEC 的 pipeline（殘差、raw far、事件直接傳入，不需要前端）：

AUDIOLIB=/path/to/audiolib
COMMON_LIB="$(make -s -C $AUDIOLIB/common lib print-lib-path | tail -1)"
make -C stream/aiaec AIAEC_MODEL=align COMMON_DIR=$AUDIOLIB/common COMMON_LIB="$COMMON_LIB" lib
make -C stream/aiaec/ulcnet COMMON_DIR=$AUDIOLIB/common COMMON_LIB="$COMMON_LIB" lib
cc app.c -Istream/aiaec -Istream/common -I$AUDIOLIB/common \
   "$(make -s -C stream/aiaec AIAEC_MODEL=align COMMON_DIR=$AUDIOLIB/common COMMON_LIB="$COMMON_LIB" print-lib-path)" \
   "$(make -s -C stream/aiaec/ulcnet COMMON_DIR=$AUDIOLIB/common COMMON_LIB="$COMMON_LIB" print-lib-path)" \
   "$COMMON_LIB" -lm -o app

獨立 sample（沒有自己的 AEC）另連結前端 libaiaec_front.a 與它依賴的 AEC 函式庫；libaiaec.a 本身不依賴 AEC。每個 make 都帶同一組 COMMON_DIR／COMMON_LIB，使 front、libaiaec.a、backend 與 AEC 的 archive 都對齊同一份 audiolib：

AEC=/path/to/AEC/c_impl
make -C stream/aiaec/front COMMON_DIR=$AUDIOLIB/common COMMON_LIB="$COMMON_LIB" lib
make -C $AEC COMMON_DIR=$AUDIOLIB/common COMMON_LIB="$COMMON_LIB" lib
cc app.c -Istream/aiaec -Istream/aiaec/front -Istream/common -I$AUDIOLIB/common \
   "$(make -s -C stream/aiaec/front COMMON_DIR=$AUDIOLIB/common COMMON_LIB="$COMMON_LIB" print-lib-path)" \
   "$(make -s -C stream/aiaec AIAEC_MODEL=align COMMON_DIR=$AUDIOLIB/common COMMON_LIB="$COMMON_LIB" print-lib-path)" \
   "$(make -s -C stream/aiaec/ulcnet COMMON_DIR=$AUDIOLIB/common COMMON_LIB="$COMMON_LIB" print-lib-path)" \
   "$(make -s -C $AEC COMMON_DIR=$AUDIOLIB/common COMMON_LIB="$COMMON_LIB" print-lib-path | tail -1)" \
   "$COMMON_LIB" -lm -o app

archive 的順序是前端、libaiaec.a、backend、AEC、audiolib；前端的 aiaec_front_preprocess() 引用 libaiaec.a 的 aiaec_preprocess()，所以 libaiaec.a 必須排在前端之後。漏掉 libulcnet_stream.a 會缺 ulcnet_stream_*，漏掉 AEC archive 會缺 aec_*。預設 AIAEC_MODEL=both 的 libaiaec.a 同時引用兩款 backend，只連 Align 的 backend 會缺 deepvqe_stream_*。

Graph 接線

aiaec_init() 只回報選出的圖（AiaecInfo.graph_path），不回報埠表。每個已交付 graph 的完整接線——訊號與 head 的 shape、四組 state 的 shape——放在 stream/aiaec/graph_io_alignulcnet.h：一個描述產生器依 (sr, fft, N) 的 grid 列（bins、ta_bins、延遲深度 D）產生一列，layout 18 與 19 共用同一段邏輯，N=1 四個訊號、N>1 五個。共用的接線程式 stream/common/graph_io.h（由 make -C stream/common test-graph-io 測試）負責列的展開、state 配對、開圖後的埠檢查、input buffer 大小與送件前的核對。兩者與 SDK 無關、只有標頭，aiaec.h 不引用，函式庫不含接線；sample 加 -I stream/common -I stream/aiaec並編譯 stream/common/stream_bind.c。沒有對應列的組態，或與 init 選出的 graph 不符，由 sample 的啟動檢查在任何 SDK 呼叫之前拒絕。

圖的埠順序只有一條規則：輸入 = 訊號輸入，再接 state 輸入；輸出 = head 輸出，再接 state 輸出；第 k 組 state 是輸入 signal_in_count + k 與輸出 head_out_count + k，兩端同形狀。sample 依數量迴圈處理，不比對名稱：

1184（error_mag、far_mag、error_cos、error_sin）1（複數 mask）8 ／ 54
>1195（上列四個，再加最後一個訊號輸入 frame_reset，形狀 [1, 1, 1, N]）19 ／ 54

signal 與 head 的 shape（bins = fft / 2 + 1）：四個特徵訊號 [1,1,N,bins]，N>1 的 frame_reset [1,1,1,N]，複數 mask [1,2,N,bins]。四組 state 依序是 key_history、value_history [1,32,D,ta_bins]、logit_history [1,32,5,D]、h_gru [1,4,1,128]，其中 D = ceil(0.5 s / hop)、ta_bins = (bins + 9) / 10：

16k／512／N=125732264

48k／1024／N=251347525

frame_reset 是 stream 依逐 hop 事件產生的控制值（N 個 0.0／1.0，事件 hop 為 1.0），放在 StreamWork.inputs[4]；sample 不判斷事件，把它當第五個普通訊號輸入依位置搬進加速器，沒有特例。StreamWork.inputs[0..3] 與 outputs[0] 的 shape 與元素數就是上表同一列；state 不在 StreamWork 裡。括號內的名稱是匯出器的 ONNX 名稱，C 端與 sample 不讀名稱。

初始化與每包呼叫

sample 的演算法流程只有一次啟動，之後每包 pre → sample 自己的 AI3 → post。啟動時 aiaec_get_mem_size() → aiaec_init() 備好 pool 並填 AiaecInfo（只有圖路徑；N 由 sample 從 config 算：N = hop_in / (fft / 2)）；起始 generation 由 aiaec_state_generation() 取得。AI3 的開圖、送張量、執行、讀回與 state 緩衝是 sample 自己的。獨立 sample 的線性 AEC 前端與 pre 合成一次呼叫 aiaec_front_preprocess()（前端內的 AEC 以 AEC_RESIDUAL_STATE 逐階段執行：aec_process_linear() 加 aec_process_residual()，沒有增益與輸出級，分析 seam 取 AecResidualView.formed_hop）；前端的延遲策略是內部預設（BALANCED、線上 matched filter、5 組），不是客戶選項。

AiaecConfig cfg = { sr, fft, hop_in };             /* 例：{ 16000, 256, 1024 } */
StreamMemReq req;
if (aiaec_get_mem_size(&cfg, &req) != AIAEC_OK) return -1;   /* 未登錄組態在此被拒 */
void *pool = alloc_aligned(req.alignment, req.bytes);
AiaecCtx *ctx;
AiaecInfo info;                                    /* graph_path */
int rc = aiaec_init(&cfg, pool, req.bytes, &ctx, &info);   /* 0 或負的 AIAEC_ERR_* */
if (rc != AIAEC_OK) { log(aiaec_status_text(rc)); return -1; }

/* 獨立 sample：線性 AEC 前端只吃同一個 cfg（pipeline 自帶 AEC 時略過，見下） */
int err = AIAEC_OK;
size_t front_bytes = aiaec_front_get_mem_size(&cfg);          /* 0：被拒 */
AiaecFront *front = aiaec_front_init(alloc_aligned(AIAEC_FRONT_ALIGNMENT, front_bytes), front_bytes, &cfg, &err);

/* sample 的模型設定：這個 grid 與 N 的接線列（N=1 四個訊號，N>1 多一個 frame_reset）；沒有列就在開圖前拒絕 */
int n = graph_io_frames(cfg.fft, cfg.hop_in);  /* N = hop_in / (fft / 2) */
GraphIoConfig model;
if (graph_io_alignulcnet_find(cfg.sr, cfg.fft, n, &model) != GRAPH_IO_OK) return -1;

open_graph(info.graph_path);                       /* sample 的 AI3 */
char msg[160];
if (graph_io_check_ports(&model, din, n_in, dout, n_out, msg, sizeof msg) != STREAM_PORT_OK) return -1;
unsigned seen = aiaec_state_generation(ctx);

while (read_blocks(mic, far, hop_in)) {
    StreamWork work;
    /* 線性 AEC，再接 pre；mic、far 各 hop_in 個 int16 */
    if (aiaec_front_preprocess(front, ctx, mic, far, &work) != AIAEC_OK) return -1;
    int run_status = STREAM_RUN_NOT_STARTED;       /* BYPASS 區塊不讀 */
    if (work.action == STREAM_WORK_SUBMIT) {
        int chk;
        GRAPH_IO_CHECK_WORK(chk, &model, &work);   /* work 的數量與 shape 必須等於這一列 */
        if (chk != GRAPH_IO_OK) run_status = STREAM_RUN_NOT_STARTED;    /* 不符：不送件，仍呼叫 post */
        else if (work.state_generation != seen && zero_state_buffers() != 0) run_status = STREAM_RUN_NOT_STARTED;   /* 清零失敗：seen 不更新，下一包再清 */
        else {
            seen = work.state_generation;
            /* 填 work.inputs（含 N>1 的 frame_reset），執行，讀回 work.outputs[0]（複數 mask）；
             * net_proc 之前的失敗回 STREAM_RUN_NOT_STARTED，之後的失敗回 STREAM_RUN_FAILED，全部讀回才是 0 */
            run_status = run_ai3(&work);
        }
    }                                              /* BYPASS：不呼叫加速器 */
    if (aiaec_postprocess(ctx, run_status, pcm_out) != AIAEC_OK) return -1;   /* 兩種 action 都剛好呼叫一次 */
    write_block(pcm_out, hop_in);
}

已有自己的線性 AEC 的 pipeline 略過 front，把殘差、raw far 與事件直接填進輸入，再呼叫 aiaec_preprocess()，中間不經 int16：

AiaecAlignEvent ev[N];                             /* 每個模型 hop 一筆，最舊在前 */
AiaecInput in = { .kind = AIAEC_INPUT_ALIGN_ULCNET, .samples = hop_in };
in.u.align_ulcnet.residual_in = residual;          /* 線性 AEC 的 float error hop */
in.u.align_ulcnet.far_in      = raw_far;           /* 同一 hop 的原始 far */
in.u.align_ulcnet.events      = ev;
in.u.align_ulcnet.event_count = N;

aiaec_init() 回 0 或負的 AIAEC_ERR_*，pool 小於 aiaec_get_mem_size() 的位元組數或未對齊時回 AIAEC_ERR_POOL，較大的 pool 可以。aiaec_preprocess() 成功回 AIAEC_OK（0），是否要跑加速器看 work.action。每包 pre／post 只交換這一包的特徵（前四個訊號輸入；N>1 的最後一個訊號輸入是 frame_reset）與模型 head（複數 mask）。開圖後、第一次執行前，共用接線程式的 graph_io_check_ports()（內部呼叫 SDK 無關的檢查器 stream_check_ports()，在 stream/common，libaiaec.a 不含它）檢查每個埠的格式、軸、stride、容量與 state 配對；每包送件前 GRAPH_IO_CHECK_WORK 再核對 work 的數量與 shape。N=8 的每一包恆為一次 SUBMIT；N=1 時事件 hop 是 BYPASS。

輸入檢查：aiaec_preprocess() 與 aiaec_preprocess_freq() 在 kind、size、NULL 檢查之後、任何 frame 進入 stream 之前掃一次輸入。_freq 的四個平面（各 N × n_bins 個 float）有任何一個 NaN 或 Inf，或 PCM 入口的 residual_in、far_in 有任何一個 NaN、Inf，或絕對值超過 2112（AIAEC_PCM_LIMIT_BITS；float PCM 自己的分析在 2120 起溢位，限值留 8 個位元的餘裕），整包以 AIAEC_ERR_NONFINITE_INPUT（-10）拒絕。拒絕時 stream、分析器與 state generation 都沒有動，也沒有開啟的 block：sample 不要跑加速器，也不要呼叫 post，同一個 ctx 直接接下一包，輸出與從未收到這包相同。有限的頻譜 bin（到 FLT_MAX 為止）照常處理，送進加速器的特徵都是有限值，模型無法表示的結果由函式庫旁路，不會輸出 Inf。aiaec_front_preprocess() 的殘差在線性 AEC 跑完之後才掃到：回這個碼時 reset front 與 ctx。

pool 大小（本庫 host 建置讀出，單位 bytes）：

_freq 的 pool 不含 FFT、STFT／ISTFT 與 PCM 暫存（呼叫端自己做分析與合成），所以比 PCM 小。

State

  • recurrent state 留在 AI3 的 buffer。每對 state 輸入與輸出依位置（輸入 signal_in_count + k 與輸出 head_out_count + k）綁同一塊 buffer；Align-ULCNet 有 4 對。
  • 定點 state 埠兩端的 zero_point 都必須是 0（清零用位元組填 0，只有 zero_point 0 時才等於量化後的 0）。5/5、0/5、5/0 都在第一次送件前被埠檢查（stream_check_ports()）以 STREAM_PORT_ERR_STATE_ZERO_POINT（-110）拒絕；float 的 state 埠不看 zero_point，清零仍是填位元組 0，不受 FLOAT_IN／FLOAT_OUT 影響（見Float I/O 模式）。
  • init 時每塊 state buffer 清零一次（memset 加 cache flush）。正常連續推論不碰 state，每包只交換特徵與 head。
  • 函式庫在 reset、輸出被拒（非有限）、回報的狀態表示執行可能已碰過 state 時讓 work.state_generation 改變；sample 看到 generation 改變就清。狀態值見 stream_run.h：STREAM_RUN_OK（0）＝每個 head 寫完；STREAM_RUN_NOT_STARTED＝沒有啟動執行、裝置 state 沒被碰，generation 不動（N>1 封包內有事件 hop 時例外：graph 沒跑到那次重設，函式庫改成 generation +1）；其他值（含 STREAM_RUN_FAILED）＝state 可能髒了，generation +1。sample 不必自己追蹤失敗，下一次送件前比較 generation 即可。N>1 封包的事件 hop 由 graph 內的 frame_reset 重設模型 state，generation 不變，host 不需要清 buffer。

對齊事件

事件 hop 是 changed 為真，或 solid 由假轉真（前面已有 hop；前一個 hop 的 solid 跨包延續）。事件 hop 的模型 state 重設，該 hop 的輸出是殘差頻譜不變。各入口的行為：

入口N=1N=8（封包 graph）
aiaec_*（PCM → PCM）事件 hop 是 BYPASS，不呼叫加速器；只重啟模型，stream 自己的分析與 ISTFT 照跑，該 hop 的 PCM 輸出是殘差頻譜經過它們的結果（有訊號），前一個輸入 hop 的音訊照常輸出。一包恆為一次 SUBMIT，graph 內以 frame_reset（0.0／1.0）重設 state 並直通該 hop；stream 自己的 STFT 分析與 ISTFT 合成不重啟。PCM 輸出與同樣事件的 N=1 逐樣本相同。
_freq（頻譜 → 頻譜，aiaec）只重啟模型；呼叫端的分析器與 ISTFT 不重啟，overlap 連續。同 N=1：只有模型在 graph 內重設，分析與 ISTFT 的 overlap 連續。不要為此重設 ISTFT。
桌面 pipeline（mono_alignulcnet、4ch_alignulcnet 經 ulcnet_stream_*_freq）只重啟模型；應用端的分析器與 ISTFT 不重啟，overlap 連續。不適用：兩支範例建的是一幀一包的 stream（frames_per_call 0），封包 graph（layout 19）的 descriptor 在啟動時被 main.c 拒絕。
  • N=8 的事件由 graph 處理，generation 不變，一包仍是一次 AI3 呼叫。stream 把事件寫成 frame_reset：包內第 3 個 hop 是事件時為 0 0 1 0 0 0 0 0，sample 原樣搬進第五個訊號輸入。24 個 hop、第 3 個 hop 有事件的情境，N=1 送件 23 次（事件 hop 是 BYPASS，不送件，仍呼叫 post），N=8 每個完整包送一次、共 3 次。
  • PCM 入口（aiaec_* PCM 家族）與 _freq 加上呼叫端的分析與合成逐樣本相同，事件 hop 沒有少音訊；Python 參考實作走的也是這個流程。
  • 事件由線性 AEC 的 delay 狀態轉成：CHANGED 同時設 changed 與 solid，LOCKED 只設 solid，UNLOCKED 兩者皆 0。CHANGED 的下一個 hop 是 LOCKED，不會再觸發第二個事件；aiaec_front 與各 pipeline 都用這個對應。
  • 執行失敗、加速器輸出非有限，或 mask 有限但增強後的頻譜非有限時為 fail-open：線性 AEC 的殘差頻譜不變地通過，模型失敗不會比沒有模型更糟。

Python 的事件重播

C 的事件由線性 AEC 的 delay 狀態逐 hop 給出。Python 的線性 AEC 沒有這個存取器，無法從音訊推出事件，只能從記錄檔重播：inference.py 與 inference.py calib 的 --events PATH，N=1 與 N=8 共用同一條邊緣規則。記錄檔每個真實模型 hop 一筆 (changed, solid)，筆數等於 ceil(樣本數 / hop_len)：

格式內容
.json{"schema": "aiaec-align-events-v1", "events": [[changed, solid], ...]}、單純的 list，或 {"changed": 0, "solid": 1} 項目
.csv標頭 changed,solid（可有從 0 起算的 hop 欄）
.npz一維整數陣列 changed 與 solid

Python 沿用 _freq 的流程：STFT 與 ISTFT 在事件 hop 繼續跑，所以事件 hop 附近的 Python PCM 與 C 的 PCM 家族不同；與 C 的 _freq 才是同一個流程。沒有給 --events 時不會有任何事件。格式細節與行為見 alignment.md 與 README。

延遲

輸出比輸入晚一個模型 hop（model_hop = fft / 2 個樣本），以最終 PCM 的樣本數計（_freq 是呼叫端自己的 ISTFT 之後），兩個家族相同，與 N 無關：只有 stream 自己的一個框化 hop，模型沒有佇列。

組態延遲（樣本，＝ model_hop）
16 kHz／256／N=1128
16 kHz／256／N=8128
16 kHz／512／N=1256
48 kHz／1024／N=1、N=2512

函式庫不修剪也不補尾：每一包照常前端／pre／AI3／post，輸出與輸入逐包對應，起點晚上述延遲。外部 ISTFT 的 AC_OLA_ACCUMULATE 沒有 flush（ac_istft_flush() 回 0）。

驗證狀態
