State 表

ONNX/匯出邊界:export_onnx.py 交付 one-frame stateless graph；cache 尺寸由 stream_model.initial_inputs(model) 從 module tree 推導（不寫死 grid： spectrum 寬度隨 n_fft，cache extent 隨 GT block kernel/dilation 與 encoder stride）， 六個 conv window、h_tra 與 h_dpgrnn 都是 graph input/output。 這八個 state 張量歸應用端：float host 在 GTCRNProcessConfig 以 state[]／state_elements[] （依 enum GTCRNStateId，graph 順序）註冊八組 (pointer, 元素數)，全部註冊或全不註冊；板端的加速器自己保存定點 state， 什麼都不註冊。只有就地綁定: runtime 把每個 state input 與對應 *_out 綁到同一塊 buffer， 更新後的 state 就是下一次呼叫的輸入，沒有複製；須先讀完所有 state 輸入才寫同位址的輸出（目標平台已確認 NPU 的行為）。 呼叫端在每次 invocation 後用 gtcrn_process_state_validate() 檢查（見下）。 匯出不 pin 單一 grid——config 與 checkpoint 不成對時在 strict load_state_dict（形狀）或 checkpoint contract（同形語意）就大聲失敗。 固定前後端全在 host：gtcrn_model_input（magnitude＋ERB 前向矩陣） 產生 mag/real/imag 三個獨立輸入（各自量化 scale）；圖回傳 ERB 域 complex mask，gtcrn_model_output 做 ERB 逆矩陣＋CRM。ERB 矩陣由 export_erb_matrix.py --runtime-bins 匯出成 raw float32 的 erb_fwd.bin（bin-major [192][64]）／erb_inv.bin（band-major [64][192]）；layout 與 C 迴圈一致，json 記 shape；C 只吃應用端載入的指標（GTCRNProcessConfig.erb_fwd／erb_inv， 或 gtcrn_process_set_erb_matrices()），函式庫不讀檔。ERB split 出貨為 65+64=129， graph I/O 寬度就是 grid.erb_bands。inference.py calib 會在同一 process 同一 model instance 一併匯出並 parity-check graph（預設 <output>.onnx，--onnx 可改）。

State 邊界(layout version 8):所有 state tensor 都是 rank 4,輸入與 *_out 輸出 shape 完全相同; metadata 記 state_binding = in_place_same_address。版本 3–7 已退役(RETIRED_LAYOUT_VERSIONS)。

  • conv_enc0/1/2、conv_dec0/1/2 (1,16,3|5|11,33):depth-conv 的完整因果 window(= 歷史 + 新的一幀)。 圖在輸入上做一個 Slice(axes=[2]、starts=[1]、ends=[K]、step 1,end 是明確整數)丟掉最舊一幀,接上新的一幀,卷積, 並把整個 K 幀 Concat 結果當作 conv_*_out。輸入只有這一個 consumer,沒有任何 state 輸出由 Slice 產生。 decoder 的 window 深度與 encoder 反向(11、5、3)。
  • h_tra (1,6,1,16):六顆 TRA attention GRU,列順序 encoder 0–2 再 decoder 0–2;h_dpgrnn (1,4,33,8):四顆 grouped inter GRU (h_dpgrnn1_0、h_dpgrnn1_1、h_dpgrnn2_0、h_dpgrnn2_1),hidden batch 是頻率軸。 每顆 GRU 用輸入上 dim 1 的 Slice 取自己的列再 squeeze,下一個 state 以一個 Concat(dim 1)接回。

新 window 的前 K−1 幀等於輸入 window 的後 K−1 幀,h_tra／h_dpgrnn 是六個／四個 hidden 依序串接。匯出圖經 exporter 內建 onnxoptimizer ＋ ORT 常數折疊後本機量測 299 節點(36 個 Slice,皆 step 1;合約測試門檻 ≤ 300)。 AINR/onnx_streaming_contract.py 的 validate_inplace_state_graph() 在匯出時檢查上述條件, AINR/check_state_quantization.py 可對量化後的圖與報告再檢查 state 輸入／輸出的 dtype、scale、zero point、shape 是否一致。 Slice 沿 axis 2 的起點在 int8 下落在 33 byte 的整數倍(window 一列 33 個元素),不是 16 byte 對齊;對齊處理由量化工具鏈決定,尚未在板上驗證。

gtcrn_process_state_validate(p):每次 invocation 後就地檢查已註冊的 8 個 state 張量, 全部有限(或沒有註冊)回 0;任何 NaN/Inf 則八個全部歸零、state generation 加 1 並回 -1(前一個 state 已被覆寫;寫一半而仍有限者偵測不到;可信 runtime 可不呼叫)。 gtcrn_process_mask_validate(p, mask_erb) 檢查 mask,拒絕時同樣回 -1(此框改讓頻譜原樣通過);先 mask 後 state,兩者連續被拒 generation 至多加 1。 gtcrn_process_state_generation() 回傳 generation:gtcrn_process_init() 後為 1,每次 gtcrn_process_reset() 與每次被拒的驗證加 1(mod 2^32),有沒有註冊 state 都一樣; 加速器那份定點 state 看不到這兩件事,runtime 發現數值與上一幀不同就把自己的 state tensor 填成量化後的零。 八個 state 張量合計 84,864 bytes(21,216 f32);各形狀取自 stream_model.initial_inputs() 與匯出 graph schema,本目錄 model.py 無 cache 介面。

延遲與 warm-up

  • 演算法 lookahead = 0 框:圖內所有時間 conv 都是左填充 causal (GTConvBlock 的 F.pad(h1,[0,0,pad_size,0])),TRA 與 inter RNN 單向, intra RNN 只在單框的頻率軸上雙向。
  • I/O 延遲 = OLA 重疊 win−hop = 256 samples = 16 ms @16 kHz。
  • Warm-up:無「無輸出」暖機框(第 0 hop 即有輸出);但 conv/TRA/inter cache 由零起始, 且 C 串流的首框以零填充取代 PyTorch 離線 center=True 的 reflect padding (README 明載此差異只影響 clip 起點)。
  • 時間感受野:encoder/decoder 各 3 個 GTConvBlock 累積 (kT−1)·dilation = 2+4+10 = 16 框過去 context(conv window 深度 = 歷史 + 新的一幀,即 3、5、11),加上 RNN 無限記憶。
