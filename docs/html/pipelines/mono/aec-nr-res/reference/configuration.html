執行期控制與診斷

執行期強度控制

int aec_set_level(Aec* a, AecLevel level, float ramp_ms);
int anr_set_level(AnrDenoiser* nr, AnrLevel level);           /* nr = 你自己 anr_init() 的物件 */

/* 使用者轉旋鈕:在兩個 hop 之間呼叫,不重建、不動 pool */
aec_set_level(aec, AEC_LEVEL_AGGRESSIVE, 100.0f);        /* 100 ms 內以 dB 線性走到新地板 */
anr_set_level(nr, ANR_LEVEL_MILD);
aec_process_context(aec, mic, ref);                        /* 下一個 hop 起生效 */
呼叫改什麼回 −1 的情況(−1 時什麼都不寫)
aec_set_level()Aec 的 far-active 殘留回音地板(三個 level 唯一的差異軸之一;mono 的 g_res_ctx 就是這個 lane 算的)與 aggressive 的 DT 地板a 為 NULL;level 超出 enum;ramp_ms 非有限值或超出 [0, 60000]
anr_set_level()降噪器的強度 levelnr 為 NULL(例如 --no-nr 沒有建降噪器);level 超出 enum;L／num_init_frames 與實例不符

ramp_ms == 0 下一個 hop 套用(不是錯誤),落點與「用該 level 從頭建一個新實例」完全相同;> 0 以 dB 線性走過去,上限 60 s(mild ↔ aggressive 的 far-active 地板差 18 dB、地板又是硬 clamp,互動式旋鈕應給 ramp)。DT 地板與 split-floor 開關(NO_FLOOR)一律立即階躍,不受 ramp 影響。ramp 途中再呼叫會從當前 live 值重新起走。兩個 setter 都不是重啟:AEC 濾波器與延遲鎖定、NR 噪聲底與增益平滑歷史全部繼續跑(要重啟用 aec_reset()、anr_reset()、ac_istft_reset())。在兩個 hop 之間呼叫、與 process 序列化;非 thread-safe。

範例的降噪器以 anr_config_for_level_grid() 建立、沒有覆寫任何欄位,所以 anr_set_level() 直接換強度。在 level 之上改過欄位的實例,anr_set_level() 會把那些覆寫蓋回 level 值,要自己組好完整 target 再呼叫 anr_reconfigure()。

C 稱 level,Python 稱 preset(NR 為 strength):C level == Python preset,值名與整數相同。舊名 AecPreset／AEC_PRESET_*、AnrMode／ANR_MODE_* 仍保留在公開 header(同值),舊函式名已移除。

A/B 量測時該預期什麼。far-active 地板只在 far-active 且非 double-talk 的 hop 生效:DT 期間套的是 DT 地板(mild 與 balanced 相同,aggressive 較深),far-active latch 觸發前套的是 far-silent 地板。同一個 ctx.res_gain 還決定注入的 comfort noise 量(振幅 ∝ sqrt(1 − G_res²) 再乘該 bin 的 NR gain(下限 −10 dB,範例的 CNG_NR_GAIN_FLOOR)——地板越深、CNG 反而越多)。所以整段錄音的平均移動幅度會小於 dB 落差所暗示的量,而且只量 echo／degradation 的 A/B 會把 CNG 的變化錯記到別的機制。請在 echo 對齊或 degradation 對齊的條件下比較,並實際試聽。

逐階段耗時(診斷用)

/* aec.h: the fields of AecStageTiming; aec_get_last_timing(aec, &t) copies them */
    uint32_t delay_us;      /* 延遲估計 + ring 寫入／補償讀(EXTERNAL_ALIGNED 恆為 0) */
    uint32_t frontend_us;   /* 進入主濾波器之前,不含 delay                         */
    uint32_t linear_us;     /* 主 adaptive filter,含 far-end FFT                     */
    uint32_t res_us;        /* AEC3 post／RES 區塊                                   */
    uint32_t steering_us;   /* stationarity、coarse-error 發布、DT analyzer、EPV、shadow_rise、失調估計 */

五欄由 lib/aec 帶出(五個階段加起來不等於整通呼叫,每次呼叫開頭清零)。鏈與合成的耗時是範例程式自己在呼叫前後讀時鐘量的(mono/aec_nr_res/main.c 的 process_hop() 與 timing_now_us();範例的 --timing 表只彙整 delay／frontend／linear／res 四列,steering_us 與其他餘額落在 unattributed),不是任何函式庫的 API。與 4ch 的差異:4ch 的共用 estimator 由應用建立、交給 mcab 驅動,delay_us 是 McabLastTiming 的獨立欄位(mcab_get_last_timing());這裡 estimator 留在單一 AEC 內部,經 aec_get_last_timing() 帶出。mono 沒有 fuse_us(只有一條 lane)。

預設關閉。release build 不做任何 clock 讀取,欄位讀 0。make PROFILE=1 開啟(-DAEC_STAGE_TIMING=1)。呼叫端的顯示旗標(兩支 CLI 的 --timing)決定「印不印」,不決定「有沒有量」;建置一種、讀成另一種,AEC 那幾列就是 0(CLI 會用文字說明)。

目標平台沒有 CLOCK_MONOTONIC 時。clock_gettime 是 POSIX 而非 C99。這種平台用 make PROFILE=1 EXTRA_CFLAGS='-DAEC_NOW_US=board_timer_us -include my_timer.h' 換掉 AEC 的時鐘:巨集要是純識別字(Makefile 的 FP policy 不允許 EXTRA_CFLAGS 出現括號),指向不收參數、回傳 uint32_t 微秒的函式,宣告由整合者自備。替代時鐘必須單調,否則無號減法會產生接近 32-bit 全距的荒謬值。每個元件各有自己的覆寫點(lib/aec 的 AEC_NOW_US、mcab 的 MCAB_NOW_US),刻意不共用。開著旗標但指向常數函式是合法用法,所有欄位讀 0,--timing 報表無法分辨這種情況與「根本沒開旗標」。

記錄本身不是條件編譯的,只有取樣是——欄位無論旗標開關都在 struct 裡;aec_nr_pipeline_static --print-mem-size 在 PROFILE=1 與一般 build 都是 424,288 B(16 kHz/256,ne10,實測)。

本機量測範例(桌面 aarch64 NEON、ne10、16 kHz/256、以 -DAEC_STAGE_TIMING=1 建置、合成 10 s 回音訊號 = 1250 hops,aec_nr_pipeline_static --timing,連跑兩次):AEC delay 10.34／7.71 us(53.2%／54.0%)、frontend 2.01／1.46 us、linear 1.37／0.93 us、post/RES 3.26／2.36 us、gain chain 1.40／1.05 us、synthesis 0.22／0.15 us,整通呼叫 19.44／14.28 us/hop(絕對值隨負載浮動,佔比穩定)。最大的一塊是 matched filter(delay),不是主濾波器,對應 delay_num_filters(1..5)這個可調旋鈕。這是本機合成訊號的數字,不是目標平台的算量;目標平台待量測(Mono 參數與診斷 的記憶體旋鈕與這條線同源)。
