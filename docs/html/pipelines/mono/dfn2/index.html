Audio_ALG / 選擇 pipeline

Mono · DFN2

概要

pipelines/mono/aec_dfn_res/main.c:範例直接組合獨立的函式庫:lib/aec 的 Aec(aec_process_linear() 加 aec_process_residual())→ aec_get_residual()(AecResidualView,渲染基底 B = base_spec)→ main.c 的 rig_process() 自己形成 P(AEC 自己的 RES 增益 res_gain:aec_apply_gain(aec, NULL, post) 把它套在 B 上,--cng 才呼叫 aec_apply_cng)→ dfn/dfn_hop.h 把 DeepFilterNet2 插在「post-RES 頻譜」與「合成」之間。每個物件(Aec、模型串流 DFN2Stream、8/16 kHz 路徑的 AinrBridge、48 kHz 路徑的 AcIstft)各有自己的 mem_size 與 init;DFN2 這一段由 dfn/dfn_hop_pool.h 一次算好並切塊,main.c 加上 Aec 與 P 緩衝。DfnHop 是非擁有指標的 phase 機器。模型這一段走模型串流層 stream/ainr/dfn2 的 dfn2_stream_pre_process_freq_dual()／dfn2_stream_post_process_freq()(記憶體模式,ERB 矩陣由應用端提供),與 4ch 範例共用同一份 dfn_hop.h。兩條路徑逐位元一致(dfn/tests/test_dfn_hop.c、test_dfn_stream_equivalence.c)。

Host 跑產品自己的取樣率(預設 16 kHz),只有 DFN2 模型在模型的取樣率(出貨 48 kHz)。--sample-rate 接受 8000 / 16000 / 48000;48 kHz 時模型串流直接吃 host 的頻譜(dfn_hop_init_direct()),8/16 kHz 時範例改建一個 AinrBridge(stream/ainr/bridge;dfn_hop_init_bridge())負責兩個格點之間的來回,每個 native hop 進一個、出一個。AEC、RES、CNG 一律留在產品取樣率,呼叫端不再需要在 API 之外把訊號 resample 到 48 kHz。

為什麼「估計用 B、套用在 P」

DFN2 是以未經處理的 noisy speech 訓練的,RES 挖出的頻譜洞不在它的訓練分佈裡,所以 hop 把兩件事拆開(dfn2_stream_pre_process_freq_dual() 的 est／app 兩組輸入):B = aec_get_residual() 的 base_spec(渲染基底:守衛未觸發的 hop 逐位元等於 error_spec = E,即 RES gain 當初據以估計的 pre-RES 頻譜;守衛觸發的 hop 為 E + echo)只用來估計(特徵、[t-(2-M)..t+M] 視窗、三個 head);P = rig_process() 組出的頻譜(= B * G_res + CNG)才是三個 head 套用的對象(ERB mask、deep filter、alpha blend、atten limit)。分工是:像語音的 far-end 殘留由 DFN 保留、交給 RES 處理;不像語音的兩級都壓。error_spec 只是分析 seam,不拿來渲染;mono 範例把 B 傳給估計輸入,4ch 範例以 v.error_spec 作估計。dfn_hop_* 的參數名仍叫 E／P。

Comfort-noise fill 關閉時 B 與 P 逐 bin 同相位(G_res 是實數),deep-filter tap 不會相位錯配;開啟時 comfort noise 在 RES 挖得最兇的 bin 改變 P 的相位,estimate/apply 一致性在那裡不成立。所以本變體預設關閉(--cng 才開);雙輸入拓樸仍是產品假說,C 端 gate 只證明結構正確。

API 用法

呼叫順序:derive_lane()(aec_resolve_signal_grid() 加 aec_config_from_level())→ 參數解析以 dfn2_grid_make() 建模型 grid,再讀 ERB 矩陣(--erb-fwd／--erb-inv)、填 model callback → 各物件 mem_size → 切塊 init → 每 hop 一次(aec_process_linear、aec_process_residual、aec_get_residual、自寫的 P 形成、dfn_hop_process)→ destroy。每次吃剛好一個 host hop 的 mic 與 ref、寫出同樣長度(16 k/256 預設 128、16 k/512 為 256、48 k/1024 為 512)。完整範例、時序圖與參數表收在 DFN2 pipeline 呼叫與時序、DFN2 pipeline 呼叫與時序 與 DFN2 pipeline 參數與狀態。每 hop 的核心:

AecResidualView v = { .struct_size = sizeof(v) };
if (aec_process_linear(aec, mic, ref) != AEC_OK ||           /* 剛好一個 host hop */
    aec_process_residual(aec, NULL) != AEC_OK ||
    aec_get_residual(aec, &v) != AEC_OK) { /* 被拒: aec + hop 一起 reset */ }
follow_post_reset();                                         /* aec_post_reset_serial() 變動: 清 OLA 尾巴(CNG 種子由 AEC 自己回 AEC_CNG_SEED) */
aec_apply_gain(aec, NULL, post);                             /* P 必須在 dfn_hop_begin 之前形成: P = B * G_res;B = v.base_spec */
if (cng_on)                                                  /* 預設關: B 與 P 要同相位 */
    aec_apply_cng(aec, NULL, post);

dfn_hop_process(&hop, v.base_spec, post, out);                      /* (a) 一次完成:模型由 model.infer 執行(沒設就是 identity) */
/* (b) 或自己在中間跑加速器:dfn_hop_begin → while (dfn_hop_nn_begin() > 0) { 跑 NPU; dfn_hop_nn_end(rc) } → dfn_hop_end(&hop, out) */

pool plan、模型串流與 bridge 的 reject-first 清單(最容易踩到的是 erb_inv 必須是 partition of unity:範例由 dfn_hop_pool_build() 內的 dfn2_stream_init_ex() 拒絕,main 印 pipeline init failed)與入口的逐項語意收在 DFN2 pipeline 參數與狀態。任一步失敗,整合者要把 Aec 與 DfnHop 一起 reset(main.c 的 rig_reset())。

訊號泳道圖

48 kHz host 的泳道很短:每 hop 一次推論(前 M 個 hop 沒有 job,模型不跑),模型串流前 L 個 hop 輸出全零頻譜(valid = 0),之後第 p 個 hop 的輸出就是「傳統 pipeline 的 hop#(p-L) 輸出」(出貨 pair:M=1、L=2,合計 3 hop 純延遲,見「延遲與 warm-up」)。原生格點則多了 bridge 的兩個時鐘:

原生格點 host + rate bridge(16 kHz / fft 256 / hop 128)

lane \ native hop   #0            #1            #2            #3            #4(週期重複)
─────────────────── ───────────── ───────────── ───────────── ───────────── ─────────────
host(16 kHz)        AEC+RES(+CNG),每 hop 交出 B,P [129]
bridge 原生 WOLA    e0,p0(各 128) e1,p1         e2,p2         e3,p3         e4,p4

48k 分析(每滿 512)  0 幀         1 幀         1 幀         1 幀         0 幀
模型串流(dfn2_stream) 不跑          ×1            ×1            ×1            不跑
48k WOLA → 降頻 ×1/3 → 原生 out FIFO(init 預填 prefill = 128 個零)
out(128 samples)    每個 hop 恰好吐 1 個 hop;內容 = host 自己的輸出再延後 added delay

一個 hop 內最多兩次推論,板端算力預算該看這個峰值而非平均

E 與 P 一路都是兩個指標。它們從 AecResidualView 與 P 緩衝出來就分開,在 dfn2_process.c 內部也踩互斥的狀態(est 走特徵/視窗,app 走 noisy ring);est == app 時 ..._freq_dual() 等同dfn2_prepost_pre_process_freq()。Bridge 內也維持這個分離:E、P 各有自己的原生 AcIstft、升頻器、48 kHz FIFO 與 AcStft,只有降頻器與 48 kHz 合成物件是一份,因為模型只輸出一條訊號。

延遲與 warm-up

端到端演算法延遲 = host 的 1 hop WOLA + DFN2 段(main.c 印 hop 加 ainr_bridge_added_delay_samples() 或 hop * (dfn_hop_lookahead_frames(grid) + 1))。48 kHz 時 DFN2 段就是 L = M + D 個 hop 的模型 lookahead(grid.mask_lookahead + grid.df_lookahead,串聯相加而非取 max;出貨 pair 1/1 → L = 2);原生格點時是 bridge 的 added delay。下表與數字都是出貨 pair 1/1(其餘 pair 的規則見 DFN2 pipeline 參數與狀態「lookahead pair」):

  • added delay = prefill + 升頻群延遲 + (L+1)×512×sr/48000 + 降頻群延遲(整數除法);兩個群延遲在每個支援格點都各是 16 個原生樣本,測試即以此釘死。(L+1)×512 = 48 kHz 格點的 1 個分析/合成 hop 加 L 個 lookahead hop(出貨 pair 為 1536);L+1 不是 3 的倍數時含小數個原生樣本,向下取整。prefill 不是寫死的常數:init 用真正的 resampler 在靜音上走一遍排程,量出「吐出 − 產生」的最大缺口。
  • 原生格點不是逐位元等值:訊號走過兩顆 FIR resampler,通帶響應被套用兩次,測試因此用容差而非 memcmp,延遲本身由脈衝精確釘住。bridge 測試閘 < 5e-3(現查 4.36e-04 / 9.47e-04 / 9.46e-04);test_mono_dfn 把兩路都過 0.35 fs 低通後比對,閘 < 1e-3(現查 8.73e-06 / 8.91e-06 / 1.30e-05)。
  • Warm-up:開頭的輸出是全零(48 kHz 為 L 個 hop;原生格點為 added delay,來自預填的 out FIFO)。暖機時 dfn2_stream_post_process_freq() 回報 valid = 0,dfn_hop_close_frame() 把輸出頻譜寫滿零,所以 hop 無條件合成。前 M 幀沒有 job(視窗湊不齊右鄰居:模型不跑,state 與 generation 不動;出貨 M=1 即第 0 幀);48 kHz 其餘每 hop 恰好一次推論,原生格點照泳道圖排程,一個 hop 0、1 或 2 次。
  • AEC delay 改變不 reset 模型串流/bridge。它們不消費 far-end,兩個輸入仍然連續;reset 會讓遞迴狀態重來。只有整合者的 reset(dfn_hop_reset() 連帶 reset 模型串流、bridge 與 model.reset)。收尾 flush 要再推 L+1 個全零 hop(原生格點推滿 added delay)才吐得出最後的 source frame,那幾拍加速器也要照跑。
