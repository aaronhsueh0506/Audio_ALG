audio_pipeline_4ch 細節 — 執行期強度控制與逐階段耗時

概要

本頁收 pipeline_4ch 的兩段會把單頁撐過 30 KB 的 API 細節:(1) 單元的 RES 與你自己的降噪器上 aec_res_set_preset()／anr_set_mode()／aec_res_split_floor() 的執行期強度控制(單元本身沒有強度 setter,只交出 RES 的 handle),(2) four_aec_nr_res_get_last_timing()／audio_pipeline_4ch_last_core_timing() 的逐階段耗時診斷。最小呼叫範例、前端輸出契約、block diagram、泳道圖、I/O 表、State 表、延遲與檔案清單仍留在原頁。

執行期強度控制

int aec_res_set_preset(AecRes* r, AecPreset preset, float ramp_ms);
int anr_set_mode(AnrDenoiser* nr, AnrMode mode);                     /* nr = 你自己 anr_init() 的物件 */
int aec_res_split_floor(const AecRes* r, float* live, float* target);  /* 唯讀 */

AecRes* res = audio_pipeline_4ch_res(p);                   /* 單元的 RES; enable_res=0 或 core.enable_post=0 時為 NULL */
aec_res_set_preset(res, AEC_PRESET_AGGRESSIVE, 100.0f);    /* 100 ms 內以 dB 線性走到新地板 */
anr_set_mode(nr, ANR_MODE_MILD);

float live, target;                                        /* 線性功率,不是 dB */
aec_res_split_floor(res, &live, &target);              /* live == target ⇒ ramp 已走完 */

本節最重要的一件事:對四條 lane 重新指定 preset 是無效操作。四條 lane 都以 spatial_linear_context 建立,因此沒有任何一條會走到自己的殘留抑制器;它們各自的地板什麼都不塑形。真正乘上本產品輸出、也真正決定 comfort noise 量的那個 gain,來自唯一一個共用的 post-beam 抑制器(單元擁有的 AecRes)——上面的 preset setter 針對的就是它,這也是它存在、而不是要呼叫端自己對四條 lane 迴圈呼叫 aec_set_preset() 的原因。同理 NR 也只有一個共用實例(對 beamform 後的訊號跑),不是每條 lane 一個。RES 由單元擁有、經 audio_pipeline_4ch_res(p) 交出 handle;降噪器由應用自己初始化與持有。前端 FourAecNrRes 與單元 AudioPipeline4Ch 都沒有 preset／mode setter 本身(核心連 RES 都沒有)。這一點由 tests/test_audio_pipeline_4ch.c(單元 RES 的 preset／ramp／split_floor 與 reset 後保留)與 pipelines/tests/test_se_common.c(anr_set_mode() 對每個 mode)釘住,不是推測。

呼叫改／讀什麼回 −1 的情況(−1 時什麼都不寫)
aec_res_set_preset()共用 post 級抑制器的 far-active split floorres NULL(enable_res=0 或 core.enable_post=0 時 audio_pipeline_4ch_res() 回 NULL);preset 超出 enum;ramp_ms 非有限值或超出 [0, 60000]
anr_set_mode()你持有的那一個降噪器nr NULL(例如範例沒有建降噪器);mode 超出 enum
aec_res_split_floor()唯讀。live=抑制器當下套用的值,target=撐得過 reset 的已設定值;只有 ramp 走到一半時兩者不同。任一指標可為 NULLres NULL

live/target 這一對是板端唯一值得記錄的強度量:它是真正塑形輸出的東西,兩個值合在一起就回答「我要求的改動落地了沒有」。

ramp_ms == 0 下一個 hop 套用(不是錯誤),落點與「用該 preset 從頭建一個新實例」完全相同;> 0 以 dB 線性走過去,上限 60 s。ramp 途中再呼叫會從當前 live 值重新起走。兩個 setter 都不是重啟:四條 lane 的濾波器、共用延遲鎖定、NR 噪聲底與增益平滑歷史全部繼續跑。preset 改動撐得過 該 stage 的 reset(目標值另存一份,reset 會重新套用;audio_pipeline_4ch_reset() 也保留經 handle 設的 preset),ramp 進度則會被丟掉。在兩個 hop 之間呼叫、與單元的 audio_pipeline_4ch_process*() 序列化;非 thread-safe。Python 對應 PostBeamResidualSuppressor.set_preset(preset, ramp_ms=0.0)(FourChannelAecPipeline 擁有一個,以 pipeline.post_beam_res.set_preset() 取得;沒有 set_aec_preset())。

範例的降噪器以 anr_config_for_mode_grid() 建立、沒有覆寫任何欄位,所以 anr_set_mode() 直接換強度。在 preset 之上改過欄位的實例,anr_set_mode() 會把那些覆寫蓋回 preset 值,要自己組好完整 target 再呼叫 anr_reconfigure()。

A/B 量測時該預期什麼。far-active 地板只在 far-active 且非 double-talk 的 hop 生效:DT 期間套用 DT 地板(三個 preset 完全相同),far-active latch 觸發前套的是 far-silent 地板。同一個 gain 還決定注入的 comfort noise 量(振幅 ∝ sqrt(1 − G_res²) 再乘該 bin 的 NR gain(下限 −10 dB),見 pipeline_4ch block diagram 的 CNG 步驟——地板越深、CNG 反而越多)。所以整段錄音的平均移動幅度會小於 dB 落差所暗示的量,而且只量 echo/degradation 的 A/B 會把 CNG 的變化錯記到別的機制。請在 echo 對齊或 degradation 對齊的條件下比較,並實際試聽。

逐階段耗時(診斷用)

typedef struct FourAecNrResLastTiming {
    uint32_t delay_us, frontend_us, linear_us, lane_res_us;   /* four_aec_front_process */
    uint32_t fuse_us;                                         /* four_aec_fuse          */
} FourAecNrResLastTiming;

void four_aec_nr_res_get_last_timing(const FourAecNrRes* p, FourAecNrResLastTiming* out);
void audio_pipeline_4ch_last_core_timing(const AudioPipeline4Ch* p, FourAecNrResLastTiming* out);  /* 單元: 同一份, 經 get_core */

最近一個 hop 前端每個階段的 wall-clock 成本(微秒,CLOCK_MONOTONIC)。純診斷:pipeline 自己不回讀,也不影響處理。p 為 NULL 或已銷毀時把 out 清零而不是失敗;out 不得為 NULL。欄位:delay_us(update_shared_delay() 的共用 estimator,不含 align_render() 的 ring-buffer 複製與 realign 掃描)、fuse_us(four_aec_fuse()),以及四條 lane 加總的 frontend_us／linear_us／lane_res_us。RES(單元內的 AecRes,在 audio_pipeline_4ch_fuse() 裡)、NR、CNG 與逆轉換的耗時由應用自己量,不在這個記錄內。

後三者由 aec_get_last_timing()(aec.h)逐 lane 讀出後相加,受 -DAEC_STAGE_TIMING=1 這個另一半的旗標管轄——只建核心那半(FOUR_AEC_NR_RES_STAGE_TIMING),這三欄讀 0 而其餘照常量測,是可讀的狀態而非壞掉;make PROFILE=1 開啟 AEC 那半。lane 內部的 delay_us 也一併加進上面的 delay_us,但它結構上恆為 0:四條 lane 都是 AEC_DELAY_EXTERNAL_ALIGNED,沒有自己的 ring 或 estimator。相加而不是丟棄,是為了讓日後改變 lane 模式時不會靜默漏掉那筆成本。

目標平台沒有 CLOCK_MONOTONIC 時。clock_gettime 是 POSIX 而非 C99。用 make PROFILE=1 EXTRA_CFLAGS='-DFOUR_AEC_NR_RES_NOW_US=board_timer_us -DAEC_NOW_US=board_timer_us -include my_timer.h' 換掉時鐘;巨集要是純識別字(FP policy 不允許 EXTRA_CFLAGS 出現括號),指向不收參數、回傳 uint32_t 微秒的函式。替代時鐘必須單調。這層與四條 lane 各有自己的覆寫點,刻意不共用。開著旗標但指向常數函式是合法用法,所有欄位讀 0。

呼叫端若要呈現完整分解,前端的未歸屬餘額要自己用減法算:front_total − (delay_us + frontend_us + linear_us + lane_res_us) 涵蓋輸入去交錯／有限值檢查、align_render()、realign 掃描與 lane 迴圈自己的餘額。

前半在 four_aec_front_process() 接受引數後清零,fuse_us 在 four_aec_fuse() 清零,所以中途失敗的 hop 對沒跑到的階段回報 0 而不是上一個 hop 的數字;被引數檢查直接拒絕的呼叫不動記錄。
