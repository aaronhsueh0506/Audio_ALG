AINR GTCRN (16 kHz complex-mask baseline)

概要

超輕量 16 kHz 降噪模型(ShuffleNetV2 conv + SFE + TRA + 2×DPGRNN, 輸出 complex ratio mask)。model layout v5 起固定前後端全部搬到 host；出貨的 split layout(state layout version 6、19 個 graph input)把 packed recurrent state 拆成每個 block/GRU 各自的 graph I/O: C 端 gtcrn_process.c 負責串流 STFT/WOLA 之外,還以 gtcrn_model_input(magnitude＋ERB 前向矩陣 erb_fwd.bin) 產生 mag/real/imag 三個 (1,129,1) 獨立輸入(各自量化 scale),圖只保留 learned compute(concat 後 SFE/conv/GRU),輸出 ERB 域 complex mask 由 gtcrn_model_output(ERB 逆矩陣 erb_inv.bin＋CRM)在 host 展開套用。

項目值(以現行程式碼為準)
取樣率 / grid16000 Hz;FFT/win/hop = 512/512/256(32 ms 窗、16 ms hop;GTCRN_N_FFT/GTCRN_HOP_LEN)
頻譜 bins257(GTCRN_N_BINS)
ERB 混合解析度(host 前後端)erb_subband_1=65(低頻原 bins)+ erb_subband_2=64(ERB 帶)= 129;DPGRNN width = 33(由 encoder stride 導出)
參數量trainable 23,669;含固定 ERB matrix 共 48,245(實際建構量測)
輸出ERB 域 complex mask;host 端 ERB 逆矩陣展開後 CRM 乘回同幀頻譜
STFT 正規化無(torch.stft 預設;C 端 norm=1.0f),root-Hann 窗

論文數據與逐層架構筆記見 docs/architecture_notes.md 與 README.md;上游原始 repo(含論文 PDF 與串流參考實作) vendored 於 AINR/gtcrn_github/。

API 用法

#include "GTCRN/gtcrn_process.h"

GTCRNProcessState st;               /* 10,256 bytes, 呼叫端配置 */
FftHandle *fft = fft_init(caller_fft_pool, caller_fft_pool_bytes,
                          GTCRN_N_FFT);
gtcrn_process_init(&st, fft);       /* state 只借用 caller-owned handle */

float spec[GTCRN_N_BINS][2];        /* bin-major [re, im] */
float mag[GTCRN_MODEL_ERB_BANDS], re_b[GTCRN_MODEL_ERB_BANDS],
      im_b[GTCRN_MODEL_ERB_BANDS];
float mask_erb[GTCRN_MODEL_ERB_BANDS][2];
float enhanced[GTCRN_N_BINS][2];
for (each hop of 256 new samples) {
    gtcrn_analysis(&st, in256, spec);       /* 未正規化 RFFT 一框 */
    gtcrn_model_input(spec, erb_fwd, mag, re_b, im_b); /* host 固定前端:
                                magnitude + ERB 前向矩陣 (erb_fwd.bin) */
    /* NPU: 三個 (1,129,1) 輸入 -> ERB 域 mask (1,129,1,2)
     * — 圖內只有學到的運算 */
    run_model(mag, re_b, im_b, mask_erb);
    gtcrn_model_output(mask_erb, erb_inv, spec, enhanced); /* host 固定後端:
                                ERB 逆矩陣 (erb_inv.bin) + CRM */
    gtcrn_synthesis(&st, enhanced, out256);  /* WOLA, 256 samples */
}

Python 離線:inference.py --config config.ini --model ckpt.pt --input in.wav --output out.wav (整段 torch.stft → model(spec) → torch.istft)。

圖內中間特徵(不跨越模型邊界):concat (B,3,T,129) → SFE (B,9,T,129) → encoder (B,16,T,33) → decoder → mask_erb (B,2,T,129)。 離線 Python GTCRN.forward(spec) 仍是整段自含(特徵/ERB/CRM 在模型內), host 前後端邊界(v5 起)只描述部署用的 stream graph。

State 表

ONNX/匯出邊界:export_onnx.py 交付 one-frame stateless graph；cache 尺寸由 stream_model.initial_inputs(model) 從 module tree 推導（不寫死 grid： spectrum 寬度隨 n_fft，cache extent 隨 GT block kernel/dilation 與 encoder stride）， 六個 conv history、六個 TRA hidden 與四個 DPGRNN hidden 都由 host 作為 graph input/output 送回，加速器本身不保存跨次呼叫狀態。v6 把 v5 的 packed state 拆成實際的 block／GRU 槽位，總 bytes 不變，graph 不再為了拆裝 state 而執行 Slice/Gather/Concat（conv history 與新框相接那一個 Concat 屬於運算本身）。 匯出不再 pin 單一 grid——config 與 checkpoint 不成對時在 strict load_state_dict（形狀）或 checkpoint contract（同形語意）就大聲失敗。 v5 起固定前後端全在 host：gtcrn_model_input（magnitude＋ERB 前向矩陣） 產生 mag/real/imag 三個獨立輸入（各自量化 scale）；圖回傳 ERB 域 complex mask，gtcrn_model_output 做 ERB 逆矩陣＋CRM。矩陣由 export_erb_matrix.py --runtime-bins 匯出成 raw float32 的 erb_fwd.bin／erb_inv.bin（layout 與 C 迴圈一致，json 記 shape）；C 只吃呼叫端載入的指標，loader 擁有檔案、可隨時替換 .bin 不需重編譯。因 ERB split 固定 65+64=129，graph I/O 在任何 n_fft 下都是 129 帶寬。inference.py calib 會在同一 process 同一 model instance 一併匯出並 parity-check graph（預設 <output>.onnx，--onnx 可改）。

State layout(--state-layout,export_onnx.py 與 inference.py calib 同旗標): split = version 6,出貨合約——mag/real/imag 三個特徵入,加六個 conv history、六個 h_tra_*、四個 h_dpgrnn*, 共 19 個 input,即上表與 GTCRNModelState 綁定的那組。 combined = version 7,EXPERIMENTAL、無 C runtime 綁定(號碼在 gtcrn_process.h 保留,下一次真正 bump 要跳 8)——十六個 state 依形狀併成三個: 實測 conv_cache (2,16,16,33)、h_tra (6,1,16)、 h_dpgrnn (4,33,8),input 只剩 6 個,總 state 值數與 bytes 不變。

併法:每一組都沿本來就有的軸接,所以沒有 tensor 多長一維(四維天花板守住)。 六個 conv history 都是 (1,C,pad,F)、C 與 F 相同只差深度,encoder 的 2+4+10 = 16 與 decoder 的 10+4+2 = 16 各自沿深度軸接起來,再讓 encoder／decoder 兩列沿原本就是 1 的 batch 軸併成 2。實作是 stream_model.CombinedStateGTCRN,它包住 StreamGTCRN 而非另寫一份,所以兩種邊界跑的是同一份 compute。 節點數實測:split 追蹤圖 595 節點(29 Slice、24 Concat),combined 618 節點 (4 Split、31 Slice、29 Concat);兩者經 exporter 內建 onnxoptimizer ＋ ORT 常數折疊後 本機量測分別為 267／278 節點(合約測試門檻 ≤ 300)。

延遲與 warm-up

  • 演算法 lookahead = 0 框:圖內所有時間 conv 都是左填充 causal (GTConvBlock 的 F.pad(h1,[0,0,pad_size,0])),TRA 與 inter RNN 單向, intra RNN 只在單框的頻率軸上雙向。
  • I/O 延遲 = WOLA 重疊 win−hop = 256 samples = 16 ms @16 kHz。
  • Warm-up:無「無輸出」暖機框(第 0 hop 即有輸出);但 conv/TRA/inter cache 由零起始, 且 C 串流的首框以零填充取代 PyTorch 離線 center=True 的 reflect padding (README 明載此差異只影響 clip 起點)。
  • 時間感受野:encoder/decoder 各 3 個 GTConvBlock 累積 (kT−1)·dilation = 2+4+10 = 16 框過去 context(cache 大小即由此而來),加上 RNN 無限記憶。
