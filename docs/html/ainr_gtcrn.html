AINR GTCRN (16 kHz complex-mask baseline)

概要

超輕量 16 kHz 降噪模型(ShuffleNetV2 conv + SFE + TRA + 2×DPGRNN, 輸出 complex ratio mask)。model layout v5 起固定前後端全部搬到 host；出貨的 state layout version 8(11 個 graph input):六個 depth-conv 各一個完整 window、兩顆 stacked GRU 狀態 h_tra／h_dpgrnn,每個 state 的輸入與 *_out 輸出 shape 相同、綁同一個位址: C 端 gtcrn_process.c 負責串流 STFT/WOLA 之外,還以 gtcrn_model_input(magnitude＋ERB 前向矩陣 erb_fwd.bin) 產生 mag/real/imag 三個 (1,129,1) 獨立輸入(各自量化 scale),圖只保留 learned compute(concat 後 SFE/conv/GRU),輸出 ERB 域 complex mask 由 gtcrn_model_output(ERB 逆矩陣 erb_inv.bin＋CRM)在 host 展開套用。

項目值(以現行程式碼為準)
取樣率 / grid16000 Hz;FFT/win/hop = 512/512/256(32 ms 窗、16 ms hop;GTCRN_N_FFT/GTCRN_HOP_LEN)
頻譜 bins257(GTCRN_N_BINS)
ERB 混合解析度(host 前後端)erb_subband_1=65(低頻原 bins)+ erb_subband_2=64(ERB 帶)= 129;DPGRNN width = 33(由 encoder stride 導出)
參數量trainable 23,669;含固定 ERB matrix 共 48,245(實際建構量測)
輸出ERB 域 complex mask;host 端 ERB 逆矩陣展開後 CRM 乘回同幀頻譜
STFT 正規化無(torch.stft 預設;C 端 norm=1.0f),root-Hann 窗

論文數據與逐層架構筆記見 docs/architecture_notes.md 與 README.md;上游原始 repo(含論文 PDF 與串流參考實作) vendored 於 AINR/gtcrn_github/。

API 用法

#include "GTCRN/gtcrn_process.h"

GTCRNProcessState st;               /* 16 bytes, 呼叫端配置 */
FftHandle *fft = fft_init(caller_fft_pool, caller_fft_pool_bytes,
                          GTCRN_N_FFT);
AcStftConfig fc;
gtcrn_framing_config(&fc, fft, NULL);            /* 512 點、hop 256、未縮放 */
AcStft  *stft  = ac_stft_init(mem_a, ac_stft_get_mem_size(&fc), &fc);   /* 窗表由它自帶 */
gtcrn_framing_config(&fc, fft, ac_stft_window(stft));   /* 合成物件借用同一張窗 */
AcIstft *istft = ac_istft_init(mem_s, ac_istft_get_mem_size(&fc), &fc);
gtcrn_process_init(&st, stft, istft);   /* state 只借用 caller-owned 物件 */

float spec[GTCRN_N_BINS][2];        /* bin-major [re, im] */
float mag[GTCRN_MODEL_ERB_BANDS], re_b[GTCRN_MODEL_ERB_BANDS],
      im_b[GTCRN_MODEL_ERB_BANDS];
float mask_erb[GTCRN_MODEL_ERB_BANDS][2];
float enhanced[GTCRN_N_BINS][2];
for (each hop of 256 new samples) {
    gtcrn_analysis(&st, in256, spec);       /* 未正規化 RFFT 一框 */
    gtcrn_model_input(spec, erb_fwd, mag, re_b, im_b); /* host 固定前端:
                                magnitude + ERB 前向矩陣 (erb_fwd.bin) */
    /* NPU: 三個 (1,129,1) 輸入 -> ERB 域 mask (1,129,1,2)
     * — 圖內只有學到的運算 */
    run_model(mag, re_b, im_b, mask_erb);
    gtcrn_model_output(mask_erb, erb_inv, spec, enhanced); /* host 固定後端:
                                ERB 逆矩陣 (erb_inv.bin) + CRM */
    gtcrn_synthesis(&st, enhanced, out256);  /* WOLA, 256 samples */
}

Python 離線:inference.py --config config.ini --model ckpt.pt --input in.wav --output out.wav (整段 torch.stft → model(spec) → torch.istft)。

State 表

ONNX/匯出邊界:export_onnx.py 交付 one-frame stateless graph；cache 尺寸由 stream_model.initial_inputs(model) 從 module tree 推導（不寫死 grid： spectrum 寬度隨 n_fft，cache extent 隨 GT block kernel/dilation 與 encoder stride）， 六個 conv window、h_tra 與 h_dpgrnn 都是 graph input/output， 加速器本身不保存跨次呼叫狀態：GTCRNModelState 就是 state buffer。只有就地綁定: runtime 把每個 state input 與對應 *_out 綁到同一個欄位（綁定表在 gtcrn_process.h）， 更新後的 state 就是下一次呼叫的輸入，沒有複製；須先讀完所有 state 輸入才寫同位址的輸出（目標平台已確認 NPU 的行為）。 呼叫端在每次 invocation 後用 gtcrn_model_state_validate() 檢查（見下）。 匯出不再 pin 單一 grid——config 與 checkpoint 不成對時在 strict load_state_dict（形狀）或 checkpoint contract（同形語意）就大聲失敗。 v5 起固定前後端全在 host：gtcrn_model_input（magnitude＋ERB 前向矩陣） 產生 mag/real/imag 三個獨立輸入（各自量化 scale）；圖回傳 ERB 域 complex mask，gtcrn_model_output 做 ERB 逆矩陣＋CRM。矩陣由 export_erb_matrix.py --runtime-bins 匯出成 raw float32 的 erb_fwd.bin／erb_inv.bin（layout 與 C 迴圈一致，json 記 shape）；C 只吃呼叫端載入的指標，loader 擁有檔案、可隨時替換 .bin 不需重編譯。因 ERB split 固定 65+64=129，graph I/O 在任何 n_fft 下都是 129 帶寬。inference.py calib 會在同一 process 同一 model instance 一併匯出並 parity-check graph（預設 <output>.onnx，--onnx 可改）。

State 邊界(layout version 8):所有 state tensor 都是 rank 4,輸入與 *_out 輸出 shape 完全相同; metadata 記 state_binding = in_place_same_address。版本 3–7 已退役(RETIRED_LAYOUT_VERSIONS)。

  • conv_enc0/1/2、conv_dec0/1/2 (1,16,3|5|11,33):depth-conv 的完整因果 window(= 舊歷史 + 新的一幀)。 圖在輸入上做一個 Slice(axes=[2]、starts=[1]、ends=[K]、step 1,end 是明確整數)丟掉最舊一幀,接上新的一幀,卷積, 並把整個 K 幀 Concat 結果當作 conv_*_out。輸入只有這一個 consumer,沒有任何 state 輸出由 Slice 產生。 decoder 的 window 深度與 encoder 反向(11、5、3)。
  • h_tra (1,6,1,16):六顆 TRA attention GRU,列順序 encoder 0–2 再 decoder 0–2;h_dpgrnn (1,4,33,8):四顆 grouped inter GRU (h_dpgrnn1_0、h_dpgrnn1_1、h_dpgrnn2_0、h_dpgrnn2_1),hidden batch 是頻率軸。 每顆 GRU 用輸入上 dim 1 的 Slice 取自己的列再 squeeze,下一個 state 以一個 Concat(dim 1)接回。

同一份 compute:舊的逐 block／逐 GRU 輸入對照以 ONNX Runtime 重播驗證——240 hops 實音訊與 27 hops 隨機輸入, 輸出 head 與舊圖逐位元相同(最大差 0),新 window 前 K−1 幀等於舊輸入、後 K−1 幀等於舊輸出,h_tra／h_dpgrnn 等於舊的六個／四個 hidden 依序串接。匯出圖經 exporter 內建 onnxoptimizer ＋ ORT 常數折疊後本機量測 299 節點(36 個 Slice,皆 step 1;合約測試門檻 ≤ 300)。 AINR/onnx_streaming_contract.py 的 validate_inplace_state_graph() 在匯出時檢查上述條件, AINR/check_state_quantization.py 可對量化後的圖與報告再檢查 state 輸入／輸出的 dtype、scale、zero point、shape 是否一致。 Slice 沿 axis 2 的起點在 int8 下落在 33 byte 的整數倍(window 一列 33 個元素),不是 16 byte 對齊;對齊處理由量化工具鏈決定,尚未在板上驗證。

gtcrn_model_state_validate(GTCRNModelState*):每次 invocation 後就地檢查 8 個 state 張量, 全部有限回 0;任何 NaN/Inf 則整個 state 歸零、state generation 加 1 並回 -1(前一個 state 已被覆寫;寫一半而仍有限者偵測不到;可信 runtime 可不呼叫)。 gtcrn_model_state_generation() 回傳 generation:gtcrn_model_state_init() 後為 1,每次 gtcrn_model_state_reset() 與每次被拒的 validate 加 1(mod 2^32); 加速器那份定點 state 看不到這兩件事,runtime 發現數值與上一幀不同就把自己的 state tensor 填成量化後的零。 sizeof(GTCRNProcessState) = 16 bytes(兩個物件指標;64-bit 本機量測);物件大小用 ac_stft_get_mem_size()／ac_istft_get_mem_size() 現查。 本目錄 model.py 無 cache 介面;上表 NPU 狀態 shape 逐一取自 stream_model.initial_inputs() 與匯出 graph schema； sizeof(GTCRNModelState) = 84,868 bytes(84,864 bytes 的八個 state tensor ＋ 4 bytes 的 generation)。

延遲與 warm-up

  • 演算法 lookahead = 0 框:圖內所有時間 conv 都是左填充 causal (GTConvBlock 的 F.pad(h1,[0,0,pad_size,0])),TRA 與 inter RNN 單向, intra RNN 只在單框的頻率軸上雙向。
  • I/O 延遲 = WOLA 重疊 win−hop = 256 samples = 16 ms @16 kHz。
  • Warm-up:無「無輸出」暖機框(第 0 hop 即有輸出);但 conv/TRA/inter cache 由零起始, 且 C 串流的首框以零填充取代 PyTorch 離線 center=True 的 reflect padding (README 明載此差異只影響 clip 起點)。
  • 時間感受野:encoder/decoder 各 3 個 GTConvBlock 累積 (kT−1)·dilation = 2+4+10 = 16 框過去 context(conv window 深度 = 歷史 + 新的一幀,即 3、5、11),加上 RNN 無限記憶。
