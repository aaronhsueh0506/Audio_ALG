index 串接範例 整合時序圖 串接範例細節 mono 4ch AEC API NR API audiolib API

整合時序圖 — 每個函式庫何時被誰呼叫

概要

只有「4 聲道線性 AEC + BF」被包成一個單元(AudioPipeline4Ch)。其餘 stage(4ch 的 RES 亦然;mono 的 RES 在 AEC 呼叫內)都是獨立函式庫,各有 *_get_mem_size() 與 *_init(),初始化、逐 hop 串接、錯誤後的 reset 順序都是整合者(應用)的責任,範例 main 就是參考寫法。本頁用時序圖把三件事畫在一起:建立(一次)、每 hop 的呼叫順序、被拒絕或換串流時的 reset。圖中的箭頭標的都是真實函式名;「借用」代表回傳的指標指向函式庫內部 buffer,只到下一次處理呼叫或 reset 之前有效,不可寫入。

責任誰擁有
pool 記憶體(16-byte 對齊的一塊或多塊)應用:每個函式庫先 *_get_mem_size()(0 = 設定無效),應用配置並 carve 成 16-byte 對齊的子區塊,*_init() 在上面建構;*_destroy() 不釋放 caller pool
格點與 config 的一致性應用:AEC、NR、合成都用同一個 grid.fft_size 導出 config(三者 n_freqs／hop 對不上不會被偵測,會在頻域靜默錯位)
輸入守衛(是否有限)mono:沒有(aec_process_context() 與 se_anr_stage_gain() 不檢輸入);4ch 核心／單元:four_aec_front_process() 拒非有限樣本。輸出守衛 se_hop_is_finite() 由應用做
RES(殘留回音增益)mono:在 aec_process_context() 內算,經 se_frame_from_aec() 以 frame.g_res_ctx 交出;4ch:單元與核心都不算(g_res_ctx 為 NULL),應用自己用 libaec 的 AecRes(se_res_stage_gain())
reset 的範圍函式庫只 reset 自己;任何一步被拒,應用把所有 stage 與自己的 CNG 亂數狀態一起 reset(見第 4 節)

1. mono:Aec + AnrDenoiser + AcIstft

應用(main)                  Aec(lib/aec)            AnrDenoiser(lib/nr)     AcIstft(audiolib)
   │                              │                          │                       │
   │═ ① 建立(一次;此後 hop 路徑零 heap)═══════════════════════════════════════════
   │ se_derive(&req,&rules,&grid,&aec_cfg)              純函式: 0=ok, -1=拒絕(格點/delay/preset)
   │ anr_config_for_mode_grid(sr, grid.fft_size, mode) -> nr_cfg      ac_stft_config_default(&syn_cfg, fft)
   │── aec_get_mem_size ───────►│  0=無效                  │                       │
   │── anr_get_mem_size ─────────────────────────────────►│  0=無效               │
   │── ac_istft_get_mem_size ───────────────────────────────────────────────────►│  0=無效
   │ pool = platform_alloc(Σ ALIGN16(各大小) + 暫存, 16)
   │── aec_init(pool,...) ─────►│  NULL=過小/未對齊/無效   │                       │
   │── anr_init(pool+a,...) ─────────────────────────────►│  NULL=同左            │
   │── ac_istft_init(pool+a+n,...) ─────────────────────────────────────────────►│  NULL=同左
   │ unity[k]=1; rng=SE_CNG_RNG_SEED
   │
   │═ ② 每 hop(mic、ref 各 grid.hop_size floats,同 sample rate、同時鐘)═══════════
   │── aec_process_context(aec,mic,ref) ►│ 線性 AEC + delay 估計 + AEC 內部 RES 增益
   │── se_frame_from_aec(aec,&f) ─────►│ 借用視圖 f: e,y,x,r2,cn,g_res_ctx;-1=lane 沒有 seam
   │── se_anr_stage_gain(nr,&f,extra,1) ───────────────►│ r2/32768² 折進噪聲底 → anr_process_gain → G_nr
   │ sk_min_f32(g_total, G_nr, f.g_res_ctx, n)             ← 應用自己呼叫 audiolib kernel
   │ sk_capply_gain_f32(spec, f.e, g_total, n)
   │ aec_cng_fill(&rng,spec,f.cn,f.g_res_ctx,G_nr,SE_CNG_NR_GAIN_FLOOR,n)   ← 選用(AecConfig.enable_cng)
   │── ac_istft_push(istft,spec,out) ───────────────────────────────────────────►│ iFFT + sqrt-Hann OLA → out[hop]
   │ se_hop_is_finite(out,hop)                              ← 輸出守衛,應用自己做
   │
   │═ ③ 任一步被拒 / 輸出非有限 / 換串流 ══════════════════════════════════════════
   │── aec_reset ─────────────►│ ── anr_reset ───────────────►│ ── ac_istft_reset ──►│   rng=SE_CNG_RNG_SEED
   │
   │═ ④ 結束 ══════════════════════════════════════════════════════════════════════
   │ anr_destroy(nr); aec_destroy(aec); platform_free(pool)          (destroy 不釋放 caller pool)

se_anr_stage_gain() 只在 use_r2=1、frame.r2 與暫存非 NULL 且 frame.usable_linear 非零時才把 r2/32768² 折進噪聲底,否則等於純降噪。--aec-only:只建 Aec,每 hop 一個呼叫 aec_process(aec,mic,ref,out)(直寫 out,0-hop lag)。逐 hop 的 swimlane 與延遲見 pipeline_mono。

2. 4ch 單元:AudioPipeline4Ch(共用 delay、4 lane、SRP-PHAT、BF)+ 應用的 RES

應用(main)       AudioPipeline4Ch                          AecRes(libaec)  AnrDenoiser  AcIstft
                  [共用 aligner + 4 lanes]  [SRP] [BF]
   │                       │
   │═ ① 建立 ═════════════════════════════════════════════════════════════════════
   │ cfg = audio_pipeline_4ch_default_config(sr)     之後可改 cfg.core.* / geometry / bf_*(見 4ch 參數頁)
   │── audio_pipeline_4ch_get_mem_requirements(&cfg,&req) ►│ 0=ok, -1=無效;req.{bytes,alignment=16,layout_version,...}
   │ pool = platform_alloc(req.bytes, req.alignment)
   │── audio_pipeline_4ch_init_ex(pool,req.bytes,&cfg,&req) ►│ carve: self,core,srp,bf,bf_spectrum,bf_weights
   │                       │  8 點閘;任何失敗一律靜默回 NULL(無診斷輸出)
   │ RES / NR / 合成另開一塊 post pool(應用自己的 init):
   │   aec_config_from_preset(&res_cfg,preset,sr); res_cfg.fft_size = audio_pipeline_4ch_fft_size(p)
   │── aec_res_get_mem_size → aec_res_init(post,...) ►│ 0 / NULL = 無效或 pool 過小;沒有 destroy
   │ anr_init、ac_istft_init(同 mono 的 ①)
   │
   │═ ② 每 hop(mics_interleaved[hop][4]、ref[hop])═══════════════════════════════
   │── audio_pipeline_4ch_process_front(p,mics,ref,&front) ►│ four_aec_front_process: 共用 delay → aligned_ref
   │                       │   → 4 條 lane(lane 0 真 far-FFT,lane 1-3 借用)
   │   front.{delay, linear_spectra[4], formed_hop[4], aligned_ref}(借用)
   │ [應用: 由 front.linear_spectra 算 frequency_mask / vad_raw / vad_out]
   │── audio_pipeline_4ch_process_beam(p,&front,vad_raw,vad_out,mask,&beam,&info) ►│ doa_step → bf_process_with_weights
   │   beam.{spectrum, weights}(借用)        (一次做完前兩步: process_with_activity / process)
   │── audio_pipeline_4ch_fuse(p,&frame) ►│ four_aec_fuse(weights,spectrum) → frame(E, R2, CN)
   │   frame.{e,y,x,r2,cn,far_hop,...}(借用;g_res_ctx 恆為 NULL)
   │── se_res_stage_gain(res,&frame) ─────────────────────────►│ aec_res_process → G_res(NULL = 被拒)
   │── se_anr_stage_gain(nr,&frame,extra,1) ──────────────────────────────────►│ G_nr
   │ sk_min_f32 -> sk_capply_gain_f32 -> aec_cng_fill(僅 frame.cn 非 NULL)   (應用自己)
   │── ac_istft_push(istft,spec,out) ─────────────────────────────────────────────────────►│ out[hop]
   │
   │═ ③ 錯誤 / 換串流 ═════════════════════════════════════════════════════════════
   │── audio_pipeline_4ch_reset(p) ►│(core,SRP,BF,fallback VAD)
   │── aec_res_reset(res) (preset 保留);  anr_reset(nr);  ac_istft_reset(istft);  rng=SE_CNG_RNG_SEED   ← 應用自己的後級
   │
   │═ ④ 結束 ═══════════════════════════════════════════════════════════════════════
   │ anr_destroy(nr); audio_pipeline_4ch_destroy(p); platform_free(post); platform_free(pool)    (AecRes 沒有 destroy;unit destroy 不釋放 caller pool)

RES 強度在執行期用 aec_res_set_preset(res, preset, ramp_ms)(res 是應用自備的 AecRes),NR 用 anr_set_mode(nr, mode),兩者都在兩個 hop 之間呼叫;見 pipeline_4ch_detail。

3. 4ch 核心 + 外部 beamformer(產品自己的波束器)

單元沒有「外部波束權重」入口(目前的能力缺口);波束器在別處時退回核心(4aec_nr_res.h),RES 就由應用自備 AecRes(aec_res_get_mem_size()／aec_res_init(),config 由 aec_config_from_preset() 在同一個 fft 上取得)。範例:4aec_nr_res_static.c(權重為每個 bin 皆 1/4 的等權佔位)。

應用            FourAecNrRes(核心)         外部 BF(產品自己的)        AecRes(應用自備)  AnrDenoiser  AcIstft
 │── four_aec_front_process(core,mics,ref,&front) ►│ 共用 delay + 4 lanes
 │   front.linear_spectra[4] / formed_hop[4] / aligned_ref / delay(delay.changed 非零 ⇒ 外部 STFT/OLA 歷史須清)
 │── front.linear_spectra ─────────────────────────►│ weights Complex[4][n_freqs](channel-major, out=Σ w·x 無共軛)
 │── four_aec_fuse(core,weights,beamformed_error|NULL,&frame) ►│ frame.g_res_ctx=NULL(核心不算增益)
 │── se_res_stage_gain(res,&frame) ──────────────────────────────►│ G_res
 │── se_anr_stage_gain(nr,&frame,extra,1) ────────────────────────────────────────►│ G_nr
 │   sk_min_f32 -> sk_capply_gain_f32 -> aec_cng_fill -> ac_istft_push ─────────────────────────────►│ out
 │── four_aec_nr_res_reset(core); aec_res_reset(res); anr_reset(nr); ac_istft_reset(istft); rng=SE_CNG_RNG_SEED

4. 錯誤與 reset:誰重設什麼

呼叫回傳／情況函式庫自己做了什麼應用要做什麼
four_aec_front_process()／audio_pipeline_4ch_process_front()INVALID_ARGUMENT(NULL 或非有限樣本)不動 adaptive state;非有限樣本時單元不再有 pending 的 front／beam(NULL 引數則維持原狀)修正輸入後重送;不需 reset
同上DSP_ERROR(lane 拒絕)核心已 reset;單元另在「front 與單元格點不符」時 reset 單元reset 自己的後級(4ch:AecRes、NR、合成、rng)
audio_pipeline_4ch_process_beam()SEQUENCE_ERROR(沒有 pending front,或本 hop 的 beam 已跑);INVALID_ARGUMENT(NULL、flag 不是 0／1、他格點的 front)不改動修正呼叫順序
audio_pipeline_4ch_fuse()INVALID_ARGUMENT(NULL 或 enable_post=0)、SEQUENCE_ERROR(本 hop 沒有 beam)不改動修正呼叫
同上其餘非 OK(含核心因權重非有限或 lane far 頻譜不一致回的值)依 audio_pipeline_4ch.c:單元整體 reset(core、SRP、BF)後回傳reset 自己的後級(含 AecRes)
four_aec_fuse()(核心)INVALID_ARGUMENT(權重全零或非有限)front frame 保持可用修正權重後可重試同一 hop
同上SEQUENCE_ERROR(沒有 front frame);DSP_ERROR(lane far 頻譜不一致或頻譜非有限)前者不改動;後者核心已 reset後者 reset 自己的後級(含 AecRes)
se_anr_stage_gain()／se_res_stage_gain()回 NULLNR 該 hop 被拒;4ch 的 RES 缺輸入(mono 對應 se_frame_from_aec() 回 −1 或 g_res_ctx 為 NULL)視為該 hop 被拒,所有 stage 一起 reset:mono CLI 把該 hop 輸出填 0 後繼續;4ch 範例 reset 後回 DSP_ERROR 並結束該次執行
輸出 se_hop_is_finite() 為 0——unit／Aec 與後級一起 reset(範例 static_hop()／raw_post() 的寫法)
4ch 的後級物件(AecRes、AnrDenoiser、AcIstft)與 CNG 的亂數種子 SE_CNG_RNG_SEED 都不在單元／核心裡,單元的 audio_pipeline_4ch_reset() 不會動它們。mono 的 mono_aec_nr_res/main.c 與 static_main.c 在 process_hop() 回 −1 時呼叫 rig_reset() 並把該 hop 輸出填 0;這兩支 CLI 本身不做輸出有限檢查,example_board_adapter.c 與 4ch 的 static_hop()／raw_post() 才有。

5. 接 NN 後級的 hop 骨架(摘要)

NN 後級把一個 hop 拆成四個呼叫,加速器夾在 nn_begin 與 nn_end 之間;細節與 fail-open 規則在 串接範例 第 5 節、pipeline_ulcnet_mono／pipeline_dfn_mono。

應用            Aec 或 4ch 單元          NN stage(範例碼)            NN runtime／加速器
 │── (Aec: aec_process_context + aec_get_res_context／aec_get_linear_context) 或 (單元: process_front/beam[/fuse]) ►│
 │── ulcnet_nn_stage_begin_time / _begin_complex  (dfn: dfn_hop_begin) ►│ 分析 err／far
 │── ulcnet_nn_stage_nn_begin(stage,&job) ►│ 回 1=有一幀、0=本 hop 無模型幀
 │── board_run_npu(job.*) ───────────────────────────────────────────────►│ out 已預填 NaN,必須寫滿
 │── ulcnet_nn_stage_nn_end(stage,rc) ►│ rc≠0 或輸出非有限 ⇒ identity(fail-open)
 │── ulcnet_nn_stage_end(stage,out) ►│ ac_istft_push_planar → out[hop]
