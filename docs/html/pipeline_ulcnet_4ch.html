audio_pipeline_4ch_ulcnet — 4ch 空間前級 + Align-ULCNet NN 後級

概要

pipelines/4ch_alignulcnet/audio_pipeline_4ch_ulcnet.{h,c}:沿用四聲道空間前級(共用 delay + 4 AEC lanes + SRP-PHAT + GSC,見 pipeline_4ch),但核心的 post-beam RES/NR 路徑不使用——每個 pre frame 以 four_aec_nr_res_abandon_pre() 釋放,由 Align-ULCNet chain 完全取代 post 級:GSC beamformed 誤差頻譜 → 本 wrapper 的 WOLA 重建成時域 beam hop → ULCNet centered STFT chain → UlcnetModel callback(外部 NPU runtime)→ WOLA → 增強 mono hop。格點僅 16 kHz / fft 512 / hop 256 / 257 bins(48 kHz 與 fft≠{0,512} 在驗證期 reject;fft_size=0 強制 512,絕不落到核心自己的 256 預設)。

ONNX/NPU graph 邊界與 runtime 保存的 NN states 與 mono 變體完全相同(graph 內:reorient/attention/GRU/mask 組合, learned compute only;graph 外:STFT/WOLA/AEC/beamform/delay policy＋固定前後端(signed-pow 壓縮特徵/逆冪, 封在 model_io prepare/commit);runtime 保存 far K/V ring、logit 史、GRU h)——見 pipeline_ulcnet_mono 的邊界表。VAD 僅提供外部版 process_with_activity()(auto-VAD fallback 留在標準 wrapper;auto_vad_* 欄位驗證但不使用)。

API 用法

AudioPipeline4ChConfig cfg = audio_pipeline_4ch_ulcnet_default_config();
/* = audio_pipeline_4ch_default_config(16000) 且 core.fft_size 預設 512 */
AudioPipeline4ChUlcnetMemReq req;
audio_pipeline_4ch_ulcnet_get_mem_requirements(&cfg, &req);
void* pool = platform_alloc(req.bytes, req.alignment);
AudioPipeline4ChUlcnet* p = audio_pipeline_4ch_ulcnet_init_ex(pool, req.bytes, &cfg, &req);

UlcnetModel model = { my_user, my_infer, my_reset, &exported_descriptor };
audio_pipeline_4ch_ulcnet_set_model(p, &model);           /* NULL 可清除; 不觸發 reset */

while (stream) {   /* mics=[256][4] interleaved, far/out=[256] */
    audio_pipeline_4ch_ulcnet_process_with_activity(p, mics, far, vad, out);
}
audio_pipeline_4ch_ulcnet_reset(p);    /* 也呼叫 model->reset; 不動 model 安裝 */
audio_pipeline_4ch_ulcnet_destroy(p);  /* 不釋放 caller pool */
  • set_model():struct by-value 複製;model->user 指向物由 caller 保活。production far branch 固定為 aligned-far seam，因此非 NULL descriptor 必須通過 ulcnet_model_io_descriptor_validate()（raw/未知 descriptor reject）。runtime 不提供 far-mode setter。
  • 診斷:audio_pipeline_4ch_ulcnet_last_beamformed_error()(最近一次成功呼叫重建的 beam hop,唯讀)、audio_pipeline_4ch_ulcnet_last_delay()。

沒有執行期強度 setter,而且是刻意的。標準 wrapper 有 audio_pipeline_4ch_set_aec_preset() / _set_nr_mode(),本變體 兩個都不提供——因為它沒有可以重新指定的強度面。本 wrapper 的核心是 core.enable_post = 0 的 pre-only 組態(validate_config() 拒絕任何其他值),而 enable_post = 0 時核心根本不存在 post 級抑制器、也不存在 NR 實例;每個 pre frame 都以 four_aec_nr_res_abandon_pre() 釋放,塑形輸出的是 ULCNet 的 mask。核心那兩個 setter 在 pre-only 核心上本來就回 −1(見 pipeline_4ch 的「執行期強度控制」表),所以這一層不轉出它們。要改強度,請重新訓練/更換模型,或改用有 DSP 後級的 pipeline_4ch。

far 一 hop 補償的理由:beam WOLA 慢一 hop,所以 far branch 也要慢一 hop(far_delay 存前一 hop 的 far 源),模型看到的 err/far 幀對才屬於同一個 input hop;拿掉這個 buffer,模型會看到 error[t-1] 配 far[t](固定 256 樣本 skew)——4ch far-timestamp 測試就是這樣設計成會紅 256 樣本。

err 分支不保證每個 hop 都是誤差。模型的 err 幀來自 GSC 對 pre.linear_spectra 的加權,而那四路是各 lane 的 formed 頻譜;四條 lane 都以 enable_res=0 / return_res_context=1 建立,而 lib/aec 的 formed 選擇器只在這個 context-only 模式多開一個 capture 候選:上一個 hop 的濾波品質判定尚未認可線性估計、且該 lane 被選中的殘差在這個 hop 的能量大於同一 hop 的 mic capture 時,該 lane 的時域 hop 與頻譜一起改送 capture(既有 30-sample crossfade 承接邊界)。這種 hop 上 beamform 出來的 err 幀混的是 mic 原樣,不是誤差。

Identity reprime(alignment 邊界,option A)

model->reset 清掉 runtime 的 K/V ring、logit 史與 GRU h,但 C 側 ULCNet STFT 狀態是連續跑的:邊界當下還在飛的分析窗仍跨在邊界上。在那種幀上 step 模型,等於用半舊的 err/far 幀對把剛清掉的 state 重建回去。

政策:從邊界 hop 起的 AUDIO_PIPELINE_4CH_ULCNET_REPRIME_FRAMES 個發射幀走 identity(誤差原樣)且完全不呼叫 infer——K/V、logit、GRU 都不前進;等到 err 與 far 兩路分析窗都只含切換後的 hop,才同時恢復 step 與 apply。reprime 期間再來一次邊界會重新武裝(不累加);audio_pipeline_4ch_ulcnet_reset() 會把它歸零(analysis history 已清空)。compute 只會少 2 幀推論,不會加倍。

常數是量出來的,不是寫死的,而且比 mono 版(1)多一幀,理由可追:本 wrapper 兩路都比輸入慢一 hop(beam WOLA 一 hop + 對應的 far 一 hop 補償),所以邊界 hop T 推入的那一格仍屬於切換前的 input hop T−1(實作上正是被清成零的 OLA/far_delay);centered 512/256 分析橫跨兩格 ⇒ hop T 與 T+1 發射的兩幀都跨界,hop T+2 才乾淨。測試 test_reprime_straddle_derivation() 用「切換前最後一個 input hop 正中央打一個單位脈衝、其餘全靜音」在一個完全沒有邊界的對照跑(FIXED delay 0)裡量:reprime 不參與量自己,而且邊界跑會把那一格清成零、反而看不到它跨界。兩路各得 2,與常數相符;實測 marked peak 0.6665(err)/0.7071(far) vs unmarked 1.257e-02/0.000e+00。邊界跑再驗:reprime 後第一個模型看得到的幀(hop 10)兩路都不含切換前樣本。

option B(邊界後照常 step、只是輸出仍套用)暫緩,要先做音檔 A/B 才能換。

延遲與 warm-up

  • 總附加演算法延遲 = 2 hops = 512 samples = 32 ms:1 hop beam-spectrum WOLA(hop p 的頻譜要到 hop p+1 才在時域閉合)+ 1 hop centered ULCNet chain。far branch 由 far_delay 補償一 hop,使 err/far 同 input hop。
  • 測試佐證:pre-acquisition seam 的 far[2085] 脈衝準確落在 out[2597](= impulse + 512;offset +0;peak 1.0000)。identity E2E:hop#0/#1 全零,out[hop p] = hop p-1 時 accessor 讀到的 beam hop。
  • delay change(pre.delay.changed):核心 reset 四條 lane;wrapper 清 beam OLA + far_delay、呼叫 model->reset 並武裝 identity reprime;C 端 chain STFT 狀態連續,跨界的 AUDIO_PIPELINE_4CH_ULCNET_REPRIME_FRAMES=2 幀改走 identity 且不 step 模型(見下節)。changed 涵蓋 unlock 後同值重鎖(新的可用 alignment generation),因此 unlocked 期間 model 持續 step 累積的 recurrent state 會在重新套用前被 flush。
  • delay lock 不閘控模型：ring 尚無法供應該 offset 時 seam 整 hop 傳 raw far(FIXED 的 ring-fill 窗也是 raw,不是靜音),模型照常步進並套用；可供應後 reset state，再改用 aligned far。
  • 錯誤處理:內部 DSP 錯誤(尺寸不符、abandon 失敗、幀數不同步)→ wrapper 自我 reset 並回核心 status code(與標準 wrapper 同慣例);2-hop 前導重新開始。
