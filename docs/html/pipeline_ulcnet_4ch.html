audio_pipeline_4ch_ulcnet — 4ch 空間前級 + Align-ULCNet NN 後級(直送路徑)

概要

pipelines/4ch_alignulcnet/audio_pipeline_4ch_ulcnet.{h,c}:沿用四聲道空間前級(共用 delay + 4 AEC lanes + SRP-PHAT + GSC,見 pipeline_4ch),但前端的 fuse 與後級(RES／NR／CNG／ISTFT)不使用——每 hop 只呼叫 four_aec_front_process(),不呼叫 four_aec_fuse(),由 Align-ULCNet chain 完全取代 post 級;沒有 token,也不需要「放棄」呼叫,下一個 four_aec_front_process() 直接接手。每個 binary 服務一個編譯期格點:16 kHz / 512 / 256 / 257 bins或48 kHz / 1024 / 512 / 513 bins；runtime config 不符該 build 即 reject。

直送路徑(direct path):GSC 的輸出頻譜就是模型的 error 幀。bf_process_with_weights() 產出的 bf_spectrum 已經是「當前 hop 的 sqrt-Hann、50% overlap、一 hop 一幀」分析幀——各 lane 的 AEC 用同一張窗、同一個 overlap 分析,beamformer 只是逐 bin 加權——所以它不經過任何重建或再分析,直接拆成 err_re/err_im 交給模型。far 分支用同一個 hop 的 far 源走同樣的一 hop 一幀 framing(ac_stft_push_planar()),沒有補償 buffer。相對於「beam WOLA 回時域再重新分析」的做法,每 hop 省下一次 IFFT 與一次 RFFT,並少一個 hop 的延遲。

ONNX/NPU graph 邊界與 runtime 保存的 NN states 與 mono 變體完全相同(graph 內:reorient/attention/GRU/mask 組合, learned compute only;graph 外:STFT/WOLA/AEC/beamform/delay policy＋固定前後端(signed-pow 壓縮特徵/mask 乘法/逆冪, 封在 model_io prepare/commit;graph 止於 complex_mask 1×1 Conv);runtime 保存 far K/V window、logit window、GRU h;四個 state 由 caller pool 保存,每個 *_out 就地綁定到同名輸入的位址)——見 pipeline_ulcnet_mono 的邊界表。VAD 僅提供外部版 process_with_activity()(auto-VAD fallback 留在標準 wrapper;auto_vad_* 欄位驗證但不使用)。

API 用法

AudioPipeline4ChConfig cfg = audio_pipeline_4ch_ulcnet_default_config();
/* sample rate/FFT 取自編譯期 ULCNET_SR/ULCNET_N_FFT */
AudioPipeline4ChUlcnetMemReq req;
audio_pipeline_4ch_ulcnet_get_mem_requirements(&cfg, &req);
void* pool = platform_alloc(req.bytes, req.alignment);
AudioPipeline4ChUlcnet* p = audio_pipeline_4ch_ulcnet_init_ex(pool, req.bytes, &cfg, &req);

UlcnetModel model = { my_user, my_infer, my_reset, &exported_descriptor };
audio_pipeline_4ch_ulcnet_set_model(p, &model);           /* NULL 可清除; 不觸發 reset */

while (stream) {   /* mics=[ULCNET_HOP][4], far/out=[ULCNET_HOP] */
    audio_pipeline_4ch_ulcnet_process_with_activity(p, mics, far, vad, out);
}
audio_pipeline_4ch_ulcnet_reset(p);    /* 也呼叫 model->reset; 不動 model 安裝 */
audio_pipeline_4ch_ulcnet_destroy(p);  /* 不釋放 caller pool */

板端把推論留給 NPU 時,同一個 hop 拆成四個呼叫(模型的 infer 回呼因此可以不設;reset 回呼若有設,邊界與 reset() 時仍會被呼叫):

UlcnetNnJob job;
audio_pipeline_4ch_ulcnet_process_begin(p, mics, far, vad);   /* 四條 lane、DOA、GSC、far 分析 */
if (audio_pipeline_4ch_ulcnet_nn_begin(p, &job) > 0) {        /* 1 = 有一幀要跑;0 = 本 hop 無模型幀(reprime) */
    int rc = board_run_ulcnet_on_npu(&job);                 /* job.err_*(GSC 頻譜)、job.far_*;寫滿 job.out_*(預填 NaN) */
    audio_pipeline_4ch_ulcnet_nn_end(p, rc);                  /* rc==0 且每個 bin 有限才採用,否則 identity */
}
audio_pipeline_4ch_ulcnet_process_end(p, out);                /* WOLA,剛好一個 hop */

process_with_activity() 就是這個序列加上已安裝的模型回呼。nn_begin 回 1(*job 借用到 nn_end)、0 或負的 FOUR_AEC_NR_RES_* 狀態;開著沒取走或沒關閉的幀走 identity(fail-open),序列錯誤回 FOUR_AEC_NR_RES_SEQUENCE_ERROR。reprime 計數在 process_begin 遞減,所以與一次呼叫版本逐位元相同。

板端若有由同一 hop 的 lane 頻譜算出的 per-bin mask 與 VAD(例如 masker 讀 lane 0),process_begin() 要在 lane 與 beamformer 之間讓出控制權:它就是 process_front() 加 process_beam(front, v, v, NULL)。

AudioPipeline4ChUlcnetFront front;
audio_pipeline_4ch_ulcnet_process_front(p, mics, far, &front);          /* 四條 lane、邊界處理、far 分析;front.lane_spectra[4] 唯讀 */
/* 呼叫端:由 front.lane_spectra[0] 算 mask(n_freqs 個 int)、vad_raw、vad_out */
audio_pipeline_4ch_ulcnet_process_beam(p, &front, vad_raw, vad_out, mask);   /* SRP-PHAT、GSC;mask 可為 NULL */
AudioPipeline4ChUlcnetBeamState st;
audio_pipeline_4ch_ulcnet_beam_state(p, &st);   /* doa_raw/smooth/used(rad,NaN = 無)、bf_adaptive */
/* 之後 nn_begin / nn_end / process_end 與上面相同 */

mask[f] 非 0:SRP 使用該 bin、GSC 凍結該 bin 的適應;NULL = 全部 bin 給 SRP、都不凍結。vad_raw 決定 SRP 該 hop 是否分析,vad_out 進 DOA smoother 並凍結 GSC 適應(須為 0／1)。front.lane_spectra 有效至下一次 process_front()／process_begin()／reset()／destroy();兩個呼叫之間只有 process_beam() 合法(其餘回 FOUR_AEC_NR_RES_SEQUENCE_ERROR)。拆分不在 instance 內新增任何狀態,pool 大小與 layout 版本不變。beam_state() 直接讀 live 的 SRP／GSC 物件,有效至下一 hop 的 beam 半邊;last_core_timing() 回前端上一 hop 的各階段微秒數(板端 profiler 用)。

  • set_model():struct by-value 複製;model->user 指向物由 caller 保活。會 infer 的 model 必須發布 descriptor(model->infer && !model->io_descriptor 直接 reject);production far branch 固定為 caller 的 raw far,因此非 NULL descriptor 必須通過 ulcnet_model_io_descriptor_validate()(aligned／未知 descriptor reject)。runtime 不提供 far-mode setter。
  • 唯讀 accessor:四個尺寸查詢(_hop_size()／_fft_size()／_n_freqs()／_sample_rate())、audio_pipeline_4ch_ulcnet_last_delay()、_beam_state()(DOA 與 GSC 適應旗標)與 _last_core_timing()。沒有 beam hop accessor:直送路徑不重建時域 beam hop,C API 沒有時域 beam hop 可取(audio_pipeline_4ch_ulcnet.h)。

沒有執行期強度 setter,而且是刻意的。標準 wrapper 有 audio_pipeline_4ch_set_aec_preset() / _set_nr_mode(),本變體 兩個都不提供——因為它沒有可以重新指定的強度面。本 wrapper 的前端是 core.enable_post = 0 的 front-only 組態(validate_config() 拒絕任何其他值),不 carve fuse 緩衝,而且 wrapper 自己也不 carve 任何 RES／NR 實例;塑形輸出的是 ULCNet 的 mask。標準 wrapper 的那兩個 setter 作用在它自己 carve 的 AecRes／AnrDenoiser 上(見 pipeline_4ch 的「執行期強度控制」表),這個變體沒有對應物,所以不提供。要改強度,請重新訓練/更換模型,或改用有 DSP 後級的 pipeline_4ch。

唯一的延遲來源是 ULCNet synthesis 的半窗 trim:幀 #0 的區塊落在被裁掉的半窗裡,所以 ac_istft_push_planar()（AC_OLA_ENV_NORM）在 hop#0 回 0 樣本(pipeline 補零),之後每 hop 一個完整 hop。兩個分支都從當前 input hop 取幀,所以模型看到的 err/far 幀對永遠屬於同一個 input hop——直送路徑沒有 one-hop far 補償 buffer,而且測試會抓:把 far 分支延一個 hop,far-timestamp 測試立刻偏 +1 hop 變紅。

err 分支不保證每個 hop 都是誤差。模型的 err 幀來自 GSC 對 front.linear_spectra 的加權,而那四路是各 lane 的 formed 頻譜;四條 lane 都以 enable_res=0 / return_res_context=1 建立,而 lib/aec 的 formed 選擇器只在這個 context-only 模式多開一個 capture 候選:上一個 hop 的濾波品質判定尚未認可線性估計、且該 lane 被選中的殘差在這個 hop 的能量大於同一 hop 的 mic capture 時,該 lane 的時域 hop 與頻譜一起改送 capture(既有 30-sample crossfade 承接邊界)。這種 hop 上 beamform 出來的 err 幀混的是 mic 原樣,不是誤差。

Identity reprime(alignment 邊界,option A)

邊界處理只做 model->reset 與武裝 identity reprime,不清任何 C 側 buffer:從邊界 hop 起的 AUDIO_PIPELINE_4CH_ULCNET_REPRIME_FRAMES(= 1)個發射幀走 identity 且完全不呼叫 infer;reprime 期間再來一次邊界會重新武裝(不累加);audio_pipeline_4ch_ulcnet_reset() 會把它歸零。常數 1 由 test_reprime_straddle_derivation() 在無邊界對照跑中以脈衝標記量出(ERROR 路是上界、FAR 路是推導);兩個 grid 的實測表、mutation 結果與 option B 暫緩的理由見 pipeline_ulcnet_detail。

頻譜一致性註記(直送路徑的已知取捨)

bf_spectrum 是逐 bin 加權的頻譜,一般不對應任何時域訊號的 STFT(即所謂 inconsistent spectrogram);經 WOLA 來回一趟會把它投影到一個 consistent 的頻譜上,直送路徑則不做這個投影,模型看到的是未投影的 GSC 頻譜。這個投影殘差是模型輸入端的差異:在真實 4ch 錄音上量到的 round-trip residual 約 −30 dB complex(−33 dB magnitude),語音帶 750–4000 Hz 為 −36..−43 dB;最差頻段是場景相關的,不能一概而論。輸出端則不受影響,因為 WOLA∘STFT∘WOLA 等於 WOLA。

延遲與 warm-up

  • 總附加演算法延遲 = 1 compiled-grid hop:16 kHz 為 256 samples / 16 ms,48 kHz 為 512 samples / 10.67 ms。組成只有 ULCNet synthesis 的半窗 trim;GSC 頻譜與 far 分析都在同一個 hop 完成,不加延遲。
  • 測試佐證:pre-acquisition seam 的 far 脈衝落點 = 脈衝 + 1 hop。16 kHz:far[2085] → out[2341](expected 2341,offset +0,peak 1.0000);48 kHz:far[4133] → out[4645](offset +0,peak 1.0000)。identity E2E:hop#0 全零,之後 out[hop p] 逐 byte 等於測試自己從「模型實際看到的頻譜」合成的參考(capture model,FIXED delay 0、無邊界;混合規則:hop 0 零、hop p≥1 混 p−1 與 p 兩幀)。
  • delay change(front.delay.changed)或 FIXED 首次 delay solid:呼叫 model->reset 並武裝 identity reprime,不清任何 buffer(前端自行 realign 四條 lane;本層的 far 分析與 synthesis 連續跑)。跨界的 1 幀改走 identity 且不 step 模型(見上節)。changed 涵蓋 unlock 後同值重鎖(新的可用 alignment generation),因此 unlocked 期間累積的 recurrent state 會在重新套用前被 flush。
  • delay lock 不閘控模型:模型從第一個 hop 起照常步進並套用(far 恆為 caller 的 raw far);alignment 可用或改變時 reset state。
  • 錯誤處理:內部 DSP 錯誤(尺寸不符、front_process 回錯誤、synthesis 吐出非 0 且非整 hop 的樣本數)→ wrapper 自我 reset 並回核心 status code(與標準 wrapper 同慣例);1-hop 前導重新開始。
