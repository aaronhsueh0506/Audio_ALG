audio_pipeline_4ch_ulcnet — 4ch 空間前級 + Align-ULCNet NN 後級

概要

pipelines/4ch_alignulcnet/audio_pipeline_4ch_ulcnet.{h,c}:沿用四聲道空間前級(共用 delay + 4 AEC lanes + SRP-PHAT + GSC,見 pipeline_4ch),但核心的 post-beam RES/NR 路徑不使用——每個 pre frame 以 four_aec_nr_res_abandon_pre() 釋放,由 Align-ULCNet chain 完全取代 post 級:GSC beamformed 誤差頻譜 → 本 wrapper 的 WOLA 重建成時域 beam hop → ULCNet centered STFT chain → UlcnetModel callback(外部 NPU runtime)→ WOLA → 增強 mono hop。格點僅 16 kHz / fft 512 / hop 256 / 257 bins(48 kHz 與 fft≠{0,512} 在驗證期 reject;fft_size=0 強制 512,絕不落到核心自己的 256 預設)。

ONNX/NPU graph 邊界與 runtime 保存的 NN states 與 mono 變體完全相同(graph 內:壓縮/attention/GRU/解壓縮;graph 外:STFT/WOLA/AEC/beamform/delay policy;runtime 保存 far K/V ring、logit 史、GRU h)——見 pipeline_ulcnet_mono 的邊界表。VAD 僅提供外部版 process_with_activity()(auto-VAD fallback 留在標準 wrapper;auto_vad_* 欄位驗證但不使用)。

API 用法

AudioPipeline4ChConfig cfg = audio_pipeline_4ch_ulcnet_default_config();
/* = audio_pipeline_4ch_default_config(16000) 且 core.fft_size 預設 512 */
AudioPipeline4ChUlcnetMemReq req;
audio_pipeline_4ch_ulcnet_get_mem_requirements(&cfg, &req);
void* pool = platform_alloc(req.bytes, req.alignment);
AudioPipeline4ChUlcnet* p = audio_pipeline_4ch_ulcnet_init_ex(pool, req.bytes, &cfg, &req);

UlcnetModel model = { my_user, my_infer, my_reset };
audio_pipeline_4ch_ulcnet_set_model(p, &model);           /* NULL 可清除; 不觸發 reset */
audio_pipeline_4ch_ulcnet_set_far_input_mode(p, ULCNET_FAR_RAW);  /* 串流前設定 */

while (stream) {   /* mics=[256][4] interleaved, far/out=[256] */
    audio_pipeline_4ch_ulcnet_process_with_activity(p, mics, far, vad, out);
}
audio_pipeline_4ch_ulcnet_reset(p);    /* 也呼叫 model->reset; 不動 model/mode 安裝 */
audio_pipeline_4ch_ulcnet_destroy(p);  /* 不釋放 caller pool */
  • set_model():struct by-value 複製;model->user 指向物由 caller 保活。中途換模型請先 reset 或裝新 reset 過的 runtime。三方一致性鎖與 mono 變體共用同一個 ulcnet_far_input_mode_agrees()(ulcnet_model_io.h):model.io_descriptor(來自 accelerator adapter,發布 checkpoint 的 far_input_mode)與 p->far_input_mode 不合則 set_model() 回 −1、已裝模型不動——與 mono 頁「init 時失敗」不同,這裡是安裝呼叫本身失敗(runtime 設定,非 init-time config 欄位),邊界細節見 pipeline_ulcnet_mono「far_input_mode 部署契約」節。
  • set_far_input_mode():RAW(預設,checkpoint 相容)/ ALIGNED(Phase-2 embedded 候選,只能配 aligned-far checkpoint);安裝性設定,survive reset;未定義值 reject 且維持原模式;同樣過 ulcnet_far_mode_agrees() 與已裝模型的 descriptor 核對。中途切換會改變在飛幀(one-hop far buffer)的輸入分布,且 frame_index!=0 時直接 reject(只能在 reset 後或串流前設定)。
  • 診斷:audio_pipeline_4ch_ulcnet_last_beamformed_error()(最近一次成功呼叫重建的 beam hop,唯讀)、audio_pipeline_4ch_ulcnet_last_delay()。

far 一 hop 補償的理由:beam WOLA 慢一 hop,所以 far branch 也要慢一 hop(far_delay 存前一 hop 的 far 源),模型看到的 err/far 幀對才屬於同一個 input hop;拿掉這個 buffer,模型會看到 error[t-1] 配 far[t](固定 256 樣本 skew)——4ch far-timestamp 測試就是這樣設計成會紅 256 樣本。

延遲與 warm-up

  • 總附加演算法延遲 = 2 hops = 512 samples = 32 ms:1 hop beam-spectrum WOLA(hop p 的頻譜要到 hop p+1 才在時域閉合)+ 1 hop centered ULCNet chain。far branch 由 far_delay 補償一 hop,使 err/far 同 input hop。
  • 測試佐證:far-timestamp(RAW)測試 far[2085] 的脈衝準確落在 out[2597](= impulse + 512;offset +0;peak 1.0000)。identity E2E:hop#0/#1 全零,out[hop p] = hop p-1 時 accessor 讀到的 beam hop。
  • delay change(pre.delay.changed):核心 reset 四條 lane;wrapper 清 beam OLA + far_delay 並呼叫 model->reset(兩種 far 模式都做);C 端 chain STFT 狀態連續,接受 1–2 幀暫態(crossfade 為後續 phase)。changed 涵蓋 unlock 後同值重鎖(新的可用 alignment generation),因此 unlocked 期間 model 持續 step 累積的 recurrent state 會在重新套用前被 flush。
  • ALIGNED 模式套用閘:pre.delay.solid && delay_samples>=0;未鎖定時 fail-open(模型仍步進)。RAW 模式從第一個發射幀就套用。mono 頁的短延遲部署注意同樣適用(短 bulk delay → acquisition 被 already-cancelling 保護永久擋下 → ALIGNED 模式 NN 永不生效)。
  • 錯誤處理:內部 DSP 錯誤(尺寸不符、abandon 失敗、幀數不同步)→ wrapper 自我 reset 並回核心 status code(與標準 wrapper 同慣例);2-hop 前導重新開始。
