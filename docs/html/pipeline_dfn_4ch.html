4aec_dfn_res — 4ch AEC → 外部 BF/GSC → RES → DeepFilterNet2 後級

概要

pipelines/4ch_aec_bf_dfn_res/4aec_dfn_res.{h,c}:包在傳統四聲道核心 FourAecNrRes(pipelines/4ch_aec_bf_nr_res/4aec_nr_res.h)外的一層 wrapper,把核心的 post-beam MMSE-LSA 換成 DeepFilterNet2。核心組態被強制為 enable_post=1 / enable_res=1 / enable_nr=0,不符即在 get_mem_requirements() 被拒(4aec_dfn_res.c:50-55)。

外部 beamformer 的接縫與核心完全相同:process_pre() 交出四條 lane 的線性結果,呼叫端算出有效權重後用 process_post()(由權重重建 beamformed 頻譜)或 process_post_trusted_spectrum()(直接交出 GSC 已經算好的頻譜)收尾。差別只在 wrapper 內部改走核心新增的兩個入口:four_aec_nr_res_process_post_view() 交出頻譜、four_aec_nr_res_synthesize_external() 用核心自己的 WOLA 收尾(pipelines/4ch_aec_bf_nr_res/4aec_nr_res.h:610-630)。中段的 DFN2 由共用的 pipelines/dfn_res_stage.{h,c} 負責,與 mono 變體是同一份程式碼——signal/timing 契約請直接看 pipeline_dfn_mono,本頁只寫四聲道特有的部分。

核心跑產品自己的取樣率(預設 16 kHz),只有 DFN2 stage 在 48 kHz。front_end.sample_rate 接受 16000 或 48000——就是核心自己的取樣率,沒有 8 kHz(4aec_dfn_res.c:50-55)。48 kHz 時 stage 直接吃核心的頻譜;16 kHz 時 wrapper 改 carve 一個 DfnRateBridge(pipelines/dfn_rate_bridge.{h,c},由 four_aec_dfn_res_get_bridge() 取得,48 kHz 回 NULL)負責原生格點 ↔ 48 kHz 的來回,每個 native hop 進一個、出一個(4aec_dfn_res.c:170-179)。四條 AEC lane、beamformer、RES 與 CNG 一律留在產品取樣率,呼叫端不再需要在 API 之外先 resample。Bridge 的排程、prefill 與 added delay 與 mono 共用,詳見 pipeline_dfn_mono。

估計用 E、套用在 P(四聲道版本)

E = view.beamformed_error:beamformed 線性誤差頻譜(由 weights 重建的 coherent projection,或呼叫端交出的 trusted_beamformed_error),也就是 RES gain 據以估計的那個 pre-RES 頻譜,只送進網路做估計。P = view.post_spectrum:beamformed_error * G_res + comfort noise,正是 process_post() 本來會合成的頻譜,才是三個 head 套用的對象。理由與 mono 相同:DFN2 是以未經處理的 noisy speech 訓練的,不能讓它看見 RES 挖出的頻譜洞;像語音的 far-end 殘留由 DFN 保留、留給 RES 處理,不像語音的兩級都壓。核心的 comfort-noise fill(front_end.enable_cng)是開關但預設關閉:關閉時 E 與 P 逐 bin 同相位,複數 deep-filter tap 不會相位錯配;開啟時 CNG 在 RES 挖掉的 bin 改變 P 的相位,estimate/apply 一致性在那裡不成立(dfn_res_stage.h 開頭)。開啟時它包在 P 裡、過同一張 mask,atten_lim_db 限制任何一個 bin 最多被壓多少。

API 用法

呼叫順序與核心一致:每個 hop 先 process_pre() 取得 token 與四條 lane 的線性頻譜,算出權重後以其中一個 post 入口收尾。只能有一個 pre frame 在飛;frame 順序由核心自己的 token gate 管(重複 pre 或無 pre 就 post 回 FOUR_AEC_NR_RES_SEQUENCE_ERROR),wrapper 只是直通(4aec_dfn_res.c:230-242)。每次 post 寫出剛好一個核心 hop(four_aec_dfn_res_hop_size():16 k/256 預設 128、16 k/512 為 256、48 k/1024 為 512)。

#include "4aec_dfn_res.h"

FourAecDfnResConfig cfg = four_aec_dfn_res_default_config();
/* 已鎖定:front_end = 核心 16 kHz 預設 + enable_post=1 + enable_res=1
 *         + enable_nr=0 + enable_cng=0   (4aec_dfn_res.c:118-127) */
cfg.front_end.sample_rate         = 16000;   /* 16000 或 48000;16 k 走 rate bridge */
cfg.front_end.delay_mode          = AEC_DELAY_MATCHED;   /* 四條 lane 共用一個決策 */
cfg.front_end.delay_num_filters   = 5;
cfg.front_end.fixed_delay_samples = -1;
cfg.front_end.enable_cng          = 0;     /* 預設關;開啟時核心的 fill 落在 P 裡 */
cfg.atten_lim_db = 0.0f;                   /* 0 = 不限制 */
cfg.erb_fwd = erb_fwd;                     /* bin-major  [513][32] */
cfg.erb_inv = erb_inv;                     /* band-major [32][513],partition of unity */

DFN2ModelIoDescriptor descriptor;          /* 板端應從匯出的模型 metadata 填;
                                            * default() 只是本 build 編譯進去的幾何 */
dfn2_model_io_descriptor_default(&descriptor);
cfg.model.user = board_ctx;
cfg.model.infer = board_run_dfn2_graph;    /* 回 0 = 已寫滿每個輸出 */
cfg.model.reset = board_reset_runtime;     /* 可為 NULL */
cfg.model.io_descriptor = &descriptor;     /* 有 infer 就必須發布 */

FourAecDfnResMemReq req;
four_aec_dfn_res_get_mem_requirements(&cfg, &req);
void *pool = platform_alloc((size_t)req.bytes, req.alignment);   /* 16-byte 對齊 */
FourAecDfnRes *p = four_aec_dfn_res_init_ex(pool, (size_t)req.bytes, &cfg, &req);

while (stream) {
    FourAecNrResPreFrame pre;
    four_aec_dfn_res_process_pre(p, mics_interleaved /* [hop][4] */, ref, &pre);
    /* ... 用 pre.linear_spectra / pre.aligned_ref 算出 weights[4][n_freqs] ... */

    /* (a) 由權重重建 beamformed 頻譜 */
    four_aec_dfn_res_process_post(p, &pre.token, weights, out);
    /* (b) 或交出 GSC 已算好的頻譜(與核心同一份 caller 契約) */
    four_aec_dfn_res_process_post_trusted_spectrum(p, &pre.token, weights,
                                                   gsc_spectrum, out);
}

four_aec_dfn_res_set_aec_preset(p, AEC_PRESET_AGGRESSIVE, 200.0f);  /* hop 之間 */
four_aec_dfn_res_set_atten_lim(p, 12.0f);                           /* hop 之間 */
DfnRateBridge *b = four_aec_dfn_res_get_bridge(p);   /* 48 kHz 時 NULL */
four_aec_dfn_res_reset(p);      /* 核心 + stage/bridge + model->reset */
four_aec_dfn_res_destroy(p);    /* 不釋放 caller pool */

訊號泳道圖

48 kHz 核心的泳道與 mono 完全相同:每 hop 一次推論,第 0 幀沒有右鄰居所以不呼叫加速器,stage 前兩個 hop 輸出全零頻譜,之後第 p 個 hop 的輸出就是「傳統核心的 hop#(p-2) 輸出」,合計 3 hop = 1536 samples 純延遲。四聲道前級(共用 delay、4 條 lane、外部 beamformer 的逐 bin 加權)本身不加延遲。16 kHz 核心多了 bridge 的第二個時鐘:

延遲與 warm-up

  • 端到端演算法延遲 = 核心的 1 hop WOLA + DFN2 段的延遲(four_aec_dfn_res_lookahead_samples(),4aec_dfn_res.c:304-311)。48 kHz 時 DFN2 段就是 2 hop 模型 lookahead(DFN2_MASK_LOOKAHEAD + DFN2_DF_LOOKAHEAD = 1+1,cascade 串聯相加而非取 max);16 kHz 時是 bridge 的 added delay。四聲道前級(共用 delay、4 條 lane、外部 beamformer 的逐 bin 加權)本身不加延遲。

  • added delay 的組成(prefill + 16 + 1536×sr/48000 + 16)與 prefill 的 init 校正和 mono 完全一樣,說明見 pipeline_dfn_mono;8 kHz 不在核心的格點清單內,wrapper 一併拒絕(tests/test_4aec_dfn_res.c:349-357)。
  • 16 kHz 不是逐位元等值:訊號走過兩顆 FIR resampler,測試用容差而非 memcmp(0.35 fs 低通後閘 < 1e-3,現查 6.8e-06 / 2.5e-06),延遲本身則由近端脈衝精確釘住。
  • Warm-up:開頭的輸出是全零(48 kHz 兩個 hop,16 kHz 為 added delay),stage 會寫滿零頻譜,所以呼叫端無條件合成、延遲是純延遲。第 0 幀 不呼叫加速器(graph 吃 [t-1,t,t+1],沒有右鄰居);之後 48 kHz 每 hop 恰好一次推論,16 kHz 照泳道圖的排程。
  • AEC delay 改變不 reset stage/bridge。pre.delay.changed 仍照舊回報給外部 far-end 消費者,但兩者都不消費 far-end,輸入在 delay 改變後仍然連續(4aec_dfn_res.c:237-239、dfn_res_stage.h:53-55)。只有 four_aec_dfn_res_reset()(或 DSP_ERROR 的自動 reset)才會連帶 reset stage/bridge 與 model.reset。收尾 flush 再推兩個全零 hop(16 kHz 推滿 added delay),那幾拍加速器也要照跑。
