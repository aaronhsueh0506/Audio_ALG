4ch AEC → BF → RES → DeepFilterNet2 後級(單元 + dfn_hop)

概要

pipelines/4ch_aec_bf_dfn_res/main.c:建在四聲道單元 AudioPipeline4Ch(pipelines/4ch_aec_bf_nr_res/audio_pipeline_4ch.h:共用 delay、四條線性 AEC lane、SRP-PHAT 與 BF)上的範例,把傳統鏈的 post-beam MMSE-LSA 換成 DeepFilterNet2。沒有 DFN wrapper 函式庫:範例直接組合獨立的函式庫——單元(core.enable_post=1)、libaec 的 AecRes(RES,範例自建)與 samples/dfn_hop.h(stage 或 rate bridge);每個物件各有自己的 mem_size 與 init,由 main.c 加總並切塊。

每 hop 呼叫 audio_pipeline_4ch_process()(delay、四條 lane、SRP-PHAT、BF)與 audio_pipeline_4ch_fuse()(填 SeSpecFrame,g_res_ctx 為 NULL),再以 se_res_stage_gain(res, &frame) 取 RES 增益。範例自己擁有 AecRes、增益暫存、comfort-noise 狀態與(48 kHz 時)ISTFT(在 DfnHop 的呼叫端物件裡),在 dfn_form() 明寫 sk_min_f32 → sk_capply_gain_f32 → aec_cng_fill 形成 P,再把 E、P 交給共用的 pipelines/dfn_res_stage.{h,c};單元不含 RES／NR／合成。要接外部 beamformer 的產品(單元沒有外部權重入口,目前的能力缺口)改走前端 four_aec_front_process()／four_aec_fuse(),同樣自備 AecRes(見 pipeline_4ch)。中段的 DFN2 與 mono 變體是同一份程式碼——signal/timing 契約請直接看 pipeline_dfn_mono,本頁只寫四聲道特有的部分。

核心跑產品自己的取樣率(預設 16 kHz),只有 DFN2 stage 在 48 kHz。--sample-rate(核心的 sample_rate)接受 16000 或 48000——就是核心自己的取樣率,沒有 8 kHz。48 kHz 時 stage 直接吃核心的頻譜;16 kHz 時範例改建一個 DfnRateBridge(pipelines/dfn_rate_bridge.{h,c},48 kHz 不建)負責原生格點 ↔ 48 kHz 的來回,每個 native hop 進一個、出一個。四條 AEC lane、SRP-PHAT／BF、RES 與 CNG 一律留在產品取樣率,呼叫端不再需要在 API 之外先 resample。Bridge 的排程、prefill 與 added delay 與 mono 共用,詳見 pipeline_dfn_mono。

估計用 E、套用在 P(四聲道版本)

E = frame.e(SeSpecFrame,pre-RES 的 beamformed 線性誤差頻譜)只送進網路做估計;P = dfn_form() 組出的頻譜(E * min(1, G_res) + comfort noise)才是三個 head 套用的對象;理由與 mono 相同,comfort-noise fill(--cng 才開)預設關閉。完整推導收在 pipeline_dfn_detail。

API 用法

每個 hop:先 audio_pipeline_4ch_process()(四條 lane、SRP-PHAT、BF),再 audio_pipeline_4ch_fuse() 填 SeSpecFrame(借用視圖),se_res_stage_gain() 取 RES 增益,自寫的 P 形成,再 dfn_hop_process() 一次收尾,或用 dfn_hop_begin → dfn_hop_nn_begin/dfn_hop_nn_end 迴圈 → dfn_hop_end 自己在中間跑加速器。沒有 token:單元用 phase 擋順序(沒有 beam 就 fuse 回 FOUR_AEC_NR_RES_SEQUENCE_ERROR),DfnHop 另有 phase 擋 begin／nn／end 的次序。每次 dfn_hop_end 寫出剛好一個核心 hop(16 k/256 預設 128、16 k/512 為 256、48 k/1024 為 512)。完整可編譯範例(設定、pool 切分、init、每 hop、reset、destroy)、流程時序圖與參數表收在 pipeline_dfn_usage、pipeline_dfn_sequence 與 pipeline_dfn_params。每 hop 的核心如下:

AudioPipeline4ChBeam beam;  SeSpecFrame frame;
audio_pipeline_4ch_process(unit, mics_interleaved /* [hop][4] */, ref, &beam, NULL);   /* delay、4 lane、SRP-PHAT、BF */
audio_pipeline_4ch_fuse(unit, &frame);                    /* frame.g_res_ctx 為 NULL */
const float *g_res = se_res_stage_gain(res, &frame);      /* 應用自備的 AecRes(libaec);NULL = 被拒,走 reset */
sk_min_f32(gain, unity, g_res, n_freqs);                  /* P 必須在 dfn_hop_begin 之前形成 */
sk_capply_gain_f32(post, frame.e, gain, n_freqs);         /* P = E * min(1, G_res) */
if (cng_on && frame.cn)                                  /* 預設關: E 與 P 要同相位 */
    aec_cng_fill(&rng, post, frame.cn, g_res, unity, SE_CNG_NR_GAIN_FLOOR, n_freqs);

dfn_hop_process(&hop, frame.e, post, out);                /* (a) 一次完成:模型由 model.infer 執行(沒設就是 identity) */
/* (b) 或自己在中間跑加速器:dfn_hop_begin → while (dfn_hop_nn_begin() > 0) { 跑 NPU; dfn_hop_nn_end(rc) } → dfn_hop_end(&hop, out) */

各 stage 與 bridge 的 reject-first 清單(其中最容易踩到的是 erb_inv 必須是 partition of unity)與入口的逐項語意,收在 pipeline_dfn_detail。單元的 process／fuse 回非 FOUR_AEC_NR_RES_OK(fuse 的拒絕已 reset 整個單元)、se_res_stage_gain() 回 NULL、stage 或 bridge 拒絕,整合者都要把單元、AecRes(aec_res_reset())、CNG RNG 與 DfnHop 一起 reset(main.c 的 dfn_reset())。

Block diagram(每 hop 程式流)

audio_pipeline_4ch_process(unit, mics_interleaved, ref, &beam, NULL)
       共用 far aligner → 4 條線性 AEC lane(lane 0 做 far-FFT,1–3 借用)
       → SRP-PHAT DOA → BF(RLS)→ beam.spectrum / beam.weights(單元借用)
       (delay.changed 只回報給外部 far 消費者;序列閘由單元的 phase 管)

audio_pipeline_4ch_fuse(unit, &frame)               → SeSpecFrame
 │     用單元自己的 BF 權重與頻譜做 coherent projection(four_aec_fuse)
 │     frame.e = E [n_freqs] Complex  (pre-RES,RES 據以估計);frame.g_res_ctx = NULL
g_res = se_res_stage_gain(res, &frame)               應用自備的 AecRes(libaec aec_res_process);NULL = 被拒
P 的形成(main.c 的 dfn_form(),自寫):
 ├─ sk_min_f32(g_total, unity, g_res) → sk_capply_gain_f32(post, frame.e, g_total)
 └─ aec_cng_fill(&rng, post, frame.cn, g_res, unity, …)   (cng=1 時)
       post = P [n_freqs] Complex  (= E*min(1,G_res) + CNG)

dfn_hop_begin(&hop, E, P)                                    (phase 0 → 1)
 ├─【48 kHz】dfn_res_stage_begin(stage, E, P, &job)       ← 與 mono 同一份
 │      inputs_valid(E,P);A = E*0x1p-5f, B = P*0x1p-5f → pre_process_freq_dual()
 │      回 1 = job 已開(兩個 warm-up hop 回 0)
 └─【16 kHz】dfn_rate_bridge_begin(bridge, E, P)
        原生 AcIstft(E、P 各一個)→ 兩顆 audio_resampler 升到 48 kHz(×3)→ 48 kHz FIFO

while (dfn_hop_nn_begin(&hop, &job) > 0) {            (phase 1 → 2;每 hop 0..2 次)
    rc = run_npu(&job);          ← 呼叫端:DFN2PrepostInputs → 加速器 → DFN2PrepostOutputs
    dfn_hop_nn_end(&hop, rc);                          (phase 2 → 1)
}   【48 kHz】dfn_res_stage_end(stage, rc, stage_output):rc≠0／輸出未寫／非有限 → frame_skip() ← fail-open
    【16 kHz】bridge:48 kHz FIFO 每滿 512 開一個 job(AcStft 1024/512 分析 E、P)
              nn_end 之後 stage_end → 48 kHz AcIstft → 降頻回 16 kHz → 原生 out FIFO

dfn_hop_end(&hop, out)                                       (phase → 0)
 ├─【48 kHz】沒被取走的 job 走 identity;ac_istft_push(istft, stage_output, out)
 │       stage_output = valid ? Y*0x1p5f(frame t-2) : 全零
 └─【16 kHz】dfn_rate_bridge_finish(bridge, out):從 out FIFO(init 預填 prefill 個零)取剛好一個 native hop

dfn_hop_process(&hop, E, P, out) = 上面四個呼叫的序列,模型由 model.infer(經 dfn_res_stage_infer)執行
任一步失敗 → 整合者 reset(單元 + AecRes + rng + hop)後重來(main.c 的 dfn_reset())

訊號泳道圖

48 kHz 核心的泳道與 mono 完全相同:每 hop 一次推論,第 0 幀沒有右鄰居所以不呼叫加速器,stage 前兩個 hop 輸出全零頻譜,之後第 p 個 hop 的輸出就是「傳統核心的 hop#(p-2) 輸出」,合計 3 hop = 1536 samples 純延遲。四聲道前級(共用 delay、4 條 lane、BF 的逐 bin 加權)本身不加延遲。16 kHz 核心多了 bridge 的第二個時鐘:

lane \ native hop   #0            #1            #2            #3            #4(週期重複)
─────────────────── ───────────── ───────────── ───────────── ───────────── ─────────────
前端(16 kHz)        audio_pipeline_4ch_process(4 lane 線性 AEC → SRP/BF)→ fuse → dfn_hop_begin;
                    每 hop 交出 E,P [129] —— 這一段完全沒離開 16 kHz
bridge 原生 WOLA    e0,p0(各 128) e1,p1         e2,p2         e3,p3         e4,p4
 → 升頻 ×3 → 48k FIFO  +384          +384          +384          +384          +384
48k 分析(每滿 512)  0 幀         1 幀         1 幀         1 幀         0 幀
dfn_res_stage       不跑          ×1            ×1            ×1            不跑
48k WOLA → 降頻 ×1/3 → 原生 out FIFO(init 預填 prefill = 128 個零)
out(128 samples)    每個 hop 恰好吐 1 個 hop;內容 = 傳統鏈的輸出再延後 added delay

每 native hop 的幀排程:16 k/hop 128 → 0,1,1,1(週期 4);16 k/hop 256 → 1,2(週期 2)。
一個 hop 內最多跑兩次推論,這是板端算力預算該看的峰值而非平均值
(dfn_rate_bridge.h 開頭;測試釘死於 4ch_aec_bf_dfn_res/tests/test_4ch_dfn.c 的原生格點閘)。phased API 下,這個 hop 內的 0..2 個 job 就是 nn_begin() 迴圈的次數

E 與 P 一路都是兩個指標。單元交出的 SeSpecFrame.e 與 dfn_form() 組出的 P 緩衝是分開的兩塊,dfn_res_stage_begin() 的 estimate_spec／apply_spec 原封不動送進 dfn2_prepost_pre_process_freq_dual()(est 走特徵與 [t-1,t,t+1] 視窗、app 走 noisy ring,互斥狀態;命名為 est/app 而非 a/b 以免對調,見 pipeline_dfn_mono 同名註)。

DFN2 模型張量(model.infer 的 DFN2PrepostInputs/Outputs)

與 mono 變體完全相同(同一個 stage、同一個 class),逐張量對照(graph 名稱 ↔ C 欄位 ↔ shape/元素數)見 pipeline_dfn_mono 的同名小節;名稱取自出貨 layout(DFN2_MODEL_IO_LAYOUT_VERSION = 8),runtime 以名稱與元素數綁定。不論核心走哪個格點,模型看到的一律是 48 kHz 的幀。frame_inputs() 只對三個 head 輸出預填 NaN,「只寫一半」會在 commit 被抓到;兩個 state 張量(h_gru、df_convp_history)位址固定,輸入與輸出綁同一個位址就地更新(commit 遇非有限時全歸零並讓 state generation 加 1);形狀不對由 18 欄位的 DFN2ModelIoDescriptor 擋下。詳見 ainr_dfn2。

延遲與 warm-up

  • 端到端演算法延遲 = 合成的 1 hop WOLA + DFN2 段的延遲(範例 main.c 以 hop 加 dfn_rate_bridge_added_delay_samples() 或 hop * (DFN_RES_STAGE_LOOKAHEAD_FRAMES + 1) 印出)。48 kHz 時 DFN2 段就是 2 hop 模型 lookahead(DFN2_MASK_LOOKAHEAD + DFN2_DF_LOOKAHEAD = 1+1,cascade 串聯相加而非取 max);16 kHz 時是 bridge 的 added delay。四聲道前級(共用 delay、4 條 lane、BF 的逐 bin 加權)本身不加延遲。
核心格點hopprefillbridge added delay總演算法延遲
16 kHz / fft 256(預設)128128672(42.0 ms)800 samples = 50.0 ms
16 kHz / fft 51225685629(39.3 ms)885 samples = 55.3 ms
48 kHz / fft 1024512—(無 bridge)—1536 samples = 32.0 ms(3 hop)
  • added delay 的組成(prefill + 16 + 1536×sr/48000 + 16)與 prefill 的 init 校正和 mono 完全一樣,說明見 pipeline_dfn_mono;8 kHz 不在核心的格點清單內,範例一併拒絕。
  • 16 kHz 不是逐位元等值:訊號走過兩顆 FIR resampler,測試用容差而非 memcmp(0.35 fs 低通後閘 < 1e-3,現查 8.70e-06 / 8.91e-06),延遲本身則由近端脈衝精確釘住。
  • Warm-up:開頭的輸出是全零(48 kHz 兩個 hop,16 kHz 為 added delay),stage 會寫滿零頻譜,所以呼叫端無條件合成、延遲是純延遲。第 0 幀 不呼叫加速器(graph 吃 [t-1,t,t+1],沒有右鄰居);之後 48 kHz 每 hop 恰好一次推論,16 kHz 照泳道圖的排程。
  • AEC delay 改變不 reset stage/bridge。front.delay.changed 仍回報給外部 far-end 消費者,但 stage 與 bridge 都不消費 far-end,輸入在 delay 改變後仍然連續(前端自己對四條 lane 做 realign;dfn_res_stage.h 開頭)。只有整合者的 reset(dfn_hop_reset() 連帶 reset stage/bridge 與 model.reset)才會這麼做;單元 fuse 拒絕時的自動 reset 只重置單元(核心、SRP、BF),範例在該處再把 AecRes、CNG RNG 與 DfnHop 一起 reset。收尾 flush 再推兩個全零 hop(16 kHz 推滿 added delay),那幾拍加速器也要照跑。
