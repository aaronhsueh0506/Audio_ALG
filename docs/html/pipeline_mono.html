mono AEC(linear) → echo-aware NR → RES — Aec + 各 main 自寫的逐 hop 串接

概要

mono 沒有 unit,也沒有 pipeline 函式庫(沒有 mono archive)。處理鏈由獨立的函式庫物件組成,各有自己的 mem_size 與 init,初始化與逐 hop 串接都是整合者(範例 main)的事:lib/aec 的 Aec(線性 AEC,連同它自己的 RES 增益,aec_process_context())→ common/se_stage.h 的 se_frame_from_aec()(填 SeSpecFrame,RES 增益在 frame.g_res_ctx)→ samples/se_anr_stage.h 的 se_anr_stage_gain()(echo-aware NR 增益)→ sk_min_f32(g_total=min(g_nr,g_res))→ sk_capply_gain_f32(頻譜套 gain)→ aec_cng_fill(CNG,有 RES 增益且設定允許時)→ ac_istft_push(irfft + sqrt-Hann OLA)。NR 的 AnrDenoiser 與合成的 AcIstft 是普通的函式庫物件,由 main 以 anr_get_mem_size()／anr_init()(anr_config_for_mode_grid(),追蹤視窗 L 用函式庫預設)與 ac_istft_get_mem_size()／ac_istft_init() 自己 carve。沒有包起來的鏈物件、沒有 ABI、沒有 layout version、沒有 descriptor。兩支 CLI(mono_aec_nr_res/main.c malloc 版 / mono_aec_nr_res/static_main.c 靜態記憶體版)就是這個組合的範例;Pool-first 建構為板端路徑:init→destroy 之間零 heap。

API 用法

static const SeRules rules = { .allow_8k = 1, .spatial_context = SE_CONTEXT_PRESET };
SeRequest req = {0};  req.sample_rate = 16000;  req.delay_mode = AEC_DELAY_MATCHED;
req.delay_num_filters = 5;  req.fixed_delay_samples = -1;  req.aec_preset = AEC_PRESET_BALANCED;
SeGrid grid;  AecConfig aec_cfg;
se_derive(&req, &rules, &grid, &aec_cfg);                   /* 格點 + AecConfig; 0=ok, -1=reject */

AnrConfig nr_cfg = anr_config_for_mode_grid(16000, grid.fft_size, ANR_MODE_BALANCED);  /* L 用函式庫預設 */
AcStftConfig syn_cfg;  ac_stft_config_default(&syn_cfg, grid.fft_size);
size_t aec_bytes = aec_get_mem_size(&aec_cfg);              /* 各物件各自查大小, 0 = invalid */
size_t nr_bytes  = anr_get_mem_size(&nr_cfg);
size_t syn_bytes = ac_istft_get_mem_size(&syn_cfg);
size_t vec  = ALIGN16(grid.n_freqs * sizeof(float)), cvec = ALIGN16(grid.n_freqs * sizeof(Complex));
/* 一塊 16-byte 對齊的 pool, 依序 carve: Aec, AnrDenoiser, AcIstft, 再加 unity / total_gain / extra_noise [n_freqs] 與 spec [n_freqs] Complex */
void* pool = platform_alloc(ALIGN16(aec_bytes) + ALIGN16(nr_bytes) + ALIGN16(syn_bytes) + 3 * vec + cvec, 16);
Aec*         aec   = aec_init(pool, aec_bytes, &aec_cfg);
AnrDenoiser* nr    = anr_init((uint8_t*)pool + ALIGN16(aec_bytes), nr_bytes, &nr_cfg);
AcIstft*     istft = ac_istft_init((uint8_t*)pool + ALIGN16(aec_bytes) + ALIGN16(nr_bytes), syn_bytes, &syn_cfg);

while (stream) {                                           /* 每 hop 一次, 皆 grid.hop_size floats */
    SeSpecFrame f;  const float* nr_gain;
    aec_process_context(aec, mic, ref);
    if (se_frame_from_aec(aec, &f) != 0 || !f.g_res_ctx ||                 /* RES 增益 = AEC 自己的 G_res */
        !(nr_gain = se_anr_stage_gain(nr, &f, extra_noise, 1))) goto refused;
    sk_min_f32(total_gain, nr_gain, f.g_res_ctx, grid.n_freqs);
    sk_capply_gain_f32(spec, f.e, total_gain, grid.n_freqs);
    if (cng_on && f.cn)                                    /* aec_cfg.enable_cng 且 RES 增益存在 */
        aec_cng_fill(&rng, spec, f.cn, f.g_res_ctx, nr_gain, SE_CNG_NR_GAIN_FLOOR, grid.n_freqs);
    ac_istft_push(istft, spec, out);
    if (se_hop_is_finite(out, grid.hop_size)) continue;
refused:                                                   /* 被拒的 hop: 各 stage 一起 reset */
    aec_reset(aec);  anr_reset(nr);  ac_istft_reset(istft);  rng = SE_CNG_RNG_SEED;
}
anr_destroy(nr);  aec_destroy(aec);                        /* 不釋放 caller pool */
platform_free(pool);

桌面便利路徑 aec_create()(內部配置)。診斷用唯讀查詢:aec_debug_status()／anr_debug_status()(--debug 旗標每秒印一行)、aec_get_res_context()(DUMP_CTX)。--no-nr 時不建 AnrDenoiser、NR 增益讀 unity 全 1 向量;--no-res 時 RES 增益改讀 unity,且不跑 CNG。逐步的呼叫表、錯誤語意與 config 對照見 docs/integration_mono_zh_TW.md。

接進外部後級(se_frame_from_aec)

se_frame_from_aec(aec, &frame)(pipelines/common/se_stage.h)在 aec_process_context() 之後把 lane 的 context 填成 SeSpecFrame:e=線性 AEC 誤差頻譜 E、y=近端頻譜、x=far 頻譜、r2=殘餘回音 PSD、cn=comfort-noise PSD、g_res_ctx=AEC 自己的 G_res、far_hop／formed_hop 與 delay 旗標;全部是借用視圖,指向 AEC 的 per-hop buffer,到下一次處理呼叫或 reset 前有效,任何 stage 都不得寫入。lane 必須帶 seam(enable_res=0、return_res_context=1,se_derive() 這樣建),否則回 −1。要在鏈上插自己的 stage,就照 mono_aec_nr_res/main.c 的 mono_form() 的順序明寫(tests/test_readme_flow.c 編譯並執行這段,單位 stage 時與手寫 oracle mono_aec_nr_res/tests/conv_chain_mono.h 逐位元相同):

aec_process_context(aec, mic, ref);  se_frame_from_aec(aec, &f);
nr_gain  = se_anr_stage_gain(nr, &f, extra, 1);        /* 無 NR 實例時用 unity 全 1 向量 */
sk_min_f32(g_total, nr_gain, f.g_res_ctx, f.n_freqs);
sk_capply_gain_f32(spec, f.e, g_total, f.n_freqs);
aec_cng_fill(&rng, spec, f.cn, f.g_res_ctx, nr_gain, SE_CNG_NR_GAIN_FLOOR, f.n_freqs);
ac_istft_push(istft, spec, out);

沒有函式指標表:每個應用把自己的幾行寫出來。目前的消費者是 pipeline_dfn_mono(不建 NR,P 交給 DFN2 hop)。

執行期強度控制

int aec_set_preset(Aec* a, AecPreset preset, float ramp_ms);
int anr_set_mode(AnrDenoiser* nr, AnrMode mode);           /* nr = 你自己 anr_init() 的物件 */

/* 使用者轉旋鈕:在兩個 hop 之間呼叫,不重建、不動 pool */
aec_set_preset(aec, AEC_PRESET_AGGRESSIVE, 100.0f);        /* 100 ms 內以 dB 線性走到新地板 */
anr_set_mode(nr, ANR_MODE_MILD);
aec_process_context(aec, mic, ref);                        /* 下一個 hop 起生效 */
呼叫改什麼回 −1 的情況(−1 時什麼都不寫)
aec_set_preset()Aec 的 far-active 殘留回音地板(三個 preset 唯一的差異軸;mono 的 g_res_ctx 就是這個 lane 算的)a 為 NULL;preset 超出 enum;ramp_ms 非有限值或超出 [0, 60000]
anr_set_mode()降噪器的強度 presetnr 為 NULL(例如 --no-nr 沒有建降噪器);mode 超出 enum

ramp_ms == 0 下一個 hop 套用(不是錯誤),落點與「用該 preset 從頭建一個新實例」完全相同;> 0 以 dB 線性走過去,上限 60 s(mild ↔ aggressive 是 18 dB 落差、地板又是硬 clamp,互動式旋鈕應給 ramp)。ramp 途中再呼叫會從當前 live 值重新起走。兩個 setter 都不是重啟:AEC 濾波器與延遲鎖定、NR 噪聲底與增益平滑歷史全部繼續跑(要重啟用 aec_reset()、anr_reset()、ac_istft_reset())。在兩個 hop 之間呼叫、與 process 序列化;非 thread-safe。

範例的降噪器以 anr_config_for_mode_grid() 建立、沒有覆寫任何欄位,所以 anr_set_mode() 直接換強度。在 preset 之上改過欄位的實例,anr_set_mode() 會把那些覆寫蓋回 preset 值,要自己組好完整 target 再呼叫 anr_reconfigure()。

A/B 量測時該預期什麼。far-active 地板只在 far-active 且非 double-talk 的 hop 生效:DT 期間套的是 DT 地板(三個 preset 完全相同),far-active latch 觸發前套的是 far-silent 地板。同一個 ctx.res_gain 還決定注入的 comfort noise 量(振幅 ∝ sqrt(1 − G_res²) 再乘該 bin 的 NR gain(下限 −10 dB),見下方 block diagram 的 CNG 步驟——地板越深、CNG 反而越多)。所以整段錄音的平均移動幅度會小於 dB 落差所暗示的量,而且只量 echo/degradation 的 A/B 會把 CNG 的變化錯記到別的機制。請在 echo 對齊或 degradation 對齊的條件下比較,並實際試聽。

逐階段耗時(診斷用)

typedef struct AecStageTiming {            /* aec.h; aec_get_last_timing(aec, &t) */
    uint32_t delay_us;      /* 延遲估計 + ring 對齊(matched filter) */
    uint32_t frontend_us;   /* 其餘的主濾波器前處理,不含 delay     */
    uint32_t linear_us;     /* pbfdkf_process_with_far_cmag2,含 far-end FFT */
    uint32_t res_us;        /* AEC3 post/RES 區塊                  */
} AecStageTiming;

四欄由 lib/aec 帶出。鏈與合成的耗時是範例程式自己在呼叫前後讀時鐘量的(mono_aec_nr_res/main.c 的 process_hop() 與 timing_now_us()),不是任何函式庫的 API。與四聲道版本的差異:那邊把 estimator 外提到共用 aligner、四條 lane 共用,所以 delay_us 是前端自己的階段;這裡 estimator 留在單一 AEC 內部,經 aec_get_last_timing() 帶出——同一個量,不同的擁有者。真正沒有的是 fuse_us(只有一條 lane)。

預設關閉。AEC 內部 7 次 clock 讀取,release build 一次都不做,欄位讀 0。make PROFILE=1 開啟(-DAEC_STAGE_TIMING=1)。呼叫端的顯示旗標(兩支 CLI 的 --timing)決定「印不印」,不決定「有沒有量」;建置一種、讀成另一種,AEC 那幾列就是 0(CLI 會用文字說明,不會假裝有數字)。

目標平台沒有 CLOCK_MONOTONIC 時。clock_gettime 是 POSIX 而非 C99。這種平台用 make PROFILE=1 EXTRA_CFLAGS='-DAEC_NOW_US=board_timer_us -include my_timer.h' 換掉 AEC 的時鐘:巨集要是純識別字(Makefile 的 FP policy 不允許 EXTRA_CFLAGS 出現括號),指向不收參數、回傳 uint32_t 微秒的函式,宣告由整合者自備。替代時鐘必須單調,否則無號減法會產生接近 32-bit 全距的荒謬值。每個元件各有自己的覆寫點(lib/aec、四路核心),刻意不共用。開著旗標但指向常數函式是合法用法,所有欄位讀 0,--timing 報表無法分辨這種情況與「根本沒開旗標」。

各階段不會加總成整通呼叫。餘數含引數檢查、aec_get_res_context(),以及 AEC 內部因此看不見的 stationarity 更新、e2_coarse/ERL 發布、DT analyzer、EPV、shadow_rise、失調估計、功率 EMA 與收斂偵測。呼叫端要呈現完整分解就必須把餘數明列。記錄本身不是條件編譯的,只有取樣是——欄位無論旗標開關都在 struct 裡,所以 profile 與 release build 切出來的 pool 逐位元相同。

16 kHz/256 ne10 的 --timing 分解(早期量測,舊版 wrapper 時代 1250 hops 平均;AEC 列來自同一個 lib/aec 計時,沒有重量):delay 21.1 us(60.9%)、frontend 2.4 us(6.8%)、linear 1.3 us(3.8%)、res 3.5 us(10.1%)。最大的一塊是 matched filter,不是主濾波器——這條線直接對應 delay_num_filters(1..5)這個可調旋鈕。鏈與合成的列隨範例而異,待重量。

Descriptor 慣例:mono 沒有 descriptor 也沒有 layout version(Aec、AnrDenoiser、AecRes、AcIstft 只提供大小查詢,串接寫在各 main 裡),所以每次 build 都要重查大小;aec_init()、anr_init()、ac_istft_init() 只擋下過小或未對齊的 pool、無效 config。需要 descriptor 8 點閘的出貨單元只有 4ch 的 AudioPipeline4Ch。組態驗證是 reject-first:sample_rate 白名單 {8000,16000,48000}、enum 逐項檢查在 se_derive() 一處把關(格點與 AecConfig 由 pipelines/common/se_config.c 的 se_derive() 推導,各應用以 SeRules 傳入自己的規則),NR 與合成的 config 由 anr_get_mem_size()／ac_istft_get_mem_size() 回 0 拒絕。

SeRequest 含四個 delay 相關欄位:filter_length(0=rate default,PBFDKF taps,init-time immutable)、delay_mode(AEC_DELAY_MATCHED|FIXED|EXTERNAL_ALIGNED,語意同 lib/aec)、delay_num_filters(僅 MATCHED,[1,5])、fixed_delay_samples(僅 FIXED,原生取樣點數;其餘模式須為 −1)。目前兩支 CLI(aec_nr_pipeline/aec_nr_pipeline_static)都沒有對應旗標——只能由呼叫端直接寫 struct 欄位(如板端 adapter 或測試);CLI 只留 --fft-size/--sample-rate。

 │
 ├─ --aec-only ──► aec_process(aec, mic, ref, out) ──► return        (0-hop lag)
 │
 ├─ aec_process_context(aec, mic, ref)  沒有時域輸出 copy
 ├─ se_frame_from_aec(aec, &f): aec_get_res_context() + aec_get_linear_context() → SeSpecFrame

 ├─ mono_form(rig, &f)(main.c; 逐 hop 串接寫在 main 內):

 │    ├─ nr_gain = se_anr_stage_gain(nr, &f, extra, use_r2)
 │    │      extra[k] = f.r2[k]/PSD_SCALE (PSD_SCALE = 32768^2) 折進噪聲底;無 NR 時 nr_gain = unity

 │    ├─ sk_capply_gain_f32(spec, f.e, g_total)

 │           * sqrt(1-res_gain²) * max(g_nr[k], 0.316) * AECB_SQRT2_SIN_LUT[ix / (ix+8)&31]
 │           ix = (rng_state*69069+1)&0x7FFFFFFF >> 26, seed SE_CNG_RNG_SEED = 0x9e3779b9

 └─ ac_istft_push(istft, spec, out)   (AcIstft, ACCUMULATE):
        fft_inverse ─► acc += ifft*w ─► emit hop ─► shift acc    (1-hop lag)
 失敗(任一步被拒或輸出非有限): rig_reset(): aec_reset(aec) + anr_reset(nr) + ac_istft_reset(istft) + rng = SE_CNG_RNG_SEED

ctx.error_spec 不保證每個 hop 都是誤差。mono lane 無條件以 enable_res=0 / return_res_context=1 建 AEC(se_derive()),而 lib/aec 的 formed 選擇器只在這個 context-only 模式多開一個 capture 候選:上一個 hop 的濾波品質判定尚未認可線性估計、且被選中的殘差在這個 hop 的能量大於同一 hop 的 mic capture 時,formed 時域 hop 與 ctx.error_spec 一起改送 capture,既有的 30-sample crossfade 承接邊界。換句話說,濾波器在加訊號的 hop 上這條 seam 就是 mic;NR/RES 照常套在它上面。--aec-only 走 aec_process(),輸出仍是 raw 線性殘差,不受影響。

State 表

全部 cross-call state 都住在 caller 的 pool(static_main.c 的一個 16-byte 對齊 block;host 只擁有 pool 記憶體本身)。carve 順序(static_main.c 的 pool_bytes()／rig_build())= Aec, nr(AnrDenoiser), istft(含 fft、窗、acc、time、spec 暫存), unity, total_gain, extra_noise, spec;main.c 的 heap 版是兩塊(Aec 一塊、其餘一塊),順序相同。RES 增益在 Aec 內,不另佔 pool(所以 --no-res 不改 pool 大小)。這些是普通的函式庫物件與緩衝,沒有 layout version。實測 bytes 為 16 kHz/256 ne10,aec_nr_pipeline_static --print-mem-size:

FFT backend 預設是 ne10(audiolib 對 NEON 目標自動偵測;見 audio_common.html);下表是 ne10 在 16 kHz/256 的量測值,合計 423,728 B(Aec 364,416 B、合成 AcIstft(含 FftHandle)11,344 B、NR 45,344 B、增益／頻譜暫存 2,624 B)。其他格點同一指令加旗標:8 kHz/256 310,160 B、16 kHz/512 575,056 B、48 kHz/1024 1,354,256 B;--no-nr 378,384 B、--aec-only 364,416 B。
