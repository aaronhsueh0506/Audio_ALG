audio_pipeline — mono AEC(linear) → echo-aware NR → RES

概要

可連結的單聲道傳統管線(pipelines/mono_aec_nr_res/audio_pipeline.{h,c}):線性 AEC → echo-aware NR gain → g_total=min(g_nr,g_res) → far/near gated near-end floor lift → 頻譜套 gain(+選配 CNG)→ irfft + sqrt-Hann OLA。兩支 CLI(mono_aec_nr_res/main.c malloc 版 / mono_aec_nr_res/static_main.c 靜態記憶體版)都是它的薄殼。Pool-first 建構為板端路徑:init→destroy 之間零 heap。

訊號格點fft/hop/bins備註
8 kHz256 / 128 / 129fft_size=0 的 rate default
16 kHz(預設)256 / 128 / 1292026-08 起的 rate default
16 kHz(替代)512 / 256 / 257需明示 fft_size=512
48 kHz1024 / 512 / 513rate default

aec_only=1 時整條 NR/RES/OLA 被跳過(FFT/NR 連 pool 都不佔),輸出即線性 AEC 殘差,鏡射 CLI 的 --aec-only。

API 用法

AudioPipelineConfig cfg = audio_pipeline_default_config(16000);
/* cfg.fft_size=0(rate default) aec_preset=BALANCED nr_mode=BALANCED
 * aec_only=0 enable_cng=1 legacy_amin=0 */
AudioPipelineMemReq req;
audio_pipeline_get_mem_requirements(&cfg, &req);      /* 0=ok, -1=reject */
void* pool = platform_alloc(req.bytes, req.alignment); /* 16-byte aligned */
AudioPipeline* p = audio_pipeline_init_ex(pool, req.bytes, &cfg, &req);

int hop = audio_pipeline_hop_size(p);                  /* 128 @16k default */
while (stream) {
    audio_pipeline_process(p, mic, ref, out);          /* 各 hop 一次, 皆 hop floats */
}
audio_pipeline_reset(p);      /* echo-path 變更時; 不動 pool */
audio_pipeline_destroy(p);    /* 不釋放 caller pool */
platform_free(pool);

桌面便利路徑 audio_pipeline_create(&cfg)(內部 posix_memalign;destroy 會 free)。診斷用唯讀 handle:audio_pipeline_get_aec() / audio_pipeline_get_nr()(aec_only 時為 NULL);byte 分解表 audio_pipeline_get_mem_breakdown()。

執行期強度控制

int audio_pipeline_set_aec_preset(AudioPipeline* p, AecPreset preset, float ramp_ms);
int audio_pipeline_set_nr_mode(AudioPipeline* p, MmseLsaNrMode mode);

/* 使用者轉旋鈕:在兩個 hop 之間呼叫,不重建、不動 pool */
audio_pipeline_set_aec_preset(p, AEC_PRESET_AGGRESSIVE, 100.0f);   /* 100 ms 內以 dB 線性走到新地板 */
audio_pipeline_set_nr_mode(p, MMSE_LSA_NR_MILD);
audio_pipeline_process(p, mic, ref, out);                          /* 下一個 hop 起生效 */
呼叫改什麼回 −1 的情況(−1 時什麼都不寫)
audio_pipeline_set_aec_preset()底層 Aec 的 far-active 殘留回音地板(三個 preset 唯一的差異軸);轉呼叫 aec_set_preset()p 或其 AEC 為 NULL;preset 超出 enum;ramp_ms 非有限值或超出 [0, 60000]
audio_pipeline_set_nr_mode()共用降噪器的 tuning 純量p 為 NULL;aec_only 建置(根本沒有降噪器);mode 超出 enum;重組出的 target 被拒

ramp_ms == 0 下一個 hop 套用(不是錯誤),落點與「用該 preset 從頭建一個新實例」完全相同;> 0 以 dB 線性走過去,上限 60 s(mild ↔ aggressive 是 18 dB 落差、地板又是硬 clamp,互動式旋鈕應給 ramp)。ramp 途中再呼叫會從當前 live 值重新起走。兩個 setter 都不是重啟:AEC 濾波器與延遲鎖定、NR 噪聲底與增益平滑歷史全部繼續跑(要重啟用 audio_pipeline_reset())。在兩個 hop 之間呼叫、與 audio_pipeline_process() 序列化;非 thread-safe。

不要繞過 set_nr_mode() 去呼叫 mmse_lsa_set_mode()。本 pipeline 的 NR 組態是「canonical 強度 preset 加上自己的覆寫」(broadband_threshold、L、alpha_decay;見 compose_nr_config())。mmse_lsa_set_mode() 組的是裸的 canonical preset,在本 pipeline 的實例上會被拒絕(它的 L 不同)——所以 audio_pipeline_set_nr_mode() 做的事是重組本 pipeline 的完整組態,再交給 mmse_lsa_reconfigure()。

A/B 量測時該預期什麼。far-active 地板只在 far-active 且非 double-talk 的 hop 生效:DT 期間套的是 DT 地板(三個 preset 完全相同),far-active latch 觸發前套的是 far-silent 地板。同一個 ctx.res_gain 還決定注入的 comfort noise 量(振幅 ∝ sqrt(1 − G_res²),見下方 block diagram 的 CNG 步驟——地板越深、CNG 反而越多)。所以整段錄音的平均移動幅度會小於 dB 落差所暗示的量,而且只量 echo/degradation 的 A/B 會把 CNG 的變化錯記到別的機制。請在 echo 對齊或 degradation 對齊的條件下比較,並實際試聽。

逐階段耗時(診斷用)

typedef struct AudioPipelineLastTiming {
    uint32_t delay_us;      /* AEC: 延遲估計 + ring 對齊(matched filter) */
    uint32_t frontend_us;   /* AEC: 其餘的主濾波器前處理,不含 delay     */
    uint32_t linear_us;     /* AEC: pbfdkf_process,含 far-end FFT       */
    uint32_t res_us;        /* AEC: AEC3 post/RES 區塊                  */
    uint32_t nr_us;         /* mmse_lsa_process_gain()                  */
    uint32_t post_us;       /* min(G_nr,G_res)+近端 lift+CNG            */
    uint32_t synth_us;      /* IFFT + WOLA + hop 送出                   */
} AudioPipelineLastTiming;

void audio_pipeline_get_last_timing(const AudioPipeline* p,
                                    AudioPipelineLastTiming* out);

前四欄由 aec_get_last_timing()(aec.h)帶出,後三欄本層自己量。與四聲道版本的差異:那邊把 estimator 外提到 wrapper、四條 lane 共用,所以 delay_us 是 wrapper 自己的階段;這裡 estimator 留在單一 AEC 內部,經 aec_get_last_timing() 帶出——同一個量,不同的擁有者。真正沒有的是 fuse_us(只有一條 lane)。

預設關閉,而且分成兩半。每 hop 這層 4 次、AEC 內部 7 次 clock 讀取,release build 一次都不做,所有欄位讀 0。make PROFILE=1 同時開兩半(-DAUDIO_PIPELINE_STAGE_TIMING=1 與 -DAEC_STAGE_TIMING=1);只開一半是可讀的狀態而非壞掉——另一半讀 0。呼叫端的顯示旗標(兩支 CLI 的 --timing)決定「印不印」,不決定「有沒有量」;建置一種、讀成另一種,報表就是一整排 0(CLI 會用文字說明,不會假裝有數字)。

目標平台沒有 CLOCK_MONOTONIC 時。clock_gettime 是 POSIX 而非 C99。這種平台用 make PROFILE=1 EXTRA_CFLAGS='-DAUDIO_PIPELINE_NOW_US=board_timer_us -DAEC_NOW_US=board_timer_us -include my_timer.h' 換掉時鐘:巨集要是純識別字(Makefile 的 FP policy 不允許 EXTRA_CFLAGS 出現括號),指向不收參數、回傳 uint32_t 微秒的函式,宣告由整合者自備。替代時鐘必須單調,否則無號減法會產生接近 32-bit 全距的荒謬值。每個元件各有自己的覆寫點(這層、lib/aec、四路 pipeline),刻意不共用——一個元件的時鐘屬於該元件自己的建置契約。開著旗標但指向常數函式是合法用法,所有欄位讀 0,--timing 報表無法分辨這種情況與「根本沒開旗標」。

各階段不會加總成整通呼叫。餘數含引數檢查、aec_get_res_context(),以及 AEC 內部因此看不見的 stationarity 更新、e2_coarse/ERL 發布、DT analyzer、EPV、shadow_rise、失調估計、功率 EMA 與收斂偵測。呼叫端要呈現完整分解就必須把餘數明列。記錄本身不是條件編譯的,只有取樣是——欄位無論旗標開關都在 struct 裡,所以 profile 與 release build 切出來的 pool 逐位元相同。

16 kHz/256 ne10 實測(--timing,1250 hops 平均):delay 21.1 us(60.9%)、frontend 2.4 us(6.8%)、linear 1.3 us(3.8%)、res 3.5 us(10.1%)、nr 1.6 us(4.6%)、post 3.1 us(8.9%)、synth 0.2 us(0.5%),已量測合計 33.1 us,未歸屬 1.6 us,整通呼叫 34.6 us。最大的一塊是 matched filter,不是主濾波器(主濾波器只有 3.8%)——這條線直接對應 delay_num_filters(1..5)這個可調旋鈕。

Descriptor 慣例:AudioPipelineMemReq 為固定 32-byte 同 endian ABI(descriptor_version=2 / layout_version=9 / backend_id KISS=1, NE10=2 / build_flags_hash=FNV-1a-32(backend+carve token 字串) / alignment=16 / reserved=0 / bytes)。init_ex 對非 NULL 的 expected 做 8 點整數比對閘(七欄位 + pool 實際 bytes),任何 build/config 變更後必須重新 query。組態驗證是 reject-first:sample_rate 白名單 {8000,16000,48000}、enum/bool 逐項檢查,全部在 derive_dims_and_configs() 一處把關。

AudioPipelineConfig 新增四個 delay 相關欄位(layout v6,取代舊版只吃 preset 的隱含 delay 行為):filter_length(0=rate default,PBFDKF taps,init-time immutable)、delay_mode(AEC_DELAY_MATCHED|FIXED|EXTERNAL_ALIGNED,語意同 lib/aec)、delay_num_filters(僅 MATCHED,[1,5])、fixed_delay_samples(僅 FIXED,原生取樣點數;其餘模式須為 −1)。audio_pipeline_default_config() 填 MATCHED/n=5/−1(行為與 layout v5 之前逐位元相同)。目前兩支 CLI(aec_nr_pipeline/aec_nr_pipeline_static)都沒有對應旗標——只能由呼叫端直接寫 struct 欄位(如板端 adapter 或測試);CLI 只留 --fft-size/--sample-rate。

audio_pipeline_process(p, mic, ref, out)
 │
 ├─ aec_only ──► aec_process(aec, mic, ref, out) ──► return        (0-hop lag)
 │
 ├─ aec_process_context(aec, mic, ref)         沒有時域輸出 copy
 ├─ aec_get_res_context(aec, &ctx)             seam: error_spec/res_gain/r2/
 │                                              comfort_noise/far_power
 ├─ extra[k] = ctx.r2[k]/PSD_SCALE             PSD_SCALE = 32768^2
 ├─ mmse_lsa_process_gain(nr, ctx.error_spec, nr_extra, NULL)
 │      nr_extra = legacy_amin ? NULL : extra  (R² 折進噪聲底)
 ├─ sk_min_f32(g_total, mmse_lsa_get_gain(nr,NULL), ctx.res_gain)
 ├─ e2[k] = |ctx.error_spec[k]|²
 ├─ near-end floor:  far_active = ctx.far_power > 1e-4
 │      near_hang 由 mean(e2) > 1e-3 觸發, 長度 = retime(8 frames@10ms)

 └─ fft_inverse(fft, spec, ifft_buf) ─► ola += ifft_buf*synth_win
        ─► memcpy(out, ola, hop) ─► shift ola                       (1-hop lag)

NR gain 與 RES gain 都在同一 hop 內算完並套在同一張 ctx.error_spec 上;唯一的 hop-lag 來自最後的 50% overlap WOLA。實測(白噪 cross-correlation,16 kHz 預設格點):full chain lag = 128 samples(1.00 hop),aec_only lag = 0 samples。

延遲與 warm-up

  • 演算法延遲:full chain = 1 hop(實測 128 samples = 8 ms @16k 預設;16k-alt 16 ms、48k ~10.7 ms)。aec_only = 0 samples(overlap-save 線性路徑,實測)。
  • warm-up:hop#0 輸出僅含半窗 ramp(≈0);AEC 線性濾波器收斂與 delay acquisition 需要 far 活動(duty-cycled estimator);NR 噪聲底估計以 wall-clock ~1.5 s 的 retimed 幀數(mmse_lsa_retime_frames(150, sr, hop))收斂。
  • audio_pipeline_reset() 重置 OLA/RNG/hangover 與子模組,等同同 pool 重 init(不重驗 alignment/size)。
  • audio_pipeline.c 在同一個 processing call 內計算並套用當前 AEC context 與 NR gain；只有最後的 WOLA time-domain emission 形成 1 hop 延遲，與 pipelines/README.md 一致。
