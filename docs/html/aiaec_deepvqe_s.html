DeepVQE-S（end-to-end AEC+RES+NR，primary）

概要

Indenbom et al.（INTERSPEECH 2023, arXiv:2306.03177）0.59 M-class 小模型的重建。task （dataset_gen/model_views.py）= end_to_end_aec_res_nr_dereverb： 輸入是未對齊的 microphone 與 far-end 複數頻譜（mic_postclip / far_render，前面沒有 linear AEC）；target 是 near_target。輸出不是 ratio mask：是 3×3（3 個時間位置 × 3 個頻率位置）的因果複數 convolving mask（CCM）， 以論文的三個 120° 向量（three_vector_complex）表示；AecOutput.mask 為 None。

16k grid 下 max_delay_frames = 63。參數量實測 632,069 trainable （16k power-of-two 改編約 0.63 M，README 記載對應論文 0.59 M class）。 stream_output_delay = 0——四候選中時間軸最乾淨（readiness §3.3）。

ONNX / NPU graph boundary（已交付： AIAEC/DeepVQE_S/export_onnx.py）： graph 內 = compressed_ri_feature（power-law pow(0.3)）、 causal conv + BatchNorm + ELU 編碼、FrameDelayAttention（softmax over D=63，每幀獨立、無累積 state）、GRU(192)、FreqUpsample（頻率 sub-pixel shuffle，無 deconv）、殘差塊與 three_vector_complex 產生複數 taps。 graph 外（C 前後處理，現由 deepvqe_prepost.c/h 這個類別統一持有）= sqrt-Hann STFT/ISTFT（aiaec_process.c/h，center=False 每 hop 一幀）、complex↔RI， 以及 deepvqe_process.c/h 保存 3 幀 raw mic 複數譜 ring 並套用 CCM taps （deepvqe_ccm_process）。壓縮在 graph 內：類別遞給加速器的 mic/far 是未壓縮的 raw RI（[1,1,257,2]）， 這一點與 Align-ULCNet（前端搬到 host）相反。全部 recurrent state 為顯式 I/O tensor； 頻譜 ring 是 host state，不在 NPU graph 內。 NPU 注意（readiness）：FrameDelayAttention 的 [B,C,T,D,F] broadcast 必須逐幀化；輸出是 9 complex MAC/bin 的 CCM，不是 ratio mask。

API 用法

from AIAEC.DeepVQE_S.inference import load_model
from AIAEC.aiaec_streaming import StreamSTFT, StreamISTFT

model, grid = load_model("ckpt.pth", "cpu")
state = model.create_stream_state()   # 14 cells + spec_ring（C 邊界展開後為 16 個 state tensor）
mic_stft = StreamSTFT(grid.n_fft, grid.hop_len, window)
far_stft = StreamSTFT(grid.n_fft, grid.hop_len, window)
istft    = StreamISTFT(grid.n_fft, grid.hop_len, window)
for s in range(0, n, grid.hop_len):
    for m, f in zip(mic_stft.push(mic[:, s:s+256]), far_stft.push(far[:, s:s+256])):
        out = model.forward_stream(m.unsqueeze(1), f.unsqueeze(1), state)
        samples = istft.push(out.enhanced[:, 0])

C pre/post 類別（deepvqe_prepost.c/h）

板端整合點：一個物件包住 caller 音訊與加速器張量之間的一切（framing、RI staging、 CCM 頻譜 ring、兩組 state bank）。它組合 aiaec_process.c ＋ DeepVQE_S/deepvqe_process.c，兩個被組合的檔都沒有改。生命週期、32-byte DeepVqePrepostMemReq 陳舊 pool 閘、交易式 frame 狀態機與「為何是第三個 TU」是三個 模型共用的形狀，寫在 onnx_prepost；以下只記 DeepVQE-S 自己的部分。grid 只支援 16 kHz/512/256——aiaec_process.h 帶 #error 守衛，Align-ULCNet 若改成 48 kHz，這裡是編譯失敗而不是張量被默默重新解讀。

DeepVqePrepostConfig cfg;  DeepVqePrepostMemReq req;
deepvqe_prepost_config_defaults(&cfg, DEEPVQE_IO_TIME, /*D=*/DEEPVQE_PREPOST_DEFAULT_D);
cfg.fft = fft;  cfg.window = window;      /* caller-owned 借用；本類別不建也不毀 */
deepvqe_prepost_get_mem_size(&cfg, &req);
DeepVqePrepost *p = deepvqe_prepost_init_ex(pool, req.bytes, &cfg, &req);  /* 或 _init / _create */
每 hop：
  deepvqe_prepost_pre_process(p, mic_hop, far_hop);   /* 恆回 1；_pre_process_freq 為頻域孿生 */
  deepvqe_prepost_frame_inputs(p, &in, &out);         /* pool 內的 view；out 全 NaN 預填 */
  my_npu_run(&in, &out);
  deepvqe_prepost_frame_commit(p);                    /* 失敗改呼叫 deepvqe_prepost_frame_skip(p) */
  deepvqe_prepost_post_process(p, out_hop, &written); /* _post_process_freq 為頻域孿生 */
其餘：_reset / _destroy / _hop_size / _num_bins / _io_mode / _descriptor
邊界查詢：_state_name(id) / _state_name_out(id) / _state_shape(id, D, dims) / _state_elements(id, D)
        / _descriptor_default(D, &desc) / _descriptor_validate(&desc) / _skip_policy_name()

一 hop 進、一次推論、一 hop 出——從 hop #0 起、兩種模式都成立。io_mode 在 init 固定（它決定 pool 大小）：DEEPVQE_IO_TIME hop 進 hop 出，framing／加窗／ overlap-add 由類別做、但呼叫的是 caller 的 FftHandle 與 window 表； DEEPVQE_IO_FREQ 頻譜進頻譜出、不做任何 transform，fft/window 可為 NULL，是串接用的模式。pre_process 的兩路必須是同一個輸入 hop： 類別不做任何內部 skew，模型自己的 alignment attention 只在那之上再搜 D 幀。

frame_skip 是 fail-CLOSED：輸出靜音 （deepvqe_prepost_skip_policy_name() 回 "mute_fail_closed"）， 不是 Align-ULCNet 的 pass-through identity。理由是 stream 0 就是原始 mic——這個模型前面 沒有 linear canceller，放行等於把完全未消的迴聲送回遠端，那正是 AEC 唯一不可以做的事。 代價是近端出現一個以「一幀」為上界的缺口；另一邊的代價是無上界的迴聲。skip 時 state bank 不交換、CCM 頻譜 ring 不前進，只有 framing 排程前進，所以模型時間與 host 時間停在 「這一幀沒發生過」。要優雅降級而不是缺口的呼叫端，得自己跑一個 canceller 並在 pipeline 層 cross-fade——類別看不到有沒有這種東西，所以那個決定不屬於它。

兩組 host bank：Align-ULCNet 的 graph 只回 delta state，DeepVQE-S 的 graph 回每一個 state tensor 的完整下一個值，所以 pool 裡放兩份、frame_commit 成功時整組交換。 也因此 NaN 預填與有限值檢查每幀都要走過整組約 700 KB 的 state：這讓「失敗時什麼都不動」是被 強制的性質而不是宣稱。commit 的順序是先驗證每個 tap 與每個 state 元素、再交換 bank、再把 CCM taps 套到 raw mic 頻譜 ring 上（deepvqe_ccm_process）。

Framing：aiaec_analysis_push_frame()（aiaec_process.h， 轉呼叫 ulcnet_analysis_push_frame()）＝center=False rolling 分析， 第一次 push 起每次恰一幀。它與 centered aiaec_analysis_push() 對同一個 hop 吐出的最後一幀位元相同（同一個幾何：win = n_fft、hop = n_fft/2、共用同一張 sqrt-Hann 表； centered 只是在開頭多發一幀 reflect 前綴），所以這是換標籤不是換訊號，也讓類別和 center=False 的 AEC/GSC seam 對得上。演算法延遲仍是 1 個 hop：它來自 synthesis 的 半窗 trim，不是分析排程。

Pool（deepvqe_prepost_get_mem_size，16 kHz、D=63）： DEEPVQE_IO_TIME 1,499,408 B、DEEPVQE_IO_FREQ 1,477,808 B （差額 21,600 B ＝ 兩路 rolling 分析歷史＋共用 transform scratch＋一個 synthesis＋輸出 hop staging）。兩組 16 個 state 的 bank 佔掉絕大部分。

形狀由 deepvqe_prepost_state_shape(id, D, dims)（回 rank：h_gru 3、 其餘 4）與 _state_elements(id, D) 給出，兩者與 pool carve 讀同一個 switch， 所以形狀不可能在某一處對、另一處錯。頻率階梯 257→129→65→33→17 是 encoder 的 stride-2 halving， 時間深度 3 = causal conv kernel 4−1、alignment score conv 是 (5,3) 所以史深 4 （DEEPVQE_CONV_HISTORY / DEEPVQE_SCORE_HISTORY）。head 輸出 output = CCM taps [1,1,257,3,3,2]，與 deepvqe_process.h 的 taps[257][3][3][2] 攤平後同一塊記憶體。

Descriptor（13 欄）：DeepVqePrepostDescriptor = layout_version／delay_depth／sample_rate／ fft_size／hop_size／spectrum_bins／time_order／ freq_taps／conv_history_frames／score_history_frames／ gru_layers／gru_hidden／state_tensor_count。 deepvqe_prepost_descriptor_default(D, &desc) 產生本 build 的值， _descriptor_validate(&desc) 把除 delay_depth 之外每一欄 都釘在本 build 的常數上（delay_depth 是 export 期的部署參數，只檢查範圍）。 DEEPVQE_PREPOST_LAYOUT_VERSION 現為 1，且刻意不與 ULCNET_MODEL_IO_LAYOUT_VERSION 共用：兩個模型的 boundary 各走各的，共用號碼會讓 一邊的 bump 看起來像另一邊的。D 範圍 DEEPVQE_PREPOST_MIN_D=1 … MAX_D=256，預設 63 ＝ 這個 grid 上的 1.0 秒搜尋範圍。

Exporter metadata：AIAEC/_streaming_export.py 的 _C_DESCRIPTORS 把 DeepVQE_S 映到 _deepvqe_c_descriptor()，它從剛建好的 graph 量這 13 欄（tap 軸、conv／score 史深、GRU 形狀、兩個 ring 的 D 與 model 自報的 D 必須一致、state 數 = input 數 − signal input 數），再把 metadata['state_layout_version'] 與 metadata['c_descriptor'] 一起寫進 ONNX props 與旁邊的 JSON。 所以拓樸改動會在板端變成一次 descriptor_validate() 拒絕，而不是默默綁錯。

延遲與 warm-up

  • NN 演算法 lookahead = 0 hop；每個算子都是因果、reset 時 zero 左 context ≡ offline 左零 padding，無 warm-up 特例（無 CRUSE 的 T≥D caveat——delay softmax 每幀獨立）。
  • 實測 stream-vs-offline（seed 0/1、96 幀、CPU fp32）：enhanced 1.5e-6、ccm_taps 4.5e-7、delay 3.7e-9；tolerances 以 ~10x headroom 釘在 2e-5 / 5e-6 （test_streaming_deepvqe_s.py 檔頭）。唯一算術差源是 GRU batched-vs-stepped kernel 路徑。
  • Framing：C 類別用 center=False、每 hop 一幀的 rolling 分析 （aiaec_analysis_push_frame）；端到端演算法延遲仍是 256 samples（16 ms）， 但它來自 synthesis 的半窗 trim、不是分析排程。Python reference 的 StreamSTFT/StreamISTFT 仍是 centered 排程，兩條排程自第二個 hop 起位元相同 （centered 只在開頭多一幀 reflect 前綴）。
