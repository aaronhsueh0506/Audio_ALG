DeepVQE-S（end-to-end AEC+RES+NR，primary）

概要

Indenbom et al.（INTERSPEECH 2023, arXiv:2306.03177）0.59 M-class 小模型的重建。task （dataset_gen/model_views.py）= end_to_end_aec_res_nr_dereverb： 輸入是未對齊的 microphone 與 far-end 複數頻譜（mic_postclip / far_render，前面沒有 linear AEC）；target 是 near_target。輸出不是 ratio mask：是 3×3（3 個時間位置 × 3 個頻率位置）的因果複數 convolving mask（CCM）， 以論文的三個 120° 向量（three_vector_complex）表示；AecOutput.mask 為 None。

16k grid 下 max_delay_frames = 32（出貨模型以 max_delay_seconds = 0.5 訓練；建構子預設仍是 1.0 s ＝ 63）。參數量實測 632,069 trainable （16k power-of-two 改編約 0.63 M，README 記載對應論文 0.59 M class）。 stream_output_delay = 0——四候選中時間軸最乾淨（readiness §3.3）。

ONNX / NPU graph boundary（已交付： AIAEC/DeepVQE_S/export_onnx.py）： graph 內 = causal conv + BatchNorm + ELU 編碼、FrameDelayAttention（softmax over D=32，每幀獨立、無累積 state）、GRU(192)、FreqUpsample（頻率 sub-pixel shuffle，無 deconv）、殘差塊；最後一層 ccm_up 之後的「3 向量→複數」換算（three_vector_complex）在匯出時折進該 conv 的權重——graph 在最後一個 Conv 之後只剩 Transpose／Reshape／Slice，沒有 Gather／Mul／Sub、也沒有 rank>4 的張量，直接輸出 [1,1,257,18] taps（與 Python reference 的差異僅浮點捨入，約 1e-6；量化校正資料須以此 graph 產生）。 graph 外（C 前後處理，現由 deepvqe_prepost.c/h 這個類別統一持有）= sqrt-Hann STFT/ISTFT（aiaec_process.c/h，center=False 每 hop 一幀）、complex↔RI， 以及 deepvqe_process.c/h 保存 3 幀 raw mic 複數譜 ring 並套用 CCM taps （deepvqe_ccm_process）。壓縮在 host：power-law x·|x|^(0.3−1)（|x| = sqrt(re²+im²+1e-12)）由 deepvqe_prepost_frame_inputs() 算出，類別遞給加速器的 mic/far 是壓縮後的 planar 頻譜（[1,2,1,257]， 先 real 平面、再 imaginary 平面），graph 自第一個 conv 起（前面只有 window 的 Slice／Concat，沒有 Sqrt／Pow／Clip）；匯出後單獨執行 onnx_batch1_optimizer.py，各 conv 的頻率軸零填補即寫在 conv 的 pads 屬性，圖內沒有獨立 Pad op（fold_frequency_pad_into_conv）；解碼端三個 upsample 的 BatchNorm（在 sub-pixel shuffle 之後）折進前一個 conv 的權重與 bias（_fold_batch_norm_into_upsample_conv），圖內不再有 BatchNormalization；3 幀 raw mic 譜 ring 另存於類別內供 CCM 使用。 壓縮指數 0.3 編進 host（DEEPVQE_COMPRESSION_EXP），匯出器拒絕 compression_exponent 不是 0.3 的 checkpoint。全部 recurrent state 為顯式 I/O tensor，每個都是 rank 4、輸入是完整 window、 輸出是同 shape 的完整下一個 window（輸入端 Slice 加 Concat，沒有 state 輸出由 Slice 產生）， 所以每個 *_out 可綁到同名輸入的位址； 頻譜 ring 是 host state，不在 NPU graph 內。 NPU 注意（readiness）：FrameDelayAttention 的 [B,C,T,D,F] broadcast 必須逐幀化；輸出是 9 complex MAC/bin 的 CCM，不是 ratio mask。

C pre/post 類別（deepvqe_prepost.c/h）

板端整合點：一個物件包住 caller 音訊與加速器張量之間的一切（framing、RI staging、 CCM 頻譜 ring、16 個 state buffer）。它組合 aiaec_process.c ＋ DeepVQE_S/deepvqe_process.c。deepvqe_ccm_process 的 CCM 內圈（bin 1..N-2，每 bin 9 個 tap）走共用 NEON 核心 skn_ctaps_mac_f32（audio_common，與標量 twin 逐位元相同）；兩個邊界 bin 走標量路徑，略過落在頻譜外的 tap。frame_inputs 的壓縮（compress_planar）是 sqrtf／逐元素 libm powf／縮放三段迴圈； 本機工具鏈已把 sqrtf 迴圈編成 fsqrt.4s，未改用 sk_fast_sqrt_f32——它把 NaN 輸入映成 0，與 sqrtf 不逐位元相同。生命週期、32-byte DeepVqePrepostMemReq 陳舊 pool 閘、交易式 frame 狀態機與「為何是第三個 TU」是三個 模型共用的形狀，寫在 onnx_prepost；以下只記 DeepVQE-S 自己的部分。grid 只支援 16 kHz/512/256——aiaec_process.h 帶 #error 守衛，Align-ULCNet 若改成 48 kHz，這裡是編譯失敗而不是張量被默默重新解讀。

一 hop 進、一次推論、一 hop 出——從 hop #0 起、兩種模式都成立。io_mode 在 init 固定（它決定 pool 大小）：DEEPVQE_IO_TIME hop 進 hop 出，framing／加窗／ overlap-add 由類別做、但呼叫的是 caller 的 FftHandle 與 window 表； DEEPVQE_IO_FREQ 頻譜進頻譜出、不做任何 transform，fft/window 可為 NULL，是串接用的模式。pre_process 的兩路必須是同一個輸入 hop： 類別不做任何內部 skew，模型自己的 alignment attention 只在那之上再搜 D 幀。

frame_skip 是 fail-CLOSED：輸出靜音 （deepvqe_prepost_skip_policy_name() 回 "mute_fail_closed"）， 不是 Align-ULCNet 的 pass-through identity。理由是 stream 0 就是原始 mic——這個模型前面 沒有 linear canceller，放行等於把完全未消的迴聲送回遠端，那正是 AEC 唯一不可以做的事。 代價是近端出現一個以「一幀」為上界的缺口；另一邊的代價是無上界的迴聲。skip 時 CCM 頻譜 ring 不前進、 state 維持原樣（就地路徑為加速器寫完的樣子；回報失敗的 runtime 視為沒有寫入），只有 framing 排程前進。要優雅降級而不是缺口的呼叫端，得自己跑一個 canceller 並在 pipeline 層 cross-fade——類別看不到有沒有這種東西，所以那個決定不屬於它。

state 就地綁定：DeepVQE-S 的 graph 回每一個 state tensor 的完整下一個值， pool 裡每個 state 只有一份 buffer、位址在實例壽命內固定，沒有第二組 bank、沒有交換，也沒有複製路徑。 runtime 把 *_out 綁到輸入位址（state_out[id] 與 inputs.state[id] 同指標）， 必須先讀完所有 state 輸入、才寫同位址的 state 輸出。 frame_inputs 只對 taps 預填 NaN，state 不預填。frame_commit 是純驗證： 檢查每個 tap、h_gru 全部，以及每個 window 的最新一幀（attention ring 的 slot 0；conv 與 score window 的最後一幀） 是否有限；較舊的幀與被丟掉的那一格不重查（它們新的時候已查過，殘留的非有限值會在之後某一幀進到 taps 被擋下）。 通過後把 CCM taps 套到 raw mic 頻譜 ring 上（deepvqe_ccm_process）；遇非有限值時 state 無法回滾，16 個 state 全部歸零、 state_generation 加一、CCM ring 不前進、幀維持開啟、回 −1。寫一半或混寫只有在非有限值時才偵測得到。

state generation：deepvqe_prepost_state_generation() 是 C 端清零 state 的次數： reset 與被拒絕的 frame_commit 各加一，新建實例為 0，成功的 commit、skip 與再次呼叫被拒的 commit 都不動它。 定點 accelerator 的 state 緩衝在 C 清零時不會跟著變，板端 sample 比較這個值，變了就用量化後的 0 重填 16 個 state 輸入。

Framing：aiaec_analysis_push_frame()（aiaec_process.h， 轉呼叫 ulcnet_analysis_push_frame()）＝center=False rolling 分析， 第一次 push 起每次恰一幀。它與 centered aiaec_analysis_push() 對同一個 hop 吐出的最後一幀位元相同（同一個幾何：win = n_fft、hop = n_fft/2、共用同一張 sqrt-Hann 表； centered 只是在開頭多發一幀 reflect 前綴），所以這是換標籤不是換訊號，也讓類別和 center=False 的 AEC/GSC seam 對得上。演算法延遲仍是 1 個 hop：它來自 synthesis 的 半窗 trim，不是分析排程。

Pool（deepvqe_prepost_get_mem_size，16 kHz、D=32）： DEEPVQE_IO_TIME 636,896 B、DEEPVQE_IO_FREQ 615,296 B （差額 21,600 B ＝ 兩路 rolling 分析歷史＋共用 transform scratch＋一個 synthesis＋輸出 hop staging）。16 個 state 張量佔掉絕大部分。

每個 window 輸入由 graph 的 Slice 位移：conv 與 score window 取輸入的 frame 1..N−1（Slice axis 2，start 1，end N，step 1） 再把新一幀 Concat 在後面；attention ring 取輸入的 slot 0..D−2 再把新一幀 Concat 在前面。Concat 的結果就是 *_out，被丟掉的那一格（conv／score window 的 frame 0、ring 的 slot D−1）只讓輸入與輸出 shape 相同，graph 不讀它。 export_graph 對寫出的檔案呼叫 validate_inplace_state_contract（每對 state shape 相同且 rank 4、 每個 window 輸入恰有一個 Slice 消費者、沒有 state 輸出由 Slice 產生、metadata 帶 state_binding = in_place_same_address）。

形狀由 deepvqe_prepost_state_shape(id, D, dims)（回 rank，恆為 4） 與 _state_elements(id, D) 給出，兩者與 pool carve 讀同一個 switch， 所以形狀不可能在某一處對、另一處錯。頻率階梯 257→129→65→33→17 是 encoder 的 stride-2 halving， conv window = causal conv kernel 4 幀（3 幀過去加目前一幀）、alignment score conv 是 (5,3) 所以 window 是 5 幀 （DEEPVQE_CONV_WINDOW / DEEPVQE_SCORE_WINDOW）。head 輸出 output = packed CCM taps [1,1,257,18]；末軸保持 [time][frequency][RI] 次序，與 deepvqe_process.h 的 taps[257][3][3][2] 攤平後同一塊記憶體，不需 transpose 或 copy。

Descriptor（13 欄）：DeepVqePrepostDescriptor = layout_version／delay_depth／sample_rate／ fft_size／hop_size／spectrum_bins／time_order／ freq_taps／conv_window_frames／score_window_frames／ gru_layers／gru_hidden／state_tensor_count。 deepvqe_prepost_descriptor_default(D, &desc) 產生本 build 的值， _descriptor_validate(&desc) 把除 delay_depth 之外每一欄 都釘在本 build 的常數上（delay_depth 是 export 期的部署參數，只檢查範圍）。 DEEPVQE_PREPOST_LAYOUT_VERSION = 4（mic/far 的名稱與元素數 2×257 不隨 layout 變，state 的名稱不變但每個 window 多一幀、h_gru 是 rank 4，版號是唯一能攔下舊板綁新圖的閘門；舊 layout 產生的 ONNX／JSON 與 calibration 資料須重新匯出、加速器程式須重編；1–3 已退役），且刻意不與 ULCNET_MODEL_IO_LAYOUT_VERSION 共用：兩個模型的 boundary 各走各的，共用號碼會讓 一邊的 bump 看起來像另一邊的。D 範圍 DEEPVQE_PREPOST_MIN_D=1 … MAX_D=256，預設 32 ＝ 這個 grid 上的 0.5 秒搜尋範圍（ceil(0.5 × 16000/256)）。

Exporter metadata：AIAEC/_streaming_export.py 的 _C_DESCRIPTORS 把 DeepVQE_S 映到 _deepvqe_c_descriptor()，它從剛建好的 graph 量這 13 欄（tap 軸、conv／score window 深度、GRU 形狀、兩個 ring 的 D 與 model 自報的 D 必須一致、state 數 = input 數 − signal input 數），再把 metadata['state_layout_version'] 與 metadata['c_descriptor'] 一起寫進 ONNX props 與旁邊的 JSON。 所以拓樸改動會在板端變成一次 descriptor_validate() 拒絕，而不是默默綁錯。

延遲與 warm-up

  • NN 演算法 lookahead = 0 hop；每個算子都是因果、reset 時 zero 左 context ≡ offline 左零 padding，無 warm-up 特例（無 CRUSE 的 T≥D caveat——delay softmax 每幀獨立）。
  • 實測 stream-vs-offline（seed 0/1、96 幀、CPU fp32）：enhanced 1.5e-6、ccm_taps 4.5e-7、delay 3.7e-9；tolerances 以 ~10x headroom 釘在 2e-5 / 5e-6 （test_streaming_deepvqe_s.py 檔頭）。唯一算術差源是 GRU batched-vs-stepped kernel 路徑。
  • Framing：C 類別用 center=False、每 hop 一幀的 rolling 分析 （aiaec_analysis_push_frame）；端到端演算法延遲仍是 256 samples（16 ms）， 但它來自 synthesis 的半窗 trim、不是分析排程。Python reference 的 StreamSTFT/StreamISTFT 仍是 centered 排程，兩條排程自第二個 hop 起位元相同 （centered 只在開頭多一幀 reflect 前綴）。
