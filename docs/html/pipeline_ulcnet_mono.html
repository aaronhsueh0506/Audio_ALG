mono AEC(linear) → Align-ULCNet NN 後級(Aec + ulcnet_nn_stage)

概要

pipelines/mono_alignulcnet/main.c:沒有 mono unit、也沒有 ULCNet wrapper 函式庫。範例直接組合 lib/aec 的 Aec(線性 AEC,aec_process_context())與範例 stage pipelines/samples/ulcnet_nn_stage.{h,c}(Align-ULCNet 神經後濾波),各有自己的 mem_size 與 init(aec_get_mem_size()、ulcnet_nn_stage_mem_size(1))。stage 經 ulcnet_process.h 的 UlcnetModel 每幀 callback 驅動外部 NPU runtime;它只擁有已驗證的 C 前後處理(rolling center=False sqrt-Hann STFT、每 hop 恰一幀且至多一次推論、WOLA)與模型周邊的 delay-state policy。stage 是範例碼:沒有 ABI、沒有 layout version、沒有 descriptor。一個 binary 服務一個編譯期格點:16 kHz / 512 / 256 / 257 bins或48 kHz / 1024 / 512 / 513 bins(ULCNET_SR/N_FFT/HOP/BINS);runtime config 若不符該 build 即 reject(se_derive() 的 fixed-grid rules)。

兩路 analysis 都由 rolling center=False 的 AcStft(center 0,ac_stft_push_planar())驅動——自 hop#0 起每 hop 恰一幀、每 hop 至多一次推論。端到端延遲 1 hop;ULCNET_NN_STAGE_REPRIME_FRAMES 是 1,每 hop 遞減;幀 scratch 為 1 幀。

accelerator adapter

AIAEC/Align_ULCNet/ulcnet_accelerator_adapter.{h,c} 是「graph 內」那格的參考實作:accelerator 的單次呼叫無狀態(UlcnetAcceleratorRun run(user, inputs, outputs),一次一幀),K/V window、attention-logit window、GRU hidden 由 CPU 端 UlcnetModelIoState 的 caller-owned pool 在呼叫之間保存,每個 *_out 就地綁定到同名輸入的位址(export metadata state_binding = in_place_same_address)。state 張量的排列、每幀 prepare → run → commit-or-discard 交易與記憶體大小見 pipeline_ulcnet_detail。

API 用法

呼叫順序:se_derive()(固定格點、context-only 的 lane)→ ulcnet_model_io_descriptor_default(D, &desc) → ulcnet_accelerator_adapter_get_mem_size() / _init() → aec_get_mem_size()、ulcnet_nn_stage_mem_size(1) → 切塊 aec_init()、ulcnet_nn_stage_init() → ulcnet_accelerator_adapter_model() 交給 ulcnet_nn_stage_set_model() → 每 hop 一次(aec_process_context、取 context、ulcnet_nn_stage_begin_time、ulcnet_nn_stage_process)→ destroy。完整可編譯範例(含 phased 變體)、流程時序圖與參數表收在 pipeline_ulcnet_usage、pipeline_ulcnet_sequence 與 pipeline_ulcnet_params。每 hop 的核心如下:

AecResContext rctx;  AecLinearContext lctx;  UlcnetNnDelay delay;
aec_process_context(aec, mic, ref);                                  /* mic/ref/out 各 ULCNET_HOP 個 float */
aec_get_res_context(aec, &rctx);  aec_get_linear_context(aec, &lctx);
delay.changed = lctx.delay_state == AEC_LINEAR_DELAY_CHANGED;
delay.solid   = lctx.delay_state != AEC_LINEAR_DELAY_UNLOCKED;
ulcnet_nn_stage_begin_time(stage, rctx.formed_hop, ref, delay);      /* err／far 兩路分析;模型的 far = 原始 ref */
ulcnet_nn_stage_process(stage, out);                                 /* 已安裝的模型回呼 + WOLA */
/* 或 ulcnet_nn_stage_nn_begin() → 在 NPU 上跑 → ulcnet_nn_stage_nn_end(rc) → ulcnet_nn_stage_end(stage, out) */
/* 任一步回負值: aec_reset(aec); ulcnet_nn_stage_reset(stage);  (後者也呼叫 model->reset) */

板端把推論留給 NPU 時,同一個 hop 拆成 nn_begin／nn_end／end(模型的 infer 回呼因此可以不設;reset 回呼若有設,邊界與 reset() 時仍會被呼叫)。

ulcnet_nn_stage_process() 就是這個序列加上 stage 設定的模型回呼;nn_begin 回 1、0 或負值(序列錯誤),開著沒取走或沒關閉的幀走 identity(fail-open)。mono 範例每 hop 以 aec_get_res_context() 的 formed_hop 走 ulcnet_nn_stage_begin_time() 做 error 分析(不重用 AEC 的頻譜),所以兩路分析都在 begin 內;4ch 範例則用 ulcnet_nn_stage_begin_complex() 直接吃 BF 頻譜。任何一步回負值,整合者把 Aec 與 stage 一起 reset。

沒有執行期強度 setter,而且是刻意的。pipeline_mono 與 pipeline_4ch 的後級有 aec_set_preset() / anr_set_mode(),本範例 兩個都不提供——因為它沒有可以重新指定的強度面。這條範例完全沒有 NR 實例(anr_* 在 main.c 與 stage 一次都沒出現);AEC 側以 enable_res=0 / return_res_context=1 / spatial_linear_context=AEC_CONTEXT_LINEAR_ONLY 建立:post 區塊在 AecState 更新後停止,G_res、R²、comfort noise 都不計算(res_gain/r2/comfort_noise 為 NULL),範例只讀 formed_hop 與線性 context 的 delay_state(模型的 far 取 caller 的 raw ref)——塑形輸出的是 ULCNet 的 mask。所以「回音壓多深」在這裡是模型的性質,不是一個 runtime 旋鈕。aec_preset 仍是 SeRequest 要填的欄位(須為定義內的 enum 值),但它只決定那個不執行的抑制器的地板。要改強度,請重新訓練/更換模型,或改用有 DSP 後級的 pipeline_mono。

模型 error 分支不保證每個 hop 都是誤差。context-only(enable_res=0 / return_res_context=1)是 lib/aec 唯一開放 formed capture 候選的模式:上一個 hop 的濾波品質判定尚未認可線性估計、且被選中的殘差在這個 hop 的能量大於同一 hop 的 mic capture 時,formed_hop 與 error_spec 一起改送 capture 本身(時域與頻譜同步切換,既有 30-sample crossfade 承接邊界)。所以「濾波器在加訊號」的 hop 上模型看到的是 mic 原樣;AIAEC/dataset_gen/linear_aec.py 產生訓練用 linear error 時走的是同一組設定。

固定 raw-far 部署契約

production 沒有 raw/aligned runtime switch。模型固定讀 caller 傳入的 raw ref；PBFDKF 的 aligned 副本只用來形成 linear error，對齊由模型的 TA block 負責。取得對齊(或 delay 變動)的 hop 會先 reset 外部 K/V、logit 與 GRU state。raw/aligned 比較只保留在 sweep_delay_depth.py。export 的 training_far_input_mode 是 checkpoint provenance，far_input_mode=raw_far 是部署 ABI，兩者必須相同。C descriptor 只接受 ULCNET_FAR_RAW，其他值的 descriptor 在 init/set_model 被拒；io_descriptor==NULL 只允許 all-zero 的 identity model。

UlcnetModel callback 契約(step-always,唯一例外 = reprime)

  • Fail-open identity:infer==NULL(all-zero model)、infer() 回非 0、或輸出幀含任何非有限值(ulcnet_frame_is_finite() 逐 bin isfinite)→ 該幀改走誤差頻譜原樣;NaN/Inf 永不進 WOLA。STFT/WOLA 時序不因模型存在與否改變。
  • Step-always:只要裝了 infer callback,每個發射幀都呼叫 infer；delay lock 不閘控模型。唯一例外是下面的 identity reprime(每個 alignment generation 少 1 幀推論——compute 只會少,不會加倍)。
  • Delay 事件:MATCHED 的 AEC_LINEAR_DELAY_CHANGED，以及 FIXED 首次 UNLOCKED→LOCKED，都先呼叫 model->reset 清除 recurrent state，並武裝 identity reprime。

Identity reprime(alignment 邊界,option A)

alignment 邊界(MATCHED 的 AEC_LINEAR_DELAY_CHANGED、FIXED 首次 UNLOCKED→LOCKED)呼叫 model->reset 後,從邊界 hop 起的 ULCNET_NN_STAGE_REPRIME_FRAMES(= 1)個發射幀走 identity(誤差原樣)且完全不呼叫 infer;之後才同時恢復 step 與 apply。常數是在無邊界對照跑中用脈衝標記量出的,推導與兩個 grid 的實測數字見 pipeline_ulcnet_detail。

延遲與 warm-up

  • 端到端演算法延遲 = 1 compiled-grid hop:16 kHz 為256 samples/16 ms，48 kHz 為512 samples/10.67 ms。延遲來源是 synthesis 的半窗 trim,不是 analysis 排程(rolling push 從 hop#0 起就吐幀)。
  • warm-up:hop#0 就推入 1 幀並跑 1 次推論(history 全零),但 synthesis 的第一幀吃在半窗 trim 內,輸出仍全零;hop#1 起每 hop 正常輸出 256(16 kHz)/512(48 kHz)樣本。identity E2E 測試:out[hop p] ≈ formed_history[p-1](2e-4 內),hop 0 精確為零。
  • 模型從第一個發射幀就執行並套用(far 恆為 caller 的 raw far)。取得 alignment(或 delay 變動)時 reset recurrent state;邊界後 1 幀走 identity reprime(不 step 模型),第 2 幀起恢復 step+apply。
  • reset:整合者呼叫 aec_reset() 與 ulcnet_nn_stage_reset()(後者重置兩路 analysis/synthesis 並呼叫 model->reset);timing 前導(hop#0 零輸出)重新開始。

短延遲注意:echo path 落在線性濾波器涵蓋範圍內時，matched estimator 可能因 already-cancelling 保護而維持 UNLOCKED。這不會停用模型；模型繼續看到 raw far，能否解掉偏移取決於 export-time D。
