audio_pipeline_ulcnet — mono AEC(linear) → Align-ULCNet NN 後級

概要

pipelines/mono_alignulcnet/audio_pipeline_ulcnet.{h,c}:與 audio_pipeline 同一套 pool-first 建構紀律,但後級換成 Align-ULCNet 神經後濾波,經 ulcnet_process.h 的 UlcnetModel 每幀 callback 驅動外部 NPU runtime。此 pipeline 只擁有已驗證的 C 前後處理(centered sqrt-Hann STFT、0/2/1 幀發射、WOLA)+ 線性 AEC + 模型周邊的 delay-state policy。格點編譯期固定:16 kHz / fft 512 / hop 256 / 257 bins(ULCNET_SR/N_FFT/HOP/BINS);其他 sample rate 與 fft(0→512 以外)一律 reject。

accelerator adapter(CPU 擁有 state,加速器本身無狀態)

AIAEC/Align_ULCNet/ulcnet_accelerator_adapter.{h,c} + ulcnet_model_io.{h,c} 是「graph 內」那格的參考實作,把上面模糊的「runtime 保存」變成具體的 C 結構:accelerator 的單次呼叫是無狀態的(UlcnetAcceleratorRun run(user, inputs, outputs),一次一幀),K/V ring、attention-logit 史、GRU hidden 全部由 CPU 端 UlcnetModelIoState 在呼叫之間保存並於每次呼叫前後 pack/unpack——這是刻意選的邊界(export_onnx.py 稱其 boundary 為 stateless_one_frame_delta_state):ONNX graph 本身只吃「當前幀 + 顯式 state 輸入」、只吐「當前幀增強頻譜(output)+ state 的 delta」,不在 graph 內部遞迴。

state 張量shape(ONNX 慣例,省略 batch/time)排列
key/value history[1,32,D−1,26]newest-first(index 0 = 最近一幀)
logit history[1,32,4,D]oldest-first(index 0 = 最舊一幀——與 K/V 相反,commit() 內分別用不同方向的 shift)
GRU hidden(2 層)[2,1,128]—(逐層 next 直接整組替換,無 ring)

ulcnet_model_io_prepare() 在每次 infer 前把目前的 err/far RI 與上述三組 state 包成 UlcnetModelIoInputs(唯讀視圖)並把 UlcnetModelIoOutputs(accelerator 要寫的 key_now/value_now/logit_now/h_gru*_out/output)全部預填 NaN;ulcnet_model_io_commit() 驗證 accelerator 確實寫滿每個輸出欄位(NaN 未被覆蓋 = 判定失敗,持久 state 完全不動、視同該幀被丟棄——與 pipeline 自己的 fail-open 全有限值檢查是兩層獨立保護)後才推進三組 ring/hidden 並解包 enhanced_re/im。descriptor 發布固定 aligned-far deployment ABI；raw-far 只保留為 checkpoint training provenance 與 sweep 診斷。

model.infer(user, err_ri, far_ri, out_ri)                 ← pipeline 每個發射幀呼叫一次
 │  (adapter 內部,對 pipeline 不可見)
 ├─ ulcnet_model_io_prepare(state, err_ri, far_ri, &inputs, &outputs)

 │      inputs.logit_history              ← state 的 logit 史(oldest-first 視圖)
 │      inputs.h_gru0/1                   ← state 目前的 GRU hidden
 │      outputs.*_now / h_gru*_out / output  ← 全部先填 NaN
 ├─ run(user, &inputs, &outputs)          ← 呼叫端(板端)一次無狀態 tensor invocation
 └─ ulcnet_model_io_commit(state, enhanced_re, enhanced_im)
        全欄位非 NaN?
          是 → K/V ring 前移一格塞入 key_now/value_now(newest-first)
               logit 史後移一格塞入 logit_now(oldest-first)
               h_gru0/1 ← h_gru0/1_out(整組替換)
               回 0,enhanced_re/im 解包給呼叫端
          否 → persistent state 不動,回 -1(該幀視同失敗,pipeline fail-open)

D(delay_depth)決定 ring 深度,依 export descriptor 而定;主機範例先建立 D=8 descriptor，再把它傳給 ulcnet_accelerator_adapter_get_mem_size(),實測(host, 2026-08-19)bytes=71,040(model-I/O state 71,008 B + adapter 32 B),ULCNET_MODEL_IO_LAYOUT_VERSION=5。這一組是校正而非 AEC ABI 位移:先前記的 68,912 B / layout 4 是特徵外移前那一代的 model-I/O 佈局,與本輪 sizeof(Aec) 的變動無關。此記憶體不在audio pipeline pool 內，而是 caller 另外配置。

API 用法

AudioPipelineUlcnetConfig cfg = audio_pipeline_ulcnet_default_config(16000);
/* fft_size=0→512, aec_preset=BALANCED, model=all-zero(identity);
 * production far branch 固定讀 AEC aligned-far seam */

/* 推薦路徑:用 accelerator adapter 包一個無狀態 run() callback(main.c 範例) */
UlcnetModelIoDescriptor descriptor;
size_t adapter_bytes, adapter_align;
ulcnet_model_io_descriptor_default(8 /* export-time D */, &descriptor);
ulcnet_accelerator_adapter_get_mem_size(&descriptor, &adapter_bytes, &adapter_align);
void* adapter_pool = platform_alloc(adapter_bytes, adapter_align);
UlcnetAcceleratorAdapter* adapter = ulcnet_accelerator_adapter_init(
    adapter_pool, adapter_bytes, &descriptor,
    board_run_stateless_tensor_invocation, NULL);
cfg.model = ulcnet_accelerator_adapter_model(adapter);   /* 帶 aligned-far descriptor */

AudioPipelineUlcnetMemReq req;
audio_pipeline_ulcnet_get_mem_requirements(&cfg, &req);  /* raw descriptor 會 reject */
void* pool = platform_alloc(req.bytes, req.alignment);
AudioPipelineUlcnet* p = audio_pipeline_ulcnet_init_ex(pool, req.bytes, &cfg, &req);
while (stream) {
    audio_pipeline_ulcnet_process(p, mic, ref, out);   /* 各 256 floats */
}
audio_pipeline_ulcnet_reset(p);   /* 也呼叫 model->reset */
audio_pipeline_ulcnet_destroy(p); /* 不釋放 caller pool */

沒有執行期強度 setter,而且是刻意的。pipeline_mono 與 pipeline_4ch 都有 set_aec_preset() / set_nr_mode(),本 pipeline 兩個都不提供——因為它沒有可以重新指定的強度面。這條 pipeline 完全沒有 NR 實例(mmse_lsa_* 在本 TU 一次都沒出現);AEC 側則設 enable_res=0 / return_res_context=1,post 鏈照跑並把 G_res 填進 AecResContext,但本 pipeline 只讀 formed_hop / error_spec,從不讀 ctx.res_gain——塑形輸出的是 ULCNet 的 mask。所以「回音壓多深」在這裡是模型的性質,不是一個 runtime 旋鈕。cfg.aec_preset 仍是 init 時的欄位,但它調的是那個沒有消費者的 G_res。要改強度,請重新訓練/更換模型,或改用有 DSP 後級的 pipeline_mono。

模型 error 分支不保證每個 hop 都是誤差。context-only(enable_res=0 / return_res_context=1)是 lib/aec 唯一開放 formed capture 候選的模式:上一個 hop 的濾波品質判定尚未認可線性估計、且被選中的殘差在這個 hop 的能量大於同一 hop 的 mic capture 時,formed_hop 與 error_spec 一起改送 capture 本身(時域與頻譜同步切換,既有 30-sample crossfade 承接邊界)。所以「濾波器在加訊號」的 hop 上模型看到的是 mic 原樣;AIAEC/dataset_gen/linear_aec.py 產生訓練用 linear error 時走的是同一組設定。

固定 aligned-far 部署契約

production 沒有 raw/aligned runtime switch。模型固定讀 AecLinearContext.aligned_far_hop：MATCHED/FIXED 尚未能提供對齊資料時，這個 seam 暫時承載 raw far，模型仍 infer 並套用成功且 finite 的輸出；取得對齊後，同一 seam 改承載 PBFDKF 實際消費的 aligned far。切換 hop 會先 reset 外部 K/V、logit 與 GRU state。raw/aligned 比較只保留在 sweep_delay_depth.py。export 的 training_far_input_mode 是 checkpoint provenance；far_input_mode=aligned_far 才是部署 ABI。C descriptor 只接受 ALIGNED，raw descriptor 在 init/set_model 被拒；io_descriptor==NULL 僅供 identity 或尚未發布 descriptor 的 callback。

UlcnetModel callback 契約(step-always,唯一例外 = reprime)

  • Fail-open identity:infer==NULL(all-zero model)、infer() 回非 0、或輸出幀含任何非有限值(ulcnet_frame_is_finite() 逐 bin isfinite)→ 該幀改走誤差頻譜原樣;NaN/Inf 永不進 WOLA。STFT/WOLA 時序不因模型存在與否改變。
  • Step-always:只要裝了 infer callback,每個發射幀都呼叫 infer；delay lock 不閘控模型。唯一例外是下面的 identity reprime(每個 alignment generation 少 1 幀推論——compute 只會少,不會加倍)。
  • Delay 事件:MATCHED 的 AEC_LINEAR_DELAY_CHANGED，以及 FIXED 首次 UNLOCKED→LOCKED，都先呼叫 model->reset 清除 raw-far 時期的 recurrent state，並武裝 identity reprime。

Identity reprime(alignment 邊界,option A)

reset 清掉 runtime 的 K/V ring、logit 史與 GRU h，但 C 側 STFT 狀態是連續跑的:邊界當下還在飛的分析窗仍跨在邊界上(512 樣本窗裡一半是切換前推入的 hop)。在那種幀上 step 模型，等於用半舊的 err/far 幀對把剛清掉的 state 重建回去。

政策:從邊界 hop 起的 AUDIO_PIPELINE_ULCNET_REPRIME_FRAMES 個發射幀走 identity(誤差原樣)且完全不呼叫 infer——K/V、logit、GRU 都不前進;等到 err 與 far 兩路分析窗都只含切換後的 hop，才同時恢復 step 與 apply。reprime 期間再來一次邊界會重新武裝(不累加)。audio_pipeline_ulcnet_reset() 會把它歸零(analysis history 已清空,不存在跨界幀)。

常數是量出來的,不是寫死的:mono 兩路都由當前 hop 推入(error tap 與 aligned-far tap 同 hop,無 wrapper 端 far 補償),centered 512/256 分析剛好橫跨兩個推入 hop ⇒ 邊界在 hop T 時，只有 hop T 發射的那一幀跨界，hop T+1 的窗已全是切換後樣本。測試 test_reprime_straddle_derivation() 用「切換前最後一個 hop 正中央打一個單位脈衝、其餘全靜音」在一個完全沒有邊界的對照跑(FIXED delay 0)裡量這個數字(所以 reprime 不會參與量自己),兩路各得 1,與常數相符;實測 marked peak 0.7072(err)/0.7071(far) vs unmarked 1.257e-02/0.000e+00。邊界跑再驗:reprime 後第一個模型看得到的幀,兩路都不含切換前樣本。

option B(邊界後照常 step、只是輸出仍套用)暫緩,要先做音檔 A/B 才能換;現版本選 A 是為了不讓 recurrent state 由半舊幀重建。

延遲與 warm-up

  • 端到端演算法延遲 = 1 hop = 256 samples = 16 ms(centered 分析半窗 lookahead 本身;WOLA 收尾被半窗 trim 吸收)。測試佐證:far-timestamp 測試 far[2085] 的脈衝準確落在 out[2341](+256, offset +0)。
  • warm-up:hop#0 不發射任何幀,輸出全零;hop#1 一次補發 2 幀。identity E2E 測試:out[hop p] ≈ formed_history[p-1](2e-4 內),hop 0 精確為零。
  • AEC delay acquisition 前 seam 傳 raw far；模型從第一個發射幀就執行並套用。取得 alignment 時 reset recurrent state，之後 seam 傳 aligned far;邊界後 1 幀走 identity reprime(不 step 模型),第 2 幀起恢復 step+apply。
  • reset:audio_pipeline_ulcnet_reset() 重置 AEC/兩路 analysis/synthesis 並呼叫 model->reset;timing 前導(hop#0 零輸出)重新開始。

短延遲注意:echo path 落在線性濾波器涵蓋範圍內時，matched estimator 可能因 already-cancelling 保護而維持 UNLOCKED。這不會停用模型；模型繼續看到 raw far，能否解掉偏移取決於 export-time D。
