Align-ULCNet PCM stream：stream/aiaec/ulcnet/ulcnet_stream.h

驗證範圍：本頁描述的行為已用主機端、替身加速器對照板端 sample 的逐 hop 流程驗證（逐樣本 PCM、逐 hop trace 比對，含 reprime、solid 轉態、fail-open 與明確重置四種情境各自的斷言，以及 --inject-shift 自證比對有效）。未經實板、未經真實 NPU graph 驗證。

概要

這是 Align-ULCNet 模型給板端 sample 用的單一標頭入口：把 lib/aiaec/ulcnet/ulcnet_prepost.h 的頻域 frame_open／finish／bypass 生命週期、兩路（linear-error、raw far）analysis AcStft、一路 synthesis AcIstft（AC_OLA_ENV_NORM），以及板端 sample 自己做的對齊驅動 reset＋reprime 記帳，包成「int16 PCM 進、int16 PCM 出，一 hop 一次呼叫」的介面。這個模型是線性 AEC 後面的後濾波器：兩個輸入是 AEC 自己的 error hop 與原始 far hop，永遠不是原始 mic。沒有 HPF、沒有檔案載入入口。

為什麼不包 pipelines/ulcnet/ulcnet_nn_stage.{c,h}？那是給 4 聲道 pipeline 用的另一層、更高階的元件（同步「安裝模型」callback 消費者），它的 job 結構體給的是原始複數頻譜，不是這個模型真正的 NPU 張量邊界（壓縮特徵＋歷史／GRU state）；板端 sample 實際呼叫的是 ulcnet_prepost.h，跟 DFN2／DeepVQE-S 的 sample 同一個層級。這層 stream 直接對齊 ulcnet_prepost.h，ulcnet_nn_stage 原封不動，仍是它原來呼叫端的正確入口。

API 用法

ctx = ulcnet_stream_init(&cfg, pool, pool_bytes);
while (有一個 hop 的 int16 err_in, far_in) {
    UlcnetHopIO io;
    UlcnetStreamDelay delay = { .changed = ..., .solid = ... };   // 來自呼叫端自己的 AEC
    int pre_rc = ulcnet_stream_pre_process(ctx, err_in, far_in, delay, &io);
    if (pre_rc < 0) break;                                 // 契約錯誤
    int ai_rc = 0;
    if (pre_rc == 1) ai_rc = run_accelerator(&io.inputs, &io.outputs);   // 0 = mask 已寫
    if (ulcnet_stream_post_process(ctx, ai_rc, pcm_out) < 0) break;
    // pcm_out 永遠完整一個 hop；pre_rc 為 0（reprime）時 ai_rc 會被忽略
}

對齊驅動的 reset／reprime：delay.changed（新的對齊世代開始）或「delay.solid 從上一拍的假變成這一拍的真」兩者之一，在這一 hop 分析之前觸發：完整重置（兩路 STFT、ISTFT 與 UlcnetPrepost 一起，等同呼叫端自己呼叫 ulcnet_stream_reset()）並武裝 ULCNET_STREAM_REPRIME_FRAMES（= 1）個恆等 hop。只有 solid 轉態那一半邊界條件在「init／reset 後的第一個 hop」被抑制（沒有前一拍可比）；delay.changed == 1 在同一個第一個 hop 仍會觸發重置——跟板端 sample 未加防護的 changed 判斷一致，這是正確行為，不是漏洞。

Bypass 是直通式（fail OPEN），跟 DeepVQE-S 的 fail CLOSED 正好相反：reprime hop、加速器拒絕（ai_rc != 0）、或 frame_finish 自己的非有限值拒收，三者都讓 linear-error 頻譜原樣通過（不是靜音）——因為這個訊號本身已經是 AEC 的殘留，模型失敗時直通並不會比不跑模型更差。
