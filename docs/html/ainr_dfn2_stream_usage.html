DFN2 PCM stream：stream/ainr/dfn2/dfn2_stream.h

驗證範圍：本頁描述的行為已用主機端、替身加速器對照板端 sample 的逐 hop 流程驗證（逐樣本 PCM、逐 hop trace 比對，比對本身證明過會因注入錯誤而變紅）。未經實板、未經真實 NPU graph 驗證。

概要

這是 DFN2 模型給板端 sample 用的單一標頭入口：把 lib/ainr/dfn2/dfn2_prepost.h 的頻域 frame_open／finish／bypass 生命週期、audiolib 的 analysis／synthesis STFT（AC_OLA_ACCUMULATE）與選用的輸入 HPF 包成「int16 PCM 進、int16 PCM 出，一 hop 一次呼叫」的介面。只支援 frames_per_call == 1（N>1 的板端多幀版本不在此列，見 ainr_dfn2_detail）。自己做框化的頻域呼叫端應直接用 dfn2_prepost.h，不必透過這層。

兩種初始化模式：記憶體模式（dfn2_stream_init，呼叫端已載入並持有 ERB 矩陣）與檔案模式（dfn2_stream_init_from_erb_file，由 stream 自己的 pool 讀檔、持有矩陣；dfn2_stream_erb_file.c 是唯一含 <stdio.h> 的檔案，NO_STDIO build 可以不連這個檔，只用記憶體模式）。full／-DDFN2_MASK_ONLY 兩個變體各自建置，沿用既有 DFN2_VARIANT_SYMBOL 連結期檢查避免混用。

API 用法

ctx = dfn2_stream_init_from_erb_file(&cfg, erb_path, pool, pool_bytes);   // 或 dfn2_stream_init()
while (有一個 hop 的 int16 pcm_in) {
    DFN2HopIO io;
    if (dfn2_stream_pre_process(ctx, pcm_in, &io) != 1) break;            // -1 是契約錯誤
    int ai_rc = run_accelerator(&io.inputs, &io.outputs);                 // 0 = 每個輸出都寫了
    if (dfn2_stream_post_process(ctx, ai_rc, pcm_out) < 0) break;
    // pcm_out 永遠是完整一個 hop；不論內容都要寫出/播放
}

暖機（mask_lookahead 個 hop，init／reset 後）：pre_process 仍回 1、仍開一個 job，加速器仍跑一次；輸出為靜音（函式庫丟棄 heads、推進 io.state_generation）——跟正常迴圈完全一樣，不用特判。排尾：最後一個真實 PCM hop 之後，照同一個迴圈再餵 mask_lookahead + df_lookahead + 1 個全零 PCM hop，才能把最後一個真實來源幀排出（stream 的 STFT/ISTFT 框化本身多疊一個 hop，在核心自己的 L+D 延遲之上）。
