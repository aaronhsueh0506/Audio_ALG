ULCNet pipeline 細節 — accelerator adapter 與 identity reprime

概要

本頁收兩條 ULCNet 範例(mono、4ch,共用 pipelines/samples/ulcnet_nn_stage.{h,c})共用、但會把單頁撐過 30 KB 的兩段細節:(1) 參考 accelerator adapter 如何把模型 state 留在 CPU 端、(2) alignment 邊界的 identity reprime 與它的實測推導。兩頁的 API 用法、block diagram、泳道圖、I/O 表、State 表、延遲與檔案清單仍各自留在原頁。

accelerator adapter(CPU 擁有 state,加速器本身無狀態)

AIAEC/Align_ULCNet/ulcnet_accelerator_adapter.{h,c} 是「graph 內」那格的參考實作,把 pipeline_ulcnet_mono 邊界表裡的「runtime 保存」變成具體的 C 結構:accelerator 的單次呼叫是無狀態的(UlcnetAcceleratorRun run(user, inputs, outputs),一次一幀),K/V window、attention-logit window、GRU hidden 全部由 CPU 端 UlcnetModelIoState 的 caller-owned pool 在呼叫之間保存,每個 *_out 就地綁定到同名輸入的位址——這是刻意選的邊界(export_onnx.py 稱其 boundary 為 stateless_one_frame_full_state,metadata state_binding = in_place_same_address):ONNX graph 本身只吃「當前幀 + 顯式 state 輸入(完整 window)」、只吐「當前幀增強頻譜(output)+ 每個 state 的完整下一個 window」(位移在 graph 內:輸入端 Slice 加 Concat),runtime 在 run() 內先讀完所有 state 輸入、再把輸出寫到綁定的位址;沒有複製路徑,CPU 不搬 ring。不在 graph 內部遞迴。run() 不需處理 state 的清零:C 端清零(reset 或拒絕一幀)時 ulcnet_accelerator_adapter_state_generation() 加一,fixed-point 的 accelerator 另有 state 緩衝時,板端 sample 依它重填量化後的 0。

adapter 是 ULCNet 前後處理 class 的一層薄殼。每幀的 prepare → run → commit-or-discard 交易只寫在一個地方(ulcnet_prepost.c),adapter 負責驅動它:它自己不 carve 任何 framing 狀態,所以把 class 開在 ULCNET_IO_FREQ(頻譜進、頻譜出,framing 時鐘屬於呼叫端,完全不牽涉 FftHandle 或窗表)——ulcnet_accelerator_adapter.c 呼叫 ulcnet_prepost_config_defaults(cfg, ULCNET_IO_FREQ, descriptor->delay_depth)。pool 也只有一塊:adapter header + class pool,並以 ulcnet_prepost_init_ex() 讓 class 的 stale-pool gate 再驗一次這次 sizing 出來的 mode/D/build。ulcnet_model_io.{h,c} 的 state 與固定前後端由 class 持有。

state 張量shape(ONNX 慣例,省略 batch/time)排列
key/value window[1,32,D,TA_BINS]；TA_BINS=26(16 kHz)或52(48 kHz)newest-first(index 0 = 最近一幀;新幀接在前面、Slice 保留 index 0..D−2)
logit window[1,32,5,D]oldest-first(index 4 = 最近一幀,與 K/V 相反;Slice 保留 index 1..4、新列接在後面)
GRU hidden(兩顆 subband GRU 各 2 層)[1,4,1,128]—(無 ring;前兩列 subband 0、後兩列 subband 1)

ulcnet_model_io_prepare() 在每次 infer 前把目前的 err/far RI 與上述三組 state 包成 UlcnetModelIoInputs(唯讀視圖)並把 UlcnetModelIoOutputs(accelerator 要寫的 output 與四個 *_out)綁好:只有 output 預填 NaN;每個 *_out 指向對應輸入的位址,不預填。ulcnet_model_io_commit() 不更新任何 state,先驗證:output(mask)、h_gru 全部、K/V 的 slot 0 與 logit 的最後一幀(graph 這一幀新寫的那一格)皆有限才成功(NaN 未被覆蓋或任何非有限值 = 判定失敗;state 已被覆寫無法回滾,四個 state 全部歸零、state generation 加一、交易丟棄——與 pipeline 自己的 fail-open 全有限值檢查是兩層獨立保護;較舊的格子與被丟掉的那一格不重查,殘留的非有限值會在下一幀進到 output 被擋下),再乘上壓縮域 error、逆冪並解包 enhanced_re/im。descriptor 發布固定 raw-far deployment ABI(ULCNET_FAR_RAW)。

model.infer(user, err_ri, far_ri, out_ri)                 ← stage 每個發射幀呼叫一次
 │  (adapter 內部,對 pipeline 不可見;adapter 只是驅動 class)
 ├─ ulcnet_prepost_pre_process_freq(prepost, err_re, err_im, far_re, far_im)
 │      FREQ 模式下一個頻譜 = 一次 accelerator 呼叫,回傳恆 1(否則即失敗)
 ├─ ulcnet_prepost_frame_inputs(prepost, &inputs, &outputs)
 │      inputs.key_history/value_history  ← state 的 K/V window(newest-first 視圖)
 │      inputs.logit_history              ← state 的 logit window(oldest-first 視圖)
 │      inputs.h_gru                      ← state 目前的 GRU hidden(合併的單一 tensor)
 │      outputs.output                    ← 先填 NaN
 │      outputs.*_history_out / h_gru_out = 對應 inputs 的位址(不預填)
 ├─ run(user, &inputs, &outputs)          ← 呼叫端(板端)一次無狀態 tensor invocation
 │      runtime 先讀完所有 state 輸入、再寫輸出(輸出位址 = 輸入位址)
 │      回非 0 → ulcnet_prepost_frame_skip(prepost) 收掉交易,state 不動(回報失敗的 runtime 視同沒寫),回 -1
 ├─ ulcnet_prepost_frame_commit(prepost)
 │      output、h_gru、K/V slot 0、logit 最後一幀皆有限?
 │        是 → 解包 enhanced_re/im(四個 state 已由 runtime 就地寫好,commit 不位移、不複製)
 │        否 → 四個 state 全歸零(state generation +1),frame_skip 收尾,回 -1(pipeline fail-open)
 └─ ulcnet_prepost_post_process_freq(prepost, enhanced_re, enhanced_im)

D(delay_depth)決定 K/V 與 logit window 的深度,依 export descriptor 而定;主機範例以 D=8 實測 model-I/O + adapter pool 為 75,280 B(16 kHz)與 142,864 B(48 kHz)。差異來自 TA_BINS 26→52；此記憶體不在單元／Aec 與 stage 的 pool 內，而是 caller 另外配置。實際產品一律以 ulcnet_accelerator_adapter_get_mem_size() 現查，不可跨 grid 沿用常數。

Identity reprime(alignment 邊界,option A)

mono(Aec + ulcnet_nn_stage)

reset 清掉 runtime 的 K/V history、logit history 與 GRU h，但 C 側 STFT 狀態是連續跑的:邊界當下還在飛的分析窗仍跨在邊界上(ULCNET_N_FFT 樣本窗裡一半是切換前推入的 hop)。在那種幀上 step 模型，等於用半舊的 err/far 幀對把剛清掉的 state 重建回去。

政策:從邊界 hop 起的 ULCNET_NN_STAGE_REPRIME_FRAMES 個發射幀走 identity(誤差原樣)且完全不呼叫 infer——K/V、logit、GRU 都不前進;等到 err 與 far 兩路分析窗都只含切換後的 hop，才同時恢復 step 與 apply。reprime 期間再來一次邊界會重新武裝(不累加)。ulcnet_nn_stage_reset() 會把它歸零(analysis history 已清空,不存在跨界幀)。

常數是量出來的,不是寫死的:mono 兩路都由當前 hop 推入(error tap 與 raw-far tap 同 hop,無 far 補償),rolling 50%-overlap 分析在 hop T 發射的那一幀恆橫跨推入 hop T−1 與 T ⇒ 邊界在 hop T 時，只有 hop T 發射的那一幀跨界，hop T+1 的窗已全是切換後樣本。預設 16 kHz build 的脈衝推導測試兩路各得 1,與常數相符；同一拓撲也適用 48 kHz build。

邊界後不 step 模型(identity reprime),是為了不讓 recurrent state 由半舊幀重建。

4ch(AudioPipeline4Ch + ulcnet_nn_stage)

model->reset 清掉 runtime 的 K/V history、logit history 與 GRU h,但 C 側 framing 狀態是連續跑的(核心 lane 的分析、stage 的 far 分析與 synthesis 都不清):邊界當下還在飛的分析窗仍跨在邊界上。在那種幀上 step 模型,等於用半舊的 err/far 幀對把剛清掉的 state 重建回去。

政策:從邊界 hop 起的 ULCNET_NN_STAGE_REPRIME_FRAMES(兩個範例共用同一個常數)個發射幀走 identity(誤差原樣)且完全不呼叫 infer——K/V、logit、GRU 都不前進;等到 err 與 far 兩路分析窗都只含切換後的 hop,才同時恢復 step 與 apply。reprime 期間再來一次邊界會重新武裝(不累加);ulcnet_nn_stage_reset() 會把它歸零(同時 reset far 分析與 synthesis 的 AcStft/AcIstft,history 已清空,不存在跨界幀)。compute 只會少 1 幀推論,不會加倍。

常數 = 1,而且是量出來的(samples/ulcnet_nn_stage.h)。推導:兩個分支都從當前 input hop 取幀(hop T 的 BF 頻譜(beam.spectrum)、以及用 hop T 推入的 far 分析),而每個 50%-overlap 幀橫跨兩個 hop,所以只有邊界 hop T 發射的那一幀還蓋到切換前的 hop T−1,hop T+1 的幀已經只含切換後的兩個 hop。這與 mono 範例的 1 相同(mono 同樣兩路都從當前 hop 取幀)。4ch_alignulcnet/tests/test_4ch_ulcnet.c 與 mono_alignulcnet/tests/test_mono_ulcnet.c 的 test_reprime_straddle_derivation() 用「切換前最後一個 input hop 正中央打一個單位脈衝、其餘全靜音」在一個完全沒有邊界的對照跑(FIXED delay 0)裡量,所以 reprime 邏輯不參與量自己;兩路分開標記。

gridERROR 路FAR 路邊界後第一個模型可見幀
16 kHz / 5121 個跨界幀;marked peak ≥ 0.7072 vs unmarked ≤ 1.257e-02(mono);≥ 0.6761 vs ≤ 1.256e-02(4ch)1;marked peak ≥ 0.7071 vs unmarked 0.000e+00邊界 hop T=8 → hop 9(兩路皆無切換前樣本)
