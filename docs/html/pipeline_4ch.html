audio_pipeline_4ch — 4 mic 共用 delay + SRP/GSC + fused post

概要

兩層結構(pipelines/4ch_aec_bf_nr_res/):

  • 核心 4aec_nr_res:1 個共用 far aligner(delay_mode=MATCHED 時是 1 個 DelayAec3 matcher + 1 條共用 aligned render delay line;FIXED/EXTERNAL_ALIGNED 時 matcher count = 0,兩者都不 carve)→ 4 條獨立線性 AEC lane → 外部 beamformer 權重投影 → 1 個 post-beam RES + 1 個 mono NR + 1 條 iFFT/OLA(不逐 lane 複製 NR/RES)。mono 的單一 process() 在這裡拆成 process_pre() → 外部 beamformer → process_post()。
  • 完整 wrapper audio_pipeline_4ch:把 SRP-PHAT DOA + GSC(third_party/doa、third_party/GSC)接進 pre/post 縫,並提供保守 energy-VAD fallback。

結構稽核值(*_count()):matched_filter 依 cfg.delay_mode 而定——MATCHED 時 1,FIXED/EXTERNAL_ALIGNED 時 0(無 estimator 可數);linear_aec 恆 4;post_res 依 cfg.enable_post 而定(啟用 1、停用 0),nr 則要 enable_post && enable_nr 同時成立才是 1——enable_post=1 但 enable_nr=0 的 RES-only 組態下 nr 為 0。Lane 0 每 hop 跑真 far-FFT,lane 1–3 經 aec_process_context_shared_far() 借用 lane 0 的 far 頻譜(4 次 far-FFT → 1 次,測試以 four_aec_nr_res_far_fft_real_compute_count() 證明)。支援 16 kHz(fft 256 預設 / 512 明示)與 48 kHz(fft 1024)。

共用 estimator 的 duty-cycle(MATCHED):與 mono lib 同一套機器,兩個視窗直接讀自本層已經建好的 lane AecConfig(delay_est_init_s/delay_est_period_s,預設 0.3 s/0.5 s)——估計 solid 且 delay_est_init_s 不變後,matched-filter 分析降為 1-in-K(K=delay_est_period_s/hop÷5:16k/128 為 12、16k/256 為 6、48k/512 為 9,三個格點的 duty 週期都是 ~96 ms);estimator 每 hop 照餵(decimation 只作用於分析,不作用於音訊)。回全速的時機不是「立刻」:被略過的 hop 不會發佈新估計,所以 delay 改變/信心流失只能在下一個排定的分析被看見,全速從看見的那個 hop 起恢復——最壞多等一個 duty 週期(~96 ms)。windowed-ERLE 自洩漏峰值崩 6 dB 的看門狗可以提早喚醒它,但它必須先讓峰值超過同一個 6 dB 才會武裝。實測 shared delay 段 17.0→4.3µs/hop,delay 軌跡與全速版逐 hop 相同。census:four_aec_nr_res_duty_hops_run()(實跑分析的 hop)對 four_aec_nr_res_duty_hops_total()(=estimator_calls 的別名,分母)。已知邊界(已由 test_4aec_nr_res.c 的低 ERLE A/B 場景釘住):lane ERLE 壓在 6 dB 之下時看門狗永遠不會武裝,delay change 的 re-lock 完全由 1-in-K 取樣承擔——16k/256 實測全速 319 hops(5.10 s)、duty 805 hops(12.88 s),2.52 倍,峰值 lane ERLE 3.3 dB(mono 同款行為)。

Descriptor 慣例與 mono 相同(32-byte 固定 ABI、init_ex 8 點閘)。核心 FOUR_AEC_NR_RES_LAYOUT_VERSION=16、wrapper AUDIO_PIPELINE_4CH_LAYOUT_VERSION=11,兩者 descriptor_version 皆 1;wrapper 的 build_flags_hash 摺入核心的 hash(核心 layout bump 會連帶作廢外層 descriptor)。核心 config:delay_mode(AEC_DELAY_MATCHED|FIXED|EXTERNAL_ALIGNED,四條 lane 共用同一個決策)、delay_num_filters(僅 MATCHED,[1,5])、fixed_delay_samples(僅 FIXED,原生取樣點數;其餘須 −1)、capture_proxy_channel(matcher 輸入,[0,3])、max_delay_ms(僅 MATCHED 用於 sizing delay ring,預設 1024,delay ring = ceil(ms×sr/1000)+2×hop+1)、filter_length(0=rate default)、delay_backward_quarantine_enabled(bool,預設 0;開啟後只隔離比現行 delay 更早的新估計,且僅在 capture_proxy_channel 那一條 lane 仍在消除回音時;往後跳與首次取得對齊都不受影響)、delay_backward_quarantine_s(float,預設 1.0;隔離窗長,init 時換算成 hop 數,到期即採用——延後一個窗,不是治癒;不是 pre-echo 誤鎖的解藥,該誤鎖已在估計器端根治,aggregator 改為回報 dominant matched-filter peak)。Quarantine 目前只驗過合成場景與 C／Python 逐 hop 對照,真實錄音抽測待做,產品組態維持預設 OFF。

本節最重要的一件事:對四條 lane 重新指定 preset 是無效操作。四條 lane 都以 spatial_linear_context 建立,因此沒有任何一條會走到自己的 suppression_gain_get_gain();它們各自的地板什麼都不塑形。真正乘上本產品輸出、也真正決定 comfort noise 量的那個 gain,來自唯一一個共用的 post 級抑制器——上面兩個 preset setter 針對的就是它,這也是它們存在、而不是要呼叫端自己對四條 lane 迴圈呼叫 aec_set_preset() 的原因。同理 NR 也只有一個共用實例(對 beamform 後的訊號跑),不是每條 lane 一個。這一點由 tests/test_4aec_nr_res.c 的 test_runtime_strength() 釘住,不是推測。

呼叫改／讀什麼回 −1 的情況(−1 時什麼都不寫)
four_aec_nr_res_set_aec_preset()共用 post 級抑制器的 far-active split floorp NULL／已 destroy;preset 超出 enum;ramp_ms 非有限值或超出 [0, 60000];enable_post == 0(pre-only 核心沒有抑制器)
four_aec_nr_res_set_nr_mode()本核心擁有的那一個降噪器p NULL／已 destroy;enable_post == 0 或 enable_nr == 0(兩者都代表沒有降噪器實例);mode 超出 enum;重組出的 target 被拒
four_aec_nr_res_post_split_floor()唯讀。live=抑制器當下套用的值,target=撐得過 reset 的已設定值;只有 ramp 走到一半時兩者不同。任一指標可為 NULLp NULL／已 destroy;enable_post == 0

live/target 這一對是板端唯一值得記錄的強度量:它是真正塑形輸出的東西,兩個值合在一起就回答「我要求的改動落地了沒有」。完整 wrapper 兩個 setter 是薄殼(p/已 destroy/p->core 為 NULL 回 −1,其餘直接轉給核心),但不轉出核心 handle,所以這一對讀數在 wrapper 層拿不到。

ramp_ms == 0 下一個 hop 套用(不是錯誤),落點與「用該 preset 從頭建一個新實例」完全相同;> 0 以 dB 線性走過去,上限 60 s。ramp 途中再呼叫會從當前 live 值重新起走。兩個 setter 都不是重啟:四條 lane 的濾波器、共用延遲鎖定、NR 噪聲底與增益平滑歷史全部繼續跑。preset 改動撐得過 four_aec_nr_res_reset()(目標值另存一份,reset 會重新套用),ramp 進度則會被丟掉。在兩個 hop 之間呼叫、與 process_pre()／process_post() 序列化;非 thread-safe。Python 對應 FourChannelAecPipeline.set_aec_preset(preset, ramp_ms=0.0)(同樣只動共用 post-beam 抑制器)。

不要繞過 set_nr_mode() 去呼叫 mmse_lsa_set_mode()。本核心的 NR 組態是「canonical 強度 preset 加上自己的覆寫」(broadband_threshold、L、alpha_decay;見 compose_nr_config())。mmse_lsa_set_mode() 組的是裸的 canonical preset,在本核心的實例上會被拒絕(它的 L 不同)——所以 four_aec_nr_res_set_nr_mode() 做的事是重組本核心的完整組態,再交給 mmse_lsa_reconfigure()。

A/B 量測時該預期什麼。far-active 地板只在 far-active 且非 double-talk 的 hop 生效:DT 期間本核心強制套用 DT 地板(三個 preset 完全相同),far-active latch 觸發前套的是 far-silent 地板。同一個 gain 還決定注入的 comfort noise 量(振幅 ∝ sqrt(1 − G_res²),見下方 block diagram 的 CNG 步驟——地板越深、CNG 反而越多)。所以整段錄音的平均移動幅度會小於 dB 落差所暗示的量,而且只量 echo/degradation 的 A/B 會把 CNG 的變化錯記到別的機制。請在 echo 對齊或 degradation 對齊的條件下比較,並實際試聽。

逐階段耗時(診斷用)

typedef struct FourAecNrResLastTiming {
    uint32_t delay_us, frontend_us, linear_us, lane_res_us;   /* process_pre  */
    uint32_t fuse_us,  res_us,      nr_us,     synth_us;      /* process_post */
} FourAecNrResLastTiming;

void four_aec_nr_res_get_last_timing(const FourAecNrRes* p, FourAecNrResLastTiming* out);

最近一個 hop 每個階段的 wall-clock 成本(微秒,CLOCK_MONOTONIC)。純診斷:pipeline 自己不回讀,也不影響處理。p 為 NULL 或已銷毀時把 out 清零而不是失敗;out 不得為 NULL。八個欄位全部都是真的量測值:delay_us(update_shared_delay() 的共用 estimator,不含 align_render() 的 ring-buffer 複製與 realign 掃描)、fuse_us(fuse_contexts())、res_us(它消耗的功率準備 ＋ suppression_gain_get_gain())、nr_us(mmse_lsa_process_gain())、synth_us(逆轉換 ＋ 加窗 overlap-add ＋ hop 送出/位移),以及四條 lane 加總的 frontend_us／linear_us／lane_res_us。

後三者由 aec_get_last_timing()(aec.h)逐 lane 讀出後相加,受 -DAEC_STAGE_TIMING=1 這個另一半的旗標管轄——只建 wrapper 那半,這三欄讀 0 而其餘照常量測,是可讀的狀態而非壞掉;make PROFILE=1 兩半一起開。lane 內部的 delay_us 也一併加進上面的 delay_us,但它結構上恆為 0:四條 lane 都是 AEC_DELAY_EXTERNAL_ALIGNED,沒有自己的 ring 或 estimator。相加而不是丟棄,是為了讓日後改變 lane 模式時不會靜默漏掉那筆成本。

目標平台沒有 CLOCK_MONOTONIC 時。clock_gettime 是 POSIX 而非 C99。用 make PROFILE=1 EXTRA_CFLAGS='-DFOUR_AEC_NR_RES_NOW_US=board_timer_us -DAEC_NOW_US=board_timer_us -include my_timer.h' 換掉時鐘;巨集要是純識別字(FP policy 不允許 EXTRA_CFLAGS 出現括號),指向不收參數、回傳 uint32_t 微秒的函式。替代時鐘必須單調。這層與四條 lane 各有自己的覆寫點,刻意不共用。開著旗標但指向常數函式是合法用法,所有欄位讀 0。

呼叫端若要呈現完整分解,兩邊的未歸屬餘額要自己用減法算:pre_total − (delay_us + frontend_us + linear_us + lane_res_us) 涵蓋輸入去交錯／有限值檢查、align_render()、realign 掃描與 lane 迴圈自己的餘額;post_total − (fuse_us + res_us + nr_us + synth_us) 涵蓋 gain 融合、near-floor 閘與 comfort-noise 迴圈。

兩半各自在自己的進入點清零,所以中途失敗的 hop 對沒跑到的階段回報 0 而不是上一個 hop 的數字。process_post*() 回傳後讀才是完整的;只呼叫 process_pre() 時僅前半有值。此記錄使核心 struct 增加 32 B,是本輪 layout version bump 的原因。

formed seam 的第三個候選是 capture。四條 lane 都以 enable_res=0 / return_res_context=1 建立,而 lib/aec 的 formed 選擇器只在這個 context-only 模式多開一個候選:上一個 hop 的濾波品質判定尚未認可線性估計、且被選中的殘差(refined 或 coarse)在這個 hop 的能量大於同一 hop 的 mic capture 時,該 lane 的時域 hop 與其頻譜一起改送 capture,既有的 30-sample crossfade 承接邊界(不丟 OLA 歷史、不歸零任何 hop)。外部 beamformer 因此可能在這些 hop 上拿到 mic 原樣而不是誤差——那正是「濾波器在加訊號」時該有的行為。enable_res=1 的路徑不走這條,仍由 AEC3 post 自己的頻域 over-output 保護處理。

ABI 註記:aligned_ref 是 caller-stack 交接 struct 的尾端新欄位,pool byte layout 不變,故 layout_version 刻意不 bump;但對把 FourAecNrResPreFrame by-value 內嵌的 out-of-tree caller 仍是需要整體重編的 struct 變更。abandon_pre() 消耗 token 如同成功的 post,但不推進任何下游狀態(NR/RES/OLA 不動)——設計給從不呼叫 post 的外部-post 變體,不是給逐 hop 混用。

延遲與 warm-up

  • 演算法延遲:1 hop(WOLA;實測 argmax 127 samples @hop=128 → 8 ms @16k 預設)。
  • delay acquisition:估計值要 solid 且 n_updates≥3 才被接受;開始新的可用 alignment generation 的那個 hop 回報 delay.changed=1——首次 acquisition、unlock 後同值重鎖、鎖定中值改變皆屬之(不只值改變;見 4aec_nr_res.h 的 FourAecNrResDelayState 契約),核心同時 reset 四條 lane 並清 mono OLA(外部 STFT/OLA 也應照 changed 清)。ring 未累積到 delay 樣本前 aligned_ref 前導為 0。
  • SRP/GSC warm-up:DOA smoother 需 doa_switch_consecutive=3 次一致觀測才切換;GSC RLS 由 vad_out 凍結(vad_out=1 → 凍結適應)。
  • NR 噪聲底 ~1.5 s wall-clock(retimed L)。
