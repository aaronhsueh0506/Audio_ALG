audio_pipeline_4ch — 4 mic 共用 delay + SRP/GSC + fused post

概要

兩層結構(pipelines/4ch_aec_bf_nr_res/):

  • 核心 4aec_nr_res:1 個共用 far aligner(delay_mode=MATCHED 時是 1 個 DelayAec3 matcher + 1 條共用 aligned render delay line;FIXED/EXTERNAL_ALIGNED 時 matcher count = 0,兩者都不 carve)→ 4 條獨立線性 AEC lane → 外部 beamformer 權重投影 → 1 個 post-beam RES + 1 個 mono NR + 1 條 iFFT/OLA(不逐 lane 複製 NR/RES)。mono 的單一 process() 在這裡拆成 process_pre() → 外部 beamformer → process_post()。
  • 完整 wrapper audio_pipeline_4ch:把 SRP-PHAT DOA + GSC(third_party/doa、third_party/GSC)接進 pre/post 縫,並提供保守 energy-VAD fallback。

結構稽核值(*_count()):matched_filter 依 cfg.delay_mode 而定——MATCHED 時 1,FIXED/EXTERNAL_ALIGNED 時 0(無 estimator 可數);linear_aec 恆 4;nr/post_res 依 cfg.enable_post 而定,啟用時各 1、停用時各 0。Lane 0 每 hop 跑真 far-FFT,lane 1–3 經 aec_process_context_shared_far() 借用 lane 0 的 far 頻譜(4 次 far-FFT → 1 次,測試以 four_aec_nr_res_far_fft_real_compute_count() 證明)。支援 16 kHz(fft 256 預設 / 512 明示)與 48 kHz(fft 1024)。

API 用法

/* 完整 wrapper(含 SRP/GSC) */
AudioPipeline4ChConfig cfg = audio_pipeline_4ch_default_config(16000);
AudioPipeline4ChMemReq req;
audio_pipeline_4ch_get_mem_requirements(&cfg, &req);
void* pool = platform_alloc(req.bytes, req.alignment);
AudioPipeline4Ch* p = audio_pipeline_4ch_init_ex(pool, req.bytes, &cfg, &req);
AudioPipeline4ChFrameInfo info;
audio_pipeline_4ch_process(p, mics_interleaved, ref, out, &info);      /* 內建 auto-VAD */
/* 產品有 VAD 時: audio_pipeline_4ch_process_with_activity(p, mics, ref,
 *                    vad_raw, vad_out, frequency_mask, out, &info); */
audio_pipeline_4ch_destroy(p);   /* 不釋放 caller pool */

/* 只用核心 + 自備 beamformer */
FourAecNrResPreFrame pre;
four_aec_nr_res_process_pre(core, mics_interleaved, ref, &pre);
/* ... 用 pre.linear_spectra / pre.aligned_ref 算 weights ... */
four_aec_nr_res_process_post(core, &pre.token, weights, out);
/* 外部 post 變體(如 ULCNet)不跑 post: four_aec_nr_res_abandon_pre(core, &pre.token); */

Descriptor 慣例與 mono 相同(32-byte 固定 ABI、init_ex 8 點閘)。核心 FOUR_AEC_NR_RES_LAYOUT_VERSION=11、wrapper AUDIO_PIPELINE_4CH_LAYOUT_VERSION=6,兩者 descriptor_version 皆 1;wrapper 的 build_flags_hash 摺入核心的 hash(核心 layout bump 會連帶作廢外層 descriptor)。核心 config:delay_mode(AEC_DELAY_MATCHED|FIXED|EXTERNAL_ALIGNED,四條 lane 共用同一個決策)、delay_num_filters(僅 MATCHED,[1,5])、fixed_delay_samples(僅 FIXED,原生取樣點數;其餘須 −1)、capture_proxy_channel(matcher 輸入,[0,3])、max_delay_ms(僅 MATCHED 用於 sizing delay ring,預設 1024,delay ring = ceil(ms×sr/1000)+2×hop+1)、filter_length(0=rate default)、delay_backward_quarantine_enabled(bool,預設 0;開啟後只隔離比現行 delay 更早的新估計,且僅在 capture_proxy_channel 那一條 lane 仍在消除回音時;往後跳與首次取得對齊都不受影響)、delay_backward_quarantine_s(float,預設 1.0;隔離窗長,init 時換算成 hop 數,到期即採用——延後 pre-echo 誤鎖一個窗,不是治癒)。Quarantine 目前只驗過合成場景與 C／Python 逐 hop 對照,真實錄音抽測待做,產品組態維持預設 OFF。

aligned_ref(2026-08-13 新增)[hop] 本 hop 實際餵給四條 lane 的 delay-aligned 時域 far(ring 未滿時前導為 0)。給外部 NN post(Align-ULCNet far branch)用pipeline-owned;有效至 post/abandon_pre/reset/destroy

ABI 註記:aligned_ref 是 caller-stack 交接 struct 的尾端新欄位,pool byte layout 不變,故 layout_version 刻意不 bump;但對把 FourAecNrResPreFrame by-value 內嵌的 out-of-tree caller 仍是需要整體重編的 struct 變更。abandon_pre() 消耗 token 如同成功的 post,但不推進任何下游狀態(NR/RES/OLA 不動)——設計給從不呼叫 post 的外部-post 變體,不是給逐 hop 混用。

延遲與 warm-up

  • 演算法延遲:1 hop(WOLA;實測 argmax 127 samples @hop=128 → 8 ms @16k 預設)。
  • delay acquisition:估計值要 solid 且 n_updates≥3 才被接受;開始新的可用 alignment generation 的那個 hop 回報 delay.changed=1——首次 acquisition、unlock 後同值重鎖、鎖定中值改變皆屬之(不只值改變;見 4aec_nr_res.h 的 FourAecNrResDelayState 契約),核心同時 reset 四條 lane 並清 mono OLA(外部 STFT/OLA 也應照 changed 清)。ring 未累積到 delay 樣本前 aligned_ref 前導為 0。
  • SRP/GSC warm-up:DOA smoother 需 doa_switch_consecutive=3 次一致觀測才切換;GSC RLS 由 vad_out 凍結(vad_out=1 → 凍結適應)。
  • NR 噪聲底 ~1.5 s wall-clock(retimed L)。
