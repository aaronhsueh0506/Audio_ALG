audio_pipeline_4ch — 4 mic 共用 delay + 4 條線性 AEC + SRP/BF(唯一包起來的單元;RES 由應用用 libaec 自備)

概要

兩層結構(pipelines/4ch_aec_bf_nr_res/),只有「多聲道線性 AEC + BF」被包成一個單元:

  • 核心 4aec_nr_res(FourAecNrRes):1 個共用 far aligner(delay_mode=MATCHED 時是 1 個 DelayAec matcher + 1 條共用 aligned render delay line;FIXED/EXTERNAL_ALIGNED 時 matcher count = 0,兩者都不 carve)→ 4 條獨立線性 AEC lane → 外部 beamformer 權重投影。每 hop 兩個呼叫:four_aec_front_process()(delay + 四條 lane,交出借用的 FourAecFront)與 four_aec_fuse()(用外部權重投影,填 SeSpecFrame)。RES、NR、CNG 與 iFFT 不在核心內(SeSpecFrame.g_res_ctx 恆為 NULL);直接驅動核心的範例自己建一個 AecRes。
  • 單元 audio_pipeline_4ch(AudioPipeline4Ch):把 SRP-PHAT DOA + BF(audiolib/doa、audiolib/bf)接進 four_aec_front_process() 與 four_aec_fuse() 之間,擁有它們的生命週期,並提供保守 energy-VAD fallback。輸出是 BF 後誤差頻譜與有效權重(AudioPipeline4ChBeam);audio_pipeline_4ch_fuse() 是獨立的可選步驟,填 SeSpecFrame 給後級。fuse() 與核心一樣讓 frame->g_res_ctx 為 NULL。單元內沒有 RES、NR、CNG、合成與神經後濾波(單元 pool 不含 AecRes)。RES 由 libaec 管理:要在單元之後做 RES 的應用在自己的 init 用 aec_res_get_mem_size()／aec_res_init() 建 AecRes(config 取 aec_config_from_preset(preset, sample_rate),fft_size 設成單元的格點),每 hop 以 se_res_stage_gain(res, &frame)(包 aec_res_process())取增益,強度 aec_res_set_preset(),重設 aec_res_reset()(沒有 destroy)。NR(AnrDenoiser)與合成(AcIstft)同為獨立函式庫物件,由應用初始化並明寫逐 hop 串接。mono 是例外:RES 增益在 aec_process_context() 內算(見 pipeline_mono)。

結構稽核值:*_matched_filter_count() 在 MATCHED 時 1、其餘 delay_mode 為 0;*_linear_aec_count() 恆 4(核心 four_aec_nr_res_*、單元 audio_pipeline_4ch_*)。Lane 0 每 hop 跑真 far-FFT,lane 1–3 經 aec_process_context_shared_far_from() 借用 lane 0 的 far 頻譜(4 次 far-FFT → 1 次,測試以 four_aec_nr_res_far_fft_real_compute_count() 證明)。支援 16 kHz(fft 256 預設 / 512 明示)與 48 kHz(fft 1024)。

Descriptor 慣例(32-byte 固定 ABI、init_ex 8 點閘)只存在於核心、單元與 DFN stage／bridge;AnrDenoiser、AcIstft 等函式庫物件只提供大小查詢。核心 FOUR_AEC_NR_RES_LAYOUT_VERSION=24、單元 AUDIO_PIPELINE_4CH_LAYOUT_VERSION=21,兩者 descriptor_version 皆 1;單元的 build_flags_hash 摺入核心的 hash。設定欄位分級、固定常數、函式清單、狀態碼與核心輸出契約(FourAecFront／SeSpecFrame)收在 pipeline_4ch_params。

如何呼叫使用

單元的呼叫順序(括號為失敗訊號):audio_pipeline_4ch_default_config(sr) → 視需要改欄位 → get_mem_requirements()(−1 = config 無效)→ 配置 req.bytes、req.alignment(16)的 pool → init_ex(pool, bytes, &cfg, &req)(NULL = descriptor 過期、pool 過小／未對齊、config 無效,靜默無診斷)→ 應用在自己的 init 為 RES、NR、合成各自查大小、init(另一塊 post pool)→ 每 hop process_front() → process_beam() → fuse() → se_res_stage_gain() → NR 增益 → 後級 → 任一步非 OK、RES／NR 增益為 NULL 或輸出非有限時 audio_pipeline_4ch_reset() 加上自己的 aec_res_reset()、anr_reset()、ac_istft_reset()、rng 一起重設 → destroy()(不釋放 caller pool)。descriptor 與大小都不可跨 build 快取。範例已在 -Wall -Wextra -Werror 下編譯檢查(platform_alloc()、stream_next4()、product_vad() 是平台／I/O 佔位)。

單元(含 SRP/BF)+ 自備 RES + NR + 合成

AudioPipeline4ChConfig cfg = audio_pipeline_4ch_default_config(16000);
/* 建立前可改 cfg 欄位(見 pipeline_4ch_params) */
AudioPipeline4ChMemReq req;
if (audio_pipeline_4ch_get_mem_requirements(&cfg, &req) != 0) return -1;      /* -1 = 無效 */
void* pool = platform_alloc(req.bytes, req.alignment);
AudioPipeline4Ch* p = audio_pipeline_4ch_init_ex(pool, req.bytes, &cfg, &req);
if (!p) return -1;                                          /* NULL = 拒絕, 無診斷輸出 */

/* RES(libaec)、NR、合成: 應用自己的 init, 另一塊 post pool, 格點取單元解析後的值 */
int fft = audio_pipeline_4ch_fft_size(p), nf = audio_pipeline_4ch_n_freqs(p), hop = audio_pipeline_4ch_hop_size(p);
AecConfig res_cfg;  aec_config_from_preset(&res_cfg, AEC_PRESET_BALANCED, cfg.core.sample_rate);
res_cfg.fft_size = fft;
AnrConfig nr_cfg = anr_config_for_mode_grid(cfg.core.sample_rate, fft, ANR_MODE_BALANCED);
AcStftConfig syn_cfg;  ac_stft_config_default(&syn_cfg, fft);
size_t res_b = aec_res_get_mem_size(&res_cfg), nr_b = anr_get_mem_size(&nr_cfg), syn_b = ac_istft_get_mem_size(&syn_cfg);
if (!res_b || !nr_b || !syn_b) return -1;                   /* 0 = 無效 */
size_t vec = ALIGN16(nf * sizeof(float)), cvec = ALIGN16(nf * sizeof(Complex));
uint8_t* post = platform_alloc(ALIGN16(res_b) + ALIGN16(nr_b) + ALIGN16(syn_b) + 2 * vec + cvec, 16);
AecRes* res = aec_res_init(post, res_b, &res_cfg);
AnrDenoiser* nr = anr_init(post + ALIGN16(res_b), nr_b, &nr_cfg);
AcIstft* istft = ac_istft_init(post + ALIGN16(res_b) + ALIGN16(nr_b), syn_b, &syn_cfg);
if (!res || !nr || !istft) return -1;
float* total_gain = (float*)(post + ALIGN16(res_b) + ALIGN16(nr_b) + ALIGN16(syn_b));
float* extra_noise = total_gain + vec / sizeof(float);
Complex* spec = (Complex*)(extra_noise + vec / sizeof(float));
uint32_t rng = SE_CNG_RNG_SEED;

const float *mics, *ref;  float out[512];
while (stream_next4(&mics, &ref, out)) {
    AudioPipeline4ChBeam beam;  AudioPipeline4ChFrameInfo info;  SeSpecFrame frame;
    int vad = product_vad(mics);                            /* 沒有產品 VAD 時改呼叫 audio_pipeline_4ch_process() (內建 energy VAD) */
    int rc = audio_pipeline_4ch_process_with_activity(p, mics, ref, vad, vad, NULL, &beam, &info);
    if (rc == FOUR_AEC_NR_RES_OK) rc = audio_pipeline_4ch_fuse(p, &frame);   /* 需要 core.enable_post=1; frame.g_res_ctx 為 NULL */
    if (rc == FOUR_AEC_NR_RES_OK) {
        const float* g_res = se_res_stage_gain(res, &frame);                  /* RES 在單元之外, 由應用呼叫; 被拒回 NULL */
        const float* g_nr = g_res ? se_anr_stage_gain(nr, &frame, extra_noise, 1) : NULL;
        if (!g_nr) rc = FOUR_AEC_NR_RES_DSP_ERROR;
        else {
            sk_min_f32(total_gain, g_nr, g_res, frame.n_freqs);
            sk_capply_gain_f32(spec, frame.e, total_gain, frame.n_freqs);
            if (frame.cn) aec_cng_fill(&rng, spec, frame.cn, g_res, g_nr, SE_CNG_NR_GAIN_FLOOR, frame.n_freqs);
            ac_istft_push(istft, spec, out);                                  /* 一次 iFFT/OLA */
            if (!se_hop_is_finite(out, hop)) rc = FOUR_AEC_NR_RES_DSP_ERROR;
        }
    }
    if (rc != FOUR_AEC_NR_RES_OK) {                         /* 任一步被拒或輸出非有限: 單元與後級一起 reset */
        audio_pipeline_4ch_reset(p);  aec_res_reset(res);  anr_reset(nr);  ac_istft_reset(istft);  rng = SE_CNG_RNG_SEED;
        memset(out, 0, (size_t)hop * sizeof(float));
    }
}
anr_destroy(nr);  audio_pipeline_4ch_destroy(p);            /* 不釋放 caller pool; AecRes 沒有 destroy */
platform_free(post);  platform_free(pool);

產品有 VAD 時用 process_with_activity()(如上);沒有則 audio_pipeline_4ch_process()(內建 energy VAD)。要由 lane 頻譜算 mask／VAD 時拆成 process_front(p, mics, ref, &front) → 在 front.linear_spectra 上算 mask → process_beam(p, &front, vad_raw, vad_out, mask, &beam, &info)。外部 NN 後級(如 ULCNet)用 core.enable_post=0 的單元:不呼叫 fuse,下一個 process_front() 直接接手。

只用核心 + 自備 beamformer 與 RES

產品的波束器在別處時,單元沒有「外部波束權重」入口(目前的能力缺口),要退回核心:four_aec_front_process() → 自己的 beamformer → four_aec_fuse(core, weights, NULL, &frame) → 自備 AecRes 的 se_res_stage_gain() → 同樣的後級。完整、已編譯檢查的範例在 pipeline_4ch_detail;可執行範例是 4aec_nr_res_static.c。

換用別的後級(例如 DFN2)。單元只交出 SeSpecFrame(frame.e 是估計用的 pre-RES 誤差頻譜,cn／r2 是同一次投影的 PSD);想插入神經後濾波的應用用自備 AecRes 的增益自己組 P = E · G_res (+ comfort noise),現成消費者是 pipeline_dfn_4ch。

強度屬於擁有 RES 與 NR 的那一層:RES 用自建 handle 的 aec_res_set_preset(res, preset, ramp_ms),NR 用 anr_set_mode(nr, mode);單元與核心沒有 setter,對四條 lane 重新指定 preset 是無效操作。呼叫表、回 −1 條件、ramp 與逐階段耗時診斷(four_aec_nr_res_get_last_timing()／audio_pipeline_4ch_last_core_timing())收在 pipeline_4ch_detail。

延遲與 warm-up

  • 演算法延遲:1 hop(WOLA;實測 argmax 127 samples @hop=128 → 8 ms @16k 預設)。
  • delay acquisition:估計值要 solid 且 n_updates≥3 才被接受;開始新的可用 alignment generation 的那個 hop 回報 delay.changed=1——首次 acquisition、unlock 後同值重鎖、鎖定中值改變皆屬之(見 4aec_nr_res.h 的 FourAecNrResDelayState 契約),核心對四條 lane 做 aec_apply_external_realign()(濾波器依 delay 差位移,不重置、不清合成 OLA);外部 beamformer 若自帶 STFT/OLA 狀態,應照 changed 清除。ring 未累積到 delay 樣本前 aligned_ref 為 raw ref。
  • SRP/BF warm-up:DOA 平滑值為 NaN(尚無可用 DOA)時 BF 旁路取 mic 0 且不適應;DOA smoother 需 doa_switch_consecutive=3 次一致觀測才切換;BF RLS 由 vad_out 凍結(vad_out=1 → 凍結適應)。
  • NR 噪聲底的最小值追蹤視窗是函式庫預設的 wall-clock 約 512 ms。
