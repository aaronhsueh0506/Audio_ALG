AINR DeepFilterNet2 細節 — 記憶體與所有權、加速器 callback 邊界、建置

概要

本頁收 ainr_dfn2 的 dfn2_prepost 類別中會把單頁撐過 30 KB 的細節:pool 大小與所有權、DFN2Model callback 邊界與 descriptor、libainr_prepost.a 的建置、lookahead pair 的規則,以及 skip identity 所依賴的 partition-of-unity 檢查。API 用法、其餘 transaction 規則、頻譜尺度警告、block diagram、泳道圖、I/O 表、State 表、延遲與檔案清單仍留在原頁。

記憶體與所有權

io_modepool(get_mem_size,出貨 pair)說明
DFN2_IO_TIME246,320 byteshop 進、hop 出;framing/window/OLA 由本類別做(pool 內一個 AcStft 與一個 AcIstft),transform 呼叫呼叫端的 FftHandle
DFN2_IO_FREQ219,536 bytes頻譜進、頻譜出,不做 transform,不 carve 任何 framing 物件;fft 可為 NULL
  • FREQ 比 TIME 小 26,784 bytes:DFN2State 不內嵌 analysis/window/synthesis 緩衝 與 scratch,TIME 的 AcStft（16,480 B,含窗表）與 AcIstft（12,384 B,借用窗表）只在 TIME carve;FREQ 多 carve 雙輸入的第二組 staging (app_re/app_im)。io_mode 是 pool 的身分,init-time 固定,由 _init_ex 檢查。
  • DFN2_PREPOST_CARVE_VERSION = 7(dfn2_prepost.h):carve 走訪順序的版本, 摺進 build_flags_hash,所以其他 carve 版本的 pool 會在 hash 被拒。pool 內容：遞迴 state 為 5 列 h_gru 與 5 幀 pathway window(graph layout 8)；STFT／ISTFT 物件借用呼叫端的 FftHandle 與視窗表。任何 pool 大小、切分順序或 descriptor 內容的變更都會 bump 這個版本。
  • 遞迴 state:只有就地綁定:兩個 state tensor(h_gru (1,5,1,256) 與 df_convp_history (1,64,5,96), 共 32,000 float = 128,000 bytes)各只有一份 buffer、位址固定;每個 state 的輸入與 *_out 輸出 shape 完全相同並綁到同一個位址, 下一次呼叫的輸入就是這次的輸出,沒有第二份 buffer 也沒有複製。runtime 必須先讀完所有 state 輸入、才寫同位址的輸出 (目標平台已確認 NPU 先讀完所有輸入再寫輸出)。DFN2PrepostOutputs 的 *_next 指標就是輸入的同一個位址。
  • ERB 特徵與 mask 展開只走矩陣的非零範圍:dfn2_set_erb_matrices() 依矩陣內容記下每個 bin／band 的非零區間 (DFN2State.erb_fwd_lo/hi、erb_inv_lo/hi,以及正向矩陣每個 band 的 bin 範圍 erb_fwd_k0/k1),出貨矩陣 16,416 格只有 995 格非零。被略過的項都是「有限值 × ±0」, 累加器從 +0 開始、加 ±0 不改變任何值(含 Inf/NaN),保留的項順序不變,所以結果與完整矩陣乘法逐位元相同; 某個 bin 的 power 或某個 band 的 gain 非有限時(x × 0 會是 NaN),只有那一列走完整範圍。 power 全有限時正向和依 erb_fwd_k0/k1 逐 band 算(相鄰四個 band 並行、暫存器累加,band 內仍是 bin 遞增順序,逐位元不變)，任何 power 非有限時退回逐 bin 走法。 dfn2_state_init() 之後矩陣為 NULL、範圍為完整。就地改寫矩陣內容後必須再呼叫一次 set_erb_matrices; 回歸測試 AINR/tests/test_c_prepost.c 的 test_dfn_erb_spans_exact 逐位元比對稀疏與完整兩種算法(含溢位、NaN、非有限 mask、含 NaN 的矩陣)。
  • window 是借用的:cfg.window 非 NULL 時,分析與合成物件都借用它(須與物件同壽命、內容不變); NULL 時由分析物件在 pool 內自帶 sqrt-Hann 表、合成物件借用同一張。出貨路徑一律留 NULL。
  • FftHandle 與 ERB 矩陣是借用的,從不建立或銷毀。ERB 矩陣兩個模式都必填,fft 只有 TIME 需要。
  • 32-byte DFN2PrepostMemReq 七欄:descriptor_version(=1)、layout_version (DFN2_MODEL_IO_LAYOUT_VERSION)、io_mode、build_flags_hash (FNV-1a-32 蓋 grid + geometry + feature version + io_mode)、alignment(16)、reserved、bytes。

加速器 callback 邊界:DFN2Model

host 不擁有 runtime,只擁有四個指標;邊界放在 prepost 而非 dfn2_process.h,因為 dfn2_process.c 必須能單獨編給 parity build。

typedef struct DFN2Model {
    void *user;
    int (*infer)(void *user, const DFN2PrepostInputs *inputs,
                 DFN2PrepostOutputs *outputs);   /* 回 0 = 每個輸出都寫了 */
    void (*reset)(void *user);                   /* 可選;hosting stage reset 時呼叫 */
    const DFN2ModelIoDescriptor *io_descriptor;  /* NULL = 未發布 */
} DFN2Model;

int dfn2_model_run_frame(const DFN2Model *model, DFN2Prepost *p);

dfn2_model_run_frame()(io_descriptor 為 NULL 或不通過 dfn2_model_io_descriptor_validate() 時回 -1,且不呼叫 infer())把一個已開啟的 frame 走完:frame_inputs()(head 預填 NaN)→ infer() → frame_commit();infer() 回非 0 或 commit 被拒時改走 frame_skip(), 所以 framing 與 compose 兩個時鐘永遠恰好前進一次。有限性規則不在這裡重寫一份——那是 frame_commit() 的責任。回 1 = heads 已 commit、0 = 該幀被 skip、-1 = 契約錯誤(model/instance 為 NULL、 沒有 infer、或沒有開啟中的 frame)。與 AIAEC 的 identity 政策不同:被 skip 的幀仍然吐出 M+D 拍前的 source frame ——identity 是在 cascade 內部套用的,時序從不改變。

有 infer 就必須發布 descriptor。DFN2ModelIoDescriptor是 19 個欄位的圖合約:layout_version、sample_rate、fft_size、hop_size、 spectrum_bins、erb_bands、df_bins、df_order、mask_lookahead、 df_lookahead、input_frames、encoder_gru_layers、erb_gru_layers、 df_gru_layers、gru_hidden、encoder_channels、df_pathway_window(=5)、 state_tensor_count(=2)、frames_per_call(=DFN2_FRAMES_PER_CALL,出貨 1)。input_frames = DFN2_MODEL_WINDOW_FRAMES = N+2(出貨 3)。_descriptor_default() 填本 build 的值,_descriptor_validate() 逐欄位比對(不是 memcmp,padding 不得參與決定),不合即 -1。欄位全是編譯期常數(沒有 Align-ULCNet delay_depth 那種部署自由度),所以 validate(default())==0 恆真,它唯一的工作是擋掉對著另一個 layout 版本或另一組幾何匯出的圖——那正是 NaN 預填看不見的一類錯誤(抓得到「沒寫」,抓不到「形狀不對」)。

實際消費者:pipelines/dfn/dfn_res_stage.c。它在 get_mem_requirements() 就把 「有 infer 卻沒 descriptor」「descriptor 被 validate() 拒絕」「有 reset／descriptor 卻沒 infer」三種組合一併拒掉,再由 mono 與 4ch 兩支 DFN2 pipeline 使用;它們走的是雙輸入入口(估計用 pre-RES 頻譜、 套用在 post-RES 頻譜)。

Lookahead pair(M／D)

DFN2 與 DFN3 各有兩個互相獨立的 lookahead:mask_lookahead M(0..2)與 df_lookahead D(0..df_order−1 = 4),共 15 個合法 pair,M 與 D 之間沒有大小限制(config.ini [model])。pair 是模型合約:checkpoint 屬於一個 pair,另一個 pair 的 checkpoint 不會被載入。出貨的是 1/1,也是唯一有訓練好的 checkpoint 的 pair;其他 pair 的音質未量測。規則的完整敘述與匯出面在 AINR/README.md「Lookahead pairs」。

項目DFN2(cascade)DFN3(平行)
匯出的 ONNX graph與 pair 無關;匯出 metadata 帶 mask_lookahead、df_lookahead 與視窗對齊(input_window_alignment)
host 視窗與就緒heads[t] 的視窗是 [t-(2-M)..t+M](串流起點之前補零);已推入 M+1 幀(*_MODEL_READY_FRAMES)才有第一組 heads
DF 視窗[t-(4-D)..t+D]
輸出延遲(framing 之外)M+D hops(相加)max(M, D) hops
ring 深度DFN2_DF_RING = max(DF_ORDER, M+D+1);出貨 5,2/4 為 7DFN3_DF_RING = DF_ORDER + max(M,D) − D
C 建置-DDFN2_MASK_LOOKAHEAD=<M> -DDFN2_DF_LOOKAHEAD=<D>-DDFN3_MASK_LOOKAHEAD=<M> -DDFN3_DF_LOOKAHEAD=<D>
pair 符號dfn2_lookahead_mask<M>_df<D>／dfn3_lookahead_mask<M>_df<D>:由 *_process.c 定義,依賴 pair 的單元引用它,所以不同 pair 的目標檔連結失敗
  • 預設 1／1,旗標值須是單純十進位數,且要加在每一個編譯單元;範圍外的 pair 是前處理器 #error(gnu99 與 C++ 下也一樣)。另一個 pair 的 graph descriptor 或 pool 在執行期被 descriptor 驗證與 pool hash 擋下。
  • make -C AINR lib、test、test-simd 建的是出貨 pair。其他 pair:make -C AINR test-pairs(pytest,逐 pair 重建 C 端並檢查連結與編譯期守衛)。Python 側(匯出、重播、校準、離線推論)對 15 個 pair 都跑;C 端只建置、執行其中一部分 pair(清單見 AINR/README.md),不宣稱 15 組都跑過。
  • pipelines 的 stage 與 rate bridge 在這個 pair 之上的延遲與 make 變數見 pipeline_dfn_detail。板端:pair 不是 1/1 時,dfn2_process.c、dfn2_model_io.c、dfn2_prepost.c 與每個 include 它們標頭的單元都要帶同一組 -D。

每次 invocation N 個 frame(DFN2_FRAMES_PER_CALL)

出貨預設是每次 invocation 一個 frame(輸入 t-(2-M)..t+M 共 3 個 feature frame,輸出 frame t 的 heads)。export_onnx.py --frames-per-call N 可匯出一次吃 N+2 個 feature frame、一次輸出 N 個 frame heads 的 graph;適合每次呼叫加速器的固定成本高於多等 N-1 hop 的平台。下表是 DFN2 專屬,DFN3、GTCRN、RNNoise-ERB 沒有這個選項。

項目N = 1(出貨)N > 1
erb／spec 輸入(1,1,3,32)／(1,2,3,96)(1,1,N+2,32)／(1,2,N+2,96);frames [t-(2-M) .. t+N-1+M]
erb_mask／df_coefs／df_alphaframe t 的 headsframe t .. t+N-1 的 heads,舊的在前;head i 讀視窗內從槽位 i 起的 3 個 frame,與 N=1 時 frame t+i 的視窗相同
GRU state h_gru(1,5,1,256)形狀不變;三組 GRU(encoder 1 層、ERB decoder 2 層、DF decoder 2 層)把 N 個 frame 當一條序列跑,GRU node 仍是 5 個;h_gru_out 是最後一個 frame 之後的 hidden state,下次呼叫原樣餵回
卷積 state df_convp_history(1,64,5,96)形狀不變;輸出是 pathway 輸入的最後 5 個 frame:N<5 為「保留的舊 history 加新 frame」的 Concat,N=5 為新 frame,N>5 時最後 5 個 frame 的 DF 輸入卷積由 spec 視窗的對應切片單獨算出(state 輸出不能由 Slice 產生,見 in-place 規則)
metadata沒有新 keyframes_per_call、chunk_window_alignment;input_feature_frames = N+2、output_frames_per_invocation = N;onnx_streaming_contract.validate_frames_per_call 拒絕 metadata 與 shape 不符的 graph,也拒絕記錄了 frames_per_call 的單 frame graph
  • N=1 與以前同一個 graph。不帶旗標或 --frames-per-call 1 寫出的 ONNX／JSON 與加入此選項前相同(固定同一個 PYTHONHASHSEED 比對過種子 0..3;匯出器的 optimizer pass 順序取自 set,不固定種子時兩次匯出的 ONNX 位元組本來就會不同,這在加入選項前就存在)。inference.py calib --frames-per-call N 讓校正資料的 tensor 形狀對應 N-frame graph(--frames 計 invocation 數)。
  • C host。建置帶 -DDFN2_FRAMES_PER_CALL=<N>(1..64,單純十進位,每個編譯單元;AINR Makefile 變數 DFN2_FRAMES_PER_CALL)。視窗為 N+2 個 frame;第一次呼叫在推入 M+N 個 frame 後就緒,之後每推 N 個一次(pre_process 在第 M+N-1、M+2N-1…拍回 1);dfn2_model_io_frame_slot() 回「最近推入的 frame 完成的是下次呼叫的第幾個 head」(0..N-1;還沒有 head 時 -1)。frame_inputs() 一次發布 N 個 head,frame_commit() 一次把 N 個 frame 合成起來,post_process 仍每次回一個 hop。
  • 延遲多 N-1 hop。輸出落後輸入 1 + M + D + N - 1 hops(DFN2_PREPOST_LATENCY_FRAMES = M+D+N-1,dfn2_prepost_model_lookahead_frames() 回這個值;written = 0 的暖機拍數也是這個值)。出貨 pair 配 N=8 為 10 hops = 106.7 ms。flush 要持續推零 hop 並執行加速器,直到最後一個真實 hop 被吐出。commit 被拒時就地歸零一次 state,並把 N 個 frame 都走 identity。
  • 編譯期守衛。N 不在 1..64 是 #error(C11、gnu99、C++ 皆然);不同 N 的目標檔連結失敗(符號 dfn2_frames_per_call<N>);為一個 frame 寫的單元對 N>1 編譯失敗,除非它在包含標頭前定義 DFN2_MULTI_FRAME_HOST。N>1 折進 pool hash(另一個 N 的 pool 被拒);N=1 時 pool 大小與 hash 不變。descriptor 多一個 frames_per_call,dfn2_model_io_descriptor_validate() 與 dfn2_model_run_frame() 拒絕不同的 N。
  • 版號不變。DFN2_MODEL_IO_LAYOUT_VERSION 仍是 8(它命名 state tensor,N 不改變它們;N 由 descriptor 與 metadata 攜帶),DFN2_PREPOST_CARVE_VERSION 仍是 7(N=1 的切分相同,N>1 的 pool 以 hash 區分)。
  • pipelines 固定 N=1。pipelines/dfn 的 stage 與 rate bridge 以及 dfn2_stage.py 都是一個 frame 的單元;對它們帶 -DDFN2_FRAMES_PER_CALL>1 會停在 DFN2_MULTI_FRAME_HOST 的 #error。make -C AINR lib 可為任一 N 建置,test／test-simd 的驅動是一個 frame 的單元,只在 N=1 建置。
  • 尚未量測。目標平台工具鏈對 seq_len>1 的 GRU 的支援、N-frame graph 的量化精度,沒有量過;等價性只用隨機初始化模型與替身加速器證明(N-frame graph 分塊串流等於一個 frame graph 逐 frame 串流,torch 與 ONNX Runtime 數值一致)。N>5 時 c0(餵給下一層卷積)是兩段分別算出的 tensor 的 Concat,量化工具可能給兩個 scale。N>1 時 compose 在 commit 才跑,所以 set_atten_lim 與反向 ERB 矩陣的更換對下一次 commit 的 N 個 frame 一併生效,包含更換之前就已推入的 frame。

測試:AINR/tests/test_dfn2_frames_per_call.py(torch 與 ONNX Runtime 分塊串流對拍一個 frame graph、錯誤的 state 搬運會失敗、metadata 與 validator、校正)與 test_dfn2_frames_per_call_c.py(C host 對一個 frame host 逐位元組比對、reset、拒絕路徑、編譯與連結守衛),兩者都在 make -C AINR test-pairs。完整說明在 AINR/DeepFilterNet2/README.md「Multi-frame export」。

建置

skip identity 的 partition of unity 檢查

  • skip 是精確的 identity,不是近似:erb_inv 是 partition of unity (每個 bin 的 band 權重和為 1),unit band mask 展開後就是 unit bin gain,noisy 頻譜原樣穿過 cascade。 兩條匯出路徑都會擋:一般路徑查 inverse_unity_max_error(1e-6),--runtime-bins 在寫檔前呼叫 require_partition_of_unity()——照 df_common_expand_mask 的順序逐 band 以 float32 累加後逐位元比對 1.0f(export_erb_matrix.py)。C 側 host (pipelines/dfn/dfn_res_stage.c)在 get_mem_requirements() 再驗一次,所以載到一份 不是 partition of unity 的 erb_inv.bin 會被 init 擋下,而不是讓 identity 悄悄變成近似。
