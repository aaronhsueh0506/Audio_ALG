AINR DeepFilterNet2 細節 — 記憶體與所有權、加速器 callback 邊界、建置

概要

本頁收 ainr_dfn2 的 dfn2_prepost 類別中會把單頁撐過 30 KB 的細節:pool 與所有權、setter 的保證邊界、DFN2Model callback 邊界與 descriptor、遞迴 state 的圖邊界、lookahead pair 與每次 invocation N 個 frame 的規則、libainr_prepost.a 的建置,以及 bypass identity 所依賴的 partition-of-unity 檢查。API 用法、其餘 transaction 規則、頻譜尺度警告、block diagram、泳道圖、I/O 表、State 表、延遲與檔案清單仍留在原頁。

  • 遞迴 state:登錄或不登錄,只有就地綁定:兩個 state tensor(h_gru (1,5,1,256) 與 df_convp_history (1,64,5,96), 共 32,000 float = 128,000 bytes)各只有一份 buffer、位址固定。浮點 host 把它們登錄在 DFN2PrepostConfig(gru_hidden／df_convp_history 與各自的 *_elements;四欄全設或全空,指標配 0 個元素、元素數配 NULL 都被拒,-DDFN2_MASK_ONLY 只有 h_gru 一對):函式庫在 init 與 reset 歸零、每次 frame_finish 檢查有限、被拒時歸零,並把同一個位址交給加速器。板端不登錄(四欄 NULL／0):加速器持有 state,函式庫只計 state generation。登錄的 buffer 不在 pool 大小與 build_flags_hash 內,須與 pool 同壽命。 每個 state 的輸入與 *_out 輸出 shape 完全相同並綁到同一個位址,下一次呼叫的輸入就是這次的輸出,沒有第二份 buffer 也沒有複製。runtime 必須先讀完所有 state 輸入、才寫同位址的輸出 (目標平台已確認 NPU 先讀完所有輸入再寫輸出)。DFN2PrepostOutputs 的 *_next 指標就是輸入的同一個位址。
  • ERB 特徵與 mask 展開只走矩陣的非零範圍:dfn2_set_erb_matrices() 依矩陣內容記下每個 bin／band 的非零區間 (DFN2State.erb_fwd_lo/hi、erb_inv_lo/hi,以及正向矩陣每個 band 的 bin 範圍 erb_fwd_k0/k1),出貨矩陣 16,416 格正反向各只有 995 格非零(model.py 的 _build_erb_fb(1024, 48000, 32) 量測)。被略過的項都是「有限值 × ±0」, 累加器從 +0 開始、加 ±0 不改變任何值(含 Inf/NaN),保留的項順序不變,所以結果與完整矩陣乘法逐位元相同; 某個 bin 的 power 或某個 band 的 gain 非有限時(x × 0 會是 NaN),只有那一列走完整範圍。 power 全有限時正向和依 erb_fwd_k0/k1 逐 band 算(相鄰四個 band 並行、暫存器累加,band 內仍是 bin 遞增順序,逐位元不變)，任何 power 非有限時退回逐 bin 走法。 dfn2_state_init() 之後矩陣為 NULL、範圍為完整。就地改寫矩陣內容後必須再呼叫一次 set_erb_matrices; 回歸測試 AINR/tests/test_c_prepost.c 的 test_dfn_erb_spans_exact 逐位元比對稀疏與完整兩種算法(含溢位、NaN、非有限 mask、含 NaN 的矩陣)。
  • 框化是應用端的:窗、FFT 與 STFT 物件都不在函式庫內,窗與尺度的契約寫在 dfn2_process.h 檔頭(見 ainr_dfn2);ERB 矩陣是借用的,從不建立或銷毀。
  • 32-byte DFN2PrepostMemReq 七欄:descriptor_version(=1)、layout_version (DFN2_MODEL_IO_LAYOUT_VERSION)、reserved0(必須為 0,_init_ex 拒絕其他值)、build_flags_hash (FNV-1a-32 蓋整個 grid(含 df_order、兩個 lookahead、frames_per_call、input_frames、兩個時間常數與 alpha、兩個 scale、四個正規化起點與 erb_norm_scale_db)、variant、layout 與 carve 版號、feature version)、alignment(16)、reserved、bytes。

Setter 的保證邊界

_set_erb_matrices()(換另一組 ERB 矩陣,borrowed 不複製)與 _set_atten_lim() 都是 hop 之間限定:frame 開著時回 -1,換手不會落在同一筆交易中間。

這買到的是 per-hop atomicity,不是 per-source-frame consistency:hop t 展開的 mask 屬於 source frame t−1、特徵視窗又橫跨三拍,一次被接受的換手仍會有幾拍同時踩到新舊矩陣。 要 per-source-frame 一致就先 reset 再換。

遞迴 state 的圖邊界

  • h_gru (1,5,1,256):五列 GRU hidden——encoder 第 0 列、ERB decoder 第 1–2 列、DF decoder 第 3–4 列(圖的合約;列序與形狀常數由應用端定義,函式庫不含)。每顆 GRU 用輸入上dim 1 的 Slice取自己的列再 squeeze 成 nn.GRU 的 (layers,1,hidden),下一個 state 以一個 Concat(dim 1)接回;ONNX 沒有 stacked GRU op,兩層的 stack 仍是兩個 GRU node,共 5 個 GRU node。 三顆 GRU 共用同一個輸入 tensor,因此共用同一個量化 scale(inference.py calib 的 gru_state_slices 報告每顆 GRU 在共用 max-abs int8 scale 下損失的位元數)。
  • df_convp_history (1,64,5,96):pathway 卷積(kernel 5)的完整因果 window。圖在輸入上做一個 Slice(axes=[2]、starts=[1]、ends=[5]、step 1,end 是明確整數)丟掉最舊一幀, 接上新的一幀,卷積,並把整個 5 幀 Concat 結果當作 df_convp_history_out。輸入只有這一個 consumer,沒有任何 state 輸出由 Slice 產生。

AINR/onnx_streaming_contract.py 的 validate_inplace_state_graph() 把上述條件逐條檢查(兩支 exporter 匯出時呼叫), AINR/check_state_quantization.py 可在量化後對圖與量化報告再檢查一次:state 輸入與輸出的 dtype／scale／zero point／shape 任一不同就中止。 版本 4–7 已退役(RETIRED_LAYOUT_VERSIONS),合約測試擋下誤 bump。int8 下 window 一列 96 byte,axis-2 Slice 起於第 1 列,對齊由量化工具鏈決定,尚未在板上驗證。

加速器 callback 邊界:DFN2Model

host 不擁有 runtime,只擁有四個指標;邊界放在 prepost 而非 dfn2_process.h,因為 dfn2_process.c 必須能單獨編給 parity build。

typedef struct DFN2Model {
    void *user;
    int (*infer)(void *user, const DFN2PrepostInputs *inputs,
                 DFN2PrepostOutputs *outputs);   /* 回 0 = 每個輸出都寫了 */
    void (*reset)(void *user);                   /* 可選;hosting stage reset 時呼叫 */
    const DFN2ModelIoDescriptor *io_descriptor;  /* NULL = 未發布 */
} DFN2Model;

int dfn2_model_run_frame(const DFN2Model *model, DFN2Prepost *p);

dfn2_model_run_frame()(io_descriptor 為 NULL 或不通過 dfn2_model_io_descriptor_validate() 時回 -1,且不呼叫 infer())把一個已開啟的 frame 走完:frame_open()(head 預填 NaN)→ infer() → frame_finish();infer() 回非 0 或 finish 被拒時改走 frame_bypass(), 所以 framing 與合成兩個時鐘永遠恰好前進一次(N=1 的暖機幀上 infer() 成功也回 1,雖然它的 heads 被丟棄)。有限性規則不在這裡重寫一份——那是 frame_finish() 的責任。回 1 = heads 已 commit、0 = 該幀被 bypass、-1 = 契約錯誤(model/instance 為 NULL、 沒有 infer、或沒有開啟中的 frame)。與 AIAEC 的 identity 政策不同:被 bypass 的幀仍然吐出 M+D 拍前的 source frame ——identity 是在 cascade 內部套用的,時序從不改變。

有 infer 就必須發布 descriptor。DFN2ModelIoDescriptor是 18 個欄位(72 bytes)的圖合約,分兩組。12 個外部欄位:layout_version、sample_rate、fft_size、hop_size、 spectrum_bins、erb_bands、df_bins、df_order、mask_lookahead、 df_lookahead、input_frames、state_tensor_count(2;mask-only 為 1)。6 個內部欄位:encoder_gru_layers、erb_gru_layers、 df_gru_layers、gru_hidden、encoder_channels、df_pathway_window——應用端記帳用,_descriptor_default 填 0、validate 不讀。input_frames = grid.input_frames = N+2(N=1 時 3),N 由 input_frames - 2 得出,descriptor 沒有另外的 N 欄位。_descriptor_default(grid, &d) 填外部欄位,_descriptor_validate(grid, &d) 逐欄位比對外部欄位(不是 memcmp,padding 不得參與決定),不合即 -1(grid 無效也是 -1)。幾何與兩個 lookahead 取自傳入的 grid,layout_version 與 state_tensor_count 是本 build 的常數,所以 validate(grid, default(grid))==0 恆真,它的工作是擋掉對著另一個 layout 版本、另一組幾何或另一個 lookahead pair 匯出的圖——那正是 NaN 預填看不見的一類錯誤(抓得到「沒寫」,抓不到「形狀不對」)。

實際消費者:pipelines/dfn/dfn_res_stage.c。它在 get_mem_requirements() 就把 「有 infer 卻沒 descriptor」「descriptor 被 validate() 拒絕」「有 reset／descriptor 卻沒 infer」三種組合一併拒掉,再由 mono 與 4ch 兩支 DFN2 pipeline 使用;它們走的是雙輸入入口(估計用 pre-RES 頻譜、 套用在 post-RES 頻譜)。

Lookahead pair(M／D)

DFN2 與 DFN3 各有兩個互相獨立的 lookahead:mask_lookahead M(0..2)與 df_lookahead D(0..df_order−1 = 4),共 15 個合法 pair,M 與 D 之間沒有大小限制(config.ini [model])。pair 是模型合約:checkpoint 屬於一個 pair,另一個 pair 的 checkpoint 不會被載入。出貨的是 1/1,也是唯一有訓練好的 checkpoint 的 pair;其他 pair 的音質未量測。規則的完整敘述與匯出面在 AINR/README.md「Lookahead pairs」。兩者的 pair 都是 grid spec 的兩個欄位(DFN2GridSpec／DFN3GridSpec 的 mask_lookahead、df_lookahead),執行期給定,不是建置設定。

項目DFN2(cascade)DFN3(平行)
匯出的 ONNX graph與 pair 無關;匯出 metadata 帶 mask_lookahead、df_lookahead 與視窗對齊(input_window_alignment)
host 視窗與就緒heads[t] 的視窗是 [t-(2-M)..t+M](串流起點之前補零);第一組 heads 要 dfn2_model_io_ready_frames() = M + N 幀(N = 1:M+1)同一視窗;已推入 M+1 幀(dfn3_model_io_ready_frames())才有第一組 heads

  • pipelines 的 stage 與 rate bridge 在這個 pair 之上的延遲與 make 變數見 pipeline_dfn_detail。板端:grid 與 pair 由 sample 的表給定。

每次 invocation N 個 frame(frames_per_call)

出貨預設是每次 invocation 一個 frame(輸入 t-(2-M)..t+M 共 3 個 feature frame,輸出 frame t 的 heads)。export_onnx.py --frames-per-call N 可匯出一次吃 N+2 個 feature frame、一次輸出 N 個 frame heads 的 graph;適合每次呼叫加速器的固定成本高於多等 N-1 hop 的平台。下表是 DFN2 專屬,DFN3、GTCRN、RNNoise-ERB 沒有這個選項。

項目N = 1(出貨)N > 1
erb／spec 輸入(1,1,3,32)／(1,2,3,96)(1,1,N+2,32)／(1,2,N+2,96);frames [t-(2-M) .. t+N-1+M]
erb_mask／df_coefs／df_alphaframe t 的 headsframe t .. t+N-1 的 heads,舊的在前;head i 讀視窗內從槽位 i 起的 3 個 frame,與 N=1 時 frame t+i 的視窗相同
GRU state h_gru(1,5,1,256)形狀不變;三組 GRU(encoder 1 層、ERB decoder 2 層、DF decoder 2 層)把 N 個 frame 當一條序列跑,GRU node 仍是 5 個;h_gru_out 是最後一個 frame 之後的 hidden state,下次呼叫原樣餵回
卷積 state df_convp_history(1,64,5,96)形狀不變;輸出是 pathway 輸入的最後 5 個 frame:N<5 為「保留的舊 history 加新 frame」的 Concat,N=5 為新 frame,N>5 時最後 5 個 frame 的 DF 輸入卷積由 spec 視窗的對應切片單獨算出(state 輸出不能由 Slice 產生,見 in-place 規則)
metadata沒有新 keyframes_per_call、chunk_window_alignment;input_feature_frames = N+2、output_frames_per_invocation = N;onnx_streaming_contract.validate_frames_per_call 拒絕 metadata 與 shape 不符的 graph,也拒絕記錄了 frames_per_call 的單 frame graph
  • N=1 與以前同一個 graph。不帶旗標或 --frames-per-call 1 寫出的 ONNX／JSON 與加入此選項前相同(固定同一個 PYTHONHASHSEED 比對過種子 0..3;匯出器的 optimizer pass 順序取自 set,不固定種子時兩次匯出的 ONNX 位元組本來就會不同,這在加入選項前就存在)。inference.py calib --frames-per-call N 讓校正資料的 tensor 形狀對應 N-frame graph(--frames 計 invocation 數)。
  • C host。N 是 DFN2GridSpec.frames_per_call(1..DFN2_MODEL_MAX_FRAMES_PER_CALL = 64,執行期欄位,範圍外回 DFN2_GRID_ERR_FRAMES_PER_CALL)。視窗為 N+2 個 frame;第一次呼叫在推入 M+N 個 frame 後就緒,之後每推 N 個一次(pre_process_freq 在第 M+N-1、M+2N-1…拍回 1);dfn2_model_io_frame_slot() 回「最近推入的 frame 完成的是下次呼叫的第幾個 head」(0..N-1;還沒有 head 時 -1)。frame_open() 一次發布 N 個 head,frame_finish() 一次把 N 個 frame 合成起來,post_process_freq 仍每次回一個 hop。
  • 只有 N=1 才每拍回 1。N>1 沒有暖機幀:pre_process_freq 照上面回 0 或 1,frame_open()、加速器與 frame_finish() 只在回 1 之後呼叫;N=1 且 M≥1 時每拍回 1,前 M 拍是暖機幀(heads 丟棄、state 歸零、generation 加 1,見 ainr_dfn2)。
  • 延遲多 N-1 hop。輸出落後輸入 1 + M + D + N - 1 hops(dfn2_prepost_latency_frames(grid) = M+D+N-1,dfn2_prepost_model_lookahead_frames() 回這個值;valid = 0 的暖機拍數也是這個值)。出貨 pair 配 N=8 為 10 hops = 106.7 ms。flush 要持續推零 hop 並執行加速器,直到最後一個真實 hop 被吐出。finish 被拒時登錄的 state 就地歸零一次,並把 N 個 frame 都走 identity。
  • N 在 grid、pool 與 descriptor 裡。N 折進 pool 大小與 build_flags_hash(另一個 N 的 pool 被 _init_ex 拒)。descriptor 不加欄位、大小維持 72 bytes:N 由 input_frames(= N+2)攜帶,dfn2_model_io_descriptor_validate() 與 dfn2_model_run_frame() 拒絕不同的 N;依一個 frame 的 grid 描述的 adapter(input_frames = 3)被 N>1 的 grid 拒絕。DFN2_MODEL_IO_LAYOUT_VERSION 仍是 8(它命名 state tensor,N 不改變它們)。
  • pipelines 固定 N=1。pipelines/dfn 的 stage(以及其上的 rate bridge)拒絕 grid.frames_per_call != 1;make test／test-simd 的驅動跑 N=1。
  • 尚未量測。目標平台工具鏈對 seq_len>1 的 GRU 的支援、N-frame graph 的量化精度,沒有量過;等價性只用隨機初始化模型與替身加速器證明(N-frame graph 分塊串流等於一個 frame graph 逐 frame 串流,torch 與 ONNX Runtime 數值一致)。N>5 時 c0(餵給下一層卷積)是兩段分別算出的 tensor 的 Concat,量化工具可能給兩個 scale。N>1 時合成在 finish 才跑,所以 set_atten_lim 與反向 ERB 矩陣的更換對下一次 finish 的 N 個 frame 一併生效,包含更換之前就已推入的 frame。

測試:AINR/tests/test_dfn2_frames_per_call.py(torch 與 ONNX Runtime 分塊串流對拍一個 frame graph、錯誤的 state 搬運會失敗、metadata 與 validator、校正)與 test_dfn2_frames_per_call_c.py(C host 對一個 frame host 逐位元組比對、reset、拒絕路徑、descriptor 與 pool 的拒絕、72-byte ABI),兩者都在 make -C AINR test-pairs。完整說明在 AINR/DeepFilterNet2/README.md「Multi-frame export」。

  • grid、pair 與 N 都不是建置選項:archive 與它們無關,應用端以 dfn2_grid_make() 在執行期給定。建置只決定 variant:-DDFN2_MASK_ONLY 要加在每一個編譯單元(make -C AINR lib 建完整版),不同 variant 的目標檔連結失敗(符號 dfn2_variant_{full|mask_only})。完整規則、各 grid 的大小與限制見 ainr_dfn2_grids。
  • 兩支 DFN2 pipeline不連這個 archive:pipelines/Makefile 直接把三個 DFN2 TU 編進 libaudio_pipeline_dfn.a（pipelines/ 建置）或 libdfn_res_stage.a（4ch_aec_bf_nr_res/ 建置）。

bypass identity 的 partition of unity 檢查

  • bypass 是精確的 identity,不是近似:erb_inv 是 partition of unity (每個 bin 的 band 權重和為 1),unit band mask 展開後就是 unit bin gain,noisy 頻譜原樣穿過 cascade。 匯出時檢查:export_erb_matrix.py 的 --runtime-bins 在寫檔前、一般輸出在寫檔後呼叫 require_partition_of_unity()(後者被拒時檔案已寫出)——照 df_common_expand_mask 的順序逐 band 以 float32 累加後逐位元比對 1.0f(一般路徑另印 inverse_unity_max_error)。C 側 host (pipelines/dfn/dfn_res_stage.c)在 get_mem_requirements() 再驗一次,所以載到一份 inverse 不是 partition of unity 的 ERB 矩陣會被 init 擋下,而不是讓 identity 悄悄變成近似。
