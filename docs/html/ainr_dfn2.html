AINR DeepFilterNet2 (48 kHz cascade + learned alpha)

概要

48 kHz 全頻帶降噪模型。網路只預測三個 head(ERB mask、低頻 deep-filter 係數、alpha 殘差混合權重),頻譜合成(cascade:全頻 ERB mask → 低頻 5-tap 複數 FIR → alpha blend) 全部由 C 端 dfn2_process.c 以 parameter-free 算式重現,對應 model.py 的 heads() / compose() 邊界。

項目值(以現行程式碼為準)
取樣率 / grid48000 Hz;FFT/win/hop = 1024/1024/512(21.33 ms 窗、10.67 ms hop;config.ini [signal]、DFN2_N_FFT/DFN2_HOP_LEN)
頻譜 bins513(DFN2_N_BINS)
ERB 帶數32(DFN2_N_ERB;Glasberg-Moore 三角 filterbank)
Deep filterdf_bins=96(0..4.5 kHz)、df_order=5、window [t-3 .. t+1]
Lookaheadmask_lookahead=1、df_lookahead=1;cascade 串聯 ⇒ 總延遲 2 hops(非 max)
參數量2,134,971(以出貨 config 實際建構 DeepFilterNet2(...) 量測)

深入數學與上游對齊紀錄見 README 與 UPSTREAM_ALIGNMENT。

API 用法

整合者直接用下一節的 dfn2_prepost 類別即可;以下是它底下的低階 API:部署端用 dfn2_compose_stream(),dfn2_compose() 是 frame-aligned 的 parity 參考, 兩者不可混用(切換須重新 dfn2_state_init())。

#include "DeepFilterNet2/dfn2_process.h"

DFN2State st;                       /* 85,536 bytes, 呼叫端配置 */
dfn2_state_init(&st);

for (each hop of 512 new samples) {
    dfn2_analysis(&st, frame512, spec_re, spec_im);        /* 原尺度頻譜 [513] */
    dfn2_compute_features(&st, spec_re, spec_im,
                          feat_erb /*[32]*/, feat_spec /*[192]*/);
    /* 送 (feat_erb, feat_spec) 給模型; 這一拍取回的是上一框
     * (current-1) 的 heads。前 1 拍 heads_valid=0。 */
    int valid = dfn2_compose_stream(&st, spec_re, spec_im, heads_valid,
                                    erb_mask /*[32]*/, coefs /*[960]*/,
                                    alpha, /*atten_lim_db=*/0.0f,
                                    out_re, out_im, &out_frame_idx);
    if (valid == 1)                          /* out 屬於 current-2 框 */
        dfn2_synthesis(&st, out_re, out_im, out512);
    /* valid==0: 暖機(不送 ISTFT); valid==-1: pointer/時序合約錯誤 */
}

Python 離線推論:inference.py --config config.ini --model ckpt.pt --input in.wav --output out.wav (torch STFT center=True,與 C 串流僅差 clip 起點框對齊,見 dfn2_process.h 檔頭 parity 限制)。

dfn2_prepost 類別(建議整合入口)

把「呼叫端音訊 ↔ 加速器張量」之間的每一件事收進一個物件:framing、ERB/複數特徵前端、deep-filter ring 與遞迴 cache 都不再由整合者直接碰。它是第三個 TU(dfn2_prepost.c),組合 dfn2_process.c 與 dfn2_model_io.c 而兩者都不改(它們必須各自可獨立連結)。 API 形狀與 AIAEC 的 ulcnet_prepost／deepvqe_prepost 一致。

DFN2PrepostConfig cfg;                            /* dfn2_prepost.h */
dfn2_prepost_config_defaults(&cfg, DFN2_IO_TIME);
cfg.fft = caller_fft;    /* TIME 必填,borrowed */   cfg.window = NULL;  /* 內建 sqrt-Hann */
cfg.erb_fwd = erb_fwd;   /* 兩個模式都必填 */        cfg.erb_inv = erb_inv;
cfg.atten_lim_db = 0.0f; /* 0 = 關閉 */

DFN2PrepostMemReq req;
dfn2_prepost_get_mem_size(&cfg, &req);        /* DFN2_IO_TIME: 314,496 bytes */
DFN2Prepost *p = dfn2_prepost_init_ex(pool, req.bytes, &cfg, &expected);

for (each hop of DFN2_HOP_LEN samples) {
    if (dfn2_prepost_pre_process(p, in_hop) == 1) {   /* 第 0 拍回 0,之後恆 1 */
        DFN2PrepostInputs in; DFN2PrepostOutputs out;
        dfn2_prepost_frame_inputs(p, &in, &out);      /* 指向本實例 pool 的 view */
        if (my_npu_run(&in, &out) != 0 || dfn2_prepost_frame_commit(p) != 0)
            dfn2_prepost_frame_skip(p);               /* identity,保住 framing 節奏 */
    }
    int written = 0;
    dfn2_prepost_post_process(p, out_hop, &written);  /* 前 2 拍 written = 0 */
}

_hop_size / _num_bins / _io_mode
_layout_version / _model_lookahead_frames		查詢,失敗 -1。後兩者 = DFN2_MODEL_IO_LAYOUT_VERSION,以及 framing 之外模型多付的 MASK_LOOKAHEAD + DF_LOOKAHEAD = 2 框
_pre_process(p, in_hop)
_pre_process_freq(p, re, im)		回這一拍需要的加速器呼叫次數:第 0 拍 0、之後 1。NULL／模式不符／frame 仍開著 → -1。_freq 吃已分析好的一框(見下方尺度警告),不做 transform
_pre_process_freq_dual(p, est_re, est_im, app_re, app_im)雙輸入(DFN2_IO_FREQ):est 餵估計分支(ERB/複數特徵、EMA 正規化器、[t-1,t,t+1] 圖視窗,即 heads),app 餵套用分支(mask／deep filter／atten-lim 作用的 noisy ring)。同一個 frame clock,兩者在 dfn2_process.c 內踩互斥的狀態,所以 est == app 時恰等於 _pre_process_freq()。命名為 est/app 而非 a/b:同型別的 pair 正是參數對調藏身處。回傳同 _pre_process_freq

_post_process(p, out_hop, &written)

Transaction 規則

  • frame_inputs 把每個可寫輸出預填 NaN,「加速器只寫了一半」會在 commit 被抓到。
  • frame_commit 先驗證再搬動。失敗時什麼都不動(持久狀態 byte-identical、frame 維持開啟、回 -1), 接著只有兩條路:frame_skip(),或重新 frame_inputs() 再跑一次加速器。
  • commit 前一定要有一次 frame_inputs(prepared 閂鎖):沒跑過的加速器不能把 沒被碰過的 buffer 當結果。frame 開著時 pre_process 回 -1,一拍被拒絕而不是默默疊上去。
  • skip 是精確的 identity,不是近似:erb_inv 是 partition of unity (每個 bin 的 band 權重和為 1),unit band mask 展開後就是 unit bin gain,noisy 頻譜原樣穿過 cascade。 兩條匯出路徑都會擋:一般路徑查 inverse_unity_max_error(1e-6),--runtime-bins 在寫檔前呼叫 require_partition_of_unity()——照 df_common_expand_mask 的順序逐 band 以 float32 累加後逐位元比對 1.0f(export_erb_matrix.py:27-43, 86)。C 側 host (pipelines/dfn_res_stage.c:86-105)在 get_mem_requirements() 再驗一次,所以載到一份 不是 partition of unity 的 erb_inv.bin 會被 init 擋下,而不是讓 identity 悄悄變成近似。
  • pre_process 回的是次數不是布林:analysis 是 center=False,一拍就是一框,但圖吃 [t-1, t, t+1],第 0 拍沒有右鄰居、不可以呼叫加速器,所以回 0;之後每拍恰好一次推論。

Setter 的保證邊界

_set_erb_matrices()(換 --runtime-bins 產出的 .bin,borrowed 不複製)與 _set_atten_lim() 都是 hop 之間限定:frame 開著時回 -1,換手不會落在同一筆交易中間。

這買到的是 per-hop atomicity,不是 per-source-frame consistency:hop t 展開的 mask 屬於 source frame t−1、特徵視窗又橫跨三拍,一次被接受的換手仍會有幾拍同時踩到新舊矩陣。 要 per-source-frame 一致就先 reset 再換。

⚠ DFN2_IO_FREQ 的頻譜尺度

本類別在 DFN2_IO_FREQ 收發的頻譜是 torch.stft(normalized=True):sqrt-Hann 加窗後 DFN2_N_FFT 區塊的 rfft 再乘 1/√DFN2_N_FFT = 1/32(dfn2_analysis() 套上、 dfn2_synthesis() 還原)。AIAEC 模型與 pipeline 的 AEC seam 交出的都是未正規化(audio-scale)的 rfft, 直接餵進來會剛好過驅動 32 倍,反向欠驅動 32 倍;兩邊都偵測不到——都是量綱合法的 float 頻譜, ERB 特徵又是 EMA 正規化的,mask 仍看起來合理,只有輸出電平是錯的。跨這個邊界必須自己換算 (× 1/32 進、× 32 出)。

兩支 DFN2 pipeline 就是這樣做的:pipelines/dfn_res_stage.c 以 hex-float 0x1p-5f/0x1p5f 精確的 2 的次方換算(dfn_res_stage.h:86-89)。AIAEC 那條路另外還跨 grid (這裡 48 kHz/1024/512,AIAEC 16 kHz/512),中間本來就有 resampler,換算就放在那一層。 DFN2_ANALYSIS_SCALE 不是這個因子——那是特徵分支內部(libDF wnorm 殘留), 只作用在餵給正規化器的那份拷貝,從不碰 masking/ISTFT 路徑上的頻譜。

加速器 callback 邊界:DFN2Model

host 不擁有 runtime,只擁有四個指標(dfn2_prepost.h:438-444);邊界放在 prepost 而非 dfn2_process.h,因為 dfn2_process.c 必須能單獨編給 parity build。

typedef struct DFN2Model {
    void *user;
    int (*infer)(void *user, const DFN2PrepostInputs *inputs,
                 DFN2PrepostOutputs *outputs);   /* 回 0 = 每個輸出都寫了 */
    void (*reset)(void *user);                   /* 可選;hosting stage reset 時呼叫 */
    const DFN2ModelIoDescriptor *io_descriptor;  /* NULL = 未發布 */
} DFN2Model;

int dfn2_model_run_frame(const DFN2Model *model, DFN2Prepost *p);

dfn2_model_run_frame() 把一個已開啟的 frame 走完:frame_inputs()(NaN 預填)→ infer() → frame_commit();infer() 回非 0 或 commit 被拒(輸出未寫或非有限)時改走 frame_skip(), 所以 framing 與 compose 兩個時鐘永遠恰好前進一次。有限性規則不在這裡重寫一份——那是 frame_commit() 的責任。回 1 = heads 已 commit、0 = 該幀被 skip、-1 = 契約錯誤(model/instance 為 NULL、 沒有 infer、或沒有開啟中的 frame)。與 AIAEC 的 identity 政策不同:被 skip 的幀仍然吐出兩拍前的 source frame ——identity 是在 cascade 內部套用的,時序從不改變(dfn2_prepost.h:446-456)。

有 infer 就必須發布 descriptor。DFN2ModelIoDescriptor(dfn2_model_io.h:40-59)是 18 個欄位的圖合約:layout_version、sample_rate、fft_size、hop_size、 spectrum_bins、erb_bands、df_bins、df_order、mask_lookahead、 df_lookahead、input_frames、encoder_gru_layers、erb_gru_layers、 df_gru_layers、gru_hidden、encoder_channels、df_pathway_history、 state_tensor_count(=4)。_descriptor_default() 填本 build 的值,_descriptor_validate() 逐欄位比對(不是 memcmp,padding 不得參與決定),不合即 -1。欄位全是編譯期常數(沒有 Align-ULCNet delay_depth 那種部署自由度),所以 validate(default())==0 恆真,它唯一的工作是擋掉對著另一個 layout 版本或另一組幾何匯出的圖——那正是 NaN 預填看不見的一類錯誤(抓得到「沒寫」,抓不到「形狀不對」)。

實際消費者:pipelines/dfn_res_stage.c。它在 get_mem_requirements() 就把 「有 infer 卻沒 descriptor」「descriptor 被 validate() 拒絕」「有 reset／descriptor 卻沒 infer」三種組合一併拒掉(:79-85),再由 mono 與 4ch 兩支 DFN2 pipeline 使用;它們走的是雙輸入入口(估計用 pre-RES 頻譜、 套用在 post-RES 頻譜)。

ONNX/匯出邊界:model.py heads() 即匯出邊界——圖內只有網路 (encoder/ERBDecoder/DFDecoder),ERB mask 展開、DF FIR、alpha blend、PF、atten-lim、ISTFT 全在圖外的 C。 stateless heads graph 每次由 host 傳入 3 幀 feature window 與四個顯式 state (出貨 split layout 共六個 input:erb、spec、h_encoder、 h_erb、h_df、df_convp_history),取回三個 head 與四個 *_out;加速器本身不保存跨次呼叫狀態。C 端 dfn2_model_io_commit_state()／_commit_arrays() 在寫入前驗證整批 next-state, NULL/NaN/Inf 回 -1 且保留上一筆 state。

Recurrent state layout(--gru-state-layout,export_onnx.py 與 inference.py calib 同旗標):split = state layout version 5,出貨合約——每顆 GRU 一個 tensor, 維持 PyTorch 原生 stacked 形狀 (num_layers, 1, hidden),與 DFN2ModelIOState 的 [layers][hidden] 陣列逐一對位;dfn2_model_io.h 綁的就是這個 layout。 combined = version 7,EXPERIMENTAL、無 C runtime 綁定(三顆併成一個 h_gru (1,5,1,256), 只用來量測共用量化 scale 的代價)。version 4 與 6 已退役;合約測試把 DFN2_MODEL_IO_LAYOUT_VERSION 同時對退役號碼與 combined 號碼檢查,C 端誤 bump 到 4、6、7 會當場失敗。

易誤解處:ONNX 沒有 stacked GRU op,兩層的 stack 仍展開成兩個 GRU node——實測兩種 layout 都是 5 個 GRU node(1+2+2 層)。version 5 換掉的不是 Slice,是 PTQ scale 的粒度:per-GRU 而非 per-layer,h_erb 兩層共用同一個 input tensor 與同一個量化 scale。

延遲與 warm-up

  • 演算法延遲(模型側)= 2 hops = 1024 samples = 21.33 ms @48 kHz:DFN2 是 cascade——DF 的未來 tap 需要「已套 mask 的 t+1」,mask(t+1) 又需要 feat(t+2),所以 MASK_LOOKAHEAD + DF_LOOKAHEAD = 1+1 = 2 框,相加而非取 max。
  • STFT framing 結構延遲:win−hop = 512 samples = 10.67 ms(WOLA 重疊)。
  • Warm-up:dfn2_compose_stream() 前 2 次呼叫回 0(無輸出,不送 ISTFT); 右端 flush 須由中介硬體以訓練同款 zero padding 產生剩餘 heads 再以零頻譜續呼。
  • 正規化器 EMA warm-up:tau = 1.0 s(α=0.989,3·tau ≈ 273 框);init 用 libDF linspace 值。
  • 對齊守衛:tests/test_c_prepost.c: test_dfn_stream_alignment() 用逐框變動的 mask/coefs 驗證 output_frame_index 與逐 bin 3e-6 一致性,off-by-one 的配對無法以「輸出有限」矇混過關。
