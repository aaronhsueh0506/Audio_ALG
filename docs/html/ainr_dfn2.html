AINR DeepFilterNet2 (48 kHz cascade + learned alpha)

概要

48 kHz 全頻帶降噪模型。網路只預測三個 head(ERB mask、低頻 deep-filter 係數、alpha 殘差混合權重),頻譜合成(cascade:全頻 ERB mask → 低頻 5-tap 複數 FIR → alpha blend) 全部由 C 端 dfn2_process.c 以 parameter-free 算式重現,對應 model.py 的 heads() / compose() 邊界。

API 用法

不想自己管 framing、特徵前端與 ring 的整合者,直接用下一節的 dfn2_prepost 類別。 以下是它底下的低階 API:部署端(串流/加速器 handoff)用 dfn2_compose_stream(); dfn2_compose() 是 frame-aligned 的 parity 參考,兩者不可混用 (切換須重新 dfn2_state_init())。

#include "DeepFilterNet2/dfn2_process.h"

DFN2State st;                       /* 85,632 bytes, 呼叫端配置 */
dfn2_state_init(&st);

for (each hop of 512 new samples) {
    dfn2_analysis(&st, frame512, spec_re, spec_im);        /* 原尺度頻譜 [513] */
    dfn2_compute_features(&st, spec_re, spec_im,
                          feat_erb /*[32]*/, feat_spec /*[192]*/);
    /* 送 (feat_erb, feat_spec) 給模型; 這一拍取回的是上一框
     * (current-1) 的 heads。前 1 拍 heads_valid=0。 */
    int valid = dfn2_compose_stream(&st, spec_re, spec_im, heads_valid,
                                    erb_mask /*[32]*/, coefs /*[960]*/,
                                    alpha, /*atten_lim_db=*/0.0f,
                                    out_re, out_im, &out_frame_idx);
    if (valid == 1)                          /* out 屬於 current-2 框 */
        dfn2_synthesis(&st, out_re, out_im, out512);
    /* valid==0: 暖機(不送 ISTFT); valid==-1: pointer/時序合約錯誤 */
}

dfn2_prepost 類別(建議整合入口)

把「呼叫端音訊 ↔ 加速器張量」之間的每一件事收進一個物件:framing、ERB/複數特徵前端、 deep-filter ring 與遞迴 cache 都不再由整合者直接碰。它是第三個 TU (dfn2_prepost.c),組合 dfn2_process.c 與 dfn2_model_io.c 而兩者都不改(它們必須各自可獨立連結:test_python_c_prepost_parity.py 只編前者)。API 形狀與 AIAEC 的 ulcnet_prepost／deepvqe_prepost 一致。

#include "DeepFilterNet2/dfn2_prepost.h"

DFN2PrepostConfig cfg;
dfn2_prepost_config_defaults(&cfg, DFN2_IO_TIME);
cfg.fft          = caller_fft;   /* TIME 必填,borrowed,DFN2_N_FFT 尺寸 */
cfg.window       = NULL;         /* NULL = 內建 sqrt-Hann(出貨路徑都用這個) */
cfg.erb_fwd      = erb_fwd;      /* 兩個模式都必填,borrowed */
cfg.erb_inv      = erb_inv;
cfg.atten_lim_db = 0.0f;         /* 0 = 關閉 */

DFN2PrepostMemReq req;
dfn2_prepost_get_mem_size(&cfg, &req);        /* DFN2_IO_TIME: 314,464 bytes */
DFN2Prepost *p = dfn2_prepost_init_ex(pool, req.bytes, &cfg, &expected);

for (each hop of DFN2_HOP_LEN samples) {
    int n = dfn2_prepost_pre_process(p, in_hop);   /* 第 0 拍回 0,之後恆 1 */
    if (n == 1) {
        DFN2PrepostInputs  in;
        DFN2PrepostOutputs out;
        dfn2_prepost_frame_inputs(p, &in, &out);   /* 指向本實例 pool 的 view */
        if (my_npu_run(&in, &out) != 0 || dfn2_prepost_frame_commit(p) != 0)
            dfn2_prepost_frame_skip(p);            /* identity,保住 framing 節奏 */
    }
    int written = 0;
    dfn2_prepost_post_process(p, out_hop, &written);  /* 前 2 拍 written = 0 */
}

Transaction 規則

  • frame_inputs 把每個可寫輸出預填 NaN,「加速器只寫了一半」會在 commit 被抓到, 而不是把上一框的值當成本框結果。
  • frame_commit 先驗證再搬動。失敗時什麼都不動——持久狀態 byte-identical、 frame 維持開啟、回 -1;接著只有兩條路:frame_skip(),或重新 frame_inputs() 再跑一次加速器。
  • commit 後面一定要有一次 frame_inputs(prepared 閂鎖):沒跑過的加速器 不能把沒被碰過的 buffer 當結果送出。frame 開著時 pre_process 回 -1,一拍被拒絕而不是默默疊上去。
  • skip 是精確的 identity,不是近似:erb_inv 是 partition of unity (每個 bin 的 band 權重和為 1),unit band mask 展開後就是 unit bin gain,noisy 頻譜原樣穿過 cascade。 這個性質由 export_erb_matrix.py 的矩陣匯出路徑檢查(inverse_unity_max_error,門檻 1e-6); --runtime-bins 那條路徑提早 return,不跑這道檢查。
  • pre_process 回的是次數不是布林。DFN2 analysis 是 center=False,一拍進去就是一框; 但圖吃 [t-1, t, t+1],第 0 拍沒有右鄰居,不可以在那拍呼叫加速器,所以回 0。之後每拍恰好一次推論。

Setter 的保證邊界

_set_erb_matrices()(換 export_erb_matrix.py --runtime-bins 產出的 erb_fwd.bin／erb_inv.bin,borrowed 不複製)與 _set_atten_lim() 都是 hop 之間限定:frame 開著時回 -1,所以換手絕不會落在同一筆交易中間(特徵已經過 erb_fwd、mask 還沒過 erb_inv)。

這買到的是 per-hop atomicity,不是 per-source-frame consistency。 MASK_LOOKAHEAD = 1,hop t 展開的 mask 屬於 source frame t−1, 而圖的特徵視窗 [t-1, t, t+1] 又橫跨三拍;一次被接受的 between-hop 換手仍會有幾拍同時踩到新舊矩陣。 atten-lim 同理:限制在「落後特徵一個 lookahead」的發射點才套上。要 per-source-frame 一致就是一個 stream boundary——先 reset,再換。

⚠ DFN2_IO_FREQ 的頻譜尺度

本類別在 DFN2_IO_FREQ 收發的頻譜是 torch.stft(normalized=True):sqrt-Hann 加窗後 DFN2_N_FFT 區塊的 rfft 再乘 1/√DFN2_N_FFT = 1/32(dfn2_analysis() 套上、 dfn2_synthesis() 還原)。AIAEC 模型交出的是未正規化的 rfft,把 AIAEC 頻譜直接餵進 _pre_process_freq() 會剛好過驅動 32 倍,反向欠驅動 32 倍。兩邊都偵測不到: 都是量綱合法的 float 頻譜,ERB 特徵又是 EMA 正規化的,mask 仍然看起來合理,只有輸出電平是錯的。 跨這個邊界必須自己換算:

aiaec_spectrum -> dfn2 :  乘 1.0f / sqrtf(DFN2_N_FFT)
dfn2 -> aiaec_spectrum :  乘 sqrtf(DFN2_N_FFT)

兩者也不在同一個 grid(這裡 48 kHz/1024/512,AIAEC 16 kHz/512),中間本來就有 resampler, 換算就放在那一層。DFN2_ANALYSIS_SCALE 不是這個因子——那是特徵分支內部(libDF wnorm 殘留), 只作用在餵給正規化器的那份拷貝,從不碰 masking/ISTFT 路徑上的頻譜。

延遲:類別不改變模型自己的 2 hop lookahead。實測 identity 路徑(unit mask、alpha 0): 最新輸出落後最新吃進的輸入 3 hops = 1536 samples = 32.0 ms @48 kHz = WOLA framing 1 hop + 模型 lookahead 2 hops;post_process() 前兩拍 written = 0 就是付掉它們的地方。 收尾 flush 用全零 hop 再跑 2 拍,加速器那兩拍也要照跑(訓練時的 zero padding)。詳見下面「延遲與 warm-up」。

State 表

ONNX/匯出邊界:model.py heads() 即匯出邊界——圖內只有網路 (encoder/ERBDecoder/DFDecoder);ERB mask 展開、DF FIR、alpha blend、PF、atten-lim、 ISTFT 全在圖外的 C。export_onnx.py 已交付 stateless heads graph： 每次由 host 傳入 3 幀 feature window、三個 GRU hidden tensor 與 DF pathway history (出貨 split layout 共六個 input:erb、spec、 h_encoder、h_erb、h_df、df_convp_history)， 並取回三個 head 與四個 *_out state；加速器本身不保存跨次呼叫狀態。 C 端 dfn2_model_io_commit_state()／dfn2_model_io_commit_arrays() 收下 erb_hidden_next[2][256] 與 df_hidden_next[2][256] 兩個 stacked 陣列， 在寫入前驗證整批 next-state，NULL/NaN/Inf 會回傳 -1 且保留上一筆 state。

Recurrent state layout(--gru-state-layout,export_onnx.py 與 inference.py calib 同旗標): split = state layout version 5,出貨合約——每顆 GRU 一個 tensor,維持 PyTorch 原生 stacked 形狀 (num_layers, 1, hidden),與 DFN2ModelIOState 的 [layers][hidden] 陣列逐一對位,runtime 一個 tensor 綁一塊連續欄位; dfn2_model_io.h 綁的就是這個 layout。 combined = state layout version 7,EXPERIMENTAL、無 C runtime 綁定——三顆併成一個 h_gru (1,5,1,256),input 只剩四個,用來量測「三顆共用一個量化 scale 值多少」 (inference.py calib 額外輸出 gru_state_slices 報告)。 version 4 與 6 已退役(RETIRED_LAYOUT_VERSIONS);合約測試把 DFN2_MODEL_IO_LAYOUT_VERSION 同時對退役號碼與 combined 號碼檢查, C 端誤 bump 到 4、6 或 7 會當場失敗。

易誤解處:ONNX 沒有 stacked GRU op,兩層的 stack 仍展開成兩個 GRU node、 由 per-layer Slice 餵入——實測兩種 layout 都是 5 個 GRU node(1+2+2 層)。 version 5 換掉的不是 Slice,是 PTQ scale 的粒度:per-GRU 而非 per-layer, h_erb 兩層共用同一個 input tensor 與同一個量化 scale。version 3 是把 stack 複製成單層 module 才買到 per-layer scale;此合約選的是原生形狀與 C struct 的精確對位。

延遲與 warm-up

  • 演算法延遲(模型側)= 2 hops = 1024 samples = 21.33 ms @48 kHz: DFN2 是 cascade——DF 的未來 tap 需要「已套 mask 的 t+1」,而 mask(t+1) 又需要 feat(t+2), 所以 MASK_LOOKAHEAD + DF_LOOKAHEAD = 1+1 = 2 框,相加而非取 max (見 dfn2_process.h 與 dfn2_compose_stream())。
  • STFT framing 結構延遲:win−hop = 512 samples = 10.67 ms(WOLA 重疊)。
  • Warm-up:dfn2_compose_stream() 前 2 次呼叫回 0(無輸出,不送 ISTFT); 右端 flush 須由中介硬體以訓練同款 zero padding 產生剩餘 heads 再以零頻譜續呼。
  • 正規化器 EMA warm-up:tau = 1.0 s(α=0.989,3·tau ≈ 273 框); init 用 libDF linspace 值,故起始特徵即在上游量級。
  • 對齊守衛:tests/test_c_prepost.c: test_dfn_stream_alignment() 用逐框變動的 mask/coefs 驗證 output_frame_index 與逐 bin 3e-6 一致性,off-by-one 的 head/spectrum 配對無法以「輸出有限」矇混過關。
