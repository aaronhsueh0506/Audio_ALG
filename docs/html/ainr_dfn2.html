AINR DeepFilterNet2 (cascade + learned alpha;出貨 48 kHz grid)

概要

如何呼叫、流程時序圖、外部／內部參數表：ainr_dfn2_usage。

全頻帶降噪模型,本頁數字為出貨 grid(48 kHz)。函式庫只處理頻譜:框化、FFT、窗與反 FFT 是應用端以 audiolib 的 AcStft／AcIstft 做的;grid 由應用端於執行期以 DFN2GridSpec 給定、經 dfn2_grid_make() 得到 DFN2Grid,見 ainr_dfn2_grids。網路只預測三個 head(ERB mask、低頻 deep-filter 係數、alpha 殘差混合權重),頻譜合成(cascade:全頻 ERB mask → 低頻 5-tap 複數 FIR → alpha blend) 全部由 C 端 dfn2_process.c 以 parameter-free 算式重現,對應 model.py 的 heads() / compose() 邊界。

API 用法

整合者直接用下一節的 dfn2_prepost 類別即可;以下是它底下的低階 API:部署端用 dfn2_enhance_spectrum_stream(),dfn2_enhance_spectrum() 是 frame-aligned 的 parity 參考, 兩者不可混用(切換須 dfn2_state_reset())。函式庫不持有窗、FFT 或 STFT 物件;應用端的 AcStft／AcIstft 須照訓練:audiolib 預設的 sqrt-Hann、center 0、hop = n_fft/2、AC_OLA_ACCUMULATE,spec_scale = grid.stft_scale(1/√n_fft,出貨 1/32)、ispec_scale = grid.stft_unscale(32)。窗或尺度錯了函式庫偵測不到;與訓練圖 center=True 的差別只在 clip 第一框(dfn2_process.h 檔頭)。

#include "DeepFilterNet2/dfn2_process.h"
#include "audio_stft.h"

DFN2Grid grid;                      /* spec 為 DFN2GridSpec,出貨值見 ainr_dfn2_grids */
dfn2_grid_make(&grid, &spec);       /* 回 DFN2_GRID_OK 才可用 */
DFN2State st;                       /* 標頭;陣列在下面那一塊 */
dfn2_state_init(&st, block, dfn2_state_mem_size(&grid), &grid);  /* 48 kHz 1/1: 67,904 bytes, 16 bytes 對齊 */
dfn2_set_erb_matrices(&st, erb_fwd, erb_inv);   /* 應用端載入的 ERB 矩陣;特徵與 mask 展開之前必呼叫 */

AcStftConfig fc;                    /* 框化是應用端的 */
ac_stft_config_default(&fc, grid.n_fft);
fc.spec_scale = grid.stft_scale;  fc.ispec_scale = grid.stft_unscale;
AcStft  *stft  = ac_stft_init(mem_a, ac_stft_get_mem_size(&fc), &fc);
AcIstft *istft = ac_istft_init(mem_s, ac_istft_get_mem_size(&fc), &fc);

for (each hop of 512 new samples) {
    ac_stft_push_planar(stft, hop_in, spec_re, spec_im);        /* normalized=True 頻譜 [513] */
    dfn2_compute_features(&st, spec_re, spec_im,
                          feat_erb /*[32]*/, feat_spec /*[192]*/);
    /* 送 (feat_erb, feat_spec) 給模型; 這一拍取回的是上一框
     * (current-M) 的 heads。前 M 拍 heads_valid=0(出貨 M=1)。 */
    int valid = dfn2_enhance_spectrum_stream(&st, spec_re, spec_im, heads_valid,
                                    erb_mask /*[32]*/, coefs /*[960]*/,
                                    alpha, /*atten_lim_db=*/0.0f,
                                    out_re, out_im, &out_frame_idx);
    if (valid == 1)                          /* out 屬於 current-(M+D) 框 */
        ac_istft_push_planar(istft, out_re, out_im, out_hop);
    /* valid==0: 暖機(不送 ISTFT); valid==-1: pointer/時序合約錯誤 */
}

dfn2_prepost 類別(建議整合入口)

把「呼叫端頻譜 ↔ 加速器張量」之間的每一件事收進一個物件:ERB/複數特徵前端、deep-filter ring、遞迴 state 的有限性檢查都不再由整合者直接碰;框化與 FFT 仍是應用端的 audiolib。它是第三個 TU(dfn2_prepost.c),組合 dfn2_process.c 與 dfn2_model_io.c 而兩者都不改(它們必須各自可獨立連結)。

DFN2PrepostConfig cfg;                            /* dfn2_prepost.h */
dfn2_prepost_config_defaults(&cfg, &grid);        /* 複製 grid */
cfg.erb_fwd = erb_fwd;  cfg.erb_inv = erb_inv;    /* 必填,借用 */
cfg.atten_lim_db = 0.0f;                          /* 0 = 關閉 */
cfg.gru_hidden = gru;  cfg.gru_hidden_elements = 5 * 256;                    /* 浮點 host:登錄自己的 state; */
cfg.df_convp_history = convp;  cfg.df_convp_history_elements = 64 * 5 * 96;  /* 板端:四個欄位留 NULL／0 */

DFN2PrepostMemReq req;
dfn2_prepost_get_mem_size(&cfg, &req);        /* 48 kHz 1/1: 92,608 bytes */
DFN2Prepost *p = dfn2_prepost_init_ex(pool, req.bytes, &cfg, &req);
unsigned seen = dfn2_prepost_state_generation(p); /* 上次看到的 state generation */
my_npu_fill_state_with_quantized_zero();          /* 板端:啟動時先填量化後的零 */

for (each hop of grid.hop samples) {
    ac_stft_push_planar(stft, hop_in, re, im);
    dfn2_prepost_pre_process_freq(p, re, im);          /* N=1:每 hop 回 1;前 M 拍是暖機幀 */
    DFN2PrepostInputs in; DFN2PrepostOutputs out;
    dfn2_prepost_frame_open(p, &in, &out);          /* 指向本實例 pool 與登錄 state 的 view;位址固定 */
    if (dfn2_prepost_state_generation(p) != seen) {   /* reset、暖機幀或被拒的 commit 清了 state */
        my_npu_fill_state_with_quantized_zero();      /* 板端:加速器自己那份定點 state 也要歸零 */
        seen = dfn2_prepost_state_generation(p);
    }
    if (my_npu_run(&in, &out) != 0 ||              /* state 輸入與 *_next 綁同一個位址,就地寫入 */
        dfn2_prepost_frame_finish(p) != 0)
        dfn2_prepost_frame_bypass(p);                 /* 原頻譜直通,保住 framing 節奏 */
    dfn2_prepost_post_process_freq(p, out_re, out_im, NULL);   /* 前 M+D 拍輸出零頻譜 */
    ac_istft_push_planar(istft, out_re, out_im, out_hop);      /* 每 hop 都 push */
}
函式語意(以 dfn2_prepost.h 為準)
_config_defaults(cfg, grid)複製 grid(無效 grid 回 -1);ERB 矩陣與 state 登錄留 NULL／0
_get_mem_size(cfg, &req)精確 pool 大小。reject-first:NULL、缺 ERB、非有限 atten_lim_db、grid 無效、state 登錄不合規則(見細節頁) → -1 且 *req 不動
_init(pool, bytes, cfg)
_init_ex(..., expected)		在呼叫端記憶體建構,起始即 reset;_init_ex 多一道 stale-pool gate(32-byte DFN2PrepostMemReq 不符即拒絕)
_create(cfg) / _destroy(p)host 工具/測試用;destroy 只釋放 create 配置的東西,對 _init 實例是 no-op,也從不釋放矩陣或登錄的 state
_reset(p)清空 ring、登錄的 state,丟掉未結束的 frame,時鐘與正規化器回 init 值;state generation 加 1。應用端自己的 AcStft／AcIstft 要另外 reset
_state_generation(p)遞迴 state 被函式庫歸零的次數計數:init 後為 1,每次 _reset、每個暖機幀與每次被拒的 _frame_finish 加 1;NULL 回 0。有自己一份定點 state 的 runtime 在啟動時先填成量化後的零,之後每發現數值變了就再填一次;沒有登錄 state 時函式庫只計數
_hop_size / _num_bins
_layout_version / _model_lookahead_frames / _grid		查詢,失敗 -1(_grid:NULL)。_layout_version = DFN2_MODEL_IO_LAYOUT_VERSION;_model_lookahead_frames = dfn2_prepost_latency_frames() = M+D+N-1 框(出貨 2);_grid = 實例的 grid
_pre_process_freq(p, re, im)吃已分析好的一框(見下方尺度警告),回這一拍需要的加速器呼叫次數:N=1 每拍 1(前 M 拍暖機);N>1 見細節頁。NULL／frame 仍開著 → -1
_pre_process_freq_dual(p, est_re, est_im, app_re, app_im)雙輸入:est 餵估計分支(ERB/複數特徵、EMA 正規化器、[t-(2-M)..t+M] 圖視窗,即 heads),app 餵套用分支(mask／deep filter／atten-lim 作用的 noisy ring)。同一個 frame clock,兩者踩互斥的狀態,所以 est == app 時恰等於 _pre_process_freq()。回傳同 _pre_process_freq
_frame_open(p, &in, &out)公開本框加速器邊界;三個 head 預填 NaN,state 不預填(登錄的 buffer 原址、未登錄為 NULL／0)。無開啟的 frame → -1
_frame_finish(p)驗證每個 head 與登錄的 state 有限(純驗證,不複製)→ 建構增強頻譜(ERB 展開、deep filter、alpha blend、atten-lim)。暖機幀不看 heads:state 歸零、generation +1、回 0
_frame_bypass(p)本框取 identity:unit ERB mask + alpha 0;遞迴 state 維持原樣(就地路徑為加速器寫完的樣子;回報失敗的 runtime 視為沒有寫入),framing 與合成時鐘照走;暖機幀同 finish(歸零、+1)
_post_process_freq(p, re, im, &valid)輸出頻譜與輸入同一個 normalized=True 尺度;前 M+D 拍 *valid = 0 且頻譜為零(valid 只是資訊,可為 NULL),之後 1;frame 仍開著 → -1
_output_frame_index(p, &frame)最近一次輸出屬於哪個 source frame(自 reset 起算);尚未輸出或 NULL → -1
_set_erb_matrices(p, fwd, inv) / _set_atten_lim(p, db)只能在 hop 之間呼叫,保證邊界見 ainr_dfn2_detail

Transaction 規則

  • frame_open 對三個 head 預填 NaN,「加速器只寫了一半」會在 finish 被抓到。
  • frame_finish 是純驗證:head 與登錄的 state 皆有限才進合成。就地路徑遇非有限值時 state 已被覆寫、無法回滾, 登錄的遞迴張量歸零、state generation 加 1(沒有登錄 state 時只加 generation,由應用端重填加速器的 state),合成不執行、framing／feature window 不動、frame 維持開啟、回 -1; 接著只有兩條路:frame_bypass(),或 frame_open() 從冷 state 重跑。寫一半而仍有限者偵測不到。
  • finish 前一定要有一次 frame_open(prepared 閂鎖):沒跑過的加速器不能把 沒被碰過的 buffer 當結果。frame 開著時 pre_process_freq 回 -1。
  • bypass 是精確的 identity,不是近似:erb_inv 須是 partition of unity,匯出與 host 都會擋(見細節頁)。
  • pre_process_freq 回的是次數不是布林:圖吃 [t-(2-M), .., t+M],前 M 拍(出貨 M=1:第 0 拍)是暖機幀:加速器照跑,heads 丟棄、state 歸零、generation +1,音訊不變;N=1 每拍 1,N>1 與 M=0 不變。

⚠ 頻譜尺度

本類別收發的頻譜是 torch.stft(normalized=True):sqrt-Hann 加窗後 grid.n_fft 區塊的 rfft 再乘 1/√n_fft(grid.stft_scale,出貨 grid 為 1/32;由應用端 AcStft 的 spec_scale 套上、AcIstft 的 ispec_scale = grid.stft_unscale 還原)。AIAEC 模型與 pipeline 的 AEC seam 交出的都是未正規化(audio-scale)的 rfft, 直接餵進來會剛好過驅動 √n_fft 倍(出貨 grid 32 倍),反向欠驅動同倍;兩邊都偵測不到——都是量綱合法的 float 頻譜, ERB 特徵又是 EMA 正規化的,mask 仍看起來合理,只有輸出電平是錯的。跨這個邊界必須自己換算 (出貨 grid × 1/32 進、× 32 出;一般用 grid.stft_scale／stft_unscale)。

兩支 DFN2 pipeline 的 stage 收 audio-scale 頻譜,以 DfnResStageConfig.grid 的 stft_scale／stft_unscale（出貨 grid 為 2-5／25）自行換算,其 AcStft／AcIstft 留 scale 1。 特徵分支內部另有一次同值的縮放(libDF wnorm 殘留), 只作用在餵給正規化器的那份拷貝,從不碰 masking/ISTFT 路徑上的頻譜。

State 表

ONNX/匯出邊界:model.py heads() 即匯出邊界——圖內只有網路 (encoder/ERBDecoder/DFDecoder),ERB mask 展開、DF FIR、alpha blend、PF、atten-lim、ISTFT 全在圖外的 C 與應用端。 stateless heads graph 每次由 host 傳入 3 幀 feature window 與兩個顯式 state (出貨 layout 8 共四個 input:erb、spec、h_gru、 df_convp_history),取回三個 head 與兩個 *_out;state 的 *_out 與輸入綁同一個位址;加速器本身不保存跨次呼叫狀態。C 端 dfn2_model_io_validate_state(state)／_validate_arrays(...) 在加速器寫完後驗證登錄的兩個遞迴陣列: 全部有限回 0;任何非有限值則陣列歸零並回 -1(_validate_state 同時讓 state generation 加 1;沒有登錄 state 時回 0)。DFN2Prepost 類別的 frame_finish() 內部做同一件事。

State 邊界(layout version 8,export_onnx.py、inference.py calib):兩個 state tensor 都是 rank 4,輸入與 *_out 輸出 shape 完全相同;metadata 記 state_binding = in_place_same_address。函式庫不含這兩個張量的形狀常數:它們是應用端登錄(或板端加速器持有)的 buffer,元素數由應用端給(dfn2_test_grid.h 的 DFN2_TEST_GRU_*／DFN2_TEST_CONVP_* 是一例)。圖內的 Slice／Concat 結構、GRU 列序、量化後檢查與退役版號見 ainr_dfn2_detail「遞迴 state 的圖邊界」。

延遲與 warm-up

  • 演算法延遲(模型側)= M+D hops(出貨 1/1:2 hops = 1024 samples = 21.33 ms @48 kHz):DFN2 是 cascade——DF 的未來 tap 需要「已套 mask 的 t+D」,mask(t+D) 又需要 feat(t+D+M),所以 mask_lookahead + df_lookahead 框,相加而非取 max。
  • STFT framing 結構延遲:win−hop = 512 samples = 10.67 ms(WOLA 重疊)。
  • Warm-up:dfn2_enhance_spectrum_stream() 前 M+D 次呼叫回 0(無輸出,不送 ISTFT); 右端 flush 須再推 M+D+1 個全零 hop(含 ISTFT 重疊 1 個),加速器照跑;N 個 frame 時再加 N-1。
  • 正規化器 EMA warm-up:tau = 1.0 s(α=0.989,有效 tau 0.9644 s ≈ 90.4 框,3·tau ≈ 271 框);init 用 libDF linspace 值。
  • 對齊守衛:tests/test_c_prepost.c: test_dfn_stream_alignment() 用逐框變動的 mask/coefs 驗證 output_frame_index 與逐 bin 3e-6 一致性,off-by-one 的配對無法以「輸出有限」矇混過關。
